# Поставщики

Функциональная документация страницы. Основание: [ТЗ «Поставщики»](https://app.clickup.com/t/90182877012/z8wf5rju4k), PDF от 10 ноября 2026 года и уточнения пользователя от 11 ноября 2026 года. Функциональный прогон по этому документу ещё не выполнялся.

## План тестирования

[Единый чек-лист страницы](CHECKLIST.md) содержит все семь блоков. Проходить их можно по порядку; внутри каждого блока выделены согласованные правила, исследовательские сценарии и проверки при готовности зависимостей.

| Блок | Состав | Проверки |
| --- | --- | --- |
| 1. Список поставщиков | Открытие страницы, дерево стран и переключение, фильтры статуса и счётчики, поиск и сочетание с фильтрами, отображение данных, редактирование User ID, смена статуса, меню ☰, открытие TRN и License. | [Блок 1](CHECKLIST.md#1-список-поставщиков) |
| 2. Добавление поставщика | Форма, реквизиты и файлы, аккаунт админа, выбор страны, автоматический ID, сохранение и первоначальный статус. | [Блок 2](CHECKLIST.md#2-добавление-поставщика) |
| 3. Редактирование поставщика | Форма и изменение User Name, Company Name, Shipping From и Doc прямо в таблице; Enter и клик вне поля; смена страны с сохранением User ID. | [Блок 3](CHECKLIST.md#3-редактирование-поставщика) |
| 4. Работа с менеджерами | Список пользователей, редактирование, ограничения по статусу поставщика, вход за пользователя и логи, удаление менеджера и запрет удаления админа. | [Блок 4](CHECKLIST.md#4-работа-с-менеджерами) |
| 5. Настройка доступа к каталогу | Дерево привилегий, каскады, сохранение, наследование новыми и скопированными товарами, запрет выключения при стоке. | [Блок 5](CHECKLIST.md#5-настройка-доступа-к-каталогу) |
| 6. Удаление поставщика | Подтверждение, запрет при активных заказах, предупреждение о стоке, его удаление и прекращение доступа пользователей. | [Блок 6](CHECKLIST.md#6-удаление-поставщика) |
| 7. Архив | Список удалённых поставщиков и исследование восстановления поставщика, его админа, менеджеров и связанных данных. | [Блок 7](CHECKLIST.md#7-архив) |

Права просмотра и редактирования по каждой стране включены в соответствующие блоки при готовности прав. Завершение сессий админа поставщика и его менеджеров проверяется вместе со сменой статуса в блоке 1, вывод Shipping From в накладных — в блоке 3, наследование привилегий — в блоке 5, ограничения из-за заказов — в блоке 6.

## 1. Назначение и основные данные

Страница управляет поставщиками по странам поставки: реквизитами, документами, статусами, доступом к номенклатуре и пользователями поставщика.

- Поставщик принадлежит стране поставки, например UAE или USA. Страны реализации и страна спецификации товара не заменяют эту принадлежность.
- При создании поставщика обязательно создаётся аккаунт его админа. Менеджеры — дополнительные пользователи того же поставщика; их добавляет и настраивает админ поставщика в своём ЛК.
- **Name / User Name — одно имя поставщика и его админа.** Изменение этого поля меняет имя админа. Отдельное независимое имя основного пользователя не вводится. У менеджеров собственные имена.
- **Company Name** — название компании. Оно не подменяет Name.
- **User ID** — уникальный среди всех поставщиков идентификатор. Он генерируется автоматически при создании и допускает ручное редактирование.
- **Purchases** — страна поставки. При открытии добавления выбрана страна текущей ветки дерева; её можно изменить в форме. При смене страны существующего поставщика он переходит в список новой страны и сохраняет прежний User ID.
- **Shipping From** — текстовое поле, значение которого выводится в накладных поставщика.
- **Doc / Documents** — сумма списания за документ. Необязательное значение; если не задано, сохраняется 0. Дробные суммы допустимы; точность и числовые пределы требуют исследования.

## 2. Дерево стран и права

В меню слева находится папка «Поставщики», внутри — страны поставки из [«Закупки и реализации»](<../Settings/Procurement and sales/README.md>).

- Состав и порядок стран совпадают с этой страницей.
- Название выводится как есть, включая входящий в него флаг.
- Новая страна появляется сразу после создания, удалённая сразу исчезает.
- Выключенная страна остаётся в дереве.
- Выбор страны открывает панель и таблицу её поставщиков.
- Просмотр и редактирование настраиваются отдельно для каждой страны на странице «Пользователи».

Доступность изменения страны поставщика при ограниченных правах на исходную или целевую страну пока не определена — **SUP-Q09**.

## 3. Панель, поиск и фильтр статуса

Панель содержит название выбранной страны, кнопку «Добавить», поиск «Name or ID» и фильтр «Status» со счётчиками.

### Поиск

- Работает по User ID и User Name: по части или полному совпадению.
- Ищет только в выбранной стране, среди поставщиков всех статусов.
- Подсказки имеют вид `D 017 — BMG`.
- После выбора подсказки в таблице остаётся только выбранный поставщик; фильтр переключается на его статус.
- Крестик поиска возвращает полный список. Какой статус остаётся выбранным после сброса, требует исследования — **SUP-Q01**.

### Статус

- Доступны «Все», «Активен», «Не активен», «Заблокирован» со счётчиками.
- По умолчанию выбран «Активен».
- Все варианты отображаются, в том числе со счётчиком 0.
- Крестик сбрасывает статус. Точное значение после сброса требует исследования — **SUP-Q01**.

Новый поставщик создаётся со статусом «Не активен». Автоматическое переключение фильтра после создания в ТЗ не установлено.

## 4. Таблица и редактирование в строке

Шапка таблицы закреплена при прокрутке.

| Колонка | Правило |
| --- | --- |
| User ID | Автоматическое назначение при создании; ручное редактирование в таблице. Глобальная уникальность, включая поставщиков других стран. |
| User Name | Поле Name поставщика и его админа; редактируется в таблице. |
| Company Name | Название компании; редактируется в таблице. |
| Shipping From | Текст для накладных поставщика; редактируется в таблице. |
| Doc | Сумма Documents; редактируется в таблице. |
| TRN | Иконка загруженного файла, открывающая PDF; без файла отображается «—». |
| License | Иконка загруженного файла, открывающая PDF; без файла отображается «—». Обязательность License при создании сохраняется. |
| End Date | Окончание лицензии; просроченная дата красная. |
| Balance | Баланс поставщика. Расчёт и содержание подсказки ⓘ определяются вместе с финансами. |
| Sales | Количество продаж за последние 30 дней, рассчитанное по накладным, завершённым за этот период. Учитывается дата завершения накладной; единица подсчёта и точная граница периода требуют уточнения — SUP-Q14. |
| Статус | Меняется прямо в строке: «Активен», «Не активен», «Заблокирован». |
| Действия | Меню ☰: привилегии, пользователи и редактирование. |

Для редактируемых ячеек сохранение выполняется по Enter или клику в пустое место. Правила соответствующих полей действуют и в форме, и в таблице. Ручное изменение User ID не отменяет его глобальную уникальность.

Лицензия и её срок служат информацией для наших менеджеров. Просрочка выделяется красным; автоматическая блокировка поставщика из-за неё не предусмотрена. Граница просрочки для сегодняшней даты и часовой пояс пока не определены — **SUP-Q04**.

## 5. Добавление поставщика

Кнопка «Добавить» открывает форму. Страна по умолчанию соответствует ветке, из которой открыли добавление; до сохранения её можно изменить. Поставщик создаётся в выбранной в форме стране со статусом «Не активен».

### Реквизиты и документы

| Поле | Обязательность | Правило |
| --- | --- | --- |
| Name | Обязательно | User Name поставщика и имя его админа. Совпадающие имена у разных поставщиков допустимы. |
| Company Name | Обязательно | Совпадающие названия компаний допустимы. |
| Company Address | Необязательно | Адрес компании. |
| TRN Number | Необязательно | Номер TRN. Формат и ограничения пока не заданы. |
| TRN | Необязательно | Файл PDF. |
| Purchases | Выбрана страна | По умолчанию страна ветки; выбор можно изменить. |
| License | Обязательно | Файл PDF. |
| License end date | Обязательно | Дата окончания лицензии. |
| Логотип / Лого в стикере | Необязательно | JPG или PNG. |
| Documents | Необязательно | Сумма списания за документ, по умолчанию 0. Дробные значения разрешены. |

Shipping From редактируется как текст в таблице и используется в накладных. Его наличие и начальное значение в новой форме добавления отдельно не установлены — **SUP-Q03**.

### Аккаунт админа поставщика

При создании поставщика обязательно создаётся основной пользователь с ролью «Админ»:

| Поле | Правило |
| --- | --- |
| Email | Обязательный логин, уникальный. Точная область проверки уникальности требует исследования — **SUP-Q05**. |
| Phone | Обязателен при создании согласно новому ТЗ. |
| Password | Обязателен, не короче 8 символов. |
| Repeat password | Обязателен, должен совпадать с Password. |

Кнопка Save активна, когда заполнены все обязательные поля. Условия совпадения паролей, минимальной длины, уникальности Email и допустимых файлов также должны выполняться для успешного создания.

User ID присваивается автоматически по шаблону из «Конфигурации». У каждой страны своя нумерация; итоговый идентификатор уникален среди всех поставщиков. Ручное редактирование ID и перенос между странами не отменяют глобальную уникальность.

## 6. Редактирование поставщика и смена страны

Карандаш в меню действий открывает форму с текущими данными.

- По новому ТЗ форма содержит Name, Company Name, Company Address, TRN Number, TRN, License, License end date, логотип, Documents и Comment.
- Purchases допускает изменение страны. После сохранения поставщик относится к новой стране; его прежний User ID сохраняется, автоматического переназначения по новой стране нет.
- Name, Company Name, License и License end date обязательны. Правила полей совпадают с добавлением.
- Comment — внутренняя заметка, доступная только нашему админу.
- TRN и логотип можно удалить корзиной. License можно только заменить.
- Почта, телефон и пароль меняются в окне «Пользователи», в строке «Админ».
- Изменение Name меняет имя админа поставщика; это одно поле, независимо от места редактирования.

Форматы актуального ТЗ: TRN и License — PDF, логотип — JPG/PNG. Подписи других форматов на скриншотах старого варианта не меняют эти требования. Лимит размера файлов пока не установлен; лимит 2 МБ из номенклатуры сюда не переносится — **SUP-Q04**.

## 7. Статусы и доступ в ЛК

| Статус поставщика | Новый вход в ЛК | Уже открытые сессии |
| --- | --- | --- |
| Активен | Не блокируется статусом поставщика; остальные условия авторизации сохраняются. | Отдельного завершения по этому статусу не задано. |
| Не активен | Запрещён админу поставщика и всем его менеджерам. | Завершаются у админа поставщика и всех его менеджеров. |
| Заблокирован | Запрещён админу поставщика и всем его менеджерам. | Завершаются у админа поставщика и всех его менеджеров. |

Ограничения менеджеров зависят от статуса поставщика. Их собственные настройки не должны позволять вход при неактивном или заблокированном поставщике.

Влияние этих статусов на клиентскую видимость товаров, возможность новых покупок и обработку уже оформленных заказов пока не определено — **SUP-Q08**.

## 8. Привилегии на номенклатуру

Замок в меню ☰ открывает окно «<User ID> <User Name>» с деревом номенклатуры. Галочка разрешает поставщику продавать соответствующий товар. У нового поставщика включено всё. Изменения сохраняются сразу.

Для галочек согласована логика каскадов, используемая в [«Процентах»](../Settings/Percents/README.md):

- Включение родителя включает всех вложенных потомков.
- Выключение родителя снимает разрешения у всех вложенных потомков, если нет запрета из-за стока.
- Включение одного ребёнка включает его предков. Остальные дети остаются в прежнем состоянии, в том числе выключенными.
- Если включена только часть детей, у родителя остаётся галочка. Галочка родителя не означает, что включены все дети.
- Выключение последнего включённого ребёнка не выключает родителя.

Привилегии относятся к выбранному поставщику. Особенности страницы «Проценты», такие как отсутствие тумблера у бренда, пары стран и типы оплаты, не определяют состав элементов этого окна.

### Новые и скопированные товары

- Новый товар наследует галочку своего родителя.
- Скопированный товар наследует галочку исходного товара.

### Ограничение по стоку

- Нельзя снять галочку товара, если у этого поставщика есть его сток.
- Для родительского узла проверяются все вложенные товары; интерфейс сообщает, какой товар препятствует выключению.
- При таком запрете сток не удаляется. Старое описание удаления стока при выключении привилегий не применяется.

Точное определение учитываемого стока, включая нулевой остаток и будущую дату, а также атомарность каскада при блокирующем товаре пока требуют исследования — **SUP-Q07**.

## 9. Пользователи поставщика

Действие с человечками открывает окно «<User Name>» со списком пользователей: Login, Phone, Name, Роль, Действия.

- **Админ** — основной пользователь, создаваемый вместе с поставщиком. Его удалить нельзя.
- **Менеджер** — дополнительный пользователь. Его создаёт и настраивает админ поставщика в своём ЛК. Добавление менеджеров нашим админом на этой странице в новом ТЗ не предусмотрено.
- Для пользователя доступен вход в его кабинет. Каждый такой вход фиксируется в логах: кто вошёл, за кого и когда.
- При редактировании пользователя доступны Name, Email, Phone и пароль; Name и Email обязательны.
- У основного пользователя Name — то же поле, что Name поставщика. У менеджера собственное имя.
- Менеджера можно удалить с подтверждением.
- При неактивном или заблокированном поставщике ограничения входа и завершение сессий распространяются на менеджеров, как описано в разделе 7.

Скриншоты показывают селектор у менеджера, но новый PDF называет «Админ» и «Менеджер» ролями и не перечисляет отдельные статусы менеджера. Назначение селектора, допустимые изменения и отдельные ограничения пользователя требуют исследования — **SUP-Q06**. Лимит пяти менеджеров и сценарий приглашения по email в новом ТЗ не установлены.

## 10. Удаление и архив

Удаление вызывается из формы редактирования поставщика и требует подтверждения.

- Удаление мягкое: поставщик попадает в архив в «Конфигурации».
- Если есть активные заказы, удалить поставщика нельзя. Точный состав активных статусов пока не определён — **SUP-Q10**.
- При наличии стока выводится предупреждение: «У поставщика N товаров в стоке, они будут удалены. Удалить?».
- При успешном удалении сток поставщика удаляется, пользователи поставщика теряют доступ.

Архив со способностью восстановления показан на предоставленном скриншоте старой админки. Состав восстановления в новом варианте пока исследовательский: предполагается возвращение поставщика и его пользователей; наличие аккаунта админа и менеджеров, их доступ, статус поставщика, реквизиты, файлы и привилегии нужно установить фактически — **SUP-Q11**. Автоматическое восстановление стока не подтверждено. Срок хранения и окончательное удаление не заданы.

## 11. Неопределённые детали

Ниже перечислены вопросы, для которых пока не установлен полный ожидаемый результат. Они не меняют согласованные правила выше.

- **SUP-Q01 — поиск и фильтры.** Регистр и пробелы при поиске; результат без совпадений; значение Status после сброса поиска и после собственного крестика; область счётчиков при выбранной подсказке; поведение фильтра после смены статуса строки и создания поставщика.
- **SUP-Q02 — генерация и ручная правка User ID.** Допустимый формат и длина; влияние ручной правки на следующий автоматически выдаваемый номер; резервирование ID удалённых поставщиков и конфликт при восстановлении. Уникальность среди всех поставщиков и сохранение ID при переносе уже согласованы.
- **SUP-Q03 — текстовые и числовые поля.** Длины и допустимые символы Name, Company Name, адреса, Shipping From, TRN Number и Comment; обязательность, начальное значение и наличие Shipping From в новой форме добавления; предел и знак Documents, точность, разделитель дробной части и округление. Совпадающие названия и дробные суммы разрешены.
- **SUP-Q04 — файлы и дата лицензии.** Лимиты размеров, повреждённые файлы и проверка фактического формата, отображение логотипа в стикере; возможность сохранения уже прошедшей даты, граница просрочки и часовой пояс. Лицензия информационная; автоматическая блокировка из-за просрочки не предусмотрена.
- **SUP-Q05 — учётные данные.** Область уникальности Email между странами, поставщиками, менеджерами, иными типами пользователей и архивом; регистр логина; формат телефона; смена пароля при редактировании, включая пустое поле; завершение сессий при смене учётных данных.
- **SUP-Q06 — управление менеджерами.** Допустимые значения и назначение селектора в строке, индивидуальная блокировка менеджера и её связь с ролью; возможность входа нашим админом за пользователя заблокированного поставщика. Лимиты пользователей и создание менеджеров в ЛК определяются в документации этого кабинета.
- **SUP-Q07 — дерево привилегий и сток.** Точные уровни и элементы управления дерева; учитываемые состояния стока; атомарность запрета выключения родителя; применение разрешений в ЛК и при выгрузке товаров.
- **SUP-Q08 — статусы и продажи.** Последствия неактивности и блокировки для товаров, новых покупок и действующих заказов; поведение после возврата в «Активен». Запрет входа и завершение всех сессий админа поставщика и менеджеров при обоих запрещающих статусах уже согласованы.
- **SUP-Q09 — смена страны.** Доступ по правам исходной и целевой страны; перенос привязок стока и настроек; последствия для заказов, финансов и документов; ограничения переноса при наличии зависимостей. Страна меняется, прежний User ID сохраняется.
- **SUP-Q10 — удаление.** Состав активных статусов заказа, подсчёт N товаров в предупреждении и последствия удаления для действующих сессий пользователей.
- **SUP-Q11 — восстановление.** Расположение архива в новом интерфейсе; состав возвращаемых данных и пользователей; статус и доступ после восстановления; конфликты ID и Email; судьба стока. Предположение о возвращении поставщика и менеджеров требует фактической проверки.
- **SUP-Q12 — Balance.** Расчёт баланса и содержание подсказки ⓘ определяются вместе с финансами.
- **SUP-Q13 — сохранение и ошибки.** Отмена черновика при закрытии форм, состояние после сбоя сохранения или загрузки файла, конкурентные изменения и повторные отправки. Конкретные уведомления, визуальный откат и сохранение черновиков не заданы.

- **SUP-Q14 — Sales.** Количество продаж считается по накладным, завершённым за последние 30 дней. Требуют уточнения единица подсчёта (накладные, позиции или единицы товара), включение граничного момента, календарные дни или последние 30 × 24 часа и часовой пояс. Дата создания накладной не заменяет дату её завершения.
