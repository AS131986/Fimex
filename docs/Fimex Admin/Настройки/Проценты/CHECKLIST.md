# Чек-лист: Настройки → Проценты

[Бизнес-правила и вопросы](README.md). Все пункты ожидают прогона. Отметка означает выполненную проверку; результат, дата, фактическое поведение и дефект фиксируются при прогоне.

**Сейчас:** выбор стран, дерево, состав колонок на готовых данных, список процентов, сохранение и связи внутри страницы (раздел 1).

**Требует ответа:** исследование неоднозначного поведения без вердикта «соответствует» (раздел 2).

**Отложено:** зависимости номенклатуры, конфигураций, других настроек, стока, приложения и заказов, а также все права доступа (раздел 3). Проверка сохранённого числа на странице не подтверждает клиентскую цену или запрет покупки.

Управление типами оплаты переносится в «Конфигурации». Их добавление, переименование, валидация названий, удаление и перестановка не проверяются как операции страницы «Проценты». Здесь проверяются получившиеся колонки и значения. Кнопка «+» возле выбора реализации — добавление типа опта, она также переносится в «Конфигурации». Управление списком допустимых процентов относится к этому же разделу, здесь проверяется результат его настройки.

## Подготовка

- Использовать тестовый набор и тестовую учётную запись. Права не переключать в рамках текущего прогона.
- Подготовить четыре пары: UAE × Deira, USA × Deira, UAE × Free zone и USA × Free zone. Использовать общие сущности стран, а не разные записи с похожими названиями.
- Для проверки колонок нужны минимум два типа оплаты у одной реализации. Названия Cash/Online ниже условные; брать фактические названия и сущности справочника.
- В дереве нужны два бренда, у одного — минимум две категории, в категории — две модели, у модели — два варианта. Нужны свёрнутые строки и ветка, не помещающаяся на одном экране.
- Зафиксировать исходные значения. Для разных колонок и связок задать разные проценты из текущего справочника, например 0.5, 1, 2 и 3, если они доступны; тестируемая категория/модель не должна содержать важные рабочие данные.
- Для проверки включения ребёнка сначала выключить его категорию, чтобы у всех вложенных строк было известное выключенное состояние.
- Новые позиции и типы оплаты для проверки дефолтов подготавливаются в соответствующих разделах после готовности зависимостей. Уже существующие строки с «-» не считать доказательством дефолта нового товара.
- Перед прогоном зафиксировать актуальный список процентов из «Конфигураций». В README 5.1 приведён исходный набор; он не является неизменным диапазоном. «-» запрещает покупку только по выбранному типу оплаты, 0 задаёт продажу без наценки. Они не взаимозаменяемы; общий тумблер от выбора значения не меняется. Произвольный ввод запрещён.

- Для проверки различий «-»/0 нужны включённые закупка, общие продажи, тумблер строки и минимум два типа оплаты. Менять значения одной колонки при неизменных остальных: например, Cash = «-», Online = 1%.
- Для проверки 0 как цены без наценки использовать предложение с известной ценой поставщика и без других неоднозначных компонентов. Фактическая покупка и админский/поставщицкий сток проверяются только в отложенном блоке.

### Что означает «проверить сохранение»

Дождаться успешного ответа сохранения, переключить страну поставки и вернуться, переключить реализацию и вернуться, перезагрузить страницу и снова выбрать исходную пару. Проверить нужные строку и тип оплаты. Для родительского изменения раскрыть все затронутые уровни, включая ранее свёрнутые и находившиеся ниже экрана.

## 1. Доступно сейчас

### 1.1. Выбор страны поставки и реализации

- [ ] **PCT-FLT-01** — Поочерёдно выбрать каждую из четырёх подготовленных пар → таблица и заголовки колонок относятся к выбранной паре; видны оба текущих выбора.
- [ ] **PCT-FLT-02** — При неизменной Deira переключить UAE → USA → UAE → проценты и тумблеры каждой пары сохраняют свои значения.
- [ ] **PCT-FLT-03** — При неизменной UAE переключить Deira → Free zone → Deira → возвращаются проценты, тумблеры и колонки выбранной реализации.
- [ ] **PCT-FLT-04** — Изменить настройку UAE × Deira и проверить остальные три пары → изменение не скопировано в другую страну поставки или реализацию.
- [ ] **PCT-FLT-05** — Открыть и закрыть список выбора без нового выбора → активная пара и настройки не меняются.
- [ ] **PCT-FLT-06** — Повторно выбрать текущие страны → настройки не сбрасываются, строки и колонки не дублируются.
- [ ] **PCT-FLT-07** — При замедленной загрузке быстро переключить пары → после завершения запросов таблица соответствует последнему выбору, запоздалый ответ другой пары её не подменяет.
- [ ] **PCT-FLT-08** — После сохранения перезагрузить страницу и вручную выбрать исходную пару → загружены её сохранённые данные; автоматический выбор пары после перезагрузки этим пунктом не задаётся.

### 1.2. Дерево номенклатуры

- [ ] **PCT-TREE-01** — Сопоставить дерево с подготовленной номенклатурой → присутствуют все позиции, в том числе без текущего стока; нет дублей одной сущности.
- [ ] **PCT-TREE-02** — Раскрыть категорию и модель → соблюдена иерархия бренд → категория → модель → вариант, позиции относятся к своим родителям.
- [ ] **PCT-TREE-03** — Проверить строку бренда → это заголовок без процентных полей и тумблера.
- [ ] **PCT-TREE-04** — Проверить категории, модели и варианты → доступные проценты и тумблеры соответствуют этим строкам, а не соседним.
- [ ] **PCT-TREE-05** — Раскрывать и сворачивать разные ветки → меняется только отображение вложенных строк; значения процентов и тумблеров не меняются.
- [ ] **PCT-TREE-06** — Выключить позицию → она остаётся на странице настроек и отображается серой; её не удаляют из дерева вместе со стоком.
- [ ] **PCT-TREE-07** — Сравнить одноимённые позиции в разных ветках → изменение одной не затрагивает другую с отдельной сущностью.
- [ ] **PCT-TREE-08** — Проверить длинные названия, глубокую ветку и нижние строки → название и элементы управления остаются доступны, процент визуально относится к правильной колонке.
- [ ] **PCT-TREE-09** — Свернуть ветку, сменить пару и вновь раскрыть → показаны данные новой пары; сохранение самого раскрытия между парами не оценивается как бизнес-требование.

### 1.3. Колонки типов оплаты

- [ ] **PCT-COL-01** — Открыть реализацию с несколькими подготовленными типами оплаты → каждому выводимому типу соответствует одна колонка; число и названия сверены со справочником, отсутствуют лишние и повторные колонки.
- [ ] **PCT-COL-02** — У одной реализации переключить страны поставки → состав типов оплаты остаётся общим для реализации, а их сохранённые проценты загружаются отдельно для каждой пары.
- [ ] **PCT-COL-03** — Переключить реализации с разным составом типов → выводятся колонки выбранной реализации; колонки предыдущей не остаются как её данные.
- [ ] **PCT-COL-04** — Одной строке задать разные проценты в двух колонках и проверить сохранение → каждое значение осталось в своём типе оплаты.
- [ ] **PCT-COL-05** — Изменить процент в первой колонке → вторая колонка той же строки и её вложенных строк не меняется.
- [ ] **PCT-COL-06** — Повторить изменение и проверку сохранения для каждой доступной колонки → нет работающей только первой/последней колонки или перепутанных типов.
- [ ] **PCT-COL-07** — На готовых данных с одним типом оплаты → отображается одна колонка; выбор и сохранение процентов работают.
- [ ] **PCT-COL-08** — На готовых данных с большим числом колонок → все колонки доступны; после прокрутки или перезагрузки значения привязаны к тем же типам, не сдвинуты по индексу.
- [ ] **PCT-COL-09** — Переключить тумблер строки при нескольких колонках → меняется состояние позиции, отдельные тумблеры оплаты не создаются; сохранённые числовые проценты не подменяются состоянием тумблера.

### 1.4. Список процентов и доступная валидация

- [ ] **PCT-VAL-01** — Нажать процент категории, модели и варианта → у каждого уровня открывается список выбора для выбранной строки и колонки.
- [ ] **PCT-VAL-02** — Сверить весь выпадающий список с текущим справочником → совпадают состав и число вариантов, числовые значения идут по возрастанию; «-» и 0 представлены как разные значения, запрет продажи не объединён с нулевой наценкой.
- [ ] **PCT-VAL-03** — На исходном наборе README проверить 0, 0.01, 0.05, 0.1 и остальные малые дроби → доступны именно настроенные варианты, дроби не округляются до целого или 0. На изменённом справочнике брать соответствующие доступные дроби.
- [ ] **PCT-VAL-04** — На исходном наборе проверить участок 16 → 16.5 → 21.5 → 22 → 22.5 → 23 → отсутствующие в справочнике числа не генерируются автоматически. Если промежуточное число добавили в конфигурации, оно должно присутствовать на своём месте.
- [ ] **PCT-VAL-05** — Выбрать 0 и проверить сохранение → сохранена явная нулевая наценка; после перезагрузки показан 0, а не «-». Общий тумблер строки и значения других колонок сохраняют свои состояния.
- [ ] **PCT-VAL-06** — На стенде с вариантом 0.01 выбрать его и проверить сохранение → дробь не потеряна, не превращена в 1 или 0.1. Если конфигурация изменилась, подготовить допустимое малое значение в отдельном разделе.
- [ ] **PCT-VAL-07** — Выбрать максимальный числовой вариант текущего справочника, в исходном наборе 23 → сохраняется этот процент, без умножения или деления на 100; большее число произвольным вводом не назначается.
- [ ] **PCT-VAL-08** — Поочерёдно сохранить дробь с двумя знаками, дробь с одним знаком и целое число → числовое значение сохраняется без непредусмотренного округления; формат завершающих нулей не задаётся.
- [ ] **PCT-VAL-09** — Проверить список во второй колонке и другой паре на неизменной конфигурации → доступен тот же актуальный набор процентов, а не ранее закешированный список.
- [ ] **PCT-VAL-10** — Открыть и закрыть список без выбора → сохранённый процент не меняется.
- [ ] **PCT-VAL-11** — Открыть список у одной строки, затем у другой → выбор применяется к последней выбранной ячейке, а не к старой строке или колонке.
- [ ] **PCT-VAL-12** — Выбрать новое число → оно сохраняется сразу без поиска общей кнопки «Сохранить».
- [ ] **PCT-VAL-13** — Повторно выбрать текущее число → значение не удваивается, не прибавляется к прежнему проценту и не сбрасывает тумблер.
- [ ] **PCT-VAL-14** — Поочерёдно выбрать все варианты текущего справочника на отдельной тестовой строке → каждый вариант принимается и сохраняется; не проверять только удобный равномерный шаг и не требовать старое число вариантов после изменения конфигурации.
- [ ] **PCT-VAL-15** — На варианте, модели и категории поочерёдно выбрать «-» и 0, проверить сохранение и потомков → выборы различаются после перезагрузки: «-» остаётся запретом, 0 — нулевой наценкой. Тумблеры, остальные колонки и пары не меняются; прежние частные проценты потомков не восстанавливаются.
- [ ] **PCT-VAL-16** — Попробовать печатать и вставлять в контрол произвольные числа и текст: буквы, пробелы, отрицательное число, отсутствующее в актуальном справочнике число, число с лишней точностью и запятой → назначить произвольное значение нельзя. Если есть строка поиска, ввод может фильтровать варианты, но не создавать новый процент.
- [ ] **PCT-VAL-17** — Выбрать новый допустимый процент у выключенной позиции → значение сохраняется после смены пары и перезагрузки; сама позиция и её выключенные предки не включаются.
- [ ] **PCT-VAL-18** — Изменить процент категории или модели с выключенными потомками → у потомков сохранён новый процент выбранной колонки, их тумблеры не включаются; другая колонка и другая пара не затронуты.
- [ ] **PCT-VAL-19** — Изменить процент строки без стока → выбор и сохранение доступны; после обновления процент остаётся заданным, отсутствие стока не сбрасывает его. Фактическую цену будущего товара проверять отдельно.
- [ ] **PCT-VAL-20** — У включённой строки задать Cash = «-», Online = 1%, затем Cash = 0 → общий тумблер остаётся включённым на каждом шаге, Online сохраняет 1%, Cash сохраняет отдельно «-», затем 0 после смены пары и перезагрузки.
- [ ] **PCT-VAL-21** — Поочерёдно задать «-» во всех колонках включённой строки → тумблер остаётся включённым после сохранения и перезагрузки, «-» не превращается в 0. Запрет покупки при таком сочетании проверять в отложенном блоке.

Список значений редактируется только в «Конфигурациях»; текущая страница не разрешает ручное назначение произвольного числа. «-» — отдельный запрет продажи по типу оплаты, 0 — явная нулевая наценка; нормализация одного значения в другое недопустима. Валидация названий типов и чисел самого справочника относится к отдельному разделу.

### 1.5. Перезапись вложенных процентов

- [ ] **PCT-CASCADE-01** — В одной колонке задать моделям категории разные проценты, затем выбрать новый процент категории → все вложенные модели и варианты получили новое значение, прежние исключения перезаписаны.
- [ ] **PCT-CASCADE-02** — Задать вариантам одной модели разные проценты, затем изменить процент модели → все её варианты получили новое значение.
- [ ] **PCT-CASCADE-03** — Повторить изменение категории при свёрнутых моделях и вариантах → после раскрытия и перезагрузки новые значения есть и у скрытых строк.
- [ ] **PCT-CASCADE-04** — Изменить категорию с вариантами ниже текущего экрана → обновились все потомки, а не только отрисованные строки.
- [ ] **PCT-CASCADE-05** — Изменить процент модели → соседние модели и их варианты вне этой ветки сохраняют свои значения.
- [ ] **PCT-CASCADE-06** — Изменить процент категории → другая категория и другой бренд сохраняют свои значения.
- [ ] **PCT-CASCADE-07** — Массово изменить категорию в Cash → Online той же категории и потомков не меняется.
- [ ] **PCT-CASCADE-08** — Массово изменить категорию у UAE × Deira → USA × Deira и обе пары Free zone не меняются.
- [ ] **PCT-CASCADE-09** — После массового изменения выбрать 0 у родителя → все потомки выбранной колонки и пары получают именно 0, а не «-» или прежние частные значения; тумблеры и остальные колонки не меняются.
- [ ] **PCT-CASCADE-10** — Изменить родителя, затем вручную изменить одну модель, затем снова изменить родителя → последняя родительская операция снова перезаписывает эту модель и её варианты.
- [ ] **PCT-CASCADE-11** — После успешного каскада выполнить проверку сохранения → все затронутые потомки имеют сохранённое значение, остальные колонки и пары сохранены.
- [ ] **PCT-CASCADE-12** — Изменить процент включённой строки, в том числе выбрать «-» и затем 0 → действие не выключает и не включает её общий тумблер, предков или другие ветки; значения сохраняются как разные настройки.
- [ ] **PCT-CASCADE-13** — Задать потомкам разные числа и 0, затем выбрать «-» у категории/модели в одной колонке → все затронутые потомки этой колонки получили «-», включая свёрнутые; тумблеры, другие колонки и пары не изменились.
- [ ] **PCT-CASCADE-14** — После каскада «-» выбрать 0 у того же родителя → значения его потомков в выбранной колонке стали 0 и сохранились; выключенные тумблеры не включились, остальные типы оплаты не изменились.

### 1.6. Тумблеры и связи внутри дерева

- [ ] **PCT-SW-01** — Выключить включённый конечный вариант → он выключается и становится серым, соседние варианты и включённые родители сохраняют состояния, в том числе при выключении последнего активного варианта.
- [ ] **PCT-SW-02** — Включить вариант под включёнными предками → вариант включается, его соседние позиции не меняются.
- [ ] **PCT-SW-03** — Выключить модель с несколькими включёнными вариантами → выключаются модель и все её варианты.
- [ ] **PCT-SW-04** — Выключить категорию с несколькими моделями → выключаются категория, все её модели и варианты.
- [ ] **PCT-SW-05** — Повторить выключение категории со свёрнутыми ветками и строками ниже экрана → после раскрытия все потомки выключены.
- [ ] **PCT-SW-06** — После выключения категории включить один её вариант → включаются этот вариант, его модель и категория; другие варианты этой модели и другие модели категории остаются выключенными.
- [ ] **PCT-SW-07** — После выключения одной модели включить один её вариант → включаются вариант и его выключенные предки; остальные варианты остаются выключенными, соседняя модель сохраняет своё состояние.
- [ ] **PCT-SW-08** — Включить ещё один вариант той же восстановленной ветки → первый остаётся включённым; ранее выключенные, не выбранные варианты не включаются сами.
- [ ] **PCT-SW-09** — Включить вариант под выключенной категорией → у бренда не возникает тумблер или процент.
- [ ] **PCT-SW-10** — Выключить ветку UAE × Deira → у остальных трёх пар её тумблеры не меняются.
- [ ] **PCT-SW-11** — Выключить одну категорию → другая категория и другой бренд сохраняют состояния своих позиций.
- [ ] **PCT-SW-12** — Выполнить выключение родителя, включение одного ребёнка и проверку сохранения → сохраняются состояния конкретного ребёнка, его предков и выключенных соседей, а не только общий вид родителя.
- [ ] **PCT-SW-13** — Переключить тумблер строки с разными процентами по типам оплаты → числовые проценты не теряются и не копируются между колонками; нулевой процент сам не выключает товар.
- [ ] **PCT-SW-14** — Выключить модель с несколькими вариантами, затем включить саму модель → включаются модель и все её варианты, а не только ранее включённые. Проверить сохранение.
- [ ] **PCT-SW-15** — Выключить категорию с несколькими моделями, затем включить саму категорию → включаются категория, все её модели и варианты, включая свёрнутые и расположенные ниже экрана. Проверить сохранение.
- [ ] **PCT-SW-16** — Оставить один включённый вариант у включённой модели и выключить его → все варианты выключены, но модель остаётся включённой после перезагрузки.
- [ ] **PCT-SW-17** — Оставить одну включённую модель у включённой категории и выключить её → категория остаётся включённой, модель и её варианты выключены после перезагрузки.
- [ ] **PCT-SW-18** — На ветке с частично включёнными детьми выключить родителя и включить его обратно → включаются все дети, прежний частичный набор не восстанавливается.
- [ ] **PCT-SW-19** — После включения только одного ребёнка под выключенным родителем проверить соседние ветки, другую колонку и другие пары → включены только ребёнок и его предки в выбранной паре, остальные выключенные дети не активированы; проценты не перезаписаны.
- [ ] **PCT-SW-20** — У строки с Cash = «-», Online = 0 выключить и включить общий тумблер → значения колонок сохраняют различие «-»/0, включение тумблера не подставляет 0 вместо «-». Другие строки и пары не затронуты.

### 1.7. Сохранение и устойчивость страницы

- [ ] **PCT-SAVE-01** — По отдельности изменить процент и тумблер, дождаться успешного сохранения и перезагрузить → состояние соответствует последней сохранённой операции.
- [ ] **PCT-SAVE-02** — Сохранить разные значения одной позиции в четырёх парах и двух колонках → после повторных переключений и перезагрузки нет переноса значений между парами или колонками.
- [ ] **PCT-SAVE-03** — Сохранить процент одной строки и тумблер другой → обе независимые настройки сохраняются, одна операция не затирает другую.
- [ ] **PCT-SAVE-04** — После успешного сохранения переключить пару, пока таблица другой пары загружается → сохранённая настройка не оказывается записана в новой паре.
- [ ] **PCT-SAVE-05** — На готовом пустом дереве → страница не падает и не показывает строки предыдущей пары; отсутствующим позициям не назначаются настройки.
- [ ] **PCT-SAVE-06** — На готовых данных без колонок оплаты → дерево и фильтры не ломаются, фиктивный тип оплаты не появляется. Точный текст пустого состояния пока не задан.
- [ ] **PCT-SAVE-07** — После ошибочного запроса повторно загрузить страницу → показаны данные, реально принятые сервером; ошибочная операция не считается успешной только по локальному отображению.
- [ ] **PCT-SAVE-08** — Повторить разрешённое изменение после устранения сетевой ошибки → настройка может быть сохранена, страница не остаётся заблокированной или привязанной к устаревшей паре.

## 3. Отложенные проверки

### 3.1. Номенклатура и начальные значения

- [ ] **PCT-DEF-NOM-01** — После создания нового товара номенклатуры открыть страницу → товар появился в правильной ветке во всех применимых парах, значения дефолтные «-», тумблер выключен. Это запрет продажи, а не 0%; настройки не берутся из другого товара.
- [ ] **PCT-DEF-NOM-02** — Создать вариант под включённым родителем с ненулевым процентом → у нового варианта дефолтные «-» и выключенный тумблер; существующие строки не сброшены и не изменены его появлением.
- [ ] **PCT-DEF-NOM-03** — Переименовать или переставить существующую позицию в номенклатуре без смены её сущности → таблица обновляет представление, её сохранённые проценты и тумблеры не прикрепляются к соседней строке.

### 3.2. Изменения конфигураций типов оплаты и списка процентов

Выполнять после готовности «Конфигураций». Операции справочника служат подготовкой; их формы и собственная валидация проверяются в чек-листе того раздела.

- [ ] **PCT-DEF-COL-01** — После добавления нового типа оплаты обновить «Проценты» → появилась одна новая колонка с «-» у всех позиций; по новому типу покупки запрещены, прежние колонки и тумблеры сохранены, разрешённые старые типы продолжают работать.
- [ ] **PCT-DEF-COL-02** — Проверить новый тип той же реализации в другой стране поставки → колонка также появилась с исходными значениями новой колонки, другие реализации не получили чужие значения.
- [ ] **PCT-DEF-COL-03** — Выключить существующий тип в конфигурации → его колонка скрылась, остальные типы не получили его проценты.
- [ ] **PCT-DEF-COL-04** — Вернуть выключенный тип с заранее различающимися «-», 0 и положительными значениями по строкам и парам → восстановлены именно его прежние значения, «-» и 0 не объединены; доступность соответствует каждому значению и общим ограничениям.
- [ ] **PCT-DEF-COL-05** — Удалить тип и затем восстановить эту же сущность → колонка скрывается и возвращается со своими сохранёнными процентами по ТЗ. Проверить доступность механизма восстановления после готовности справочника.
- [ ] **PCT-DEF-COL-06** — После создания другого типа с названием удалённого открыть страницу → новая колонка с «-» запрещает покупки только по новому типу, значения удалённой сущности ей не присвоены; остальные типы и общий тумблер не изменились.
- [ ] **PCT-DEF-COL-07** — После переименования/перестановки типов в конфигурации → заголовки и порядок отражают справочник, проценты следуют своим сущностям типов, а не старому номеру колонки.
- [ ] **PCT-DEF-COL-08** — После удаления типа оплаты, по которому есть активные заказы, обновить таблицу → его колонка скрылась, оставшиеся колонки и проценты не сдвинулись; оформленные заказы продолжают обычную обработку до «Заказ выдан». Разрешение и подтверждение удаления проверяются в «Конфигурациях».
- [ ] **PCT-DEF-LIST-01** — После добавления значения процента в конфигурации открыть списки разных строк, колонок и пар → новое значение доступно в правильном числовом порядке, выбирается и сохраняется; прежние настройки не сброшены.
- [ ] **PCT-DEF-LIST-02** — После удаления неиспользуемого значения в конфигурации обновить страницу → этот вариант больше не предлагается ни в одной проверяемой паре или колонке; сохранённые значения остальных позиций не меняются.
- [ ] **PCT-DEF-LIST-03** — На подготовленном наборе с процентом, установленным хотя бы у одного товара в любой паре, сверить список после работы со справочником → используемый процент и его сохранённые назначения не исчезли. Сам запрет удаления используемого значения проверяется в чек-листе «Конфигураций».

### 3.3. Страны, закупка и продажи

- [ ] **PCT-DEF-CTR-01** — Добавить страну поставки или реализации → у номенклатуры новых пар значения всех колонок дефолтные «-», покупки по ним запрещены; прежние пары сохраняют настройки. Начальные тумблеры новой пары — PCT-Q04.
- [ ] **PCT-DEF-CTR-02** — Выключить закупку страны поставки, изменить у неё проценты и локальные тумблеры разных строк/колонок, перезагрузить обе страницы → настройки сохранены, «Закупка» осталась выключенной; товар не возвращён в покупку только от редактирования.
- [ ] **PCT-DEF-CTR-03** — До удаления страны задать разные «-», 0 и ненулевые проценты по её парам и колонкам, затем восстановить → все её значения дефолтные «-», включая ранее нулевые, покупки по этим типам запрещены; другие страны не сброшены. Тумблеры — PCT-Q04, КТ/доставка проверяются по правилам «Закупки и реализации».
- [ ] **PCT-DEF-CTR-04 / PCT-Q06** — Удалить выбранную страну реализации → проверить её отсутствие/смену выбора по согласованному правилу, без сохранения последующей операции в исчезнувшую пару.
- [ ] **PCT-DEF-CTR-05** — Выключить общие «Продажи» реализации, изменить её проценты и локальные тумблеры на разных странах поставки, перезагрузить обе страницы → «Продажи» остались выключенными, проценты сохранены отдельно по парам.
- [ ] **PCT-DEF-CTR-06** — При одновременно выключенных закупке и общих продажах изменить процент выключенной позиции и выполнить доступные настройки строки → ни общий тумблер закупки, ни продажи не включились как побочный эффект; значения других пар сохранены.
- [ ] **PCT-DEF-GATE-01** — При включённых закупке, общих продажах и тумблере строки, числовом проценте выбранного типа (включая 0) и подходящем стоке → товар доступен по этому типу; «-» в другой колонке его не блокирует.
- [ ] **PCT-DEF-GATE-02** — При выключенной закупке и включённой позиции → товары этой страны не возвращаются в покупку от включения локального тумблера; товары другой страны проверяются отдельно.
- [ ] **PCT-DEF-GATE-03** — При выключенных общих продажах реализации и включённой позиции → товары этой реализации не возвращаются в покупку; другая реализация сохраняет свои ограничения.
- [ ] **PCT-DEF-GATE-04** — У включённой строки задать Cash = «-», Online = 1% → с Cash покупка недоступна, с Online доступна с наценкой 1%; общий тумблер не выключается, другая пара сохраняет свои условия.
- [ ] **PCT-DEF-GATE-05** — Поменять сочетание на Cash = 0, Online = «-» → Cash доступен без наценки, Online запрещён; направление запрета соответствует нужному типу, а не первой колонке таблицы.
- [ ] **PCT-DEF-GATE-06** — Задать «-» во всех колонках при включённом тумблере строки → покупка недоступна по всем типам, хотя тумблер остаётся активным. Заменить одну колонку на 0 → по ней покупка без наценки разрешена при остальных выполненных условиях.
- [ ] **PCT-DEF-GATE-07** — Задать 0 или положительный процент, затем выключить общий тумблер строки → покупка запрещена по всем типам, независимо от сохранённой нулевой или положительной наценки. Выбор 0 не отменяет выключенные закупку и общие продажи.

### 3.4. Фактическая наценка и сток

- [ ] **PCT-DEF-PRICE-01** — Поставщик выставил товар за 1000, выбран процент 1 → в соответствующей паре и типе оплаты клиентская цена 1010 для простого примера ТЗ без иных компонентов и неоднозначного округления.
- [ ] **PCT-DEF-PRICE-02** — Одному товару задать разные проценты по двум типам оплаты → при применимом типе клиент получает соответствующую наценку, а не значение соседней колонки.
- [ ] **PCT-DEF-PRICE-03** — Одной позиции задать разные проценты по четырём парам → цена использует процент нужных поставки и реализации, а не глобальное значение реализации.
- [ ] **PCT-DEF-PRICE-04** — Изменить родительский процент после частных значений моделей → цена всех соответствующих текущих предложений использует перезаписанное значение.
- [ ] **PCT-DEF-PRICE-05 / PCT-Q05** — Проверить нулевой процент, минимальный ненулевой и максимальный варианты текущего справочника (в исходном наборе 0.01 и 23) на дробных ценах, разных валютах и количестве больше 1 → после согласования математики проверить базу, конвертацию, округление единицы и суммы.
- [ ] **PCT-DEF-PRICE-06** — При включённых общих ограничениях, тумблере строки и подходящем стоке сравнить «-» и 0 одной колонки → при «-» покупка по этому типу запрещена, при 0 доступна без наценки страницы. Цена другого разрешённого типа и состояние общего тумблера не меняются.
- [ ] **PCT-DEF-PRICE-07** — Изменить процент без стока либо у выключенной позиции, затем выставить товар или включить позицию при разрешённых закупке/продажах → для нового доступного предложения применяется сохранённый процент нужной пары и типа оплаты. Точные округления — PCT-Q05.
- [ ] **PCT-DEF-PRICE-08 / PCT-Q05** — Изменить процент при открытом прайсе/покупке клиента → проверить актуализацию и реакцию на изменение цены по согласованному сценарию; не требовать real-time обновления только по факту автосохранения админки.
- [ ] **PCT-DEF-PRICE-09** — Изменить наценку площадки → исходная цена поставщика не заменяется рассчитанной клиентской ценой, процент не начисляется повторно при перезагрузках.
- [ ] **PCT-DEF-PRICE-10** — Для предложения с ценой поставщика 1000 пройти в одной колонке 1% → «-» → 0 при остальных выполненных условиях → соответственно цена 1010, покупка недоступна, цена 1000. После повторного открытия результат не смешивается, общий тумблер остаётся включённым.

### 3.5. Видимость товара, заказы и подписки

- [ ] **PCT-DEF-STOCK-01** — Выключить конечный вариант → клиент не видит его предложения для покупки в выбранной паре; админ видит товар в стоке как неактивный, а поставщик продолжает видеть товар и работать с ним. Другие пары сохраняют собственную доступность.
- [ ] **PCT-DEF-STOCK-02** — Выключить модель и категорию → недоступны соответствующие вложенные позиции; другая ветка не скрывается.
- [ ] **PCT-DEF-STOCK-03** — После выключения категории включить один вариант → для продажи разрешена только выбранная восстановленная ветка, остальные дети остаются выключенными; общие ограничения закупки/продаж продолжают действовать.
- [ ] **PCT-DEF-STOCK-04** — Снять позицию с продажи локальным тумблером → не удаляются сущности номенклатуры, страны, поставщики и клиенты; состояние настроек других пар сохранено.
- [ ] **PCT-DEF-STOCK-05** — При выключенной позиции поставщик изменяет доступные параметры товара, например цену и количество → изменения сохраняются в его контуре и видны админу, но сами не возвращают товар клиенту и не включают позицию.
- [ ] **PCT-DEF-STOCK-06** — Повторно включить позицию при разрешённых закупке/продажах → админский сток перестаёт показывать её как отключённую этой настройкой, клиент получает подходящие предложения с актуальными данными поставщика; выключенные соседние позиции не возвращаются.
- [ ] **PCT-DEF-STOCK-07** — Задать «-» одному типу оплаты при разрешённом другом → клиент с запрещённым типом не может купить товар, клиент с разрешённым типом может; админ и поставщик не теряют запись товара, поставщик продолжает работу с ним. Не требовать полной неактивности админской строки по одному запрещённому типу.
- [ ] **PCT-DEF-STOCK-08** — Исследование: сравнить отображение в админском стоке при «-» одной колонки, «-» всех колонок и выключенном общем тумблере → зафиксировать индикацию по типам и состояние строки. Клиентские ограничения проверить по PCT-DEF-GATE-04–07; единое визуальное оформление этих состояний пока не задано.
- [ ] **PCT-DEF-ORDER-01** — Изменить процент или выключить товар при уже оформленном заказе → ранее оформленный заказ не пересчитывается как текущий сток и не отменяется самим переключением позиции; доступность его штатной обработки сохраняется. Точные расчёты изменяемых компонентов заказа проверяются в документации заказов.
- [ ] **PCT-DEF-SUB-01** — Исследование по поручению пользователя: подготовить подписки на появление и цену, выключить вариант, модель и категорию → зафиксировать, сохранились ли подписки или удалились, для выбранной и другой пары. Обязательный исход не задан — PCT-Q07; вердикт о соответствии до согласования не выставлять.
- [ ] **PCT-DEF-SUB-02** — Исследование: повторно включить позицию и обновить приложение → зафиксировать наличие прежних подписок и их работу после изменения цены/стока, отдельно проверить другую пару. Результат связать с PCT-Q07, не требовать заранее восстановления либо удаления.
- [ ] **PCT-DEF-SUB-03** — Исследование: при созданных клиентских подписках выбрать «-» только по одному типу, затем вернуть 0 → зафиксировать судьбу подписок и уведомлений для запрещённого и другого типа оплаты, сравнить с выключением общего тумблера. Ожидаемое сохранение или удаление подписок не задано — PCT-Q07.

### 3.6. Права доступа — всё отложено

- [ ] **PCT-DEF-ACL-01** — После реализации прав пользователь с просмотром открывает страницу и читает настройки, но не меняет проценты и тумблеры ни через интерфейс, ни прямым запросом.
- [ ] **PCT-DEF-ACL-02** — Пользователь с редактированием меняет разрешённые настройки, изменения сохраняются; отсутствие прав на «Конфигурации» не заменяется доступом к странице «Проценты».
- [ ] **PCT-DEF-ACL-03** — Пользователь без просмотра не получает данные страницы по прямому адресу или запросу; конкретная форма отказа проверяется после согласования модели прав.

## 4. Условия завершения согласования

- Определены тумблеры новой/восстановленной пары (PCT-Q04), точная математика и обновление цены (PCT-Q05), оставшиеся правила выбора стран (PCT-Q06).
- По результатам отложенного исследования подписок зафиксировано ожидаемое поведение PCT-Q07. Комментарий о «Конфигурациях» учтён как зависимость, её собственные CRUD-проверки в текущую страницу не перенесены.
- Исследования ошибок, конкурентных изменений и отображения смешанного родительского процента получили согласованные ожидания либо явно исключены.
- При готовности зависимостей отложенные проверки переносятся в текущий прогон; существующая отметка локального сохранения не закрывает интеграционный пункт автоматически.
