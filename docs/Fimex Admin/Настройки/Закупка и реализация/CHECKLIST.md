# Чек-лист: Настройки → Закупка и реализация

Рабочий чек-лист страницы. Отметки отдельных пунктов используются для учёта прогона; для результата фиксируются дата, фактическое поведение и ссылка на дефект при его наличии.

**Доступно сейчас:** интерфейс, валидация, сохранение данных и связи между элементами внутри страницы.

**Отложено:** проверки зависимых разделов и приложений (раздел 4). Все проверки прав доступа отложены: права ещё не реализованы (раздел 4.9).

**Правило ещё не согласовано:** доступное поле можно исследовать сейчас по разделу 3.3, записав фактическое поведение. До согласования правила из раздела 5 нельзя считать такое поведение правильным только потому, что система его допускает.

Формат пункта: **ID — действие → ожидаемый результат**. При прогоне фиксировать результат и ссылку на дефект, если он найден.

## Подготовка

- Использовать тестовые данные и доступную тестовую учётную запись. Проверки различий между ролями сейчас не выполнять.
- Для сравнения вкладок нужны две страны поставки, далее условно UAE и USA, с различающимися временем КТ, рабочими днями и состоянием закупки.
- Для проверки общих настроек нужны одни и те же страны реализации Deira и Free zone, связанные с обеими странами поставки. Одинаковых названий у разных сущностей недостаточно.
- Для проверки независимости доставки задать различающиеся значения у UAE × Deira, USA × Deira, UAE × Free zone и USA × Free zone.
- Добавление, переименование, удаление и восстановление выполнять на отдельных тестовых записях. Для удаления страны поставки со связками подготовить отдельный набор данных. Перед удалением зафиксировать состав связок и значения всех настроек. Для сравнения до/после восстановления не менять общие настройки через другие вкладки в промежутке между удалением и восстановлением.
- Для доступных сейчас позитивных сценариев выключения и удаления использовать данные без активных заказов и подписок; для изменения регионов — регионы без клиентов. Проверки самих ограничений находятся в отложенном блоке.
- Если нужную связку или тестовые данные пока нельзя получить через интерфейс, соответствующий пункт отложить до подготовки данных.
- Для файлов подготовить исправные PNG и SVG заметно меньше 2 МБ, файлы больше 2 МБ, неподдерживаемые форматы, пустой и повреждённый файл.

### Проверка сохранения

Проверка сохранения включает: дождаться завершения сохранения, переключиться на другую страну поставки и вернуться, затем перезагрузить страницу и снова выбрать проверяемую страну. Данные должны соответствовать успешно сохранённым значениям. Для модальных форм дополнительно открыть форму повторно.

КТ, рабочие дни, тумблеры, валюта и дни доставки сохраняются автоматически. Формы добавления и редактирования сохраняются кнопкой «Сохранить».

### Область действия настроек

| Уровень | Что относится к уровню |
| --- | --- |
| Страна поставки | Название, время КТ, рабочие дни, «Закупка». |
| Страна реализации | Название, регионы, стикер, часовой пояс отображения для клиента, валюта, курс, счётчик клиентов, возможность добавления клиента, «Продажи». |
| Связка страны поставки и страны реализации | Сроки доставки по дням недели; удаление карточки из выбранной страны поставки. |

## 1. Доступно сейчас: страна поставки

### 1.1. Переключение вкладок

- [x] **TAB-01** — Открыть страницу с несколькими странами поставки → активные записи представлены отдельными вкладками; удалённые страны среди них отсутствуют.
- [x] **TAB-02** — Поочерёдно выбрать UAE и USA → выбранная вкладка выделена, время КТ, рабочие дни, «Закупка» и набор карточек соответствуют выбранной стране.
- [x] **TAB-03** — Несколько раз переключиться UAE → USA → UAE → значения не подменяются данными предыдущей вкладки, карточки не дублируются.
- [x] **TAB-04** — Нажать уже выбранную вкладку → страна остаётся выбранной, настройки не изменяются, лишняя карточка или вкладка не создаётся.
- [x] **TAB-05** — При замедленной загрузке быстро переключать страны → после завершения запросов содержимое соответствует последней выбранной вкладке.
- [x] **TAB-06** — Сохранить настройку UAE, перезагрузить страницу и снова выбрать UAE → сохранённое значение загружено; конкретная вкладка, выбранная автоматически после перезагрузки, этим пунктом не задаётся.

### 1.2. Время КТ накладных

- [x] **KT-01** — Изменить часы, сохранив минуты, например 22:15 → 21:15 → новое время автоматически сохраняется у выбранной страны.
- [x] **KT-02** — Изменить минуты, сохранив часы, например 21:15 → 21:45 → новое время автоматически сохраняется без изменения часов.
- [x] **KT-03** — Поочерёдно задать 00:00 и 23:59 → корректные значения времени суток принимаются и сохраняются без сдвига даты или времени в поле.
- [x] **KT-04** — Если поле допускает ручной ввод, ввести невозможное время, например 25:00 или 12:60 → невозможное значение не сохраняется; корректная сохранённая настройка не повреждается.
- [x] **KT-05** — Если поле допускает ввод или вставку текста, попытаться ввести буквы вместо времени → текст не сохраняется как время КТ.
- [x] **KT-06** — Изменить КТ UAE и проверить USA → КТ USA, рабочие дни и тумблеры обеих стран сохраняют свои значения.
- [x] **KT-07** — Изменить КТ и выполнить проверку сохранения → в поле остаётся новое время; срокам доставки и общим настройкам Deira/Free zone оно не присваивается.

Фактическое наступление КТ, перенос товара и работа с активными заказами проверяются в отложенном блоке.

### 1.3. Рабочие и выходные дни

- [x] **DAY-01** — Открыть настройки → представлены все семь дней недели без пропусков и повторений; выбранные и невыбранные дни визуально различаются.
- [x] **DAY-02** — Сделать рабочим один невыбранный день → выбран только этот дополнительный день, изменение автоматически сохраняется.
- [x] **DAY-03** — Сделать выходным один выбранный день, оставив другие рабочие дни → выбор снимается с этого дня, остальные дни не изменяются.
- [x] **DAY-04** — Сделать выходной снова рабочим → день возвращается в набор рабочих, состояние сохраняется.
- [x] **DAY-05** — Поочерёдно выполнить добавление и исключение каждого дня недели, сохраняя хотя бы один рабочий день → изменяется именно выбранный день, названия и сохранённые дни не перепутаны.
- [x] **DAY-06** — Задать все семь дней рабочими → сохраняются семь выбранных дней.
- [x] **DAY-07** — Задать один рабочий день, затем несколько несмежных дней → каждый набор сохраняется без самопроизвольного включения соседних дней.
- [x] **DAY-08** — Изменить рабочие дни UAE и выполнить проверку сохранения → USA, время КТ, «Закупка» и дни доставки карточек не изменяются.

Снятие всех рабочих дней можно исследовать сейчас по OBS-06; оценка допустимости пустого расписания ожидает Q-DAY-01.

### 1.4. Тумблер «Закупка»

- [x] **BUY-01** — Выключить «Закупка» в выбранной стране → состояние меняется на выключенное и автоматически сохраняется.
- [x] **BUY-02** — Включить «Закупка» обратно → состояние меняется на включённое и автоматически сохраняется.
- [x] **BUY-03** — Оставить разные состояния закупки у UAE и USA и выполнить проверку сохранения → каждая вкладка показывает своё состояние.
- [x] **BUY-04** — Выключить закупку UAE при включённых продажах Deira и Free zone → на странице сохраняется сочетание «Закупка выключена, Продажи включены»; сами тумблеры продаж автоматически не выключаются.
- [x] **BUY-05** — Переключить закупку → время КТ, рабочие дни, валюты и сроки доставки не сбрасываются, связки не удаляются.

Эти пункты подтверждают состояние настроек. Скрытие товаров от клиентов проверяется отдельно после появления соответствующих разделов.

### 1.5. Редактирование страны поставки

- [x] **SUP-EDIT-01** — Открыть редактирование выбранной страны → в форме указано её текущее название.
- [x] **SUP-EDIT-02** — Задать новое уникальное название и сохранить → обновляется название существующей вкладки; новая страна не создаётся.
- [x] **SUP-EDIT-03** — После переименования выполнить проверку сохранения → новое название сохранено вместе с прежними КТ, рабочими днями, закупкой и связками.
- [x] **SUP-EDIT-04** — Переименовать UAE в точное название другой существующей страны поставки → изменение отклоняется, обе исходные страны сохраняются.
- [x] **SUP-EDIT-05** — Сохранить форму без изменения названия → страна не конфликтует сама с собой, дубликат не создаётся.
- [x] **SUP-EDIT-06** — Открыть и закрыть форму без изменений → данные страны сохраняются.

### 1.6. Удаление страны поставки

- [x] **SUP-DEL-01** — Нажать удаление страны поставки → до удаления появляется подтверждение.
- [x] **SUP-DEL-02** — Отказаться от удаления в подтверждении → вкладка, её настройки и связки сохраняются после перезагрузки.
- [x] **SUP-DEL-03** — Подтвердить удаление отдельной тестовой страны → вкладка исчезает из активных; страна появляется в списке удалённых.
- [x] **SUP-DEL-04** — После удаления повторно открыть страницу → удалённая страна не возвращается в активные вкладки.
- [x] **SUP-DEL-05** — Удалить одну из двух стран с общей страной реализации → оставшаяся страна поставки, её карточки и их общие настройки сохраняются.
- [x] **SUP-DEL-06** — В отдельном наборе данных удалить последнюю страну поставки → страница открывается без ошибок и без данных удалённой страны; возможность добавления новой страны остаётся доступной.

### 1.7. Список удалённых и восстановление

- [x] **SUP-REST-01** — Открыть список удалённых стран круговой стрелкой → доступны удалённые страны и действие «Восстановить» для каждой; активные страны не предлагаются для восстановления.
- [x] **SUP-REST-02** — Закрыть список без действий → страны не восстанавливаются.
- [x] **SUP-REST-03** — Восстановить одну страну без конфликта названия → она появляется одной активной вкладкой и перестаёт предлагаться как удалённая.
- [x] **SUP-REST-04** — Восстановить ранее удалённую страну со связками → вместе со страной возвращаются все карточки стран реализации, привязанные на момент удаления; состав связок совпадает с зафиксированным до удаления, дубликатов нет.
- [x] **SUP-REST-05** — После восстановления переключить вкладки и перезагрузить страницу → страна остаётся активной, все восстановленные связки и сохранённые настройки доступны.
- [x] **SUP-REST-06** — При нескольких удалённых странах восстановить одну → остальные остаются в списке удалённых; действующие страны не изменяются.
- [x] **SUP-REST-07** — Открыть пустой список удалённых → нет вымышленных записей или доступного действия для несуществующей страны; форму можно закрыть.

- [x] **SUP-REST-08** — До удаления задать отличающиеся от начальных название, КТ и рабочие дни, затем восстановить страну → все эти значения совпадают с сохранёнными перед удалением.
- [x] **SUP-REST-09** — Поочерёдно удалить и восстановить страну с включённой и выключенной закупкой → восстанавливается сохранённое состояние тумблера; выключенная закупка не включается автоматически.
- [x] **SUP-REST-10** — До удаления задать разные сроки доставки по дням недели для Deira и Free zone, затем восстановить страну → каждая связка сохраняет свой набор из семи значений, сроки не обнуляются и не копируются между карточками.
- [x] **SUP-REST-11** — Восстановить страну и сравнить общие поля её карточек с данными до удаления → сохранены названия, регионы и их порядок, стикеры, клиентские часовые пояса, валюты, курсы, возможность добавления клиента и продажи. Включённые и выключенные состояния сохраняются.
- [x] **SUP-REST-12** — После восстановления UAE изменить общее поле Deira, например часовой пояс → изменение видно и у Deira на USA; восстановлена связь с прежней общей сущностью, а не создана её копия. Индивидуальная доставка каждой связки сохраняется.
- [x] **SUP-REST-13** — Отредактировать восстановленную страну поставки, затем повторно удалить и восстановить её → возвращаются последнее сохранённое название и настройки, прежние связки не теряются и не дублируются.

- [ ] **SUP-REST-14** — До удаления страны поставки отдельно удалить одну её связку, зафиксировать оставшийся состав, затем удалить и восстановить страну → возвращаются только связки, существовавшие на момент удаления страны; ранее удалённая отдельно карточка не появляется сама.

Поведение при конфликте названия во время восстановления вынесено на уточнение Q-REST-01; изменение общей настройки в период удаления — OBS-14 / Q-REST-03.

### 1.8. Добавление страны поставки

- [ ] **SUP-ADD-01** — Нажать верхний плюс → открывается форма добавления страны поставки.
- [ ] **SUP-ADD-02** — Создать страну с уникальным названием, заполнив доступные обязательные поля формы → появляется одна новая вкладка с указанным названием.
- [ ] **SUP-ADD-03** — Выполнить проверку сохранения новой страны → страна доступна для выбора и редактирования, повторная запись не возникает.
- [ ] **SUP-ADD-04** — Создать страну с названием, точно совпадающим с названием действующей страны поставки → дубликат не создаётся, ранее существовавшая страна не изменяется.
- [ ] **SUP-ADD-05** — Открыть и закрыть пустую форму без сохранения → новая страна не создаётся.
- [ ] **SUP-ADD-06** — Добавить страну и проверить ранее существовавшие вкладки → их настройки и связки сохраняются.

Общие проверки названий приведены в разделе 3.1. Пустой ввод, ограничения длины и начальные значения исследуются сейчас по OBS-01–OBS-03 и OBS-07; неизвестные правила не подменяются текущим поведением интерфейса.

## 2. Доступно сейчас: страна реализации и связка

### 2.1. Карточки и добавление страны реализации

- [ ] **REAL-ADD-01** — Выбрать страну поставки → показываются её связанные страны реализации, без карточек связок, существующих только у другой страны поставки.
- [ ] **REAL-ADD-02** — Нажать «Добавить» под карточками → открывается сценарий добавления страны реализации для выбранной страны поставки.
- [ ] **REAL-ADD-03** — Создать страну реализации с уникальным названием, корректным часовым поясом, стикером и остальными применимыми обязательными полями и завершить привязку → появляется одна карточка в выбранной стране поставки.
- [ ] **REAL-ADD-04** — Проверить другую страну поставки после создания новой страны реализации → новая связка там автоматически не возникает.
- [ ] **REAL-ADD-05** — Выполнить проверку сохранения → карточка и сохранённые поля новой страны реализации доступны после повторного открытия страницы.
- [ ] **REAL-ADD-06** — Поочерёдно не заполнить название, часовой пояс и стикер при остальных корректных данных → создание не завершается без каждого обязательного поля.
- [ ] **REAL-ADD-07** — Сохранить корректную новую страну реализации с выключенной «Возможностью добавления клиента» → выключенное состояние принимается как допустимое значение, включать тумблер для сохранения не требуется.
- [ ] **REAL-ADD-08** — Создать страну реализации с названием, точно совпадающим с существующей, в том числе связанной только с другой страной поставки → новая глобальная сущность с таким названием не создаётся.
- [ ] **REAL-ADD-09** — Открыть и закрыть пустую форму без сохранения → страна реализации и связка не создаются.

### 2.1.1. Привязка существующей страны реализации

Подготовить общую страну реализации, уже связанную с USA, но ещё не связанную с UAE, с различимыми валютой, курсом, поясом и состоянием продаж. Для проверки смены выбора нужны две доступные страны реализации с разными общими значениями.

- [ ] **LINK-ADD-01** — На UAE нажать «Добавить» → окно содержит выбор страны реализации, валюту, курс, «Создать новую страну реализации», «Сохранить» и закрытие.
- [ ] **LINK-ADD-02** — Раскрыть список → существующая страна реализации, связанная только с USA, доступна для выбора на UAE; её не требуется создавать заново.
- [ ] **LINK-ADD-03** — Нажать «Сохранить» без выбранной страны реализации → привязка не создаётся, общие настройки существующих записей не меняются.
- [ ] **LINK-ADD-04** — Выбрать существующую страну реализации → валюта и курс автоматически соответствуют её общим значениям на USA.
- [ ] **LINK-ADD-05** — Попытаться изменить валюту и курс в этом окне мышью, с клавиатуры и вставкой → оба поля недоступны для редактирования, произвольные значения не сохраняются.

- [ ] **REG-04** — Оставить новую строку региона пустой → пустой код региона не появляется в сохранённом списке.
- [ ] **REG-05** — Поочерёдно ввести цифры, кириллицу, знак пунктуации, пробел внутри кода и смесь букв с цифрами → значения, не соответствующие формату «1–3 латинские буквы», не сохраняются.
- [ ] **REG-06** — Изменить свободный код региона на другой корректный → обновляется выбранная строка; остальные регионы сохраняются.
- [ ] **REG-07** — Удалить один неиспользуемый регион и сохранить → удаляется только выбранный регион, остальные остаются.
- [ ] **REG-08** — Переставить регионы перетаскиванием и сохранить → заданный порядок сохраняется при повторном открытии формы.
- [ ] **REG-09** — За одно сохранение добавить один регион, изменить второй и удалить третий → все три действия отражены в итоговом списке, остальные строки не потеряны.
- [ ] **REG-10** — Изменить список Deira на UAE и выполнить проверку сохранения → в Deira на USA тот же список и порядок; Free zone не получает регионы.

- [ ] **REG-11** — Повторить REG-02–REG-05 при изменении существующего региона без клиентов → ограничения 1–3 латинские буквы работают и при редактировании; отклонённое значение не заменяет прежний код после повторного открытия.
- [ ] **REG-12** — Вставить вместо набора четыре буквы, кириллицу, `A1`, пробелы, табуляцию или перенос строки → вставка не позволяет сохранить код вне формата 1–3 латинские буквы. Нормализацию пробелов проверять отдельно по OBS-04.
- [ ] **REG-13** — Заменить ошибочный код на свободный корректный и повторить сохранение → исправленный регион сохраняется, прежняя ошибка не блокирует действие.
- [ ] **REG-14** — Добавить два корректных региона, удалить первую новую строку до сохранения и сохранить → в списке остаётся только вторая новая строка; существующие регионы не удалены.

- [ ] **REG-16** — Добавить и изменить регионы, закрыть форму крестиком без сохранения, затем открыть снова → несохранённые изменения не записаны; сохранённый список и порядок прежние.

- [ ] **FILE-08** — Выбрать файл неподдерживаемого содержимого, переименованный в `.png` или `.svg` → одного расширения недостаточно для принятия некорректного стикера.

## 3. Доступно сейчас: сохранение, ошибки и совместная работа элементов

Для ошибок загрузки и сохранения использовать управляемый отказ или прерывание соответствующего запроса в тестовой среде. Подтверждённый отказ сервера отличать от потери ответа: во втором случае сначала повторно загрузить данные и установить фактический итог операции. Если управление запросами недоступно, соответствующие пункты отложить до подготовки среды.

- [ ] **SAVE-01** — Поочерёдно изменить КТ, рабочий день, закупку, продажи, валюту и дни доставки → каждое изменение сохраняется без дополнительной кнопки «Сохранить» на основной странице.
- [ ] **SAVE-02** — Поочерёдно вызвать ошибку автосохранения для этих элементов → отображается тост с ошибкой.
- [ ] **SAVE-03** — После подтверждённого отказа сохранения перезагрузить страницу → загружается фактически сохранённое значение, неуспешное изменение не выдаётся за сохранённое. Поведение поля до перезагрузки рассматривается отдельно в Q-SAVE-01.
- [ ] **SAVE-04** — После ошибки восстановить возможность сохранения и повторить изменение → настройка успешно сохраняется, страница не остаётся заблокированной.
- [ ] **SAVE-05** — При замедленном сохранении изменить настройку UAE и сразу перейти на USA → изменение относится к UAE, одноимённое поле USA не перезаписывается.
- [ ] **SAVE-06** — Быстро изменить два разных поля одной страны и дождаться завершения сохранения → оба успешных изменения сохранены; один запрос не возвращает другое поле к прежнему значению.
- [ ] **SAVE-07** — В форме изменить несколько допустимых полей и нажать «Сохранить» → все успешно сохранённые поля доступны при повторном открытии, соседняя сущность не изменена.
- [ ] **SAVE-08** — Несколько раз быстро нажать «Сохранить» при создании тестовой страны → не возникает нескольких одинаковых стран или связок.
- [ ] **SAVE-09** — Несколько раз быстро нажать подтверждение удаления или восстановление → действие относится только к выбранной записи; дубликаты восстановленной страны не возникают.
- [ ] **SAVE-10** — Вызвать подтверждённый отказ создания, удаления или восстановления и заново загрузить данные → состояние соответствует результату операции: несозданная запись отсутствует, неудалённая остаётся активной, невосстановленная остаётся удалённой.
- [ ] **FLOW-01** — Создать тестовую страну поставки, задать КТ и дни, переименовать, выключить и включить закупку → последовательные сохранения сохраняют одну и ту же страну со всеми заданными настройками.

- [ ] **UI-02** — Проверить страницу с длинными названиями и несколькими вкладками → названия не перекрывают действия, нужную страну можно выбрать.

### 3.1. Ввод, валидация и исправление ошибок

Выполнять применимые проверки отдельно при создании и редактировании. Для формы привязки существующей страны реализации использовать LINK-ADD: название там выбирается из списка, валюта и курс недоступны для редактирования. Проверки ниже не вводят неподтверждённых ограничений длины названия или количества дней.

- [ ] **VAL-NAME-01** — При создании страны реализации оставить название пустым, затем повторить с одними пробелами → обязательное название не заполнено, сущность и связка не создаются.
- [ ] **VAL-NAME-02** — При создании и переименовании обоих типов стран ввести точное название другой существующей записи, в том числе вставкой → проверка уникальности не обходится способом ввода; новая запись или переименование не сохраняются.
- [ ] **VAL-NAME-03** — После ошибки дубликата заменить название на свободное и сохранить → операция завершается, сохраняется исправленный вариант, а не прежнее ошибочное значение.
- [ ] **VAL-NAME-04** — Изменить название в форме редактирования и закрыть её крестиком без сохранения → после повторного открытия и перезагрузки остаётся прежнее сохранённое название. Наличие предупреждения о несохранённых данных уточняется отдельно.
- [ ] **VAL-NAME-05** — В сохранённом названии проверить кириллицу, латиницу и эмодзи на допустимых примерах, которые принимает форма → после перезагрузки текст не искажён, символы не заменяются на «?», соседние записи не повреждаются. Сам перечень разрешённых символов уточняется в Q-NAME-02.
- [ ] **VAL-NAME-06** — На тестовой записи ввести текст `<b>QA</b>` → если он принят, в заголовках, карточках, списке выбора и подтверждении удаления он отображается как текст, не становится HTML-разметкой. Допустимость символов имени этим пунктом не устанавливается.
- [ ] **VAL-01** — Поочерёдно попытаться нарушить подтверждённое правило формата или обязательности поля → недопустимый ввод блокируется контролом либо, если неверное значение удалось оставить в поле, сохранение отклоняется с видимой ошибкой. Некорректное значение не попадает в сохранённые данные. При блокировке ввода дополнительное сообщение об ошибке не обязательно.
- [ ] **VAL-02** — После ошибки очистить неверный ввод и ввести корректное значение → ошибку можно исправить в той же форме, сохранён именно исправленный вариант; повторное открытие страницы не требуется для разблокировки формы.
- [ ] **VAL-03** — В форме создания страны реализации оставить несколько обязательных полей пустыми и исправлять по одному → оставшиеся ошибки продолжают препятствовать созданию; полностью корректная форма сохраняется один раз.
- [ ] **VAL-04** — Выполнить сохранение с клавиатуры, если форма поддерживает Enter → действуют те же проверки, что при нажатии «Сохранить»; не возникает двойной отправки или обхода обязательности.
- [ ] **VAL-05** — После ошибки одной записи открыть форму другой → чужая ошибка и введённые данные не подставляются в другую страну или регион.
- [ ] **SAVE-11** — Несколько раз быстро изменить одно автосохраняемое поле, например дни доставки 2 → 7 → 3 → после завершения успешных запросов и перезагрузки остаётся последнее значение 3; поздний ответ не возвращает 2 или 7. Повторить для тумблера вкл → выкл → вкл.
- [ ] **SAVE-12** — При потере ответа на создание/привязку сначала перезагрузить данные и проверить итог, затем при необходимости повторить действие → не создаются дубликаты. Потеря ответа сама по себе не считается доказательством, что сервер не сохранил запись.
- [ ] **SAVE-13** — В двух вкладках браузера попытаться привязать одну и ту же существующую страну реализации к одной стране поставки → после обновления данных существует одна активная пара, без двойной карточки.
- [ ] **SAVE-14** — В модальной форме изменить название страны поставки и вызвать подтверждённый отказ запроса сохранения → после повторной загрузки остаётся прежнее название, остальные настройки и связки не потеряны. После устранения ошибки повторное сохранение в доступной форме успешно изменяет ту же запись без дубликата.
- [ ] **SAVE-15** — Замедлить сохранение нового КТ, затем подтвердить удаление этой страны поставки и дождаться всех ответов → если удаление завершилось успешно, поздний ответ сохранения не возвращает вкладку в активные; после перезагрузки страна остаётся удалённой, остальные страны не изменены.
- [ ] **SAVE-16** — Замедлить сохранение доставки UAE × Deira, затем подтвердить удаление этой связки и дождаться всех ответов → успешное удаление не отменяется поздним ответом доставки; карточка отсутствует после перезагрузки, другие связки и общая Deira сохраняются.
- [ ] **SAVE-17** — В первой вкладке браузера открыть переименование страны поставки, во второй удалить её, затем в первой попытаться сохранить старую форму → устаревшая форма не восстанавливает страну и не создаёт новую запись. Отказ сообщается пользователю; после обновления страна остаётся удалённой. Штатная кнопка восстановления остаётся отдельным действием.

Для SAVE-15 и SAVE-16 использовать данные без блокирующих заказов и подписок. Если интерфейс запрещает удаление до завершения сохранения, проверить запрет и отсутствие отправки удаления; затем выполнить удаление после завершения сохранения. Не считать блокировку интерфейса ошибкой сама по себе.
- [ ] **UI-03** — При пустом списке доступных стран реализации открыть добавление → нет вымышленных вариантов, сохранение без выбора не создаёт карточку, создание новой страны реализации и закрытие доступны.
- [ ] **UI-04** — Последовательно открыть добавление и редактирование разных стран → заголовок, значения и цель сохранения соответствуют текущей форме; данные предыдущей формы не переносятся в другую запись.
- [ ] **UI-05** — Перейти по адресу с удалённой или несуществующей страной поставки → данные другой страны не выдаются за запрошенную, страница не падает, можно выбрать доступную страну. Конкретный вариант перехода или сообщения уточняется в Q-UI-01.

### 3.2. Загрузка, ошибки и повторное открытие

Для ошибки загрузки подготовить существующие записи, чтобы отличить отказ запроса от действительно пустых данных. После устранения ошибки допускается доступное действие повтора либо перезагрузка страницы; отдельная кнопка повтора этим пунктом не требуется.

- [ ] **LOAD-01** — Вызвать подтверждённый отказ первоначальной загрузки страницы → пользователь видит ошибку загрузки; отказ не показывается как успешная загрузка без стран. После устранения ошибки повторная загрузка возвращает реальные вкладки и настройки без создания новых записей.
- [ ] **LOAD-02** — На странице с загруженной UAE вызвать отказ получения данных при выборе USA, если переключение отправляет запрос → данные UAE не выдаются за успешно загруженные данные USA. После восстановления загрузки настройки и карточки соответствуют USA.
- [ ] **LOAD-03** — Вызвать отказ получения списка существующих стран реализации в окне добавления, если список загружается отдельным запросом → отказ отличим от пустого списка; выбрать вымышленную запись или создать связку без действительного выбора нельзя. После повторной загрузки доступны реальные варианты.
- [ ] **LOAD-04** — Вызвать отказ получения удалённых стран → ошибка не выдаётся за достоверно пустой архив, восстановление несуществующей записи недоступно. После повторной загрузки отображается фактический список удалённых.
- [ ] **LOAD-05** — При выборе существующей страны реализации вызвать отказ подстановки её валюты и курса, если для этого нужен отдельный запрос → значения предыдущей страны не показаны как данные нового выбора. После восстановления загрузки подставлены правильные общие значения, поля остаются недоступными для редактирования. Если список и значения получены одним запросом, выполнить LOAD-03.

## 4. Отложено: зависимости от других разделов и приложений

Эти пункты пока не выполняются. Для каждого блока указано, что должно появиться для его проверки.

### 4.1. Активные заказы: запреты и предупреждения

**Зависимость:** создание заказов и управление статусами, связи заказов со страной поставки и страной реализации.

Каждую проверку активных заказов выполнять отдельно для каждого применимого статуса:

| Страна реализации | Активные статусы | Неактивный для этих ограничений |
| --- | --- | --- |
| Deira / Mabetex | Pending assembly; Packed; Order pending delivery | Released |
| Free zone / Fimex | Pending assembly; Order pending delivery | Released |

- [ ] **D-ORDER-01** — При активном заказе UAE в Deira или Free zone попытаться выключить закупку UAE → выключение запрещено, сохранённое состояние закупки остаётся включённым.
- [ ] **D-ORDER-02** — При активном заказе USA × Deira попытаться выключить продажи Deira на вкладке UAE → выключение запрещено: проверка общих продаж охватывает все страны поставки.
- [ ] **D-ORDER-03** — Повторить запрет выключения общих продаж для Free zone → учитываются её активные статусы во всех связанных странах поставки.
- [ ] **D-ORDER-04** — При активном заказе выбранной страны поставки попытаться удалить её → удаление запрещено, страна и связки сохраняются.
- [ ] **D-ORDER-05** — При активном заказе конкретной связки попытаться удалить её карточку → удаление запрещено, связка сохраняется.
- [ ] **D-ORDER-06** — Оставить активные заказы только у другой страны поставки и выключить закупку проверяемой страны → чужие заказы не блокируют локальную закупку. Повторить для локального удаления с учётом отдельной проверки подписок.
- [ ] **D-ORDER-07** — Оставить активные заказы только в другой связке и удалить проверяемую связку без заказов → проверка заказов не расширяется на чужую связку.
- [ ] **D-ORDER-08** — При наличии только Released-заказов, без иных блокирующих условий, выполнить выключение и удаление → выданные заказы не блокируют действия.
- [ ] **D-ORDER-09** — При активном заказе изменить время КТ его страны поставки → показано предупреждение, сохранение нового КТ разрешено.
- [ ] **D-ORDER-10** — При активном заказе сделать рабочий день выходным → показано предупреждение, сохранение нового расписания разрешено.
- [ ] **D-ORDER-11** — После сохранения изменений из D-ORDER-09 и D-ORDER-10 проверить заказы → их даты и статусы не изменились.
- [ ] **D-ORDER-12** — Оставить активные заказы только у другой страны поставки либо только Released-заказы у выбранной и изменить её КТ/назначить выходной → предупреждение о наличии активных заказов выбранной страны не появляется.

- [ ] **D-ORDER-13** — Открыть подтверждение удаления страны поставки без активных заказов, затем до подтверждения создать её активный заказ и подтвердить удаление → учитывается актуальное состояние, удаление запрещено, страна и её зависимости сохраняются. Повторить для удаления связки с новым заказом этой связки и для каждого применимого активного статуса.

### 4.2. Подписки Free zone

**Зависимость:** клиенты Free zone и подписки; тестовые данные без активных заказов.

- [ ] **D-SUB-01** — При активной подписке клиента Free zone попытаться удалить страну поставки в этом направлении → удаление запрещено.
- [ ] **D-SUB-02** — Повторить проверку с подписчиком, не ограниченным выбранной страной поставки → активная подписка всё равно блокирует удаление; проверяется весь список клиентов Free zone.
- [ ] **D-SUB-03** — Оставить только истёкшие или неактивные подписки при отсутствии активных заказов → проверка активных подписок не блокирует удаление.
- [ ] **D-SUB-04** — Для страны поставки только в Deira, без активных заказов, выполнить удаление → отдельное ограничение по подпискам Free zone не применяется к Deira.

- [ ] **D-SUB-05** — При отсутствии активных заказов и подписок открыть подтверждение удаления страны поставки, связанной с Free zone; до подтверждения активировать подписку клиента Free zone и подтвердить удаление → проверка учитывает новую активную подписку, удаление запрещено, страна и зависимости сохраняются.

### 4.3. Товары, закупка, продажи и авторизация

**Зависимость:** кабинет поставщика, товар, клиентские приложения Mabetex и Fimex, авторизация.

- [ ] **D-SALE-01** — Выключить закупку UAE при включённых продажах Deira и Free zone → товары поставщиков UAE скрыты от клиентов обоих направлений; доступность товаров USA не меняется.
- [ ] **D-SALE-02** — При выключенной закупке UAE открыть товар у поставщика и администратора → товар виден, поставщик может продолжать с ним работать.
- [ ] **D-SALE-03** — Повторно включить закупку при включённых продажах → товары соответствующей страны поставки возвращаются в продажу.
- [ ] **D-SALE-04** — При выключенной закупке включить продажи страны реализации → товары этой страны поставки остаются скрытыми.
- [ ] **D-SALE-05** — При выключенных продажах включить закупку → продажи отключённой страны реализации не возобновляются.
- [ ] **D-SALE-06** — Выключить продажи Deira при отсутствии активных заказов → действующие клиентские сессии Mabetex завершаются; повторный вход недоступен до включения продаж.
- [ ] **D-SALE-07** — При выключенной Deira проверить Fimex → отключение Deira не выключает Free zone. Повторить симметрично для выключения Free zone.
- [ ] **D-SALE-08** — Повторно включить продажи → вход в соответствующее приложение доступен; товары возвращаются только для стран поставки с включённой закупкой.
- [ ] **D-SALE-09** — Выключить продажи → учётные записи поставщиков и их товары сохраняются.

### 4.4. КТ, рабочие дни и даты товара

**Зависимость:** товар поставщика с назначенной датой, работа расписания КТ и фонового переноса, заказы и клиентское отображение дат.

Для проверки самой формулы даты задавать одинаковую прибавку во всех семи днях недели. Правило выбора дня недели из настроек уточняется в Q-DELIVERY-02.

- [ ] **D-DATE-01** — Опубликовать 20 октября товар на 25 октября с доставкой 2 календарных дня → клиентская дата равна 27 октября.
- [ ] **D-DATE-02** — Для товара на 25 октября задать доставку 0 → клиентская дата равна 25 октября.
- [ ] **D-DATE-03** — Задать прибавку, пересекающую выходные или границу месяца → прибавляются календарные дни без пропуска выходных, дата следующего месяца рассчитана корректно.
- [ ] **D-DATE-04** — Задать разные сроки для одной страны реализации в UAE и USA → дата для клиента рассчитывается по сроку соответствующей связки.
- [ ] **D-DATE-05** — Изменить время КТ до наступления сегодняшней КТ → работа расписания использует новое время для предстоящей КТ.
- [ ] **D-DATE-06** — Изменить время КТ после наступления сегодняшней КТ → новое время применяется со следующей КТ, уже прошедшая КТ повторно не выполняется.
- [ ] **D-DATE-07** — Сделать день выходным, когда на него выставлен товар → товар с неактуальной датой переносится на следующую ближайшую КТ по рабочему расписанию.
- [ ] **D-DATE-08** — Задать несколько подряд выходных → перенос выбирает ближайшую следующую КТ рабочего дня, а не промежуточный выходной.
- [ ] **D-DATE-09** — Изменить доставку, КТ или рабочие дни при наличии ранее оформленных заказов разных статусов, включая Released → даты заказов сохраняются; изменение дат относится к выставленным товарам с неактуальной датой.
- [ ] **D-DATE-10** — Проверить расчёт около смены календарного дня в часовом поясе поставщика → исходная дата определяется по поясу поставщика, а не по времени компьютера администратора.

- [ ] **D-DATE-11** — После уточнения критерия неактуальности в Q-DELIVERY-02 подготовить в одной стране поставки товар с датой, требующей переноса, и контрольный товар с актуальной будущей датой, не требующей переноса. Изменить КТ или рабочие дни и дождаться фоновой обработки → переносится только первый товар; дата контрольного товара и даты оформленных заказов прежние.
- [ ] **D-DATE-12** — Подготовить товары UAE и USA с зафиксированными датами, изменить КТ или рабочие дни только UAE и дождаться обработки → даты и расписание товаров USA не изменились; перенос в UAE соответствует её собственным настройкам.

### 4.5. Часовой пояс в клиентском приложении

**Зависимость:** клиентские приложения и данные с известным исходным временем. До появления приложений проверка клиентского отображения недоступна.

- [ ] **D-TZ-01** — Задать пояс страны реализации и открыть в приложении данные с известным временем → клиент видит время в выбранном поясе.
- [ ] **D-TZ-02** — Изменить пояс Deira на UAE → новое отображение применяется к данным Deira из всех стран поставки; отображение Free zone не изменяется.
- [ ] **D-TZ-03** — Сравнить отображение события около полуночи в разных поясах → часы и календарная дата согласованно преобразованы по выбранному поясу.
- [ ] **D-TZ-04** — Изменить клиентский пояс → фактический момент КТ страны поставки не меняется.

### 4.6. Клиенты и регионы

**Зависимость:** отдельные списки клиентов Deira и Free zone, создание клиентов, статусы и связи с регионами.

- [ ] **D-CLIENT-01** — Подготовить клиентов разных статусов → счётчик каждой страны реализации равен числу клиентов всех статусов в её списке.
- [ ] **D-CLIENT-02** — Изменить состав клиентов Deira → её общий счётчик обновляется на UAE и USA; счётчик Free zone не получает клиентов Deira.
- [ ] **D-CLIENT-03** — Включить и выключить возможность добавления клиента → на странице «Клиенты» соответствующей страны реализации кнопка добавления появляется и скрывается.
- [ ] **D-CLIENT-04** — При создании клиента Deira выбрать регион → связь клиента с регионом сохранена, обозначение региона участвует в его User ID.
- [ ] **D-CLIENT-05** — Для каждого статуса связанного клиента попытаться изменить код его региона → изменение запрещено.
- [ ] **D-CLIENT-06** — Для каждого статуса связанного клиента попытаться удалить его регион → удаление запрещено, клиент и регион сохраняют связь.

### 4.7. Справочник валют

**Зависимость:** раздел «Валюта» с сохранёнными валютами и курсами.

- [ ] **D-CUR-01** — Подготовить валюты в справочнике и открыть выбор в карточке → доступны соответствующие валюты из справочника.
- [ ] **D-CUR-02** — Выбрать валюту с известным курсом относительно USD → в карточке показан соответствующий курс, одинаковый на всех вкладках этой страны реализации.
- [ ] **D-CUR-03** — Подготовить USD с курсом 1 и другую валюту с известным курсом к USD → выбор каждой показывает её данные без смешения курсов и кодов валют.

Момент обновления после изменения справочника проверяется после уточнения Q-CUR-01.

### 4.8. Каскадное удаление

**Зависимость:** поставщики и их товар, отсутствие блокирующих заказов и подписок.

- [ ] **D-DEL-01** — Удалить страну поставки → относящиеся к ней поставщики и товары мягко удалены.
- [ ] **D-DEL-02** — После удаления UAE проверить поставщиков и товары USA → они сохраняются.
- [ ] **D-DEL-03** — Удалить только UAE × Deira → общая Deira, USA × Deira и поставщики UAE не удаляются вместе с одной связкой.

Восстановление поставщиков и товара после восстановления страны поставки требует отдельного правила Q-REST-02.

### 4.9. Права доступа — отложено

**Статус:** права доступа ещё не реализованы. Все пункты D-RIGHT выполняются только после их реализации.

**Зависимость:** страница «Пользователи», настроенные роли и учётные записи с разными разрешениями.

- [ ] **D-RIGHT-01** — Открыть страницу под пользователем с правом только просмотра → просмотр доступен, изменение и удаление через интерфейс недоступны.
- [ ] **D-RIGHT-02** — Выдать право редактирования без удаления → разрешённые настройки изменяются, удаление недоступно.
- [ ] **D-RIGHT-03** — Выдать право удаления → удаление доступно в пределах разрешённых действий, с подтверждением и бизнес-проверками.
- [ ] **D-RIGHT-04** — Скрыть папку или отдельную функцию для роли → соответствующий элемент отсутствует в интерфейсе; оставшиеся разрешённые действия доступны.
- [ ] **D-RIGHT-05** — Сравнить супер-админа и пользователя без специальных прав на настройку добавления клиентов → доступ к этому блоку соответствует согласованным ограничениям роли.

Права на создание и восстановление уточняются отдельно.
