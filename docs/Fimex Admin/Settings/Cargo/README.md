# Настройки → Карго

Рабочая функциональная документация. [Чек-лист](CHECKLIST.md). Проверки по документу ещё не выполнялись.

## 1. Назначение и термины

Страница задаёт тариф доставки, вес товара и рассчитывает стоимость карго для одной единицы товара. Пустой тариф запрещает новые покупки; явный 0 разрешает продажу без стоимости карго при остальных выполненных условиях.

| Понятие | Значение |
| --- | --- |
| Страна поставки | UAE, USA и другие страны поставщиков. |
| Страна реализации | Deira (Mabetex), Free zone (Fimex) и другие реализации. |
| Связка | Конкретная пара, например UAE × Deira. |
| Модель | Например, iPhone 13; включает её конфигурации и товары. |
| Конфигурация | Например, iPhone 13 A2633 Australia. Страна спецификации устройства отличается от страны поставки. В ТЗ этот уровень назван вариантом. |
| Товар | Конкретная позиция номенклатуры, например iPhone 13 A2633 Australia 128Gb Midnight. Её вес общий для всех связок. |
| Тариф | Стоимость доставки одного килограмма в USD/кг; редактируемое поле. |
| Вес | Фактический вес одной единицы товара в граммах; редактируемое поле. |
| Карго | Рассчитанная стоимость доставки одной единицы товара в USD; вручную не редактируется. |

В формуле умножается на вес именно тариф за килограмм. Уже рассчитанное карго второй раз на вес не умножается.

## 2. Область действия

| Настройка | Область действия |
| --- | --- |
| Тариф товара | Только выбранная связка страны поставки и реализации. Внутри неё тариф общий для типов оплаты. |
| Вес товара | Одно общее поле товара для «Карго» и «Номенклатуры», всех стран поставки и реализаций. Изменения применяются сразу в обоих разделах после успешного сохранения. |
| Карго | Результат тарифа конкретной пары и общего веса товара. |
| Массовое изменение тарифа | Все товары выбранной модели либо конфигурации, только в выбранной паре. Прежние частные тарифы перезаписываются. |
| Массовое изменение веса | Все товары выбранной модели либо конфигурации. Их новые веса применяются во всех парах; тарифы остаются индивидуальными. |

### 2.1. Единый вес с «Номенклатурой»

- После успешного сохранения веса в «Карго» у того же товара в «Номенклатуре» сразу установлено это же число.
- После успешного сохранения веса в «Номенклатуре» у того же товара в «Карго» сразу установлено новое число во всех связках.
- Индивидуальное изменение относится к одной позиции товара; массовое изменение модели/конфигурации в «Карго» обновляет веса всех её затронутых товаров и в «Номенклатуре».
- Очистка веса в «Карго» сохраняет общий 0, который отображается и в «Номенклатуре». Явная установка 0 в любом из разделов также обновляет общий вес.
- При изменении из любого раздела карго пересчитывается по собственным тарифам каждой связки. Тарифы и веса других, не затронутых товаров сохраняются; при пустом тарифе карго остаётся пустым.
- Оформленные заказы сохраняют зафиксированную стоимость. Проверка этой связи с заказами относится к отдельному отложенному сценарию.

При проверке сразу после успешного сохранения открыть тот же товар в другом разделе и сверить число. Последовательные изменения из обоих разделов должны показывать последнее успешно сохранённое общее значение.

Пример: тариф UAE × Deira = 10, USA × Deira = 20, общий вес = 450 г. Карго соответственно 4.50 и 9.00 USD. Изменение общего веса на 500 г даёт 5.00 и 10.00 USD; сами тарифы 10 и 20 не меняются.

## 3. Просмотр страницы

- Вверху выбираются страна поставки и страна реализации. Названия «Поставщики»/«Клиенты» на проде и «Страна закупки»/«Страна реализации» новой версии обозначают эти фильтры.
- Слева дерево номенклатуры: бренд → категория → модель → конфигурация.
- Справа выводятся товары выбранной позиции: название, тариф, вес и рассчитанное карго.
- Вся номенклатура доступна для настройки, в том числе без стока и с выключенными продажами.
- Выбор модели охватывает её конфигурации и товары; выбор конфигурации ограничивает работу её товарами, включая разные память и цвет.
- Тариф и карго на этой странице обозначаются в USD независимо от валюты реализации. Подпись UZS старой реализации не является правилом новой страницы.
- Раскрытие дерева и смена выбора не меняют сохранённые настройки.
- По ТЗ массовый ввод открывается элементом в заголовке соответствующей колонки. Его точный вид и способ подтверждения в новой реализации оцениваются по фактическому интерфейсу; форма другой страницы сюда не переносится.

Согласованы массовые операции для модели и конфигурации. Доступность аналогичных операций на уровне бренда/категории отдельно не установлена.

## 4. Ввод и валидация

Для тарифа и веса применяется одинаковая числовая граница:

- От 0 до **9999.99** включительно.
- Не более четырёх цифр до точки и двух после неё.
- Разделитель дробной части — **только точка**.
- Целые значения и дроби с одним или двумя знаками допустимы.
- Отрицательные числа и текст не являются допустимым тарифом или весом.
- Ограничение действует и при индивидуальном, и при массовом вводе.
- Пустое поле обрабатывается по отдельным правилам ниже; это не общая ошибка обязательности.

Максимальный вес — 9999.99 г, то есть 9.99999 кг. Для более тяжёлого товара потребуется пересмотр ограничения веса.

Невалидное значение нельзя сохранять как корректное или молча превращать в другое число. Конкретный вид ошибки и нормализация промежуточных форм ввода, пробелов и ведущих нулей не заданы — раздел исследования чек-листа. Поддержка экспоненциальной записи или разделителей тысяч не следует из установленного формата.

## 5. Пустые и нулевые значения

| Тариф | Вес | Карго | Новая покупка при остальных разрешающих настройках |
| --- | --- | --- | --- |
| Пустой, на странице может отображаться «—» | Любой, включая 0 | Пустое | Запрещена по всем типам оплаты выбранной пары. |
| 0 | Любой допустимый вес | 0 | Разрешена без стоимости карго. |
| Положительный | 0 | 0 | Разрешена без стоимости карго. |
| Положительный | Положительный | Рассчитывается | Разрешена с рассчитанным карго. |

- **Очистка тарифа** сохраняет отсутствие тарифа, а не 0. Вес не сбрасывается; карго становится пустым.
- **Очистка веса** сохраняет 0. При заполненном тарифе карго становится 0; одна очистка веса не запрещает продажу.
- При пустом тарифе и очищенном весе тариф остаётся пустым, вес равен 0, карго остаётся пустым. Нулевой вес не отменяет запрет пустого тарифа.
- Сохранение, переключение пары и перезагрузка не должны смешивать пустой тариф с явным 0.
- Нулевой результат после округления также отличается от отсутствия тарифа и сам по себе не запрещает продажу.

## 6. Редактирование и массовые операции

### 6.1. Отдельный товар

Тариф меняется в выбранной строке только для текущей пары. Вес меняется для той же позиции во всех парах. Другие товары не должны изменяться только из-за одинакового названия модели или соседства в таблице.

Тариф и вес можно изменить без текущего стока и у выключенного товара, сохранив настройки для будущих продаж. Изменение не включает общие тумблеры закупки/продаж или тумблер позиции на странице «Проценты».

### 6.2. Вся модель или конфигурация

- Массовое изменение модели применяется ко всем её конфигурациям и товарам, в том числе свёрнутым и расположенным ниже экрана.
- Массовое изменение конфигурации применяется ко всем её товарам и не захватывает другие конфигурации той же модели.
- Введённое значение перезаписывает прежние индивидуальные значения соответствующего поля.
- Массовый тариф не меняет вес и тарифы других пар.
- Массовый вес не меняет тарифы; карго пересчитывается во всех парах по их собственным тарифам. При пустом тарифе карго остаётся пустым.
- Последующее индивидуальное изменение одной строки не переписывает соседние товары. Следующая массовая операция снова заменяет её частное значение.
- Ввод 0 является массовой установкой нуля, а не командой очистить настройки.

Возможность массовой очистки, точный способ подтверждения/отмены и формат отображения смешанных значений пока не определены — **CRG-Q02**. Индивидуальная очистка тарифа и веса уже определена разделом 5.

## 7. Расчёт и округление

Если тариф заполнен:

`карго USD за единицу = тариф USD/кг × вес в граммах / 1000`

Результат округляется до двух знаков после точки. Подтверждён пример 4.567 → 4.57. Направление округления на точной середине, например 0.005, требует отдельной фиксации — **CRG-Q01**. Это не мешает проверкам примеров без такой границы.

| Тариф USD/кг | Вес, г | Расчёт до округления | Карго USD |
| --- | --- | --- | --- |
| 10 | 450 | 4.5 | 4.50 |
| 37 | 340 | 12.58 | 12.58 |
| 10 | 456.70 | 4.567 | 4.57 |
| 10 | 456.40 | 4.564 | 4.56 |
| 0 | 450 | 0 | 0 |
| 10 | 0 | 0 | 0 |
| 0.01 | 0.01 | 0.0000001 | 0.00 |
| 9999.99 | 9999.99 | 99999.8000001 | 99999.80 |
| Пустой | 450 или 0 | Расчёт не выполняется | Пустое |

Числовые значения 4.5 и 4.50 равны; обязательность отображения завершающих нулей не установлена. Пустое значение и числовой 0 не равны.

Лимит четырёх цифр до точки относится к входным тарифу и весу, а не к рассчитанному карго: корректный результат может содержать пять цифр до точки.

Изменение тарифа пересчитывает карго текущей пары. Изменение веса пересчитывает карго того же товара во всех парах по их собственным тарифам.

## 8. Цена клиента и валюта

Для одной единицы товара при сопоставимых валютах:

`цена = цена поставщика × (1 + процент / 100) + карго`

Процент площадки начисляется на цену поставщика; на карго этот процент не начисляется.

Пример в USD без других компонентов: поставщик = 1000, процент = 1%, карго = 10 → цена = **1020**, а не 1020.10.

Тариф и карго страницы остаются в USD. Если реализация продаёт в другой валюте, карго конвертируется по установленному для неё курсу. При курсе K единиц валюты реализации за 1 USD его компонент равен `карго USD × K`. Перед сложением все компоненты цены должны быть выражены в одной валюте.

Расчёт тарифа по весу выполняется один раз. Конвертация уже рассчитанного карго не требует повторно умножать его на вес и делить на 1000.

Точность/округление конвертированного карго, итоговой цены и суммы количества, а также порядок промежуточных округлений не заданы полностью — **CRG-Q01**. Дополнительная наценка реселлера и процент экспорта являются отдельными правилами приложения.

## 9. Продажа и связанные разделы

Пустой тариф запрещает новую покупку товара **во всех типах оплаты выбранной пары**. Он не запрещает покупку той же позиции в другой паре с собственным заполненным тарифом и остальными выполненными условиями.

| Контур при пустом тарифе | Результат |
| --- | --- |
| Клиент | Товар не участвует в продаже выбранной пары; создать новую покупку нельзя. |
| Админский сток | Товар остаётся видимым как неактивный. |
| Поставщик | Товар остаётся видимым, поставщик продолжает работу с ним. |

Очистка тарифа не переключает «Закупку», общие «Продажи» или тумблер позиции «Процентов». Она также не удаляет номенклатуру, поставщика или клиента.

Для новой покупки одновременно нужны:

- Включённая «Закупка» страны поставки и общие «Продажи» реализации.
- Включённый тумблер позиции на странице «Проценты».
- Числовой процент выбранного типа оплаты, включая 0; «-» запрещает этот тип.
- Заполненный тариф карго, включая 0; пустой тариф запрещает все типы.
- Подходящее предложение и остальные условия покупки.

Нулевое карго не отменяет ни одно из других ограничений. Заполнение пустого тарифа возвращает возможность покупки только при выполнении остальных условий.

Уже оформленные заказы не пересчитываются после изменения тарифа или веса, не отменяются очисткой тарифа и продолжают обычную обработку. Новая настройка относится к текущим и будущим предложениям для продажи.

## 10. Начальные значения и жизненный цикл

- У нового товара номенклатуры тариф 0.
- Если при создании товара вес не указали, его вес 0.
- У существующего товара в новой связке тариф по умолчанию 0; тариф другой пары не копируется.
- При восстановлении страны её тарифы получают дефолт 0, а не ранее сохранённый ненулевой либо пустой тариф.
- Вес является общим свойством товара и не становится отдельной копией из-за создания/восстановления пары; изменение страны не должно сбрасывать общий вес.
- Добавление товара после прежнего массового редактирования не означает автоматического наследования той старой операции: действуют дефолт тарифа и вес, заданный при создании товара.

На странице нет самостоятельного процесса добавления/удаления товара или восстановления страны: эти действия относятся к номенклатуре и «Закупке и реализации». Очистка поля тарифа не является удалением сущности.

Сравнение с [«Процентами»](<../Percents/README.md>): в новой или восстановленной паре тариф карго равен 0, но проценты имеют собственный дефолт «-». Поэтому один дефолт карго не включает продажи пары. Эти разные дефолты не противоречат друг другу.

## 11. Сохранение и границы проверки

Изменения сохраняются автоматически. Успех проверяется сменой выбранной позиции/пары и повторной загрузкой страницы. Веса загружаются общими, тарифы — индивидуальными, рассчитанные суммы соответствуют обоим полям.

Ошибочный ввод или неудачный запрос не должен считаться успешной записью. Точные уведомления, способ визуального отката и обработка конкурентных массовых изменений исследуются отдельно — **CRG-Q03**.

**Доступно сейчас:** фильтры, дерево, валидация, индивидуальный и массовый ввод, сохранение, глобальность веса, независимость тарифов и автоматический расчёт карго внутри страницы.

**Отложено:** межстраничная проверка немедленного обновления общего веса «Карго» ↔ «Номенклатура», создание/удаление/восстановление стран, курс, реальный сток, цена/доступность в приложении, заказы и подписки. **Все права доступа отложены**: они ещё не реализованы. В ТЗ предусмотрены просмотр и редактирование через «Пользователей».

## 12. Детали для исследования

- **CRG-Q01:** направление округления на точной середине; промежуточные округления при конвертации, расчёте итоговой цены и суммы количества.
- **CRG-Q02:** массовая очистка, подтверждение/отмена массового ввода, отображение смешанных значений, возможные операции на уровнях бренда/категории.
- **CRG-Q03:** точный UI ошибок/отката, одновременные сохранения и операции родитель/потомок, промежуточный ввод и ведущие нули.
- **CRG-Q04:** начальный выбор фильтров, поведение при удалённой выбранной стране и пустых справочниках.
- **CRG-Q05:** реакция уже открытого клиентского прайса и судьба подписок при запрете/возврате покупки. Переходы доступа по новой загрузке заданы, но real-time обновление и подписки отдельно не определены.

Эти пункты фиксируют фактическое поведение без преждевременного вердикта о соответствии, пока ожидаемый результат не согласован.
