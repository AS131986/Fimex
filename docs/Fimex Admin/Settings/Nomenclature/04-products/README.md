# Номенклатура → Создание, редактирование и удаление товаров

[Все блоки](../README.md) · [Чек-лист](CHECKLIST.md)

Основание: ТЗ «Номенклатура», PDF от 14.11.2026, и ранее согласованные правила проекта. Лимит изображений 2 МБ на файл имеет приоритет над отсутствием лимита в PDF. Функциональный прогон ещё не выполнялся.

## Подготовка и область

Работа выполняется в таблице выбранной конфигурации. Общее дерево и просмотр уже описаны в блоке 1, настройка характеристик и вывода — в блоке 3. Данные LADA и профили H/O/G брать из [его README](../03-category-model-settings/README.md); их фактическое наличие нужно проверить перед прогоном. Основные операции — на отдельных товарах без стока. Предложения, заказы и права проверяются отдельно при готовности зависимостей.

## Добавление

«+» над таблицей открывает «Добавить товар». Поля: фото, код, исходный вес, характеристики. Фото необязательно, один файл изображения; PNG/JPG и другие поддерживаемые изображения конвертируются в WEBP. Для каждого загружаемого изображения действует не более 2 МБ, ровно 2 МБ допустимо. Точный перечень прочих форматов и единицу МБ нужно установить, не придумывая ограничения.

Код обязателен, содержит буквы и цифры, генерируется автоматически. Для одного товара допускается ручной код; при последующем выборе нескольких значений он сбрасывается на автоматический. Пара «код + RC» уникальна во всей номенклатуре. RC необязателен и назначается после создания. MJXN4, MJXN4 X/A и MJXN4 ZD/A — разные пары.

Характеристики берутся из доступного набора «Главных» и выводятся в форме по алфавиту. Каждая обязательна; можно выбрать одно или несколько значений. Создаётся товар для каждой комбинации выбранных значений. Если хотя бы одна комбинация уже существует в группе, весь набор не сохраняется; показаны конфликтующие комбинации. Save активна при заполнении обязательных полей. Без доступного набора характеристик добавление блокируется с предупреждением; без значений обязательной характеристики сохранить нельзя.

Над полями — название по первой комбинации выбранных значений, обновляемое по мере заполнения. Название и иконки товара используют блок «По умолчанию» вывода. Точный формат и разделители остаются предметом исследования, как в блоке 3.

## Вес

По новому PDF вес обязателен и положителен, задаётся в граммах. Хранятся исходный и увеличенный на 5% веса. Рядом с полем показан итог; в списке — вес с +5%. Для исходного 1000 г контрольное значение 1050 г без вопроса округления. Точность, ввод дробей и округление не установлены.

В существующей документации «Карго» вес описан как общее фактическое поле, включая 0. Какое из двух новых значений связано с ним и как совместить требования к 0, не согласовано — **NOM-P-Q01**. Межстраничную проверку выполнять исследовательски; не начислять +5% повторно и не менять документы карго без уточнения. Массовая смена веса в номенклатуре не установлена; её наличие в карго не добавляет такую функцию здесь.

## Редактирование и RC

Карандаш строки открывает текущие данные. Каждая характеристика допускает одно значение; код меняется по правилам добавления. В поле веса показан исходный вес, рядом итог. Фото имеет превью, может заменяться и удаляться. Повтор комбинации в группе запрещён. При изменении характеристик продаваемого товара требуется предупреждение «Товар в продаже. Изменение поменяет его название. Продолжить?».

Код и RC меняются также кликом по ячейке, сохраняются по Enter или клику в пустое место. «+ RC» назначает RC всем товарам текущего списка, кроме конфликтующих по паре «код + RC»; конфликты выводятся списком. Перечень форматов RC, очистка, нормализация кодов, регистр и область архивных значений требуют исследования — **NOM-P-Q02**.

## Сканирование

Иконка строки открывает «Настройка сканирования» выбранного товара. Режимы: «Без IMEI» (по умолчанию, товар не сканируется), «Один», «Два». В двух последних одинаковый набор полей; режим означает число IMEI устройства.

В «Один»/«Два» обязательны цифровой код производства и количество символов серийного номера. Код производства уникален между товарами. «Больше одного» позволяет несколько кодов списком, каждый удаляется корзиной. Длину можно задать одним значением или несколькими через запятую: «11, 15» допускает 11 и 15 символов, но не 14. Способ сохранения, переход в «Без IMEI», формат ошибочных длин, ведущие нули и судьба снятых кодов не заданы — **NOM-P-Q03**. Фактическая проверка сканером зависит от реализации сканирования.

## Удаление

Корзина строки требует подтверждения «Удалить товар «Название»?». Удаление мягкое; товар попадает в архив. Если товар есть в стоке поставщика, удалить нельзя, интерфейс указывает поставщика. По новому PDF этот запрет относится к самому товару и шире критерия «в продаже», ранее согласованного для родительских узлов. Границы стока с нулевым остатком/будущей датой исследуются; правила родительских узлов автоматически не меняются.

Вместе с товаром архивируются проценты, карго, гарантии и привилегии. Оформленные заказы не затрагиваются, новую покупку удалённого товара сделать нельзя. Не добавлять из правил другой страницы отдельный запрет удаления при активном заказе: для товара новый PDF описывает сохранность заказа; сценарий со стоком остаётся запрещённым. Общий вопрос NOM-Q01 для узлов не закрывается автоматически.

## Остальные исследования

**NOM-P-Q04:** отмена черновика, ошибки, конкурентные изменения; точный вход добавления при отсутствии конфигураций; фото из таблицы, если такой вход реализован. **NOM-P-Q05:** точность группировки комбинаций и реакция на изменение характеристик существующих товаров — сверять со старым проектом по плану блока 3. Сортировка таблицы по названию указана в новом PDF, а ранее обязательная алфавитная сортировка не была согласована: исследовать различие, не переписывая блок 1.
