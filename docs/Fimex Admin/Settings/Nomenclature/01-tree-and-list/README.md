# Номенклатура → Дерево и список

[Раздел номенклатуры](../README.md) · [Чек-лист](CHECKLIST.md)

## 1. Назначение

Блок описывает навигацию по дереву, отображение товаров выбранной конфигурации, ручной порядок и просмотр изображений. Изменение полей товара, настройки характеристик, копирование и восстановление описываются отдельно.

## 2. Дерево

Иерархия: **бренд → категория → модель → конфигурация**. Пример: Apple → iPhone → iPhone 13 → British iPhone 13 A2633 British. Товары с конкретными памятью и цветом находятся справа в таблице.

- У свёрнутой ветки стрелка направлена вправо, дочерние элементы скрыты; у раскрытой — вниз, дочерние элементы видны с отступом под своим родителем.
- Раскрытие и сворачивание одной ветки не меняет данные и состав другой.
- Одинаковые допустимые названия у разных родителей не объединяют узлы.
- В пустой номенклатуре доступно добавление бренда. Внутри бренда доступно добавление категории, внутри категории — модели. Кнопка добавления остаётся доступной и при наличии дочерних элементов.
- Контекстное меню открывается правой кнопкой мыши и относится к нажатому узлу. Для бренда предусмотрены переименование, редактирование и удаление; для категории и модели также дублирование. Само копирование относится к отдельному блоку.
- Выбор, раскрытие веток и просмотр таблицы сами по себе не редактируют записи.

## 3. Выбор и правая таблица

| Выбранный уровень | Поведение списка товаров |
| --- | --- |
| Бренд | Сборный список вложенных товаров не выводится |
| Категория | Сборный список вложенных товаров не выводится |
| Модель | Сборный список товаров её конфигураций не выводится |
| Конфигурация | Выводятся только товары этой конфигурации |

Выбор другого родительского уровня после просмотра конфигурации не должен выдавать её прежние строки за список товаров родителя. Точная заглушка правой области до выбора конфигурации пока не установлена.

- При смене конфигурации меняется её список, без примеси товаров соседних конфигураций и без изменения сохранённых полей.
- При отсутствии товаров отображается пустое состояние; остаётся предусмотренный вход в добавление товара. Точная формулировка заглушки отдельно не согласована.
- Колонки: фото, код, RC, название товара (в интерфейсе может называться «Модель»), вес в граммах, действия.
- У строки предусмотрены редактирование, настройки сканирования, копирование и удаление. Здесь проверяются наличие и принадлежность действий строке; подробные операции входят в блок товаров.
- Таблица выводит весь список без пагинации. Товары ниже видимой области доступны прокруткой.
- При наличии фотографии нажатие открывает её увеличенный просмотр. При отсутствии фотографии показана заглушка — контурная иконка изображения; нажатие на неё не открывает просмотр несуществующего фото.
- Название и оформление товара зависят от настроек вывода данных. Их настройка и изменение проверяются в следующем блоке, а здесь состав строк сверяется с подготовленными товарами конфигурации.
- Код, RC, вес и добавление фото доступны для редактирования из таблицы; детальные проверки этих изменений относятся к блоку товаров. Поведение прибавки 5% к весу и синхронизации с «Карго» в текущем блоке не определяется.

## 4. Порядок

- Бренды перемещаются внутри корня; категории — внутри своего бренда; модели — внутри своей категории; конфигурации — внутри модели.
- Это сортировка среди соседей. Она не меняет родителя, уровень, состав вложенных элементов и принадлежность товаров.
- После отпускания узла новый порядок сохраняется автоматически.
- Новый узел появляется последним среди соседей, даже если по названию он оказался бы первым по алфавиту.
- Перемещение родительского узла сохраняет его дочерние связи и внутренний порядок ветки.
- Сохранённый порядок используется во всех местах отображения соответствующих элементов в админке и приложениях. Внешние потребители проверяются после реализации связей.
- Сортировка частей внутри названия товара не задаёт алфавитный порядок строк таблицы. Ручная перестановка отдельных строк товаров отдельно не согласована.

## 5. Перезагрузка и ошибки

Названия, изображения, связи и успешно сохранённый порядок сохраняются после повторного открытия и перезагрузки. Последняя выбранная конфигурация и раскрытые ветки не восстанавливаются как сохранённое состояние интерфейса; конкретный начальный выбор и раскрытие отдельно не заданы.

При запоздалой загрузке старой конфигурации её ответ не должен подменять данные более позднего выбора. Ошибка загрузки не подтверждает отсутствие товаров; ошибка записи порядка не подтверждает его успешное сохранение. Точный вид сообщения и визуальный откат после отказа записи исследуются отдельно.

## 6. Границы проверки

**Сейчас:** навигация, состав списков на подготовленных конфигурациях, пустые состояния, ручная сортировка, новое положение узла, сохранность данных, просмотр фото и отображение действий.

**Исследование:** начальный вид дерева и правой области, заголовок и верхние действия при выборе конфигурации, порядок строк без дополнительных требований, визуальная обработка ошибки перетаскивания и способы закрытия просмотра фото.

**Отложено:** порядок в других разделах админки и приложениях; доступность по ролям. Восстановление и полный состав архива — отдельный блок.
