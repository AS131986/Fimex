# Номенклатура → Бренды, категории и модели

[Раздел номенклатуры](../README.md) · [Чек-лист](CHECKLIST.md) · [Дерево и список](../01-tree-and-list/README.md)

## 1. Область

Блок описывает создание, изменение названия и иконок, переименование и удаление бренда, категории и модели. Модель в отдельных заголовках интерфейса и ТЗ называется подкатегорией.

У категории и модели есть вкладки «Главные», «Вывод данных», «Группы товаров»; при открытии активна «Главные». Настройка характеристик, наследование, формирование названий и работа с группами будут описаны в отдельном блоке. При проверке основных полей существующие настройки этих вкладок должны сохраняться.

## 2. Поля и валидация

| Поле | Правило |
| --- | --- |
| Название | Обязательно, от 1 до 100 символов; крайние пробелы удаляются |
| Допустимый текст | Буквы, цифры, пробелы внутри текста, специальные символы и эмодзи; ручной ввод и вставка |
| Иконка для светлой темы | Необязательная, только SVG, ограничения размера файла нет |
| Иконка для тёмной темы | Необязательная, только SVG, ограничения размера файла нет |

Пустое название и строка только из крайних пробелов не создают запись. При превышении длины и дублировании отображается ошибка соответствующего поля. Сообщение об обязательности указывает тип редактируемой сущности: бренд, категорию или модель/подкатегорию.

Для точной проверки границы 100 символов используются простые латинские символы. Подсчёт составных эмодзи и нормализация нестандартных пробелов отдельно не определены.

### Уникальность

Сравнение названий — без учёта регистра, с удалением крайних пробелов.

| Сущность | Область уникальности среди действующих записей |
| --- | --- |
| Бренд | Вся номенклатура |
| Категория | Один бренд |
| Модель | Одна категория |

Одинаковая категория в разных брендах и одинаковая модель в разных категориях разрешены. Сохранение текущего собственного названия не является созданием дубля. Название удалённой записи разрешено использовать для новой; новая запись не восстанавливает архивную и не получает её данные автоматически.

## 3. Создание

- Добавление вызывается соответствующей кнопкой дерева: бренд в корне, категория у бренда, модель у категории.
- В форме бренда доступны название и две независимые иконки. У категории и модели основные поля находятся во вкладке «Главные».
- Иконки и собственный набор характеристик необязательны. Отсутствие собственных характеристик не создаёт дополнительной обязательности в этом сценарии; правила наследования разбираются отдельно.
- По нажатию «Сохранить» выполняется проверка данных; на время записи кнопка неактивна и показывает загрузку.
- При успехе форма закрывается, одна новая запись появляется внизу списка своего родителя без перезагрузки страницы и сохраняется после перезагрузки.
- При ошибке успешное создание не показывается, отображается соответствующая ошибка; после исправления возможна повторная попытка.

## 4. Редактирование и переименование

### Форма

Правый клик по бренду, категории или модели → «Редактировать». Форма содержит актуальные сохранённые данные именно нажатого элемента. Можно изменить название, заменить или удалить одну либо обе необязательные иконки.

Успешное сохранение сразу обновляет запись. Соседние узлы, дочерние связи, порядок и не редактируемые настройки сохраняются. Повторное открытие и перезагрузка показывают сохранённые значения.

### Переименование в дереве

«Переименовать» включает ввод прямо в дереве. Enter или клик вне поля подтверждают изменение; применяются те же правила длины, пробелов и уникальности. Успешное переименование не создаёт новый узел и не переставляет его по алфавиту.

### Закрытие формы

Крестик или клик вне модального окна закрывают его и сбрасывают несохранённые изменения, включая выбор, замену и удаление иконок. Повторное открытие редактирования показывает последние сохранённые данные; повторное открытие создания не продолжает отменённый черновик.

Клик вне поля при переименовании сохраняет имя; клик вне модального окна отменяет несохранённую форму. Это разные способы завершения ввода.

## 5. Иконки

- Можно сохранить ни одной, одну любую или обе иконки. Поля светлой и тёмной темы независимы.
- После выбора отображается превью без названия файла; доступно удаление выбранного изображения.
- Замена изображения с тем же именем файла должна сохранять новое содержимое, а не прежнее превью из кеша.
- После удаления необязательной иконки разрешено сохранить пустое поле без обязательной замены.
- PNG, WEBP, JPG/JPEG и другие форматы не становятся допустимыми иконками из-за изменения расширения. При неподдерживаемом формате выводится ошибка; предыдущие сохранённые изображения не должны теряться из-за отказа.
- Для корректного SVG не действует ограничение 2 или 10 МБ. Точное поведение предпросмотра повреждённого SVG и выбор изображения при отсутствии иконки одной темы исследуются отдельно.

## 6. Удаление

- Действие из контекстного меню открывает подтверждение удаления выбранного элемента с указанием его типа и названия; доступны «Отмена» и «Удалить».
- Отмена сохраняет узел и все его данные.
- При разрешённом удалении узел исчезает из рабочего дерева без перезагрузки; связанные дочерние сущности удаляются мягко и переходят в архив. Другие ветки не затрагиваются.
- Для категории это её модели, конфигурации и товары; для модели — конфигурации и товары; для бренда — всё его поддерево.
- После успеха есть подтверждение результата. Для категории и модели предусмотрен тост; при отказе удаления форма остаётся открытой, показывает ошибку, и повторная попытка доступна.
- В ТЗ также указано каскадное удаление связанных настроек: процентов, карго, включая вес, гарантий и привилегий поставщиков. Эти связи проверяются отдельно после появления зависимостей и проверки состояния данных.
- **Удаление запрещено, если среди вложенных товаров есть товар, выставленный поставщиком на продажу.** Клиентская видимость сама по себе не заменяет эту проверку. Границы по остаткам, датам и странам пока открыты — NOM-Q02.
- **Поведение при незавершённых заказах не установлено — NOM-Q01.** В чек-листе есть отдельное отложенное исследование без заранее назначенного запрета или разрешения.

Исчезновение строки из рабочего дерева само по себе не доказывает мягкое удаление и сохранность архива. Проверка признака удаления и каскада на уровне данных отложена; состав архива и восстановление будут описаны в отдельном блоке.

## 7. Проверка сейчас и позже

**Сейчас:** основные поля, имена, SVG, формы, сохранение и отмена, уникальность действующих записей, повторное использование имени удалённого элемента, разрешённое удаление тестовых веток без выставленных предложений и без заказов.

**Исследование:** составные символы на границе длины, нестандартные пробелы, повреждённые SVG, отображение иконки при заполнении одной темы и отмена незавершённого переименования клавиатурой.

**Отложено:** запрет удаления при выставленном поставщиком товаре, незавершённые заказы, каскад настроек других страниц, данные мягкого удаления, внешние отображения и все ограничения прав. Права просмотра, редактирования и удаления настраиваются через «Пользователи» и пока не считаются реализованными.
