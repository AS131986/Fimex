# Номенклатура → Настройки категорий и моделей

[Раздел номенклатуры](../README.md) · [Чек-лист блока](CHECKLIST.md)

Категория и модель настраиваются на вкладках «Главные», «Вывод данных» и «Группы товаров». Модель в части интерфейса называется подкатегорией. Группа товаров в дереве отображается как конфигурация.

## Главные

- Через «+» открывается выбор характеристик из справочника. В окне выбора список идёт по алфавиту. Одну характеристику можно добавить один раз.
- В форме выбранные характеристики появляются в порядке выбора. Каждая новая добавляется в конец списка. Перетаскивание задаёт ручной порядок, который сохраняется вместе с настройками.
- Характеристику, используемую в «Выводе данных», можно убрать из «Главных» после того, как её убрали из вывода. Ограничение при использовании характеристики в настройке группы проверяется при прогоне.
- При отсутствии собственного набора модель использует характеристики родителя. Если задать собственный набор, применяется он целиком. При наследовании вкладка «Вывод данных» неактивна, используется настройка вывода родителя.
- Обновление наследованных настроек после изменения категории и переключение обратно на наследование после удаления последней собственной характеристики проверяются при прогоне.

Правила названий и загрузки иконок описаны во втором блоке. [Бренды, категории и модели](../02-brands-categories-models/README.md)

## Вывод данных

- В блоке «По умолчанию» выбираются характеристики, которые используются в названии товара. Через «+» доступны характеристики из «Главных». Для собственного вывода нужна хотя бы одна характеристика.
- Порядок частей названия задаётся перетаскиванием в этом блоке. Крестик убирает характеристику из вывода. Она остаётся в наборе «Главных».
- Для превью берутся первые значения выбранных характеристик из справочника в порядке вывода. Пример из ТЗ — «iPhone 16 Pro Max 128Gb Black». Кнопка Info показывает страницы, на которых используется это название.
- Изменение сохранённого вывода должно применяться к названиям уже добавленных товаров. Доступность этой связи и фактическое обновление в таблице проверяются при прогоне.
- При добавлении, удалении или перестановке частей названия для категории с товарами в продаже требуется предупреждение «Есть товар в продаже. Изменение поменяет названия товаров. Продолжить?». Момент показа предупреждения и сохранение черновика после отмены нужно проверить.

Формат разделителей, правила отображения иконок и смайликов и вид превью при пустом списке значений уточняются по реализации.

## Группы товаров

Характеристики для настройки группы выбираются из тех, которые админ добавил на вкладке «Главные». Выбранные настройки сохраняются общей кнопкой формы.

Способ формирования и именования конфигураций в дереве, доступные операции с существующей группой и результат изменения состава группы проверяются при прогоне. Удалённая группа по ТЗ архивируется вместе с вложенными записями и настройками. Вход в удаление группы и его ограничения уточняются отдельно.

## Сохранение

Кнопка «Сохранить» сохраняет изменения всех вкладок за одно действие. При переключении вкладок введённые правки остаются в форме. После сохранения и повторного открытия показываются актуальные настройки. Закрытие формы крестиком или кликом вне окна сбрасывает несохранённые изменения.

## Добавление товара после настройки модели

Чтобы сохранить товар, нужно выбрать значения обязательных характеристик. Если у обязательной характеристики нет доступных значений, сохранить товар нельзя.

Когда у модели нет доступного набора характеристик, в окне «Добавить товар» показано предупреждение о том, что сначала нужно задать характеристики на вкладке «Главные». Кнопка «Сохранить» недоступна, вместо названия показана подсказка «Название соберётся из выбранных характеристик». Этот сценарий показан на скриншоте от 4 ноября. Пустой список значений у отдельной характеристики проверяется отдельно.

## Сверка со старым проектом

На сопоставимых тестовых данных сначала проверить в старом проекте, как добавление и удаление характеристики модели влияет на значения, название и конфигурацию существующих товаров. Затем повторить на новом стенде. Зафиксировать отличия и предложить ожидаемое поведение для нового проекта по итогам сравнения.

При прогоне отдельно зафиксировать доступность применения настроек к существующим товарам и группировке. Проверки продажи, поставщицкого стока, прав и отображения в других разделах выполнять при наличии соответствующих зависимостей. [ТЗ «Номенклатура»](https://app.clickup.com/t/90182877012/z8wf5rj831)
