# Чек-лист: Настройки → Справочник характеристик

[Бизнес-правила](README.md). Все пункты ожидают выполнения. При прогоне фиксировать дату, фактический результат и ссылку на дефект; наличие пункта не означает, что проверка прошла.

**Сейчас:** интерфейс, текстовая валидация и уникальность, SVG, смайлики, любые сочетания полей, подтверждение очистки поля, сохранение по Enter/клику вне поля, алфавитный список, ручной порядок и разрешённое удаление внутри страницы — раздел 1.

**Исследование:** доступные сейчас сценарии с не полностью согласованным ожидаемым результатом — раздел 2. Наблюдение не закрывает такой пункт как успешный до уточнения правила.

**Отложено:** связи с номенклатурой и товарами, запрет удаления используемых записей, приложения, подтверждение мягкого удаления на уровне данных и все права доступа — раздел 3. Переносить в текущий прогон после появления необходимых зависимостей и тестовых данных. Без товара с назначенной записью нельзя засчитать запрет удаления как проверенный.

Восстановление характеристик и значений в интерфейсе пока не предусмотрено и в обязательный прогон не включено. Повторное создание с прежним названием — отдельная операция, а не восстановление.

## Подготовка

- Использовать тестовые характеристики, не назначенные реальным товарам. Справочник общий для всех стран поставки и реализаций; изменение существующих рабочих записей влияет на связанные товары.
- Подготовить характеристики A и B с разными уникальными основными названиями и полными обязательными карточками: название, SVG, RU, ENG. Значения внутри каждого родителя должны иметь разные названия; одинаковые названия значений подготовить только в разных характеристиках. Для негативных сценариев дубли вводятся намеренно, но не должны сохраняться.
- Для восьми сочетаний «Цвет / Иконка / Смайлик» подготовить отдельные полные характеристики с пустыми списками значений; явно задать нужное сочетание. Все включённые атрибуты обязательны при добавлении, выключенные не требуются.
- Подготовить строки длиной 1, 99, 100, 101 и 1000 символов. Для точной проверки границы использовать простые латинские символы; отдельно проверить допустимые буквы, цифры, знаки и эмодзи на коротких строках.
- Подготовить корректные SVG обычного размера и SVG 3–5 МБ, два визуально разных SVG с одинаковым именем файла; PNG, WEBP, JPG/JPEG и другие форматы подготовить для отказа. Разрешён только SVG, ограничения размера нет.
- Для цвета использовать `2B2B2B`, `CC8080`, `000000`, `FFFFFF` без `#` и строку с недопустимыми HEX-символами, например `GGHHII`.
- Положительные сценарии редактирования названий, подписей и значений проверять двумя способами: Enter и клик в пустое место, затем повторное открытие и перезагрузка. Для этих сценариев остальные обязательные поля карточки заполнены; создание до полного заполнения проверяется отдельно в CHR-NEW-03. Способ отмены несохранённого ввода — CHR-OBS-01.
- Проверки ошибок загрузки и записи выполнять на тестовых данных с контролируемым отключением сети или подменой ответа; не имитировать отказ удалением чужих данных.

## 1. Сейчас можно проверять

### 1.1. Открытие и выбор характеристики

- [ ] **CHR-LIST-01 — Открытие справочника характеристик**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Открыть «Настройки → Характеристики»
  - **Ожидаемый результат:** список загружен, доступно «New Item / Новый элемент» и добавление; данные справочника не смешаны с номенклатурой или странами поставки.

  </details>

- [ ] **CHR-LIST-02 — Отображение данных выбранной характеристики**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать A, затем B → выделена выбранная строка, справа её название, переводы, изображение, тумблеры и значения; данные A не показаны как данные B.

  </details>

- [ ] **CHR-LIST-03 — Сохранность карточек при переключении**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Несколько раз переключиться A → B → A без редактирования
  - **Ожидаемый результат:** сохранённые данные и состояния тумблеров не изменились, новые записи не создались.

  </details>

- [ ] **CHR-LIST-04 — Независимость одноимённых значений разных характеристик**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Выбрать характеристики A и B, в которых есть одинаково названные значения
  - **Ожидаемый результат:** открываются собственные значения и атрибуты каждой записи; допустимое совпадение между разными характеристиками не объединяет данные.

  </details>

- [ ] **CHR-LIST-05 — Удаление выбранной строки списка**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** В левом списке найти корзину справа от характеристики
  - **Ожидаемый результат:** действие относится к этой строке; вызов и отмена подтверждения не меняют данные другой открытой карточки.

  </details>

- [ ] **CHR-LIST-06 — Создание характеристики в пустом справочнике**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** На подготовленном пустом справочнике открыть страницу
  - **Ожидаемый результат:** доступно создание первой характеристики, нет зависания или фиктивной карточки ранее удалённой записи.
  - Не очищать рабочий справочник ради этого пункта.

  </details>


### 1.2. Создание характеристики

- [ ] **CHR-NEW-01 — Создание характеристики по Enter**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Ввести новое корректное название и один раз нажать Enter
  - **Ожидаемый результат:** создана одна характеристика с этим названием, её можно открыть; после перезагрузки запись существует.

  </details>

- [ ] **CHR-NEW-02 — Создание характеристики кнопкой «+»**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Создать другую характеристику кликом по «+»
  - **Ожидаемый результат:** результат сохраняется так же, как при Enter; одного клика достаточно для одной записи.

  </details>

- [ ] **CHR-NEW-03 — Создание неполной карточки и обязательность полей при редактировании**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Создать характеристику с названием до заполнения SVG-иконки и подписей RU/ENG
  - **Ожидаемый результат:** запись создаётся, список значений пуст, «Цвет» и «Иконка» выключены.
  - **Проверка:** При последующем редактировании поочерёдно оставить каждое обязательное поле пустым
  - **Ожидаемый результат:** редактирование не завершается успешным сохранением до заполнения всех четырёх полей;
  - затем полная карточка сохраняется.

  </details>

- [ ] **CHR-NEW-04 — Запрет создания характеристики без названия**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Попытаться создать характеристику с пустым названием и только из пробелов, отдельно через Enter и «+»
  - **Ожидаемый результат:** пустая запись не создаётся, существующий справочник не меняется.

  </details>

- [ ] **CHR-NEW-05 — Уникальность основного названия характеристики**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Попытаться создать вторую характеристику с в точности существующим основным названием
  - **Ожидаемый результат:** создание отклонено по уникальности, второй действующей записи нет после перезагрузки;
  - исходная характеристика и её данные сохранены.

  </details>

- [ ] **CHR-NEW-06 — Независимость последовательно созданных характеристик**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Последовательно создать A и B, добавить им разные значения
  - **Ожидаемый результат:** названия, значения и последующее редактирование относятся к своим карточкам, не к последней открытой записи.

  </details>

- [ ] **CHR-NEW-07 — Создание после исправления невалидного названия**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** После отказа пустому или слишком длинному названию ввести допустимое
  - **Ожидаемый результат:** создание снова работает, прежняя невалидная попытка не оставила пустую или частично созданную характеристику.

  </details>


### 1.3. Текстовые поля: длина, символы и обязательность

Общие сценарии CHR-TXT-05—11 выполнить для основного названия, RU, ENG и названия значения; при редактировании остальные обязательные поля заполнены. Проверить Enter и клик в пустое место. Любые дополнительные входы в переименование, если они есть в UI, должны сохранять те же ограничения; их наличие не требуется новым ТЗ.

- [ ] **CHR-TXT-01 — Границы длины основного названия**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Для основного названия проверить 1, 99 и 100 символов
  - **Ожидаемый результат:** допустимы; 101 и вставка 1000 символов не сохраняются целиком как корректное название.
  - Предел действует при создании и редактировании; остальные обязательные поля карточки для проверки редактирования заполнены.

  </details>

- [ ] **CHR-TXT-02 — Обязательность и длина подписи RU**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** В полной карточке для RU проверить 1, 99 и 100 символов
  - **Ожидаемый результат:** допустимы; пустое поле и только пробелы блокируют сохранение редактирования, 101 и вставка 1000 не обходят максимум.
  - Основное название и ENG не переписываются.

  </details>

- [ ] **CHR-TXT-03 — Обязательность и длина подписи ENG**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Для ENG повторить границы пусто / только пробелы / 1 / 99 / 100 / 101 / 1000
  - **Ожидаемый результат:** пустое и превышение недопустимы при редактировании, до 100 допустимо; RU и основное название сохранены.

  </details>

- [ ] **CHR-TXT-04 — Обязательность и длина названия значения**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Для названия значения проверить пусто, только пробелы, 1, 99, 100, 101 и 1000 символов
  - **Ожидаемый результат:** пустое не добавляется, до 100 допустимо, превышение целиком не сохраняется; соседние строки не меняются.

  </details>

- [ ] **CHR-TXT-05 — Сохранение кириллицы и латиницы**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Ввести и вставить кириллицу, латиницу и смешанную строку, например `Память Memory`
  - **Ожидаемый результат:** допустимый текст сохраняется без потери букв или замены на вопросительные знаки.

  </details>

- [ ] **CHR-TXT-06 — Сохранение цифр в текстовых полях**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Ввести только цифры `12345`, затем буквы с цифрами `Memory 128`
  - **Ожидаемый результат:** допустимы; текст не превращается в числовой тип и не получает непредусмотренный запрет.

  </details>

- [ ] **CHR-TXT-07 — Сохранение символов и эмодзи**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Ввести знаки и сочетания `+ - / : & ( ) ' "`, затем короткую строку с эмодзи `QA 📱 ✅`
  - **Ожидаемый результат:** допустимые символы и эмодзи сохраняются после повторного открытия.

  </details>

- [ ] **CHR-TXT-08 — Отображение HTML-подобного названия как текста**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Сохранить короткое название с угловыми скобками, например `<b>QA</b>`
  - **Ожидаемый результат:** отображается как текст названия, а не исполняемая разметка; соседние элементы страницы не повреждены.

  </details>

- [ ] **CHR-TXT-09 — Обработка крайних и внутренних пробелов**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Вставить название с пробелами в начале и конце
  - **Ожидаемый результат:** по сохранении обрезаны только крайние пробелы; внутренние пробелы текста не потеряны.

  </details>

- [ ] **CHR-TXT-10 — Запрет сохранения пустых обязательных текстовых полей**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** В редактируемой полной карточке по очереди очистить основное название, RU и ENG; отдельно очистить название значения
  - **Ожидаемый результат:** ни одно обязательное текстовое поле не сохраняется как корректное пустое значение.
  - Возможность первоначально создать незаполненную карточку не разрешает сохранять такое редактирование.

  </details>

- [ ] **CHR-TXT-11 — Сохранение после исправления длины текста**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Превысить длину, затем исправить текст до 100 символов или меньше
  - **Ожидаемый результат:** допустимое значение сохраняется; отказ не повреждает соседние поля и записи.
  - Блокировка ввода, обрезание или сообщение об ошибке фиксируются без требования конкретного варианта UI.

  </details>


### 1.3.1. Уникальность и область сравнения

- [ ] **CHR-UNIQ-01 — Отсутствие конфликта названия характеристики с самой собой**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** В полной карточке подтвердить её собственное неизменённое основное название через Enter и клик вне поля
  - **Ожидаемый результат:** запись не конфликтует сама с собой, ложной ошибки дубликата нет.

  </details>

- [ ] **CHR-UNIQ-02 — Отсутствие конфликта значения с самим собой**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Подтвердить неизменённое название существующего значения
  - **Ожидаемый результат:** оно не считается собственным дубликатом и не создаётся второй строкой.

  </details>

- [ ] **CHR-UNIQ-03 — Запрет переименования значения в существующее**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Переименовать значение A в существующее название B внутри того же родителя
  - **Ожидаемый результат:** отказ, прежние обе строки и их атрибуты сохраняются; после выбора свободного названия редактирование разрешено.

  </details>

- [ ] **CHR-UNIQ-04 — Уникальность названия независимо от дополнительных атрибутов**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Попытаться добавить значение с существующим названием, но другим цветом, SVG или смайликом
  - **Ожидаемый результат:** дополнительные атрибуты не обходят запрет одинаковых названий внутри одной характеристики.

  </details>

- [ ] **CHR-UNIQ-05 — Допустимость одинаковых переводов и значений разных родителей**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** У характеристик с разными уникальными основными названиями задать одинаковые заполненные подписи RU/ENG
  - **Ожидаемый результат:** отсутствие отдельного требования уникальности подписей не создаёт запрета;
  - уникальность значений в разных родителях также не проверяется глобально.

  </details>

- [ ] **CHR-UNIQ-06 — Защита от одновременного создания дубликатов**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** В двух вкладках страницы попытаться создать одно и то же основное название, отдельно повторить для названия значения внутри одной характеристики
  - **Ожидаемый результат:** после завершения запросов не появляются две действующие записи запрещённой области;
  - отказ второй попытке не повреждает первую.

  </details>


### 1.4. Редактирование карточки и переименование

- [ ] **CHR-EDIT-01 — Переименование характеристики по Enter**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** В полной карточке изменить основное название и нажать Enter
  - **Ожидаемый результат:** новое название сохранено в карточке и списке той же записи, её положение соответствует алфавитному порядку;
  - после перезагрузки результат сохраняется.

  </details>

- [ ] **CHR-EDIT-02 — Переименование характеристики кликом вне поля**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Изменить основное название через карточку и кликнуть в пустое место
  - **Ожидаемый результат:** изменение сохранено без Enter и без создания новой сущности; значения, SVG, подписи и тумблеры не сброшены.

  </details>

- [ ] **CHR-EDIT-03 — Запрет дубликата при переименовании характеристики**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Попытаться переименовать A в существующее основное название B, отдельно через Enter и клик вне поля
  - **Ожидаемый результат:** сохранение дубликата отклонено, у A прежнее допустимое название, у B её данные;
  - после исправления на свободное название редактирование доступно.

  </details>

- [ ] **CHR-EDIT-04 — Независимое сохранение переводов RU и ENG**

  - **Ожидаемый результат:** отображается новое изображение у той же записи, количество характеристик/значений не увеличилось, прежняя картинка не возвращается после перезагрузки.

- [ ] **CHR-IMG-04 — Обновление SVG при совпадающем имени файла**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Заменить файл другим изображением с тем же именем
  - **Ожидаемый результат:** видно новое содержимое, сохранение не определяется одним совпадением имени и не возвращает старое превью из кеша.

  </details>

- [ ] **CHR-IMG-05 — Доступность замены SVG и ограничения очистки**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Проверить загруженные SVG
  - **Ожидаемый результат:** доступна замена; отдельная очистка файла в остающемся включённым поле не предусмотрена.
  - Корзина значения удаляет запись целиком при отсутствии использования; выключение поля «Иконка» очищает SVG-атрибуты только после предупреждения, CHR-OFF.

  </details>

- [ ] **CHR-IMG-06 — Отклонение неподдерживаемых форматов иконок**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** По отдельности передать PNG, WEBP, JPG, JPEG, GIF, PDF и TXT
  - **Ожидаемый результат:** файлы отклоняются как неподдерживаемые, их нельзя засчитать обязательной SVG-иконкой.
  - Точный текст ошибки не назначен; сообщение не должно объявлять растровые форматы разрешёнными.

  </details>

- [ ] **CHR-IMG-07 — Отсутствие продуктового лимита размера SVG**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Загрузить корректные SVG больше 2 МБ, например 3 и 5 МБ, по отдельности в иконку характеристики и значения
  - **Ожидаемый результат:** файл не отклоняется по ограничению размера, поскольку продуктового лимита нет;
  - не выполнять неограниченную нагрузочную генерацию.

  </details>

- [ ] **CHR-IMG-08 — Сохранность прежней иконки при отклонённой замене**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** При замене сохранённого SVG передать неподдерживаемый формат
  - **Ожидаемый результат:** после отказа прежняя успешно сохранённая иконка остаётся, новый файл не считается успешно сохранённым;
  - большой корректный SVG не является невалидным только из-за размера.

  </details>

- [ ] **CHR-IMG-09 — Блокировка добавления при неудачной загрузке SVG**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** При добавлении значения получить отказ загрузки SVG без прежней иконки
  - **Ожидаемый результат:** обязательное поле не считается заполненным, «+» и Enter не добавляют неполную строку даже при заполненных цвете и смайлике;
  - корректный SVG позволяет продолжить добавление.

  </details>

- [ ] **CHR-IMG-10 — Отмена выбора файла без изменения данных**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Открыть выбор файла и отменить без выбора
  - **Ожидаемый результат:** сохранённое изображение и поля записи не изменились; последующий выбор корректного файла работает.

  </details>

- [ ] **CHR-IMG-11 — Соответствие превью своим характеристикам и значениям**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** После загрузки и замены сверить SVG характеристики и SVG двух значений
  - **Ожидаемый результат:** каждое превью относится к своей записи, файлы не перепутаны;
  - нет повреждённого изображения или потери видимого содержимого.
  - Оптимизация — CHR-OBS-08.

  </details>


### 1.9. Удаление внутри страницы

Здесь удаляются только неиспользуемые тестовые записи. Запрет удаления при наличии хотя бы одного товара номенклатуры проверяется в отложенном блоке. Для неиспользуемого значения отдельное подтверждение пока не является согласованным требованием.

- [ ] **CHR-DEL-01 — Отмена удаления неиспользуемой характеристики**

  <details>
  <summary>Подробности проверки</summary>

  - У неиспользуемой характеристики вызвать удаление корзиной справа от строки в левом списке → до подтверждения запись существует; отменить → название, значения, SVG и режимы сохраняются после перезагрузки.

  </details>

- [ ] **CHR-DEL-02 — Отмена удаления другой строки при открытой карточке**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** При открытой карточке A нажать корзину B в левом списке и отменить подтверждение
  - **Ожидаемый результат:** A и B сохраняются, удаление не выполняется по одному открытию окна и не подменяет целевую запись открытой карточкой.

  </details>

- [ ] **CHR-DEL-03 — Подтверждённое удаление неиспользуемой характеристики**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Подтвердить удаление неиспользуемой характеристики из левого списка
  - **Ожидаемый результат:** она исчезает из рабочего справочника и не возвращается после перезагрузки; остальные характеристики и их данные сохранены.

  </details>

- [ ] **CHR-DEL-04 — Удаление характеристики с неиспользуемыми значениями**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Удалить характеристику с несколькими значениями, ни одно из которых не связано с товарами
  - **Ожидаемый результат:** операция разрешена после подтверждения, запись и её значения больше не доступны в рабочей карточке;
  - чужие значения не удалены. Мягкое удаление подтверждается отдельно в CHR-DEF-DATA.

  </details>

- [ ] **CHR-DEL-05 — Выбор удаляемой записи после изменения сортировки**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Создать несколько различимых характеристик, выбрать A и вызвать корзину B после изменения алфавитного положения B
  - **Ожидаемый результат:** подтверждение и фактическое удаление относятся к B, а не к прежнему индексу строки или открытой A.

  </details>

- [ ] **CHR-DEL-06 — Независимость удаления от совпадающих названий**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Удалить неиспользуемую характеристику, название которой совпадает с названием значения другой характеристики
  - **Ожидаемый результат:** удалена только характеристика по её идентификатору, одноимённое значение другого родителя сохранено.

  </details>

- [ ] **CHR-DEL-07 — Удаление отдельного неиспользуемого значения**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Удалить одно неиспользуемое значение, завершив предусмотренное интерфейсом действие
  - **Ожидаемый результат:** оно исчезает из списка и не возвращается после перезагрузки;
  - характеристика, другие значения, их цвета/иконки и режимы сохранены.

  </details>

- [ ] **CHR-DEL-08 — Удаление последнего значения без удаления характеристики**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Удалить одно из нескольких разных неиспользуемых значений, затем последнее значение тестовой характеристики
  - **Ожидаемый результат:** другие строки сохраняются до их собственного удаления, затем допускается пустой список;
  - родительская характеристика остаётся и позволяет добавить новое значение.

  </details>

- [ ] **CHR-DEL-09 — Повторное использование названия удалённой записи**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** После разрешённого удаления характеристики и отдельно значения создать новую запись с прежним названием, не занятым действующей записью своей области
  - **Ожидаемый результат:** создание разрешено, новая запись самостоятельна;
  - прежние связи не восстанавливаются по тексту.

  </details>

  </details>


### 1.11. Сохранение, повторное открытие и ошибки

- [ ] **CHR-SAVE-01 — Сохранение полной карточки со всеми атрибутами**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Для разных допустимых сочетаний полей сохранить полную карточку: уникальное название, RU/ENG, SVG характеристики и значения со всеми включёнными атрибутами
  - **Ожидаемый результат:** после смены карточки и перезагрузки весь набор относится к своей записи и совпадает с успешно сохранённым состоянием.

  </details>

- [ ] **CHR-SAVE-02 — Независимое сохранение полей разных карточек**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Изменить по одному полю в A и B, повторно открыть страницу
  - **Ожидаемый результат:** у каждой записи её последнее успешно сохранённое значение, одно поле не возвращает старые данные остальных полей карточки.

  </details>

- [ ] **CHR-SAVE-03 — Сохранность корректных данных после отказа валидации**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** После отказа валидации повторно открыть запись
  - **Ожидаемый результат:** нет недопустимого длинного/пустого обязательного текста, сохранённого дубликата в запрещённой области, неверного цвета или принятого не-SVG;
  - прежние корректные данные не повреждены.

  </details>

- [ ] **CHR-SAVE-04 — Обработка отказа загрузки списка и карточки**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Получить контролируемый отказ загрузки списка или карточки
  - **Ожидаемый результат:** интерфейс не выдаёт неуспешную загрузку за успешное сохранение/удаление и не применяет данные предыдущей карточки к новой.
  - Конкретный текст и вид ошибки не назначены.

  </details>

- [ ] **CHR-SAVE-05 — Обработка отказа создания и редактирования**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Получить контролируемый отказ создания/редактирования
  - **Ожидаемый результат:** операция не показана как успешно сохранённая;
  - после восстановления связи и повторного открытия нет ложной сохранённой записи.
  - Повторная корректная операция доступна; конкретные тост и локальный откат — CHR-OBS-10.

  </details>

- [ ] **CHR-SAVE-06 — Обработка отказа удаления**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Получить контролируемый отказ удаления
  - **Ожидаемый результат:** запись не считается успешно удалённой и доступна после восстановления связи и перезагрузки; данные соседних записей сохранены.

  </details>

- [ ] **CHR-SAVE-07 — Возобновление сохранения после исправления ошибки**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Успешно сохранить корректную полную карточку после отказа валидации, уникальности, загрузки файла или сети
  - **Ожидаемый результат:** страница не остаётся заблокированной, новое состояние сохраняется;
  - неудачная попытка не создала лишнюю запись.

  </details>

  <details>
  <summary>Подробности проверки</summary>

  - **Ожидаемый результат:** оба способа сохраняют допустимые данные после повторного открытия и перезагрузки без отдельной обязательной кнопки «Сохранить»;
  - не путать выбор другого поля с фактическим подтверждением результата.

  - **Ожидаемый результат:** оба изменения сохраняются, цветовой образец соответствует последнему коду, остальные включённые атрибуты не переписаны.

  </details>


## 2. Исследовать сейчас, ожидаемый результат уточнить

Связь с открытыми вопросами указана кодами CHR-Q01—06 из README. Алфавитный список, ручной порядок значений, сохранение по Enter/клику вне поля, очистка после подтверждения и уникальность уже согласованы и не считаются исследованием.

- [ ] **CHR-OBS-01 — Исследование отмены неподтверждённого редактирования**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Для изменения названий и значений исследовать Escape, закрытие карточки до Enter/клика в пустое место и уход с новой незаполненной карточки
  - **Ожидаемый результат:** зафиксировать границу отмены без отмены уже подтверждённого сохранения.
  - Enter и клик в пустое место проверяются как согласованные способы записи, CHR-SAVE-08.

  </details>

- [ ] **CHR-OBS-02 — Исследование сортировки смешанных алфавитов**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Записать алфавитный порядок при смешении кириллицы, латиницы, цифр и эмодзи
  - **Ожидаемый результат:** согласовать локаль и сравнение;
  - базовый алфавитный порядок одного алфавита и ручное сохранение порядка значений уже обязательны.
  - CHR-Q02.

  </details>

- [ ] **CHR-OBS-03 — Исследование сравнения похожих названий**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Проверить названия, различающиеся только регистром, внутренними пробелами или похожими символами разных алфавитов
  - **Ожидаемый результат:** записать сравнение для характеристик и значений, CHR-Q01.
  - Точные дубли характеристики и дубли значения внутри родителя уже запрещены.

  </details>

- [ ] **CHR-OBS-04 — Исследование включения атрибутов у прежних значений**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Включить дополнительное поле у ранее созданных текстовых значений и зафиксировать начальное состояние «Смайлик» у новой характеристики
  - **Ожидаемый результат:** согласовать обработку незаполненных старых строк и способ выбора/число смайликов, CHR-Q04.
  - Очистка заполненного поля после подтверждения и отсутствие восстановления старого содержимого уже проверяются в CHR-OFF.

  </details>

- [ ] **CHR-OBS-05 — Исследование дополнительных форматов HEX**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Проверить `#2B2B2B`, короткий HEX, 8 знаков с прозрачностью, нижний регистр, пробелы и код только из `#`
  - **Ожидаемый результат:** записать поддержку, нормализацию и цвет по умолчанию, CHR-Q03.
  - Шестизначные коды без `#` остаются обязательным поддерживаемым вводом.

  </details>

- [ ] **CHR-OBS-06 — Исследование подтверждения удаления значения**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Удалить неиспользуемое значение
  - **Ожидаемый результат:** записать наличие/отсутствие отдельного подтверждения, CHR-Q05; если окно есть, проверить отказ и сохранность строки.
  - Не путать это с обязательным подтверждением удаления характеристики и очистки заполненного дополнительного поля.

  </details>

- [ ] **CHR-OBS-07 — Исследование выключения незаполненного поля**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Выключить дополнительное поле без заполненных данных
  - **Ожидаемый результат:** записать наличие/отсутствие предупреждения и поведение UI. Обязательное предупреждение согласовано для поля с хотя бы одним заполненным значением;
  - в любом случае чужие данные не должны удаляться.

  </details>

- [ ] **CHR-OBS-08 — Исследование оптимизации загружаемых изображений**

  <details>
  <summary>Подробности проверки</summary>

  - Зафиксировать оптимизацию загрузки по доступным ответам/файлам: исходный и итоговый формат/размер, видимое качество и прозрачность.

  </details>

- [ ] **CHR-OBS-09 — Исследование загрузки повреждённого SVG**

  <details>
  <summary>Подробности проверки</summary>

  - **Ожидаемый результат:** записать проверку содержимого и обработку ошибки; не требовать конкретного не согласованного сообщения.

  </details>

- [ ] **CHR-OBS-10 — Исследование задержек записи и повторной отправки**

  - **Ожидаемый результат:** записать защиту от повторной отправки.
  - Последовательный намеренный повтор точного названия теперь также ограничен согласованной уникальностью.

  </details>

- [ ] **CHR-OBS-11 — Исследование выбора карточки после удаления**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** На тестовом справочнике удалить выбранную и последнюю характеристику
  - **Ожидаемый результат:** записать выбор следующей карточки/пустого состояния, фокус и возможность дальнейшего создания без требования конкретного автоматического выбора.

  - **Ожидаемый результат:** записать порядок ответов и границу записи.
  - Ответ не должен отображаться как данные другой сущности; политика одновременных записей одного поля пока не согласована.

  </details>


## 3. Отложенные проверки

### 3.1. Номенклатура, товары и общий справочник

Для блока подготовить товары с несколькими характеристиками с уникальными основными названиями, несколько товаров с одной общей записью и одинаково названные значения в разных характеристиках. Использовать товары разных брендов и связок UAE × Deira, USA × Deira, UAE × Free zone и USA × Free zone. Для запрета удаления нужен хотя бы один товар номенклатуры с назначением, для разрешённого удаления — запись без назначений. Проверять результат сразу после успешной записи, открывая тот же товар в зависимом разделе.

- [ ] **CHR-DEF-NOM-01 — Доступность общего справочника в номенклатуре**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Создать характеристику и значение
  - **Ожидаемый результат:** они доступны для назначения в номенклатуре для разных стран поставки и реализаций из общего справочника; отдельная ручная копия для каждой пары не нужна.

  </details>

- [ ] **CHR-DEF-NOM-02 — Обновление названия характеристики у связанных товаров**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Назначить одну характеристику нескольким товарам разных пар и переименовать её в свободное название
  - **Ожидаемый результат:** новое название сразу относится ко всем связанным товарам;
  - прежние назначения не потеряны, другая характеристика с собственными значениями не изменилась.

  </details>

- [ ] **CHR-DEF-NOM-03 — Обновление названия используемого значения**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Изменить название используемого значения
  - **Ожидаемый результат:** оно сразу обновляется у всех товаров, связанных с этой записью; текстовое совпадение с другим значением не расширяет обновление.

  </details>

- [ ] **CHR-DEF-NOM-04 — Обновление переводов и иконки у связанных товаров**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Изменить заполненные RU/ENG и изображение используемой характеристики
  - **Ожидаемый результат:** связанные актуальные карточки товаров получают новые данные без повторного назначения характеристики;
  - подстановка при пустом переводе в этот пункт не входит.

  </details>

- [ ] **CHR-DEF-NOM-05 — Обновление дополнительных атрибутов у связанных товаров**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** При нескольких включённых полях изменить цвет, заменить SVG и изменить смайлик используемого значения
  - **Ожидаемый результат:** связанные актуальные товары сразу используют новый набор атрибутов этой записи, соседние значения и другие характеристики сохранены.

  </details>

- [ ] **CHR-DEF-NOM-06 — Изоляция обновления одноимённых значений**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Изменить одно из одинаково названных значений разных характеристик, назначенных разным товарам
  - **Ожидаемый результат:** обновляются только товары выбранной записи; допустимое совпадение между родителями не расширяет изменение.

  </details>

- [ ] **CHR-DEF-NOM-07 — Запрет удаления используемой характеристики**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Назначить характеристику хотя бы одному товару номенклатуры и попытаться удалить её
  - **Ожидаемый результат:** операция заблокирована;
  - если интерфейс предлагает подтверждение, оно не позволяет обойти запрет.
  - Характеристика, значения и назначения товарам остаются после перезагрузки.

  </details>

- [ ] **CHR-DEF-NOM-08 — Удаление характеристики после снятия последнего назначения**

  - **Проверка:** После отказа удалить используемую характеристику убрать её последнюю связь с товарами и повторить удаление
  - **Ожидаемый результат:** теперь операция разрешена после подтверждения и выполняется мягко;
  - наличие одних только значений без назначений не блокирует удаление.

  </details>

- [ ] **CHR-DEF-NOM-09 — Запрет удаления и доступность переименования используемого значения**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Назначить значение хотя бы одному товару номенклатуры и попытаться удалить
  - **Ожидаемый результат:** операция запрещена, значение и назначения сохраняются.
  - **Проверка:** Затем переименовать его в свободное название
  - **Ожидаемый результат:** изменение разрешено и сразу отражено у связанных товаров.

  </details>

- [ ] **CHR-DEF-NOM-10 — Запрет удаления при связи с неактивным товаром без стока**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Повторить запрет удаления для товара номенклатуры без стока и для выключенного товара
  - **Ожидаемый результат:** сама связь с хотя бы одним товаром продолжает блокировать удаление характеристики/значения, отсутствие продаж или активных заказов не заменяет эту проверку.

  </details>

- [ ] **CHR-DEF-NOM-11 — Доступность для назначения после удаления и повторного создания**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Разрешённо удалить неиспользуемую запись и открыть назначение другому товару
  - **Ожидаемый результат:** удалённая запись не предлагается как действующая.
  - **Проверка:** Создать новую с прежним названием
  - **Ожидаемый результат:** новая доступна для назначения и не возвращает старые связи автоматически.

  </details>

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Изменить либо удалить запись справочника, затем открыть товар, не связанный с ней
  - **Ожидаемый результат:** его характеристики, названия и атрибуты сохранены.

  </details>

- [ ] **CHR-DEF-NOM-13 — Независимость признака Country от страны поставки**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Редактировать значение `USA` характеристики Country, а при отсутствии назначений удалить его
  - **Ожидаемый результат:** изменения относятся к признаку товара;
  - страна поставки USA, её поставщики и страны реализации не удаляются и не переименовываются по совпадению текста.

  </details>


- [ ] **CHR-DEF-NOM-14 — Удаление неиспользуемого значения при используемом соседнем**

  <details>

  - **Проверка:** При используемом значении A удалить неиспользуемое значение B той же характеристики
  - **Ожидаемый результат:** B удаляется мягко, A и назначения товарам сохранены; удаление всей характеристики остаётся запрещённым из-за A.

  </details>

- [ ] **CHR-DEF-NOM-15 — Очистка атрибутов без удаления товарных назначений**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** У значения, назначенного товарам, подтвердить выключение заполненного цвета, SVG или смайлика по отдельности
  - **Ожидаемый результат:** очищен только соответствующий атрибут у связанных актуальных товаров, сами записи значений и назначения сохранены, товар не удалён и его доступность продажи не переключена.

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** У используемого значения попытаться сохранить название другого значения того же родителя
  - **Ожидаемый результат:** отказ по уникальности не теряет назначение товарам и не подставляет в них другую запись с конфликтующим названием.

  </details>

- [ ] **CHR-DEF-NOM-17 — Проверка использования записи в момент удаления**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Если характеристика/значение стали использоваться в товаре после открытия окна удаления, завершить операцию
  - **Ожидаемый результат:** сохранённая к моменту удаления связь не позволяет удалить используемую запись;
  - серверная проверка не ограничена устаревшим состоянием открытой страницы.

  </details>

### 3.3. Подтверждение мягкого удаления

Выполнять при наличии разрешённого доступа к тестовым данным/API, позволяющего проверить сохранность записей. Для разрешённого удаления брать записи без назначений товарам; отказ удалить используемые записи проверять отдельно. Исчезновение строки из активного списка само по себе не подтверждает мягкое удаление. Восстановление через интерфейс для этих проверок не требуется.

- [ ] **CHR-DEF-DATA-01 — Мягкое удаление характеристики**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** До и после удаления характеристики сверить её идентификатор и сохранённые данные
  - **Ожидаемый результат:** запись сохранена как удалённая, а не уничтожена физически; рабочий справочник её не возвращает как активную.

  </details>

- [ ] **CHR-DEF-DATA-02 — Мягкое удаление отдельного значения**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Аналогично удалить отдельное значение
  - **Ожидаемый результат:** сохранена запись того же идентификатора с признаком удаления; соседние значения и родительская характеристика не помечены удалёнными этой операцией.

  </details>

- [ ] **CHR-DEF-DATA-03 — Сохранение дочерних данных удалённой характеристики**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** После удаления характеристики проверить сохранность относящихся к ней данных значений
  - **Ожидаемый результат:** мягкое удаление не заменено физическим уничтожением дочерних данных.
  - Конкретный способ каскадной пометки не назначать без отдельного требования.

  </details>

- [ ] **CHR-DEF-DATA-04 — Новый идентификатор при повторном использовании названия**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Создать характеристику/значение с названием мягко удалённой записи
  - **Ожидаемый результат:** создана отдельная запись, прежний идентификатор не переиспользован как восстановление; у других действующих записей назначения сохранены.

  </details>


- [ ] **CHR-DEF-DATA-05 — Отсутствие частичного удаления при запрете операции**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** После запрета удалить используемую характеристику или значение сверить тестовые данные
  - **Ожидаемый результат:** признак удаления не установлен, назначение и дочерние записи не очищены частично;
  - отказ операции не является мягким удалением.

  </details>


### 3.4. Права доступа — весь блок отложен

Проверять после реализации ролей и согласования матрицы разрешений. Наличие обычной администраторской сессии не подтверждает ограничения других ролей.

- [ ] **CHR-DEF-ACL-01 — Ограничение доступа к справочнику**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Для роли без доступа к разделу проверить меню и прямой переход на страницу
  - **Ожидаемый результат:** доступ ограничен согласно матрице, данные справочника не раскрыты обходным переходом.

  </details>

- [ ] **CHR-DEF-ACL-02 — Режим просмотра без возможности изменения**

  - **Ожидаемый результат:** просмотр разрешён, создание, редактирование названий и подписей, загрузка/замена SVG, все три тумблера, смайлики, очистка полей, перетаскивание и удаление не позволяют записать изменения.

  - **Ожидаемый результат:** доступны только разрешённые операции;
  - право редактировать не считается правом удалять, наличие права удаления не обходит проверку использования в номенклатуре.

- [ ] **CHR-DEF-ACL-04 — Серверная защита операций ограниченной роли**

  <details>
  <summary>Подробности проверки</summary>
