# Чек-лист: Настройки → Характеристики

[Бизнес-правила](README.md). Все пункты ожидают выполнения. При прогоне фиксировать дату, фактический результат и ссылку на дефект; наличие пункта не означает, что проверка прошла.

**Сейчас:** интерфейс, валидация, создание, редактирование, сохранение, независимость записей и удаление внутри страницы — раздел 1.

**Исследование:** доступные сейчас сценарии с не полностью согласованным ожидаемым результатом — раздел 2. Наблюдение не закрывает такой пункт как успешный до уточнения правила.

**Отложено:** связи с номенклатурой и товарами, приложения, предупреждения об использовании, подтверждение мягкого удаления на уровне данных и все права доступа — раздел 3. Переносить в текущий прогон после появления необходимых зависимостей и тестовых данных.

Восстановление характеристик и значений в интерфейсе пока не предусмотрено и в обязательный прогон не включено. Повторное создание с прежним названием — отдельная операция, а не восстановление.

## Подготовка

- Использовать тестовые характеристики, не назначенные реальным товарам. Справочник общий для всех стран поставки и реализаций; изменение существующих рабочих записей влияет на связанные товары.
- Подготовить две характеристики A и B с разными названиями и данными, а также две отдельные записи с одинаковым названием. Для значений также нужны уникальные и одинаковые названия внутри одной характеристики и в разных характеристиках.
- Для трёх допустимых состояний тумблеров подготовить отдельные характеристики с пустыми списками значений: оба выключены, только «Цвет», только «Иконка». Так добавление в каждом режиме проверяется независимо от ещё не согласованной обработки старых значений при смене режима.
- Подготовить строки длиной 1, 99, 100, 101 и 1000 символов. Для точной проверки границы использовать простые латинские символы; отдельно проверить допустимые буквы, цифры, знаки и эмодзи на коротких строках.
- Подготовить настоящие изображения SVG, PNG, WEBP, JPG и JPEG заметно меньше 2 МБ, два визуально разных изображения с одинаковым именем файла, файл поддерживаемого формата больше 3 МБ и файлы неподдерживаемых форматов. Точный байтовый порог 2 МБ — исследование CHR-OBS-07.
- Для цвета использовать `2B2B2B`, `CC8080`, `000000`, `FFFFFF` без `#` и строку с недопустимыми HEX-символами, например `GGHHII`.
- Положительные сценарии сохранения проверять после завершения доступного в интерфейсе действия записи, затем повторным открытием карточки и перезагрузкой страницы. Не назначать заранее Enter, blur или Escape способом сохранения/отмены уже существующего поля: это CHR-OBS-01.
- Проверки ошибок загрузки и записи выполнять на тестовых данных с контролируемым отключением сети или подменой ответа; не имитировать отказ удалением чужих данных.

## 1. Сейчас можно проверять

### 1.1. Открытие и выбор характеристики

- [] **CHR-LIST-01** — Открыть «Настройки → Характеристики» → список загружен, доступно поле «Новый элемент» и добавление; данные справочника не смешаны с номенклатурой или странами поставки.
- [] **CHR-LIST-02** — Выбрать A, затем B → выделена выбранная строка, справа её название, переводы, изображение, тумблеры и значения; данные A не показаны как данные B.
- [] **CHR-LIST-03** — Несколько раз переключиться A → B → A без редактирования → сохранённые данные и состояния тумблеров не изменились, новые записи не создались.
- [] **CHR-LIST-04** — По отдельности выбрать две характеристики с одинаковым названием → открываются их собственные разные значения и настройки; совпадение названия не объединяет карточки.
- [] **CHR-LIST-05** — Открыть контекстное меню правым кликом → доступны переименование и удаление именно выбранной для действия записи; закрытие меню без действия не меняет данные.
- [] **CHR-LIST-06** — На подготовленном пустом справочнике открыть страницу → доступно создание первой характеристики, нет зависания или фиктивной карточки ранее удалённой записи. Не очищать рабочий справочник ради этого пункта.

### 1.2. Создание характеристики

- [] **CHR-NEW-01** — Ввести новое корректное название и один раз нажать Enter → создана одна характеристика с этим названием, её можно открыть; после перезагрузки запись существует.
- [] **CHR-NEW-02** — Создать другую характеристику кликом по «+» → результат сохраняется так же, как при Enter; одного клика достаточно для одной записи.
- [] **CHR-NEW-03** — Создать характеристику только с названием → отсутствие RU/ENG, изображения и значений не блокирует создание; список значений пуст, «Цвет» и «Иконка» выключены.
- [] **CHR-NEW-04** — Попытаться создать характеристику с пустым названием и только из пробелов, отдельно через Enter и «+» → пустая запись не создаётся, существующий справочник не меняется.
- [] **CHR-NEW-05** — Создать вторую характеристику с в точности существующим названием → добавление разрешено без ошибки уникальности, обе записи остаются самостоятельными после перезагрузки.
- [] **CHR-NEW-06** — Последовательно создать A и B, добавить им разные значения → названия, значения и последующее редактирование относятся к своим карточкам, не к последней открытой записи.
- [] **CHR-NEW-07** — После отказа пустому или слишком длинному названию ввести допустимое → создание снова работает, прежняя невалидная попытка не оставила пустую или частично созданную характеристику.

### 1.3. Текстовые поля: длина, символы и обязательность

Общие сценарии CHR-TXT-05—11 выполнить для основного названия, RU, ENG и названия значения, включая создание и доступное редактирование. У основного названия проверить оба места ввода: карточку и переименование в списке. Логика подстановки отсутствующего перевода в приложении в этот прогон не входит.

- [] **CHR-TXT-01** — Для основного названия проверить 1, 99 и 100 символов → допустимы; 101 и вставка 1000 символов не сохраняются целиком как корректное название. Предел действует в создании, карточке и переименовании в списке.
- [] **CHR-TXT-02** — Для RU проверить пустое поле, 1, 99 и 100 символов → допустимы; 101 и вставка 1000 не обходят максимум. Основное название и ENG не переписываются.
- [] **CHR-TXT-03** — Для ENG повторить границы пусто / 1 / 99 / 100 / 101 / 1000 → пустое и до 100 допустимы, длинное значение целиком не сохраняется; RU и основное название сохранены.
- [] **CHR-TXT-04** — Для названия значения проверить пусто, только пробелы, 1, 99, 100, 101 и 1000 символов → пустое не добавляется, до 100 допустимо, превышение целиком не сохраняется; соседние строки не меняются.
- [] **CHR-TXT-05** — Ввести и вставить кириллицу, латиницу и смешанную строку, например `Память Memory` → допустимый текст сохраняется без потери букв или замены на вопросительные знаки.
- [] **CHR-TXT-06** — Ввести только цифры `12345`, затем буквы с цифрами `Memory 128` → допустимы; текст не превращается в числовой тип и не получает непредусмотренный запрет.
- [] **CHR-TXT-07** — Ввести знаки и сочетания `+ - / : & ( ) ' "`, затем короткую строку с эмодзи `QA 📱 ✅` → допустимые символы и эмодзи сохраняются после повторного открытия.
- [] **CHR-TXT-08** — Сохранить короткое название с угловыми скобками, например `<b>QA</b>` → отображается как текст названия, а не исполняемая разметка; соседние элементы страницы не повреждены.
- [] **CHR-TXT-09** — Вставить название с пробелами в начале и конце → по сохранении обрезаны только крайние пробелы; внутренние пробелы текста не потеряны.
- [] **CHR-TXT-10** — Попытаться очистить обязательное основное название или название существующего значения → пустое обязательное имя не сохраняется как корректное. Очистка RU/ENG отдельно разрешена.
- [] **CHR-TXT-11** — Превысить длину, затем исправить текст до 100 символов или меньше → допустимое значение сохраняется; отказ не повреждает соседние поля и записи. Блокировка ввода, обрезание или сообщение об ошибке фиксируются без требования конкретного варианта UI.

### 1.4. Редактирование карточки и переименование

- [ ] **CHR-EDIT-01** — Через Rename в контекстном меню изменить основное название A → редактирование открыто в строке списка; после сохранения новое название видно в списке и карточке той же записи, после перезагрузки оно сохраняется.
- [ ] **CHR-EDIT-02** — Изменить основное название через карточку → обновляется та же строка списка, не создаётся дополнительная характеристика; значения, изображение, переводы и тумблеры не сбрасываются.
- [ ] **CHR-EDIT-03** — Переименовать A в название B → операция разрешена без проверки уникальности; у обеих записей остаются свои значения, изображения и настройки.
- [ ] **CHR-EDIT-04** — Поочерёдно заполнить RU и ENG разным текстом → оба поля сохраняются независимо, ни одно не копирует текст другого; основное название не заменяется переводом.
- [ ] **CHR-EDIT-05** — Очистить RU, затем ENG у характеристики с заполненными переводами → пустые переводы сохраняются, основное название и значения остаются; необязательные поля не блокируют запись.
- [ ] **CHR-EDIT-06** — Переименовать одно значение в корректное новое название → после сохранения и перезагрузки изменена только нужная строка, её цвет/иконка относятся к той же записи, остальные значения сохранены.
- [ ] **CHR-EDIT-07** — Одному из двух одинаково названных значений изменить название или атрибут → изменяется только выбранная запись, а не все строки с тем же текстом; повторить для одинаковых значений в разных характеристиках.

### 1.5. Добавление значений

- [ ] **CHR-VALUE-01** — При обоих выключенных тумблерах ввести название значения и нажать Enter → добавлена одна текстовая строка без обязательного цвета/иконки; она сохраняется после перезагрузки.
- [ ] **CHR-VALUE-02** — В том же режиме добавить другое значение кликом по «+» → создана одна строка выбранной характеристики, соседняя характеристика не меняется.
- [ ] **CHR-VALUE-03** — Оставить название пустым или только из пробелов в каждом из трёх допустимых состояний тумблеров → «+» неактивен, Enter не добавляет строку даже при заполненном атрибуте активного режима.
- [ ] **CHR-VALUE-04** — Внутри одной характеристики добавить значение с уже существующим названием → допустимо, две строки не сливаются; после перезагрузки их можно редактировать и удалять раздельно.
- [ ] **CHR-VALUE-05** — Добавить одинаковое название значения в A и B → обе операции разрешены, каждое значение доступно только в собственном списке, данные между характеристиками не копируются.
- [ ] **CHR-VALUE-06** — Последовательно добавить несколько значений с разными цветами в режиме «Цвет», отдельно повторить с разными изображениями в режиме «Иконка» → каждая строка сохраняет свой атрибут, данные предыдущего добавления не подменяют новую запись.
- [ ] **CHR-VALUE-07** — Не заполнить обязательный атрибут, убедиться в запрете добавления, затем заполнить его → добавление становится доступно; неудачная попытка не создала скрытую строку и не требует повторного создания характеристики.

### 1.6. Взаимоисключающие тумблеры и обязательные атрибуты

- [ ] **CHR-MODE-01** — У новой характеристики включить только «Цвет» → состояние «Иконка» остаётся выключенным; доступен цвет, добавление не требует изображения значения.
- [ ] **CHR-MODE-02** — У другой новой характеристики включить только «Иконка» → «Цвет» остаётся выключенным; доступна загрузка иконки, цвет не обязателен.
- [ ] **CHR-MODE-03** — При включённом «Цвет» включить «Иконка» → «Цвет» автоматически выключен, активен только режим «Иконка»; затем включить «Цвет» → «Иконка» автоматически выключена, активен только режим «Цвет». Для значений доступно поле выбранного режима.
- [ ] **CHR-MODE-04** — В режиме только «Цвет» выключить активный тумблер → оба выключены; отдельно повторить для «Иконка» → оба выключены. Выключение активного режима не включает другой автоматически.
- [ ] **CHR-MODE-05** — Сохранить каждое из трёх допустимых состояний тумблеров, переключиться на другую характеристику и вернуться, перезагрузить страницу → восстанавливается состояние своей записи, оба режима не оказываются включены одновременно.
- [ ] **CHR-MODE-06** — В режиме только «Цвет» заполнить название, оставив цвет пустым → «+» неактивен, Enter не добавляет значение; с допустимым цветом добавление разрешено.
- [ ] **CHR-MODE-07** — В режиме только «Иконка» заполнить название без изображения → «+» неактивен, Enter не добавляет значение; после успешной загрузки добавление разрешено.
- [ ] **CHR-MODE-08** — На добавлении значения переключить «Цвет → Иконка» и оставить иконку пустой → прежний цвет не удовлетворяет обязательности нового режима, «+» и Enter не добавляют строку; заполнить иконку → добавление разрешено. Отдельно повторить «Иконка → Цвет» с пустым цветом нового режима.
- [ ] **CHR-MODE-09** — У A переключить «Цвет → Иконка → Цвет», затем выключить активный режим → режимы B и список его значений сохраняются. Дальнейшая судьба скрытых атрибутов A проверяется как исследование, а не по предположению о сбросе или сохранении.
- [ ] **CHR-MODE-10** — Быстро попеременно включать «Цвет» и «Иконка», затем повторно открыть карточку и перезагрузить страницу → состояние с двумя активными режимами не сохраняется и не появляется после загрузки; одновременно доступен только атрибут активного режима.

### 1.7. Цвет

- [ ] **CHR-HEX-01** — Добавить значения с цветами `2B2B2B` и `CC8080` без `#` → коды сохраняются, цветовые образцы соответствуют кодам; обязательный префикс `#` не требуется.
- [ ] **CHR-HEX-02** — По отдельности сохранить `000000` и `FFFFFF` → допустимы чёрный и белый, нули не превращаются в пустой цвет; после перезагрузки значения сохранены.
- [ ] **CHR-HEX-03** — Изменить цвет одной строки между двумя заметно различающимися допустимыми кодами → образец и сохранённый код обновлены у той же строки, соседние значения и изображение самой характеристики не переписаны.
- [ ] **CHR-HEX-04** — Вставить `GGHHII`, текст или эмодзи вместо HEX-кода → ввод не принимается как корректный цвет и не сохраняет значение с таким цветом. Конкретное сообщение/нормализация не заданы; дополнительные HEX-форматы — CHR-OBS-05.

### 1.8. Изображения характеристики и значений

Общие файловые сценарии выполнить для изображения самой характеристики и иконки значения в режиме «Иконка». Отдельно проверить изображение самой характеристики при активном режиме «Цвет»: это другое поле. Успешная загрузка не должна сбрасывать текст и данные активного режима.

- [ ] **CHR-IMG-01** — Поочерёдно загрузить настоящие SVG, PNG, WEBP, JPG и JPEG меньше 2 МБ → каждый разрешённый формат принимается, превью соответствует изображению и сохраняется после повторного открытия карточки и перезагрузки.
- [ ] **CHR-IMG-02** — Сохранить характеристику без изображения, затем загрузить его → оба состояния разрешены. При активном «Цвет» изображение самой характеристики также доступно и не включает «Иконка» у значений; необязательность картинки характеристики не отменяет обязательность иконки значения в режиме «Иконка».
- [ ] **CHR-IMG-03** — Заменить загруженную картинку другой допустимой → отображается новая картинка у той же записи, количество характеристик/значений не увеличилось, прежнее изображение не возвращается после перезагрузки.
- [ ] **CHR-IMG-04** — Заменить файл другим изображением с тем же именем → видно новое содержимое, сохранение не определяется одним совпадением имени и не возвращает старое превью из кеша.
- [ ] **CHR-IMG-05** — Проверить уже загруженные изображения → доступна замена; отдельная команда удаления картинки с сохранением записи не предусмотрена. Корзина значения удаляет значение целиком, а не только его файл.
- [ ] **CHR-IMG-06** — Загрузить GIF, PDF или TXT → файл не принят; в русском интерфейсе сообщение «Формат файла не поддерживается. Разрешены: SVG, PNG, WEBP, JPG/JPEG».
- [ ] **CHR-IMG-07** — Загрузить файл поддерживаемого формата заметно больше лимита, например 3 МБ → файл не принят, сообщение «Файл слишком большой. Максимум 2 МБ»; подготовка файла не должна ограничиваться сменой расширения.
- [ ] **CHR-IMG-08** — При замене существующей картинки передать неподдерживаемый или слишком большой файл → после отказа прежняя успешно сохранённая картинка остаётся, новое изображение не считается успешно сохранённым.
- [ ] **CHR-IMG-09** — На создании значения получить отказ загрузки без ранее сохранённой иконки → обязательная иконка не считается заполненной, «+» и Enter не добавляют неполную строку; затем корректная загрузка позволяет добавить значение.
- [ ] **CHR-IMG-10** — Открыть выбор файла и отменить без выбора → сохранённое изображение и поля записи не изменились; последующий выбор корректного файла работает.
- [ ] **CHR-IMG-11** — После загрузки и замены сверить изображение характеристики и иконки двух значений → каждое превью относится к своей записи, файлы не перепутаны; нет повреждённого изображения или потери видимого содержимого. Техническую оптимизацию фиксировать отдельно, CHR-OBS-08.

### 1.9. Удаление внутри страницы

Предупреждения об использовании записи в товарах проверяются в отложенном блоке. Для неиспользуемого значения отдельное подтверждение пока не является согласованным требованием.

- [ ] **CHR-DEL-01** — В контекстном меню характеристики вызвать удаление → до подтверждения характеристика существует; отменить → название, значения, файлы и режимы сохраняются после перезагрузки.
- [ ] **CHR-DEL-02** — Повторить удаление и отмену через корзину карточки → результат тот же, другая характеристика не меняется.
- [ ] **CHR-DEL-03** — Подтвердить удаление неиспользуемой характеристики из контекстного меню → она исчезла из рабочего списка и не возвращается после перезагрузки; строки и данные других характеристик сохранены.
- [ ] **CHR-DEL-04** — Удалить другую характеристику через корзину карточки → удалена именно эта запись; оба входа в удаление действуют одинаково. Не требовать конкретного автоматического выбора следующей карточки, CHR-OBS-11.
- [ ] **CHR-DEL-05** — Правым кликом вызвать удаление A при ранее открытой B → подтверждение и фактическое удаление относятся к A, а не к прежней открытой карточке. B и её данные сохранены.
- [ ] **CHR-DEL-06** — Из двух одинаково названных характеристик с разными значениями удалить одну → вторая остаётся со своими значениями и настройками; совпадение названия не расширяет удаление.
- [ ] **CHR-DEL-07** — Удалить одно неиспользуемое значение, завершив предусмотренное интерфейсом действие → оно исчезает из списка и не возвращается после перезагрузки; характеристика, другие значения, их цвета/иконки и режимы сохранены.
- [ ] **CHR-DEL-08** — Удалить одну из одинаково названных строк, а затем последнее оставшееся значение тестовой характеристики → сначала остаётся соседняя самостоятельная строка, затем допускается пустой список; сама характеристика не удаляется и доступна для добавления новых значений.
- [ ] **CHR-DEL-09** — После удаления характеристики и отдельно значения создать новую запись с тем же названием → создание разрешено, новая запись самостоятельна; это не возвращение прежних связей и не действие восстановления.

### 1.10. Перетаскивание в списке значений

- [ ] **CHR-DRAG-01** — В списке из трёх различимых значений перенести первую строку в конец, затем обратно за drag-handle → порядок на текущем экране меняется, строки не копируются и не пропадают; название и атрибут активного режима (цвет либо иконка) перемещаются вместе со своей записью.
- [ ] **CHR-DRAG-02** — Перетащить одну из двух одинаково названных строк, различимых по цвету/иконке → перемещается выбранная запись, её атрибуты не меняются местами с атрибутами соседней; значения другой характеристики не изменились. Сохранение порядка после перезагрузки — CHR-OBS-02.

### 1.11. Сохранение, повторное открытие и ошибки

- [ ] **CHR-SAVE-01** — Для каждого из трёх допустимых состояний тумблеров отдельно сохранить название, RU/ENG, изображение характеристики и несколько значений с атрибутом активного режима либо без атрибутов при обоих выключенных → после выбора другой карточки и перезагрузки набор относится к исходной записи и совпадает с успешно сохранённым состоянием.
- [ ] **CHR-SAVE-02** — Изменить по одному полю в A и B, повторно открыть страницу → у каждой записи её последнее успешно сохранённое значение, одно поле не возвращает старые данные остальных полей карточки.
- [ ] **CHR-SAVE-03** — После отказа валидации проверить повторно открытую запись → нет недопустимого длинного/пустого обязательного имени, неверного цвета или принятого запрещённого файла; ранее сохранённые корректные данные не повреждены.
- [ ] **CHR-SAVE-04** — Получить контролируемый отказ загрузки списка или карточки → интерфейс не выдаёт неуспешную загрузку за успешное сохранение/удаление и не применяет данные предыдущей карточки к новой. Конкретный текст и вид ошибки не назначены.
- [ ] **CHR-SAVE-05** — Получить контролируемый отказ создания/редактирования → операция не показана как успешно сохранённая; после восстановления связи и повторного открытия нет ложной сохранённой записи. Повторная корректная операция доступна; конкретные тост и локальный откат — CHR-OBS-10.
- [ ] **CHR-SAVE-06** — Получить контролируемый отказ удаления → запись не считается успешно удалённой и доступна после восстановления связи и перезагрузки; данные соседних записей сохранены.
- [ ] **CHR-SAVE-07** — Успешно сохранить корректную запись после отказа валидации, загрузки файла или сети → страница не остаётся заблокированной, новое успешное состояние сохраняется; ошибка не создаёт лишнюю строку.

## 2. Исследовать сейчас, ожидаемый результат уточнить

Связь с открытыми вопросами README указана в каждом пункте. Несогласованные детали не заменяют уже определённые правила: например, любой дополнительный HEX-формат не отменяет поддержку шестизначного кода без `#`.

- [ ] **CHR-OBS-01 / README 10.2** — Для основного названия, RU/ENG, названия значения и Rename записать, что сохраняет ввод: Enter, выход из поля, отдельное действие, смена карточки. Проверить Escape и закрытие до/после записи; не требовать отмены уже сохранённого изменения.
- [ ] **CHR-OBS-02 / README 10.1** — После перетаскивания значений сменить карточку и перезагрузить страницу → записать, сохраняется ли порядок и как обрабатываются одинаковые названия. Обязательный порядок после перезагрузки согласовать отдельно.
- [ ] **CHR-OBS-03 / README 10.1** — Записать порядок самого списка характеристик до/после создания, переименования, удаления и перезагрузки. Не требовать алфавитной сортировки либо ручной перестановки без согласованного правила.
- [ ] **CHR-OBS-04 / README 10.3** — У характеристики с заполненными цветами переключить «Цвет → Иконка → Цвет», отдельно у характеристики с загруженными иконками выполнить «Иконка → Цвет → Иконка»; также включить режим у существующих текстовых значений → записать сохранение/сброс скрытых атрибутов и обработку незаполненных старых строк. Взаимоисключение тумблеров при переключении проверяется как согласованное правило.
- [ ] **CHR-OBS-05 / README 10.4** — Проверить `#2B2B2B`, короткий HEX, 8 знаков с прозрачностью, нижний регистр, пробелы и код, состоящий только из `#`; записать поддержку, нормализацию и цвет по умолчанию. Не назначать запрет/разрешение дополнительных форматов заранее.
- [ ] **CHR-OBS-06 / README 10.5** — Удалить значение без связей с товарами → записать наличие/отсутствие подтверждения. Если подтверждение есть, проверить отказ и сохранность строки; само наличие либо отсутствие окна пока не считать дефектом.
- [ ] **CHR-OBS-07** — Определить байтовую трактовку лимита 2 МБ: подготовить настоящие изображения 2 000 000 и 2 097 152 байт, затем файлы ровно на согласованной границе и на байт выше → зафиксировать порог и после согласования проверить приём на границе/отказ выше. Не подменять размеры файла размерами изображения в пикселях.
- [ ] **CHR-OBS-08** — Зафиксировать оптимизацию загрузки по доступным ответам/файлам: исходный и итоговый формат/размер, видимое качество и прозрачность. Наличие превью не доказывает оптимизацию; процент сжатия и целевой размер не согласованы.
- [ ] **CHR-OBS-09** — Попробовать загрузить пустой, повреждённый файл и файл с расширением разрешённой картинки, но другим содержимым → записать проверку содержимого и обработку ошибки; не утверждать заранее конкретное сообщение или правила преобразования.
- [ ] **CHR-OBS-10** — При задержке или отказе запроса записи зафиксировать состояние поля, индикатор/тост и повтор операции; проверить быстрые Enter и «+» при создании → согласовать защиту от повторной отправки, учитывая, что намеренное создание одинаковых названий разрешено.
- [ ] **CHR-OBS-11** — На тестовом справочнике удалить выбранную и последнюю характеристику → записать выбор следующей карточки/пустого состояния, фокус и возможность дальнейшего создания без требования конкретного автоматического выбора.
- [ ] **CHR-OBS-12** — При замедлении запросов быстро выбирать A/B и последовательно менять поля → записать порядок ответов и границу записи. Ответ не должен отображаться как данные другой сущности; политика одновременных записей одного поля пока не согласована.

## 3. Отложенные проверки

### 3.1. Номенклатура, товары и общий справочник

Для блока подготовить товары с несколькими характеристиками, несколько товаров с одной общей записью и отдельные одинаково названные характеристики/значения. Использовать товары разных брендов и связок UAE × Deira, USA × Deira, UAE × Free zone и USA × Free zone. Проверять результат сразу после успешной записи, открывая тот же товар в зависимом разделе.

- [ ] **CHR-DEF-NOM-01** — Создать характеристику и значение → они доступны для назначения в номенклатуре для разных стран поставки и реализаций из общего справочника; отдельная ручная копия для каждой пары не нужна.
- [ ] **CHR-DEF-NOM-02** — Назначить одну характеристику нескольким товарам разных пар и переименовать её → новое название сразу относится ко всем связанным товарам; прежние назначения не потеряны, другая одинаково названная запись не изменилась.
- [ ] **CHR-DEF-NOM-03** — Изменить название используемого значения → оно сразу обновляется у всех товаров, связанных с этой записью; текстовое совпадение с другим значением не расширяет обновление.
- [ ] **CHR-DEF-NOM-04** — Изменить заполненные RU/ENG и изображение используемой характеристики → связанные актуальные карточки товаров получают новые данные без повторного назначения характеристики; подстановка при пустом переводе в этот пункт не входит.
- [ ] **CHR-DEF-NOM-05** — Отдельно изменить цвет используемого значения в режиме «Цвет» и заменить изображение другого используемого значения в режиме «Иконка» → связанные товары сразу используют новый атрибут соответствующей записи; соседние значения/товары остаются со своими атрибутами.
- [ ] **CHR-DEF-NOM-06** — Изменить одно из двух одинаково названных значений, назначенных разным товарам → изменения доходят только до товаров выбранной записи, не до всех товаров с совпадающим текстом.
- [ ] **CHR-DEF-NOM-07** — Вызвать удаление характеристики, используемой товарами → показано предупреждение о влиянии на них; отмена не удаляет характеристику и ничего не меняет в товарах.
- [ ] **CHR-DEF-NOM-08** — Подтвердить удаление используемой характеристики → она и относящаяся к ней часть сразу убраны у связанных товаров всех пар; остальные характеристики и значения товаров сохранены.
- [ ] **CHR-DEF-NOM-09** — Вызвать удаление используемого значения → показано предупреждение; при отмене значение и назначения сохранены, после подтверждения у связанных товаров убрано только удалённое значение, соседние значения/характеристики не затронуты.
- [ ] **CHR-DEF-NOM-10** — Удалить используемую характеристику/значение → сами товары не удалены; их доступность продажи и настройки закупки/продаж не переключены одной этой операцией, другие ограничения продолжают действовать.
- [ ] **CHR-DEF-NOM-11** — После удаления открыть назначение характеристики/значения другому товару → удалённая запись не предлагается как действующая. Создать новую с прежним названием → новая доступна для назначения, но не возвращает прежние связи автоматически только по совпадению текста.
- [ ] **CHR-DEF-NOM-12** — Изменить либо удалить запись справочника, затем открыть товар, не связанный с ней → его характеристики, названия и атрибуты сохранены.
- [ ] **CHR-DEF-NOM-13** — Добавить, переименовать и удалить значение `USA` характеристики Country → изменения относятся к признаку товара; страна поставки USA, её поставщики и страны реализации не удаляются и не переименовываются по совпадению текста.

### 3.2. Клиентские и поставщицкие интерфейсы

- [ ] **CHR-DEF-APP-01** — После изменения используемых названий/атрибутов открыть актуальную карточку того же товара в приложении клиента и интерфейсе поставщика → данные соответствуют общему справочнику в местах, где они предусмотрены дизайном; другие товары не подменены.
- [ ] **CHR-DEF-APP-02** — После удаления характеристики или значения открыть актуальный товар в зависимых интерфейсах → удалённая часть больше не выводится, остальные данные товара сохранены; удаление атрибута само по себе не скрывает товар из продажи.
- [ ] **CHR-DEF-APP-03 / README 10.1** — После согласования порядка изменить его в справочнике → проверить применение в номенклатуре, группах/фильтрах и приложениях только в определённых правилами местах. До согласования фиксировать фактический порядок без статуса успешной проверки требования.
- [ ] **CHR-DEF-APP-04 / README 10.6** — После оформления заказа изменить и удалить использованную характеристику/значение → исследовать названия и оформление в истории заказа. Обновление либо сохранение прежних подписей пока не объявлять ожидаемым результатом.

### 3.3. Подтверждение мягкого удаления

Выполнять при наличии разрешённого доступа к тестовым данным/API, позволяющего проверить сохранность записей. Исчезновение строки из активного списка само по себе не подтверждает мягкое удаление. Восстановление через интерфейс для этих проверок не требуется.

- [ ] **CHR-DEF-DATA-01** — До и после удаления характеристики сверить её идентификатор и сохранённые данные → запись сохранена как удалённая, а не уничтожена физически; рабочий справочник её не возвращает как активную.
- [ ] **CHR-DEF-DATA-02** — Аналогично удалить отдельное значение → сохранена запись того же идентификатора с признаком удаления; соседние значения и родительская характеристика не помечены удалёнными этой операцией.
- [ ] **CHR-DEF-DATA-03** — После удаления характеристики проверить сохранность относящихся к ней данных значений → мягкое удаление не заменено физическим уничтожением дочерних данных. Конкретный способ каскадной пометки не назначать без отдельного требования.
- [ ] **CHR-DEF-DATA-04** — Создать характеристику/значение с названием мягко удалённой записи → создана отдельная запись, прежний идентификатор не переиспользован как восстановление; у других действующих записей назначения сохранены.

### 3.4. Права доступа — весь блок отложен

Проверять после реализации ролей и согласования матрицы разрешений. Наличие обычной администраторской сессии не подтверждает ограничения других ролей.

- [ ] **CHR-DEF-ACL-01** — Для роли без доступа к разделу проверить меню и прямой переход на страницу → доступ ограничен согласно матрице, данные справочника не раскрыты обходным переходом.
- [ ] **CHR-DEF-ACL-02** — Для роли только с просмотром открыть карточки → просмотр разрешён, создание, переименование, изменение полей, загрузка/замена файлов, тумблеры, перетаскивание и удаление не позволяют записать изменения.
- [ ] **CHR-DEF-ACL-03** — Для ролей с разными разрешениями на редактирование и удаление проверить оба входа удаления и остальные действия → доступны только разрешённые операции; право редактировать не считается автоматически правом удалять.
- [ ] **CHR-DEF-ACL-04** — Повторить запрещённые операции прямыми запросами к API под ограниченной ролью → сервер не сохраняет изменения даже при обходе скрытых/заблокированных элементов интерфейса; конкретный HTTP-код определяется реализованным контрактом.
