# Чек-лист: Настройки → Справочник характеристик

[Бизнес-правила](README.md). Все пункты ожидают выполнения. При прогоне фиксировать дату, фактический результат и ссылку на дефект; наличие пункта не означает, что проверка прошла.

**Сейчас:** интерфейс, текстовая валидация и уникальность, SVG, смайлики, любые сочетания полей, подтверждение очистки поля, сохранение по Enter/клику вне поля, алфавитный список, ручной порядок и разрешённое удаление внутри страницы — раздел 1.

**Исследование:** доступные сейчас сценарии с не полностью согласованным ожидаемым результатом — раздел 2. Наблюдение не закрывает такой пункт как успешный до уточнения правила.

**Отложено:** связи с номенклатурой и товарами, запрет удаления используемых записей, приложения, подтверждение мягкого удаления на уровне данных и все права доступа — раздел 3. Переносить в текущий прогон после появления необходимых зависимостей и тестовых данных. Без товара с назначенной записью нельзя засчитать запрет удаления как проверенный.

Восстановление характеристик и значений в интерфейсе пока не предусмотрено и в обязательный прогон не включено. Повторное создание с прежним названием — отдельная операция, а не восстановление.

## Подготовка

- Использовать тестовые характеристики, не назначенные реальным товарам. Справочник общий для всех стран поставки и реализаций; изменение существующих рабочих записей влияет на связанные товары.
- Подготовить характеристики A и B с разными уникальными основными названиями и полными обязательными карточками: название, SVG, RU, ENG. Значения внутри каждого родителя должны иметь разные названия; одинаковые названия значений подготовить только в разных характеристиках. Для негативных сценариев дубли вводятся намеренно, но не должны сохраняться.
- Для восьми сочетаний «Цвет / Иконка / Смайлик» подготовить отдельные полные характеристики с пустыми списками значений; явно задать нужное сочетание. Все включённые атрибуты обязательны при добавлении, выключенные не требуются.
- Подготовить строки длиной 1, 99, 100, 101 и 1000 символов. Для точной проверки границы использовать простые латинские символы; отдельно проверить допустимые буквы, цифры, знаки и эмодзи на коротких строках.
- Подготовить корректные SVG обычного размера и SVG 3–5 МБ, два визуально разных SVG с одинаковым именем файла; PNG, WEBP, JPG/JPEG и другие форматы подготовить для отказа. Разрешён только SVG, ограничения размера нет.
- Для цвета использовать `2B2B2B`, `CC8080`, `000000`, `FFFFFF` без `#` и строку с недопустимыми HEX-символами, например `GGHHII`.
- Положительные сценарии редактирования названий, подписей и значений проверять двумя способами: Enter и клик в пустое место, затем повторное открытие и перезагрузка. Для этих сценариев остальные обязательные поля карточки заполнены; создание до полного заполнения проверяется отдельно в CHR-NEW-03. Способ отмены несохранённого ввода — CHR-OBS-01.
- Проверки ошибок загрузки и записи выполнять на тестовых данных с контролируемым отключением сети или подменой ответа; не имитировать отказ удалением чужих данных.

## 1. Сейчас можно проверять

### 1.1. Открытие и выбор характеристики

- [ ] **CHR-LIST-01** — Открыть «Настройки → Характеристики» → список загружен, доступно «New Item / Новый элемент» и добавление; данные справочника не смешаны с номенклатурой или странами поставки.
- [ ] **CHR-LIST-02** — Выбрать A, затем B → выделена выбранная строка, справа её название, переводы, изображение, тумблеры и значения; данные A не показаны как данные B.
- [ ] **CHR-LIST-03** — Несколько раз переключиться A → B → A без редактирования → сохранённые данные и состояния тумблеров не изменились, новые записи не создались.
- [ ] **CHR-LIST-04** — Выбрать характеристики A и B, в которых есть одинаково названные значения → открываются собственные значения и атрибуты каждой записи; допустимое совпадение между разными характеристиками не объединяет данные.
- [ ] **CHR-LIST-05** — В левом списке найти корзину справа от характеристики → действие относится к этой строке; вызов и отмена подтверждения не меняют данные другой открытой карточки.
- [ ] **CHR-LIST-06** — На подготовленном пустом справочнике открыть страницу → доступно создание первой характеристики, нет зависания или фиктивной карточки ранее удалённой записи. Не очищать рабочий справочник ради этого пункта.

### 1.2. Создание характеристики

- [ ] **CHR-NEW-01** — Ввести новое корректное название и один раз нажать Enter → создана одна характеристика с этим названием, её можно открыть; после перезагрузки запись существует.
- [ ] **CHR-NEW-02** — Создать другую характеристику кликом по «+» → результат сохраняется так же, как при Enter; одного клика достаточно для одной записи.
- [ ] **CHR-NEW-03** — Создать характеристику с названием до заполнения SVG-иконки и подписей RU/ENG → запись создаётся, список значений пуст, «Цвет» и «Иконка» выключены. При последующем редактировании поочерёдно оставить каждое обязательное поле пустым → редактирование не завершается успешным сохранением до заполнения всех четырёх полей; затем полная карточка сохраняется.
- [ ] **CHR-NEW-04** — Попытаться создать характеристику с пустым названием и только из пробелов, отдельно через Enter и «+» → пустая запись не создаётся, существующий справочник не меняется.
- [ ] **CHR-NEW-05** — Попытаться создать вторую характеристику с в точности существующим основным названием → создание отклонено по уникальности, второй действующей записи нет после перезагрузки; исходная характеристика и её данные сохранены.
- [ ] **CHR-NEW-06** — Последовательно создать A и B, добавить им разные значения → названия, значения и последующее редактирование относятся к своим карточкам, не к последней открытой записи.
- [ ] **CHR-NEW-07** — После отказа пустому или слишком длинному названию ввести допустимое → создание снова работает, прежняя невалидная попытка не оставила пустую или частично созданную характеристику.

### 1.3. Текстовые поля: длина, символы и обязательность

Общие сценарии CHR-TXT-05—11 выполнить для основного названия, RU, ENG и названия значения; при редактировании остальные обязательные поля заполнены. Проверить Enter и клик в пустое место. Любые дополнительные входы в переименование, если они есть в UI, должны сохранять те же ограничения; их наличие не требуется новым ТЗ.

- [ ] **CHR-TXT-01** — Для основного названия проверить 1, 99 и 100 символов → допустимы; 101 и вставка 1000 символов не сохраняются целиком как корректное название. Предел действует при создании и редактировании; остальные обязательные поля карточки для проверки редактирования заполнены.
- [ ] **CHR-TXT-02** — В полной карточке для RU проверить 1, 99 и 100 символов → допустимы; пустое поле и только пробелы блокируют сохранение редактирования, 101 и вставка 1000 не обходят максимум. Основное название и ENG не переписываются.
- [ ] **CHR-TXT-03** — Для ENG повторить границы пусто / только пробелы / 1 / 99 / 100 / 101 / 1000 → пустое и превышение недопустимы при редактировании, до 100 допустимо; RU и основное название сохранены.
- [ ] **CHR-TXT-04** — Для названия значения проверить пусто, только пробелы, 1, 99, 100, 101 и 1000 символов → пустое не добавляется, до 100 допустимо, превышение целиком не сохраняется; соседние строки не меняются.
- [ ] **CHR-TXT-05** — Ввести и вставить кириллицу, латиницу и смешанную строку, например `Память Memory` → допустимый текст сохраняется без потери букв или замены на вопросительные знаки.
- [ ] **CHR-TXT-06** — Ввести только цифры `12345`, затем буквы с цифрами `Memory 128` → допустимы; текст не превращается в числовой тип и не получает непредусмотренный запрет.
- [ ] **CHR-TXT-07** — Ввести знаки и сочетания `+ - / : & ( ) ' "`, затем короткую строку с эмодзи `QA 📱 ✅` → допустимые символы и эмодзи сохраняются после повторного открытия.
- [ ] **CHR-TXT-08** — Сохранить короткое название с угловыми скобками, например `<b>QA</b>` → отображается как текст названия, а не исполняемая разметка; соседние элементы страницы не повреждены.
- [ ] **CHR-TXT-09** — Вставить название с пробелами в начале и конце → по сохранении обрезаны только крайние пробелы; внутренние пробелы текста не потеряны.
- [ ] **CHR-TXT-10** — В редактируемой полной карточке по очереди очистить основное название, RU и ENG; отдельно очистить название значения → ни одно обязательное текстовое поле не сохраняется как корректное пустое значение. Возможность первоначально создать незаполненную карточку не разрешает сохранять такое редактирование.
- [ ] **CHR-TXT-11** — Превысить длину, затем исправить текст до 100 символов или меньше → допустимое значение сохраняется; отказ не повреждает соседние поля и записи. Блокировка ввода, обрезание или сообщение об ошибке фиксируются без требования конкретного варианта UI.

### 1.3.1. Уникальность и область сравнения

- [ ] **CHR-UNIQ-01** — В полной карточке подтвердить её собственное неизменённое основное название через Enter и клик вне поля → запись не конфликтует сама с собой, ложной ошибки дубликата нет.
- [ ] **CHR-UNIQ-02** — Подтвердить неизменённое название существующего значения → оно не считается собственным дубликатом и не создаётся второй строкой.
- [ ] **CHR-UNIQ-03** — Переименовать значение A в существующее название B внутри того же родителя → отказ, прежние обе строки и их атрибуты сохраняются; после выбора свободного названия редактирование разрешено.
- [ ] **CHR-UNIQ-04** — Попытаться добавить значение с существующим названием, но другим цветом, SVG или смайликом → дополнительные атрибуты не обходят запрет одинаковых названий внутри одной характеристики.
- [ ] **CHR-UNIQ-05** — У характеристик с разными уникальными основными названиями задать одинаковые заполненные подписи RU/ENG → отсутствие отдельного требования уникальности подписей не создаёт запрета; уникальность значений в разных родителях также не проверяется глобально.
- [ ] **CHR-UNIQ-06** — В двух вкладках страницы попытаться создать одно и то же основное название, отдельно повторить для названия значения внутри одной характеристики → после завершения запросов не появляются две действующие записи запрещённой области; отказ второй попытке не повреждает первую.

### 1.4. Редактирование карточки и переименование

- [ ] **CHR-EDIT-01** — В полной карточке изменить основное название и нажать Enter → новое название сохранено в карточке и списке той же записи, её положение соответствует алфавитному порядку; после перезагрузки результат сохраняется.
- [ ] **CHR-EDIT-02** — Изменить основное название через карточку и кликнуть в пустое место → изменение сохранено без Enter и без создания новой сущности; значения, SVG, подписи и тумблеры не сброшены.
- [ ] **CHR-EDIT-03** — Попытаться переименовать A в существующее основное название B, отдельно через Enter и клик вне поля → сохранение дубликата отклонено, у A прежнее допустимое название, у B её данные; после исправления на свободное название редактирование доступно.
- [ ] **CHR-EDIT-04** — Поочерёдно заполнить RU и ENG разным текстом → оба поля сохраняются независимо, ни одно не копирует текст другого; основное название не заменяется переводом.
- [ ] **CHR-EDIT-05** — Поочерёдно очистить RU и ENG у полной карточки и попытаться сохранить через Enter и клик в пустое место → редактирование с пустой обязательной подписью не сохранено; после восстановления допустимых подписей сохранение работает.
- [ ] **CHR-EDIT-06** — Переименовать одно значение в свободное корректное название, отдельно через Enter и клик в пустое место → после перезагрузки изменена только нужная строка; её цвет, SVG-иконка и смайлик в включённых полях относятся к прежней записи, остальные значения сохранены.
- [ ] **CHR-EDIT-07** — У одинаково названных значений в разных характеристиках изменить название или атрибут одного → изменяется только выбранная запись, а не все значения с совпадающим текстом.

### 1.5. Добавление значений

- [ ] **CHR-VALUE-01** — При всех трёх выключенных дополнительных полях ввести свободное название значения и нажать Enter → добавлена одна текстовая строка без обязательного цвета, SVG или смайлика; она сохраняется после перезагрузки.
- [ ] **CHR-VALUE-02** — В том же режиме добавить другое значение кликом по «+» → создана одна строка выбранной характеристики, соседняя характеристика не меняется.
- [ ] **CHR-VALUE-03** — Оставить название пустым или только из пробелов при любом сочетании дополнительных полей → «+» неактивен, Enter не добавляет строку даже при заполненных остальных включённых полях.
- [ ] **CHR-VALUE-04** — Попытаться добавить внутри одной характеристики второе значение с в точности существующим названием → добавление отклонено по уникальности, после перезагрузки второй строки нет; действующее значение и его атрибуты сохранены.
- [ ] **CHR-VALUE-05** — Добавить одинаковое название значения в A и B → обе операции разрешены, каждое значение доступно только в собственном списке, данные между характеристиками не копируются.
- [ ] **CHR-VALUE-06** — Последовательно добавить несколько значений с разными свободными названиями и заполненными цветами, SVG и смайликами при включённых полях → каждая строка сохраняет свой набор атрибутов, данные предыдущего добавления не подменяют новую запись.
- [ ] **CHR-VALUE-07** — Не заполнить обязательный атрибут, убедиться в запрете добавления, затем заполнить его → добавление становится доступно; неудачная попытка не создала скрытую строку и не требует повторного создания характеристики.

### 1.6. Независимые поля и обязательные атрибуты

- [ ] **CHR-MODE-01** — Включить только «Цвет», оставив «Иконка» и «Смайлик» выключенными → доступны название и цвет, для добавления не нужны SVG или смайлик.
- [ ] **CHR-MODE-02** — Включить только «Иконка», оставив другие поля выключенными → требуется SVG значения, цвет и смайлик не обязательны; иконка самой характеристики это поле не заполняет.
- [ ] **CHR-MODE-03** — Включить «Цвет», затем «Иконка», затем «Смайлик»; повторить включение в обратном порядке на другой характеристике → все три могут оставаться включёнными одновременно, доступны все поля, включение нового не выключает предыдущие.
- [ ] **CHR-MODE-04** — При нескольких включённых полях выключить по одному из них; для заполненного поля пройти предусмотренное подтверждение → меняется только выбранный тумблер, остальные состояния сохраняются. Отмена очистки заполненного поля проверяется в CHR-OFF.
- [ ] **CHR-MODE-05** — По таблице README проверить все восемь сочетаний трёх тумблеров: для каждого на отдельной полной тестовой характеристике добавить значение с ровно необходимыми атрибутами, сменить карточку и перезагрузить → сочетание и данные сохранены; выключенные поля не требуются для добавления.
- [ ] **CHR-MODE-06** — При включённом «Цвет» и заполненных остальных активных полях оставить цвет пустым → «+» неактивен, Enter не добавляет строку; с допустимым цветом добавление разрешено.
- [ ] **CHR-MODE-07** — При включённой «Иконка» и заполненных остальных активных полях не загрузить SVG → «+» неактивен, Enter не добавляет строку; после успешной загрузки SVG добавление разрешено.
- [ ] **CHR-MODE-08** — При всех трёх включённых полях по очереди оставить незаполненным цвет, SVG и смайлик → отсутствие любого блокирует «+» и Enter; заполнение всех трёх вместе с уникальным названием разрешает добавить значение.
- [ ] **CHR-MODE-09** — Изменять сочетания трёх тумблеров A, включая подтверждённое выключение заполненного поля → тумблеры, значения и атрибуты B не изменяются; очистка не распространяется на другую характеристику.
- [ ] **CHR-MODE-10** — На характеристике без заполненных дополнительных атрибутов несколько раз включить и выключить разные тумблеры → состояния не переключаются взаимно, после завершённых сохранений и перезагрузки восстановлено выбранное сочетание, в том числе все три включённые.

### 1.6.1. Смайлик

- [ ] **CHR-SMILE-01** — Включить только «Смайлик»: название без смайлика не добавляется через «+» или Enter; после выбора смайлика значение с уникальным названием добавляется и сохраняет атрибут после перезагрузки.
- [ ] **CHR-SMILE-02** — Добавить эмодзи в текст названия, оставив отдельное включённое поле «Смайлик» пустым → текстовый эмодзи не заменяет обязательный атрибут, добавление заблокировано.
- [ ] **CHR-SMILE-03** — Изменить смайлик одного значения → после успешной записи и повторного открытия изменён только этот атрибут этой записи; название, цвет и SVG при включённых полях сохранены.

- [ ] **CHR-SMILE-05** — Задать разные смайлики двум значениям и отдельно значению другой характеристики → они хранятся у своих записей; одинаковый смайлик не объединяет значения и сам по себе не является дубликатом названия.

### 1.6.2. Предупреждение и очистка поля

Выполнить для «Цвет», «Иконка» и «Смайлик» на полных тестовых карточках с несколькими заполненными значениями. Очистка поля не является удалением строки значения.

- [ ] **CHR-OFF-01** — Выключить «Цвет» с заполненными цветами → до удаления данных показано «Заполненные значения будут удалены. Продолжить?»; отменить → тумблер остаётся включён, все цвета сохранены после перезагрузки.
- [ ] **CHR-OFF-02** — Выключить «Иконка» с загруженными SVG и отменить предупреждение → тумблер и все сохранённые иконки значений остаются, файлы не очищены открытием окна.
- [ ] **CHR-OFF-03** — Выключить «Смайлик» с заполненными смайликами и отменить предупреждение → поле остаётся включённым, все смайлики сохранены.
- [ ] **CHR-OFF-04** — При всех включённых полях подтвердить выключение «Цвет» → цвета очищены у всех значений выбранной характеристики, строки, их идентификаторы и названия, SVG и смайлики сохранены; остальные тумблеры включены.
- [ ] **CHR-OFF-05** — Подтвердить выключение «Иконка» → очищены SVG-атрибуты значений, но не обязательная SVG-иконка самой характеристики, цвета, смайлики или названия; сами значения остаются.
- [ ] **CHR-OFF-06** — Подтвердить выключение «Смайлик» → очищены отдельные смайлики всех значений выбранной характеристики, текстовые эмодзи в названиях, цвета, SVG и строки сохранены.
- [ ] **CHR-OFF-07** — После каждого подтверждённого выключения сменить карточку, перезагрузить и включить поле вновь → старые очищенные пользовательские данные не возвращаются. Новый добавляемый элемент требует заполнения всех включённых полей.
- [ ] **CHR-OFF-08** — Подтвердить очистку одного поля A → атрибуты одноимённых значений другой характеристики B не изменились, сама A и её список значений не удалены; переключение остальных тумблеров не выполнено за пользователя.
- [ ] **CHR-OFF-09** — При подтверждении очистки заполненного поля прервать запрос до отправки на сервер → интерфейс не сообщает об успешной очистке; после восстановления сети и перезагрузки прежние данные и состояние поля сохранены. Повторная успешная очистка выполняет предусмотренное изменение.

### 1.7. Цвет

- [ ] **CHR-HEX-02** — По отдельности сохранить `000000` и `FFFFFF` → допустимы чёрный и белый, нули не превращаются в пустой цвет; после перезагрузки значения сохранены.
- [ ] **CHR-HEX-03** — Изменить цвет одной строки между двумя заметно различающимися допустимыми кодами → образец и сохранённый код обновлены у той же строки, соседние значения, SVG-иконки, смайлики и иконка характеристики не переписаны.

### 1.8. Изображения характеристики и значений

Общие файловые сценарии выполнить для SVG самой характеристики и SVG значения, включая одновременные «Цвет + Иконка + Смайлик». Успешная загрузка не должна сбрасывать текст, цвет или смайлик; SVG самой характеристики — отдельное обязательное поле карточки.

- [ ] **CHR-IMG-01** — Загрузить настоящий корректный SVG в иконку характеристики и отдельно в иконку значения → файл принят, превью соответствует изображению и сохраняется после повторного открытия карточки и перезагрузки.
- [ ] **CHR-IMG-02** — У созданной характеристики без иконки попытаться сохранить редактирование → отсутствие обязательного SVG блокирует успешное завершение. После загрузки SVG и заполнения названия, RU и ENG редактирование сохраняется; активные поля значений не заменяют иконку характеристики.
- [ ] **CHR-IMG-03** — Заменить загруженный SVG другим допустимым SVG → отображается новое изображение у той же записи, количество характеристик/значений не увеличилось, прежняя картинка не возвращается после перезагрузки.
- [ ] **CHR-IMG-04** — Заменить файл другим изображением с тем же именем → видно новое содержимое, сохранение не определяется одним совпадением имени и не возвращает старое превью из кеша.
- [ ] **CHR-IMG-05** — Проверить загруженные SVG → доступна замена; отдельная очистка файла в остающемся включённым поле не предусмотрена. Корзина значения удаляет запись целиком при отсутствии использования; выключение поля «Иконка» очищает SVG-атрибуты только после предупреждения, CHR-OFF.
- [ ] **CHR-IMG-06** — По отдельности передать PNG, WEBP, JPG, JPEG, GIF, PDF и TXT → файлы отклоняются как неподдерживаемые, их нельзя засчитать обязательной SVG-иконкой. Точный текст ошибки не назначен; сообщение не должно объявлять растровые форматы разрешёнными.
- [ ] **CHR-IMG-07** — Загрузить корректные SVG больше 2 МБ, например 3 и 5 МБ, по отдельности в иконку характеристики и значения → файл не отклоняется по ограничению размера, поскольку продуктового лимита нет; не выполнять неограниченную нагрузочную генерацию.
- [ ] **CHR-IMG-08** — При замене сохранённого SVG передать неподдерживаемый формат → после отказа прежняя успешно сохранённая иконка остаётся, новый файл не считается успешно сохранённым; большой корректный SVG не является невалидным только из-за размера.
- [ ] **CHR-IMG-09** — При добавлении значения получить отказ загрузки SVG без прежней иконки → обязательное поле не считается заполненным, «+» и Enter не добавляют неполную строку даже при заполненных цвете и смайлике; корректный SVG позволяет продолжить добавление.
- [ ] **CHR-IMG-10** — Открыть выбор файла и отменить без выбора → сохранённое изображение и поля записи не изменились; последующий выбор корректного файла работает.
- [ ] **CHR-IMG-11** — После загрузки и замены сверить SVG характеристики и SVG двух значений → каждое превью относится к своей записи, файлы не перепутаны; нет повреждённого изображения или потери видимого содержимого. Оптимизация — CHR-OBS-08.

### 1.9. Удаление внутри страницы

Здесь удаляются только неиспользуемые тестовые записи. Запрет удаления при наличии хотя бы одного товара номенклатуры проверяется в отложенном блоке. Для неиспользуемого значения отдельное подтверждение пока не является согласованным требованием.

- [ ] **CHR-DEL-01** — У неиспользуемой характеристики вызвать удаление корзиной справа от строки в левом списке → до подтверждения запись существует; отменить → название, значения, SVG и режимы сохраняются после перезагрузки.
- [ ] **CHR-DEL-02** — При открытой карточке A нажать корзину B в левом списке и отменить подтверждение → A и B сохраняются, удаление не выполняется по одному открытию окна и не подменяет целевую запись открытой карточкой.
- [ ] **CHR-DEL-03** — Подтвердить удаление неиспользуемой характеристики из левого списка → она исчезает из рабочего справочника и не возвращается после перезагрузки; остальные характеристики и их данные сохранены.
- [ ] **CHR-DEL-04** — Удалить характеристику с несколькими значениями, ни одно из которых не связано с товарами → операция разрешена после подтверждения, запись и её значения больше не доступны в рабочей карточке; чужие значения не удалены. Мягкое удаление подтверждается отдельно в CHR-DEF-DATA.
- [ ] **CHR-DEL-05** — Создать несколько различимых характеристик, выбрать A и вызвать корзину B после изменения алфавитного положения B → подтверждение и фактическое удаление относятся к B, а не к прежнему индексу строки или открытой A.
- [ ] **CHR-DEL-06** — Удалить неиспользуемую характеристику, название которой совпадает с названием значения другой характеристики → удалена только характеристика по её идентификатору, одноимённое значение другого родителя сохранено.
- [ ] **CHR-DEL-07** — Удалить одно неиспользуемое значение, завершив предусмотренное интерфейсом действие → оно исчезает из списка и не возвращается после перезагрузки; характеристика, другие значения, их цвета/иконки и режимы сохранены.
- [ ] **CHR-DEL-08** — Удалить одно из нескольких разных неиспользуемых значений, затем последнее значение тестовой характеристики → другие строки сохраняются до их собственного удаления, затем допускается пустой список; родительская характеристика остаётся и позволяет добавить новое значение.
- [ ] **CHR-DEL-09** — После разрешённого удаления характеристики и отдельно значения создать новую запись с прежним названием, не занятым действующей записью своей области → создание разрешено, новая запись самостоятельна; прежние связи не восстанавливаются по тексту.

### 1.11. Сохранение, повторное открытие и ошибки

- [ ] **CHR-SAVE-01** — Для разных допустимых сочетаний полей сохранить полную карточку: уникальное название, RU/ENG, SVG характеристики и значения со всеми включёнными атрибутами → после смены карточки и перезагрузки весь набор относится к своей записи и совпадает с успешно сохранённым состоянием.
- [ ] **CHR-SAVE-02** — Изменить по одному полю в A и B, повторно открыть страницу → у каждой записи её последнее успешно сохранённое значение, одно поле не возвращает старые данные остальных полей карточки.
- [ ] **CHR-SAVE-03** — После отказа валидации повторно открыть запись → нет недопустимого длинного/пустого обязательного текста, сохранённого дубликата в запрещённой области, неверного цвета или принятого не-SVG; прежние корректные данные не повреждены.
- [ ] **CHR-SAVE-04** — Получить контролируемый отказ загрузки списка или карточки → интерфейс не выдаёт неуспешную загрузку за успешное сохранение/удаление и не применяет данные предыдущей карточки к новой. Конкретный текст и вид ошибки не назначены.
- [ ] **CHR-SAVE-05** — Получить контролируемый отказ создания/редактирования → операция не показана как успешно сохранённая; после восстановления связи и повторного открытия нет ложной сохранённой записи. Повторная корректная операция доступна; конкретные тост и локальный откат — CHR-OBS-10.
- [ ] **CHR-SAVE-06** — Получить контролируемый отказ удаления → запись не считается успешно удалённой и доступна после восстановления связи и перезагрузки; данные соседних записей сохранены.
- [ ] **CHR-SAVE-07** — Успешно сохранить корректную полную карточку после отказа валидации, уникальности, загрузки файла или сети → страница не остаётся заблокированной, новое состояние сохраняется; неудачная попытка не создала лишнюю запись.

- [ ] **CHR-SAVE-08** — Для основного названия, RU, ENG и названия значения отдельно выполнить два изменения: первое подтвердить Enter, второе кликом в пустое место → оба способа сохраняют допустимые данные после повторного открытия и перезагрузки без отдельной обязательной кнопки «Сохранить»; не путать выбор другого поля с фактическим подтверждением результата.
- [ ] **CHR-SAVE-09** — В заполненном значении при включённом «Цвет» изменить допустимый HEX сначала с подтверждением Enter, затем с кликом в пустое место → оба изменения сохраняются, цветовой образец соответствует последнему коду, остальные включённые атрибуты не переписаны.

Очистка заполненного поля после подтверждения и отсутствие восстановления старого содержимого уже проверяются в CHR-OFF.

- [ ] **CHR-OBS-10** — При задержке или отказе записи зафиксировать состояние поля, ошибку и повтор операции; проверить быстрые Enter и «+» при создании → записать защиту от повторной отправки. Последовательный намеренный повтор точного названия теперь также ограничен согласованной уникальностью.
- [ ] **CHR-OBS-11** — На тестовом справочнике удалить выбранную и последнюю характеристику → записать выбор следующей карточки/пустого состояния, фокус и возможность дальнейшего создания без требования конкретного автоматического выбора.
- [ ] **CHR-OBS-12** — При замедлении запросов быстро выбирать A/B и последовательно менять поля → записать порядок ответов и границу записи. Ответ не должен отображаться как данные другой сущности; политика одновременных записей одного поля пока не согласована.

## 3. Отложенные проверки

### 3.1. Номенклатура, товары и общий справочник

Для блока подготовить товары с несколькими характеристиками с уникальными основными названиями, несколько товаров с одной общей записью и одинаково названные значения в разных характеристиках. Использовать товары разных брендов и связок UAE × Deira, USA × Deira, UAE × Free zone и USA × Free zone. Для запрета удаления нужен хотя бы один товар номенклатуры с назначением, для разрешённого удаления — запись без назначений. Проверять результат сразу после успешной записи, открывая тот же товар в зависимом разделе.

- [ ] **CHR-DEF-NOM-01** — Создать характеристику и значение → они доступны для назначения в номенклатуре для разных стран поставки и реализаций из общего справочника; отдельная ручная копия для каждой пары не нужна.
- [ ] **CHR-DEF-NOM-02** — Назначить одну характеристику нескольким товарам разных пар и переименовать её в свободное название → новое название сразу относится ко всем связанным товарам; прежние назначения не потеряны, другая характеристика с собственными значениями не изменилась.
- [ ] **CHR-DEF-NOM-03** — Изменить название используемого значения → оно сразу обновляется у всех товаров, связанных с этой записью; текстовое совпадение с другим значением не расширяет обновление.
- [ ] **CHR-DEF-NOM-04** — Изменить заполненные RU/ENG и изображение используемой характеристики → связанные актуальные карточки товаров получают новые данные без повторного назначения характеристики; подстановка при пустом переводе в этот пункт не входит.
- [ ] **CHR-DEF-NOM-05** — При нескольких включённых полях изменить цвет, заменить SVG и изменить смайлик используемого значения → связанные актуальные товары сразу используют новый набор атрибутов этой записи, соседние значения и другие характеристики сохранены.
- [ ] **CHR-DEF-NOM-06** — Изменить одно из одинаково названных значений разных характеристик, назначенных разным товарам → обновляются только товары выбранной записи; допустимое совпадение между родителями не расширяет изменение.
- [ ] **CHR-DEF-NOM-07** — Назначить характеристику хотя бы одному товару номенклатуры и попытаться удалить её → операция заблокирована; если интерфейс предлагает подтверждение, оно не позволяет обойти запрет. Характеристика, значения и назначения товарам остаются после перезагрузки.
- [ ] **CHR-DEF-NOM-08** — После отказа удалить используемую характеристику убрать её последнюю связь с товарами и повторить удаление → теперь операция разрешена после подтверждения и выполняется мягко; наличие одних только значений без назначений не блокирует удаление.
- [ ] **CHR-DEF-NOM-09** — Назначить значение хотя бы одному товару номенклатуры и попытаться удалить → операция запрещена, значение и назначения сохраняются. Затем переименовать его в свободное название → изменение разрешено и сразу отражено у связанных товаров.
- [ ] **CHR-DEF-NOM-10** — Повторить запрет удаления для товара номенклатуры без стока и для выключенного товара → сама связь с хотя бы одним товаром продолжает блокировать удаление характеристики/значения, отсутствие продаж или активных заказов не заменяет эту проверку.
- [ ] **CHR-DEF-NOM-11** — Разрешённо удалить неиспользуемую запись и открыть назначение другому товару → удалённая запись не предлагается как действующая. Создать новую с прежним названием → новая доступна для назначения и не возвращает старые связи автоматически.
- [ ] **CHR-DEF-NOM-12** — Изменить либо удалить запись справочника, затем открыть товар, не связанный с ней → его характеристики, названия и атрибуты сохранены.
- [ ] **CHR-DEF-NOM-13** — Редактировать значение `USA` характеристики Country, а при отсутствии назначений удалить его → изменения относятся к признаку товара; страна поставки USA, её поставщики и страны реализации не удаляются и не переименовываются по совпадению текста.

- [ ] **CHR-DEF-NOM-14** — При используемом значении A удалить неиспользуемое значение B той же характеристики → B удаляется мягко, A и назначения товарам сохранены; удаление всей характеристики остаётся запрещённым из-за A.
- [ ] **CHR-DEF-NOM-15** — У значения, назначенного товарам, подтвердить выключение заполненного цвета, SVG или смайлика по отдельности → очищен только соответствующий атрибут у связанных актуальных товаров, сами записи значений и назначения сохранены, товар не удалён и его доступность продажи не переключена.
- [ ] **CHR-DEF-NOM-16** — У используемого значения попытаться сохранить название другого значения того же родителя → отказ по уникальности не теряет назначение товарам и не подставляет в них другую запись с конфликтующим названием.
- [ ] **CHR-DEF-NOM-17** — Если характеристика/значение стали использоваться в товаре после открытия окна удаления, завершить операцию → сохранённая к моменту удаления связь не позволяет удалить используемую запись; серверная проверка не ограничена устаревшим состоянием открытой страницы.

### 3.2. Клиентские и поставщицкие интерфейсы

- [ ] **CHR-DEF-APP-01** — После изменения используемых названий/атрибутов открыть актуальную карточку того же товара в приложении клиента и интерфейсе поставщика → данные соответствуют общему справочнику в местах, где они предусмотрены дизайном; другие товары не подменены.
- [ ] **CHR-DEF-APP-02** — У используемого значения подтвердить выключение одного заполненного дополнительного поля → в актуальных зависимых интерфейсах убран только очищенный атрибут, другие включённые атрибуты, названия, сами товары и их доступность продажи сохранены. Отказ удалить используемую запись не должен убирать её из товара.
- [ ] **CHR-DEF-APP-03** — После согласования мест применения ручного порядка переставить значения → проверить применение в номенклатуре, группах/фильтрах и приложениях по CHR-Q02. Сохранение порядка на самой странице уже проверяется в CHR-DRAG.
- [ ] **CHR-DEF-APP-04** — После оформления заказа изменить использованное название/атрибут либо подтвердить очистку дополнительного поля → исследовать подписи в истории по CHR-Q06. Удаление по-прежнему используемой в номенклатуре записи должно блокироваться, а не служить способом очистить историю.

### 3.3. Подтверждение мягкого удаления

Выполнять при наличии разрешённого доступа к тестовым данным/API, позволяющего проверить сохранность записей. Для разрешённого удаления брать записи без назначений товарам; отказ удалить используемые записи проверять отдельно. Исчезновение строки из активного списка само по себе не подтверждает мягкое удаление. Восстановление через интерфейс для этих проверок не требуется.

- [ ] **CHR-DEF-DATA-01** — До и после удаления характеристики сверить её идентификатор и сохранённые данные → запись сохранена как удалённая, а не уничтожена физически; рабочий справочник её не возвращает как активную.
- [ ] **CHR-DEF-DATA-02** — Аналогично удалить отдельное значение → сохранена запись того же идентификатора с признаком удаления; соседние значения и родительская характеристика не помечены удалёнными этой операцией.
- [ ] **CHR-DEF-DATA-03** — После удаления характеристики проверить сохранность относящихся к ней данных значений → мягкое удаление не заменено физическим уничтожением дочерних данных. Конкретный способ каскадной пометки не назначать без отдельного требования.
- [ ] **CHR-DEF-DATA-04** — Создать характеристику/значение с названием мягко удалённой записи → создана отдельная запись, прежний идентификатор не переиспользован как восстановление; у других действующих записей назначения сохранены.

- [ ] **CHR-DEF-DATA-05** — После запрета удалить используемую характеристику или значение сверить тестовые данные → признак удаления не установлен, назначение и дочерние записи не очищены частично; отказ операции не является мягким удалением.

### 3.4. Права доступа — весь блок отложен

Проверять после реализации ролей и согласования матрицы разрешений. Наличие обычной администраторской сессии не подтверждает ограничения других ролей.

- [ ] **CHR-DEF-ACL-01** — Для роли без доступа к разделу проверить меню и прямой переход на страницу → доступ ограничен согласно матрице, данные справочника не раскрыты обходным переходом.
- [ ] **CHR-DEF-ACL-02** — Для роли только с просмотром открыть карточки → просмотр разрешён, создание, редактирование названий и подписей, загрузка/замена SVG, все три тумблера, смайлики, очистка полей, перетаскивание и удаление не позволяют записать изменения.
- [ ] **CHR-DEF-ACL-03** — Для ролей с разными правами редактирования и удаления, настроенными в «Пользователи», проверить соответствующие действия → доступны только разрешённые операции; право редактировать не считается правом удалять, наличие права удаления не обходит проверку использования в номенклатуре.
- [ ] **CHR-DEF-ACL-04** — Повторить запрещённые операции прямыми запросами к API под ограниченной ролью → сервер не сохраняет изменения даже при обходе скрытых/заблокированных элементов интерфейса; конкретный HTTP-код определяется реализованным контрактом.
