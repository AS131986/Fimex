# Stock page checklist

Scope: Supplier LK → `Stock`

## 1. Добавление товара в сток

### 1.1. Выбор даты
- **Открыть `Add Stock` до КТ, без `admin holiday` и `supplier holiday`** → текущая дата доступна.
- **Открыть `Add Stock` после КТ / при `admin holiday` / при `supplier holiday` на текущую дату** → текущая дата недоступна.
- **Открыть `Add Stock`, когда часть ближайших дней недоступна** → показаны только доступные даты из окна продаж.
- **Выбрать дату в стартовом окне** → открывается список товаров для выбранной даты.
- **Сменить дату уже в окне выбора товара** → список товаров и состояния пересчитываются под новую дату.
- **Сменить дату в окне выбора товара с даты, где товар уже есть, на дату, где его нет** → количество/состояние товара обновляется под новую дату, старые данные не остаются.
- **Оставить `Add Stock` открытым до наступления КТ / назначения `admin holiday` / `supplier holiday`** → дата становится недоступной без refresh.
- **Попробовать добавить товар на дату, ставшую недоступной при открытой форме, или на дату вне списка доступных** → отображается ошибка, товар не добавляется.

### 1.2. Доступность товаров
- **Открыть дерево `Brand -> Model -> Specification`** → видны только товары, доступные поставщику.
- **Открыть ветку, где часть товаров недоступна** → недоступные товары скрыты.
- **Искать товар через поиск в `Add Stock`** → в результатах только товары, доступные поставщику.
- **Попробовать добавить товар без доступа через устаревшее состояние UI** → товар не добавляется.
- **Зайти под админом / `manager full` / `manager limited`** → доступны все товары, разрешенные поставщику или роли.

### 1.3. Уже добавленные товары в `Add Stock`
- **Открыть `Add Stock` на дату, где товар A уже добавлен** → у товара A отображается текущее `Q-ty`, совпадающее со значением в `Supplier Stock`.
- **Открыть `Add Stock` на дату, где товар A уже добавлен текущим пользователем, и изменить `Q-ty`** → новое количество сохраняется в `Supplier Stock`; если у записи есть `Price` — обновляется и в `Admin Stock`.
- **Открыть `Add Stock` под `manager limited` на дату, где товар A добавлен другим участником команды** → количество отображается, но `Q-ty` недоступно для редактирования.
- **Попробовать изменить количество чужого товара через inline-edit / Enter / клик вне поля** → изменение не сохраняется.
- **Изменить количество товара A другим пользователем при открытом `Add Stock`** → отображаемое `Q-ty` обновляется корректно.

### 1.4. Создание stock-entry
- **Добавить товар A с валидной датой и `Q-ty`, без `Price`** → товар появляется в `Supplier Stock`, отсутствует в продаже и отсутствует в `Admin Stock`.
- **Добавить товар A с валидной датой и `Q-ty`, затем задать `Price`** → товар появляется в продаже и в `Admin Stock`.
- **Добавить товар A и обновить страницу** → запись сохраняется и остается на выбранной дате.
- **Добавить товар A без `Price`, затем удалить `Q-ty`** → запись удаляется из `Supplier Stock`.
- **Добавить товар A с `Price`, затем удалить `Q-ty`** → запись удаляется из `Supplier Stock`, `Admin Stock` и продажи.
- **Добавить товар A на дату, где такой записи ранее не было** → на этой дате создается одна запись без дубля.
- **Добавить товар A, затем открыть вкладку даты и `ALL`** → запись отображается на выбранной дате и в `ALL`, без duplicate row.
- **Добавить товар A, затем сменить дату в окне добавления и добавить товар на другую дату** → на каждой дате создается своя запись, без лишних дублей на одной дате.
- **Добавить товар A на дату, где этот же товар уже существует у этого же поставщика** → лишняя строка не создается; если запись доступна для редактирования, обновляется существующая запись.
- **Добавить товар A на дату, где этот же товар уже существует у другого поставщика** → создается отдельная запись текущего поставщика, без объединения с чужой.

### 1.5. Добавление с учетом ролей
- **Зайти под админом и добавить товар A** → товар успешно добавляется.
- **Зайти под `manager full` и добавить товар A** → товар успешно добавляется.
- **Зайти под `manager limited` и добавить товар A, если на выбранную дату его не добавлял другой участник команды** → товар успешно добавляется.
- **Зайти под `manager limited` и попробовать добавить товар A на дату, где его уже добавил другой участник команды** → товар не добавляется.
- **Зайти под `manager limited` и добавить товар A на другую дату, где его еще не добавлял другой участник команды** → товар успешно добавляется.
- **Под `manager limited` открыть товар A, уже добавленный другим участником команды на выбранную дату** → количество может отображаться, но добавить/перезаписать такую запись нельзя.
- **Попробовать обойти ограничение `manager limited` через прямой запрос / устаревший экран** → ограничение сохраняется, запись не создается.

## 2. Редактирование товара в стоке

### 2.1. Редактирование количества
- **Товар A без `Price`, изменить `Q-ty`** → новое количество сохраняется в `Supplier Stock`, товар не появляется в `Admin Stock` и продаже.
- **Товар A с `Price`, изменить `Q-ty`** → новое количество сохраняется в `Supplier Stock`, `Admin Stock` и влияет на доступное количество в продаже.
- **Товар A с `Price`, покупатель выкупает часть количества** → `Q-ty` уменьшается в real-time.
- **Товар A с `Price`, одновременно купить часть товара и изменить `Q-ty` вручную** → итоговое количество сохраняется корректно, отрицательный остаток не появляется.
- **Товар A, быстро изменить `Q-ty` несколько раз подряд** → сохраняется последнее актуальное значение.
- **Товар A, изменить `Q-ty`** → новая строка не создается, обновляется существующая запись.
- **Товар A без `Price`, очистить `Q-ty`** → запись удаляется из `Supplier Stock`.
- **Товар A с `Price`, очистить `Q-ty`** → запись удаляется из `Supplier Stock`, `Admin Stock` и продажи.

### 2.2. Редактирование цены
- **Товар A без `Price`, задать `Price`** → товар появляется в продаже и `Admin Stock`.
- **Товар A с `Price`, изменить `Price` на большее или меньшее свободное значение** → сохраняется введенная цена, `price rank` пересчитывается.
- **Товар A с `Price`, повторно установить ту же самую цену, которая уже стоит у этой записи** → цена и `price rank` не меняются, лишние дубли и побочные эффекты не появляются.
- **Товар A с rank `№1`, увеличить `Price` и остаться с лучшей ценой** → rank остается `№1`.
- **Товар A с rank `№1`, увеличить `Price` и стать дороже лучшей цены** → rank меняется с `№1` на более низкий.
- **Товар A с rank не `№1`, уменьшить `Price`, но не стать лучшей ценой** → rank пересчитывается по новой позиции, `№1` не присваивается.
- **Товар A с rank не `№1`, уменьшить `Price` и стать лучшей ценой** → товар получает `№1`.
- **Товар A, ввести цену, уже занятую таким же товаром той же страны** → цена auto-increment до ближайшего свободного значения, сохраняется фактическое значение; отображается тост о том, что выбранная цена занята.
- **Товар A, ввести цену, когда у таких же товаров той же страны заняты несколько соседних значений** → цена auto-increment до первого свободного значения после цепочки занятых цен; отображается тост о том, что выбранная цена занята.
- **Товар A, повторно установить цену, равную его текущей цене** → запись не конфликтует сама с собой, auto-increment не срабатывает.
- **Товар A определённой страны на дате 16 уже имеет `Price = X`, попытаться установить `Price = X` для такого же товара той же страны на дате 17** → одинаковая цена не сохраняется даже на другой дате; срабатывает auto-increment до ближайшей свободной цены.
- **У конкурента уже есть такой же товар той же страны с `Price = X`, установить товару A `Price = X`** → сохраняется ближайшая свободная цена по правилу auto-increment.
- **Товар A с `Price`, удалить `Price`** → товар остается в `Supplier Stock`, исчезает из `Admin Stock` и продажи.
- **Товар A, изменить `Price`** → новое значение и `price rank` одинаково отображаются в `Supplier Stock`, `Admin Stock`, Buyer app.
- **Товар A, изменить `Price` без refresh страницы** → rank, лучшая цена и видимость в продаже обновляются корректно.
- **Товар A, изменить `Price`, затем оформить покупку** → цена в заказе клиента, поставщика и админа сохраняется корректно.
- **Товар A, удалить `Price`, затем снова установить прежнее значение, если цена свободна** → товар снова появляется в продаже и `Admin Stock`, auto-increment не срабатывает.
- **Товар A, удалить `Price`, затем снова установить прежнее значение, если цена занята таким же товаром той же страны** → срабатывает auto-increment, сохраняется ближайшая свободная цена, отображается тост.
- **Два пользователя одновременно устанавливают цену X одинаковым товарам одной страны** → для второго сохранения срабатывает auto-increment, итоговые цены внутри страны не конфликтуют.

### 2.3. Перенос между датами
- **Товар A без `Price`, перенести на другую доступную дату** → товар остается в `Supplier Stock`, не появляется в `Admin Stock` и продаже.
- **Товар A с `Price`, перенести на другую доступную дату** → товар исчезает со старой даты, появляется на новой дате в `Supplier Stock`, `Admin Stock` и продаже по правилам видимости.
- **Попробовать перенести товар A на дату после КТ / с `admin holiday` / с `supplier holiday`** → перенос не выполняется.
- **Перенести товар A вперед или назад между доступными датами без merge и изменения цены** → `Code`, `Description of Goods`, `Q-ty`, `Price`, rank и hover сохраняются; видимость в продаже пересчитывается по новой дате.
- **Перенести товар A на дату, где у того же поставщика уже есть идентичный товар той же страны** → лишняя строка не создается; итоговая цена остается меньшей из двух; итоговое `Q-ty` остается как у записи на целевой дате.
- **Перенести товар A на дату, где идентичный товар той же страны есть у другого поставщика** → перенос выполняется без merge; обе записи сохраняются.
- **Товар A на ранней дате дешевле, чем такой же товар той же страны на поздней дате у того же поставщика, выполнить перенос с merge** → сохраняется меньшая цена по бизнес-правилу.
- **Товар A на ранней дате дороже, чем такой же товар той же страны на поздней дате у того же поставщика, выполнить перенос с merge** → сохраняется меньшая цена по бизнес-правилу.
- **Товар A на ранней дате дешевле, чем такой же товар той же страны у конкурента на поздней дате, выполнить перенос без merge** → цены и rank сохраняются, видимость в продаже пересчитывается по новой дате.
- **Товар A на ранней дате дороже, чем такой же товар той же страны у конкурента на поздней дате, выполнить перенос без merge** → цены и rank сохраняются, видимость в продаже пересчитывается по новой дате.
- **Внутри одной страны товар A на дальней дате дешевле после manual/auto-move** → Buyer app отображает оба товара.
- **Внутри одной страны товар A на ближней дате дешевле после manual/auto-move** → товар на дальней дате скрывается.
- **Перенести `Australia = 100` на дату с `Brazil = 100`** → записи не объединяются, auto-increment не срабатывает; оба товара имеют rank `№1` и выводятся как лучшие офферы своих стран.
- **Перенести `Australia = 100` на дату с `Brazil = 101`** → записи не объединяются; Australia получает rank `№1`, Brazil — rank `№2`, оба товара выводятся как лучшие офферы своих стран.
- **Перенести `Australia = 101` на дату, где другой поставщик имеет такой же `Australia = 100`** → записи не объединяются, цены остаются 100 и 101; товар с ценой 100 имеет rank `№1` и выводится, у товара с ценой 101 rank `№2`, он не выводится на той же дате, а hover показывает 100.
- **Перенести `Australia = 100` на дату, где другой поставщик имеет такой же `Australia = 101`** → записи не объединяются, цены и rank остаются 100/`№1` и 101/`№2`; после переноса выводится оффер 100, hover оффера 101 по-прежнему показывает 100.
- **Перенести товар на дату, где у того же поставщика уже есть идентичный товар той же страны** → записи объединяются по правилу merge: остаётся меньшая цена, `Q-ty` берётся у целевой записи.
- **Перенести товар на дату, где у того же поставщика есть такой же товар другой страны** → записи не объединяются; цена, rank и hover перенесённого товара сохраняются, вывод пересчитывается отдельно внутри каждой страны по датам.
- **Внутри одной страны после переноса более дорогой оффер оказывается на более поздней дате** → поздний дорогой оффер не выводится в Buyer app.
- **Внутри одной страны после переноса более дорогой оффер оказывается на более ранней дате** → ранний дорогой и поздний дешёвый офферы выводятся в Buyer app.
- **Перенести товар без merge и изменения цены** → rank и hover не меняются, поскольку дата не участвует в их расчёте.
- **После переноса с merge состав или минимальная цена общей группы изменились** → rank и hover оставшихся записей пересчитываются; у rank `№1` hover отсутствует, у остальных показывается новая глобальная лучшая цена.
- **Перенести товар A между датами** → rank изменяется только при merge или изменении состава/цены группы, но не из-за самой даты.
- **Перенести товар A между датами** → в `Supplier Stock`, `Admin Stock`, Buyer app не появляются некорректные дубли.
- **Дождаться КТ / установить `admin holiday` / установить `supplier holiday` для даты товара A** → товар автоматически переносится на следующий доступный день.
- **Автоперенос товара A** → старая дата очищается, новая дата отображает запись без дубля.
- **Автоперенос товара A без `Price`** → товар остается только в `Supplier Stock`.
- **Автоперенос товара A с `Price`** → товар корректно отображается в `Supplier Stock`, `Admin Stock`, продаже.
- **Автоперенос товара A на дату, где уже есть идентичный товар той же страны и того же поставщика** → сохраняется меньшая цена, лишняя строка не создается, итоговое `Q-ty` остается как у записи на целевой дате.
- **Товар A одной страны на датах 16 и 17 у одного поставщика, после auto-move запись с 16 переносится на 17** → выполняется merge, остается товар с меньшей ценой.
- **Товар A у текущего поставщика на 16 дешевле или дороже, чем такой же товар той же страны у конкурента на 17, выполнить auto-move без merge** → rank и hover сохраняются, видимость в продаже пересчитывается по дате.
- **Автоперенести `Australia = 100` на дату с `Brazil = 100`** → auto-increment и merge между странами не срабатывают; оба товара имеют rank `№1` и выводятся.
- **Автоперенести `Australia = 100` на дату с `Brazil = 101`** → Australia получает rank `№1`, Brazil — rank `№2`; оба остаются в продаже как лучшие офферы своих стран.
- **Автоперенести товар на дату с идентичным товаром того же поставщика и той же страны** → применяется подтверждённое правило merge без дубля.
- **Автоперенести товар на дату с таким же товаром того же поставщика, но другой страны** → merge не выполняется; обе записи сохраняются отдельно.
- **После auto-move без merge и изменения цены** → rank и hover не меняются; пересчитывается только видимость по дате.
- **После auto-move с merge изменилась минимальная цена или состав общей группы** → rank и hover пересчитываются по итоговым записям.
- **Автоперенос товара A** → в `Supplier Stock`, `Admin Stock`, Buyer app не появляются некорректные дубли.

### 2.4. Удаление цены / количества
- **Товар A с `Price`, удалить `Price`** → `stock-entry` остается в `Supplier Stock`, исчезает из `Admin Stock` и продажи.
- **Товар A без `Price`, удалить `Q-ty`** → запись удаляется из `Supplier Stock`, не остается в `Admin Stock` и Buyer app.
- **Товар A с `Price`, удалить `Q-ty`** → запись удаляется из `Supplier Stock`, `Admin Stock` и Buyer app.
- **Удалить `Q-ty` у товара A** → редактировать удаленную запись без повторного добавления нельзя.
- **Удалить `Q-ty` у товара A** → пустая или дублирующая строка не остается.
- **Удалить `Price` или `Q-ty` у товара A** → вкладки и списки обновляются без stale data и дублей.

### 2.5. Ошибки и stale state
- **Открыть редактирование товара A и дождаться КТ / назначить `admin holiday` / назначить `supplier holiday` на его дату** → при сохранении отображается ошибка `invalid date`.
- **Открыть редактирование товара A, дождаться auto-move и сохранить старую запись** → отображается ошибка `invalid date`.
- **Получить ошибку из-за stale-state** → причина ошибки понятна: КТ / holiday / перенос / дата недоступна.
- **Получить ошибку из-за stale-state** → UI дает актуальное состояние записи или корректно обновляется.

### 2.6. Конкурентные изменения
- **Два пользователя одного поставщика одновременно меняют `Q-ty` товара A** → не создаются дубли, отрицательный остаток не появляется, после конфликта UI показывает актуальные данные.
- **Два пользователя одного поставщика одновременно меняют `Price` товара A** → итоговые цены не конфликтуют, лишняя строка не создается, после конфликта UI показывает актуальные данные.
- **Один пользователь переносит товар A, второй в это время редактирует его** → устаревшее сохранение не затирает более новую версию записи; UI показывает актуальные данные.
- **Открыть форму редактирования товара A и в это время пройти КТ / назначить holiday** → сохранение обрабатывается корректно.
- **После конфликтного сохранения товара A** → UI показывает актуальные данные, а не устаревшую локальную версию.

## 3. Список стока

### 3.1. Отображение по вкладкам дат
- **Товар A только на дате 16** → виден во вкладке `16` и `ALL`, отсутствует в других датах.
- **Товар A на датах 16 и 17** → запись `16` видна во вкладке `16`, запись `17` во вкладке `17`, обе записи видны в `ALL`.
- **Перенести товар A с 16 на 17 / выполнить auto-move** → запись исчезает со старой даты, появляется на новой, в `ALL` отображается только актуальное состояние.
- **Открыть вкладку конкретной даты** → видны только товары этой даты.
- **Открыть вкладку `ALL`** → видны товары по всем датам.

### 3.2. Товар без Price
- **Товар A имеет `Q-ty`, но не имеет `Price`** → товар виден в `Supplier Stock`, отсутствует в `Admin Stock` и Buyer app.
- **Изменить `Q-ty` или перенести товар A без `Price`** → товар остается только в `Supplier Stock`.
- **Удалить `Price` у товара A** → товар остается в `Supplier Stock`, исчезает из `Admin Stock` и Buyer app.

### 3.3. Рейтинг цены и hover на Price
- **Товар A имеет рейтинг `№1`** → у товара отображается `№1`.
- **Товар A имеет рейтинг не `№1`** → у товара отображается фактический rank.
- **`Australia = 100` имеет rank `№1`, `Brazil = 101` имеет rank `№2`; навести на `Price` Brazil** → hover показывает лучшую цену `100`, хотя она относится к другой стране.
- **`Australia = 100` и `Brazil = 100` имеют rank `№1`; навести на `Price` любого товара** → hover с лучшей ценой не отображается.
- **`Australia = 100`, `Brazil = 101`, `USA = 102`; навести на `Price` Brazil и USA** → hover обоих товаров показывает актуальную лучшую цену `100` общей таргетинговой группы.
- **Два товара одной страны имеют цены 100 и 101; навести на `Price` товара с rank не `№1`** → hover показывает лучшую цену `100`.
- **Товар с rank не `№1` является лучшим оффером своей страны и выводится в Buyer app; навести на его `Price` в Supplier Stock** → hover всё равно показывает глобальную лучшую цену общей таргетинговой группы.
- **Товар A имеет rank не `№1`, навести курсор на `Price`** → показывается лучшая цена только внутри его общей таргетинговой группы.
- **Товар A имеет rank `№1`, увеличить `Price` и потерять лучшую цену** → rank меняется с `№1`, при hover показывается новая лучшая цена.
- **Товар A имеет rank не `№1`, уменьшить `Price` до лучшей цены** → товар получает `№1`, rank остальных пересчитывается.
- **Товар A имеет rank не `№1`, уменьшить `Price`, но не до лучшей** → rank пересчитывается по новой позиции, `№1` не присваивается.
- **Конкурент снижает цену ниже `Price` товара A с rank `№1`** → rank меняется, товар теряет `№1`.
- **Конкурент с более дешевой ценой удаляет `Price`** → rank товара A пересчитывается, возможно присвоение `№1`.
- **Товар A на дате 16 и такой же товар A на дате 17, меняется цена одной из записей** → rank обеих записей пересчитывается с учетом cross-date конкуренции.
- **Товар A, повторно установить ту же самую цену** → rank не меняется, hover с лучшей ценой не меняется, лишние побочные эффекты не появляются.
- **Товар A имеет rank `№1`, навести курсор на `Price`** → hover с лучшей ценой не отображается.
- **Товар A имеет rank не `№1`, навести курсор на `Price` после изменения своей цены или цен конкурентов** → в hover показывается актуальная лучшая цена.
- **Удалить `Price` у текущего лидера общей группы** → rank остальных пересчитывается; hover показывает новую лучшую цену, а у нового rank `№1` не отображается.
- **Перенести текущего лидера на другую дату без merge и изменения цены** → rank и hover общей группы не меняются; пересчитывается только видимость в продаже.
- **После manual/auto-move с merge товар меняет rank с `№1` на более низкий** → hover появляется и показывает актуальную лучшую цену.
- **После manual/auto-move с merge товар получает rank `№1`** → ранее отображавшийся hover с лучшей ценой исчезает.
- **Товар отличается памятью, цветом или другой таргетинговой характеристикой; навести на `Price`** → tooltip не показывает цену товара из другой группы.
- **Повторно навести на `Price` после real-time изменения лидирующей цены** → hover не содержит устаревшее значение.

### 3.4. Дубли товаров
- **Добавить товар A в stock** → в `Supplier Stock` отображается одна запись товара на выбранную дату.
- **Перенести товар A или автоперенести его на дату, где такого товара ранее не было** → на новой дате одна запись, на старой записи нет.
- **Перенести товар A или автоперенести его на дату, где у того же поставщика уже есть идентичный товар той же страны** → система не создает лишнюю строку; итоговая цена остается меньшей из двух; итоговое `Q-ty` остается как у записи на целевой дате.
- **Изменить `Price` / `Q-ty` / повторно установить ту же цену у товара A** → duplicate row не появляется.
- **Удалить `Price` у товара A** → товар не дублируется в `Supplier Stock`, исчезает из `Admin Stock` и Buyer app.
- **Удалить `Q-ty` у товара A** → запись полностью исчезает, пустой или дублирующей строки не остается.
- **Товар A и конкурентный товар A на разных датах, меняются цены** → в Buyer app не появляются дубли сверх ожидаемой логики отображения по цене и дате.
- **Товар A у одного поставщика на двух датах, меняются цены** → в Buyer app не появляются дубли сверх ожидаемой логики отображения по цене и дате.
- **Открыть `ALL` после нескольких изменений одной записи / переключаться между вкладками дат после переноса** → отображается только актуальное состояние записи, старые версии строки не появляются.
- **Открыть вкладку `ALL` после auto-move товара A** → запись отображается только на новой дате, ghost-строка на старой дате отсутствует.

### 3.5. Сортировка
- **Открыть вкладку даты или `ALL`** → товары идут в порядке, настроенном в номенклатуре.
- **Добавить новый товар / изменить `Q-ty` / изменить `Price` / перенести товар / автоперенести товар** → порядок списка остается согласованным с номенклатурой.

## 4. Автопереносы и календарные правила

### 4.1. КТ / holidays
- **После КТ попытаться добавить или перенести товар на текущую дату** → операция запрещена.
- **Назначить `admin holiday` или `supplier holiday` на дату** → add/move на эту дату недоступны.
- **Оставить товар на дате до КТ / назначить holiday на дату с существующими товарами** → товар автоматически переносится на следующий доступный день.
- **Оставить на дате товар с `Price` и без `Price`** → auto-move срабатывает для обоих вариантов.
- **После КТ / holiday выполнить действие по старой записи** → stale-операция отклоняется.
- **После КТ товар A переносится на следующую доступную дату, где другой поставщик имеет более дешёвый идентичный товар той же страны** → merge не выполняется; дорогой оффер не выводится на одной дате.
- **После КТ товар A переносится через несколько недоступных дат на первую доступную дату, где у того же поставщика уже есть идентичный товар той же страны** → выполняется merge без отдельной строки; сохраняется меньшая цена и `Q-ty` целевой записи.


### 4.2. Последовательные переносы
- **Следующий день доступен** → товар переносится на ближайший следующий день.
- **Следующий день недоступен, доступен через день или позже** → товар переносится на первую доступную дату.
- **После цепочного переноса открыть вкладки пропущенных дат** → на промежуточных недоступных датах запись не появляется.

### 4.3. Fallback при несработавшем real-time
- **UI еще показывает товар на старой дате после auto-move, изменить `Price` / `Q-ty` / дату** → отображается ошибка `invalid date`.
- **После ошибки stale-state обновить экран** → отображается актуальное состояние товара.
- **Наступает КТ / holiday, но auto-move не выполняется из-за технического сбоя** → товар не дублируется между датами, ghost-строка не появляется, итоговое состояние записи в `Supplier Stock` однозначно.
- **Auto-move не выполнился из-за технического сбоя для товара с `Price`** → `Admin Stock` и Buyer app не показывают вторую или конфликтующую версию записи.
- **UI ещё показывает товар на старой дате после auto-move, а на новой дате уже есть более дешёвый конкурент** → после обновления экрана видимость пересчитывается по актуальной дате и цене.


## 5. Таргетирование и ценовая конкуренция

### 5.1. Правила группировки товаров
- **Сравнить `iPhone 13 128 GB Midnight Australia` и `iPhone 13 128 GB Midnight Brazil`** → товары входят в общую группу расчёта rank; при выводе лучшие офферы определяются отдельно для каждой страны.
- **Сравнить `iPhone 14 256 GB Green Brazil` и `iPhone 14 256 GB Green USA`** → rank рассчитывается совместно, но уникальность цены и отбор офферов для продажи выполняются отдельно внутри каждой страны.
- **Сравнить `iPhone 14 256 GB Green Brazil` и `iPhone 14 512 GB Green Brazil`** → товары не конкурируют.
- **Сравнить `iPhone 14 256 GB Green Brazil` и `iPhone 14 256 GB Red Brazil`** → товары не конкурируют.
- **Сравнить товары с одинаковыми характеристиками, кроме страны, на разных датах или у разных поставщиков** → rank рассчитывается в общей группе; auto-increment и отбор офферов по цене/дате выполняются внутри каждой страны.
- **Товар A на датах Today / Tomorrow / +2 / +3 имеет цены 100 / 90 / 80 / 70** → в Buyer app видны все четыре оффера, потому что каждая более поздняя дата дешевле предыдущей и не нарушает правило видимости.


### 5.2. Уникальность цены и auto-increment
- **`iPhone 13 128 GB Midnight Australia` имеет `Price = 100`, установить `Price = 100` для `iPhone 13 128 GB Midnight Brazil`** → обе цены сохраняются без auto-increment и тоста; оба товара получают rank `№1` и выводятся в продаже.
- **Сначала установить `Brazil = 100`, затем `Australia = 100`** → результат не зависит от порядка: обе цены сохраняются, оба товара получают rank `№1` и выводятся.
- **Установить `Australia = 100`, `Brazil = 100`, `USA = 100`** → все цены сохраняются без auto-increment; все товары получают rank `№1`, лучшие офферы всех стран выводятся.
- **`iPhone 13 128 GB Midnight Australia` имеет `Price = 100`, установить `Price = 101` для `iPhone 13 128 GB Midnight Brazil`** → цена сохраняется без auto-increment; Australia получает rank `№1`, Brazil — rank `№2`; оба выводятся как лучшие офферы своих стран.
- **Установить `Australia = 100`, `Brazil = 101`, `USA = 102`** → rank равен `№1`/`№2`/`№3`; auto-increment между странами не срабатывает, лучший оффер каждой страны выводится.
- **Изменить `Brazil` с 101 на 100 при `Australia = 100`** → цена сохраняется без auto-increment; оба товара получают rank `№1` и выводятся.
- **Изменить `Brazil` со 100 на 101 при `Australia = 100`** → Brazil получает rank `№2`, но продолжает выводиться как лучший оффер своей страны.
- **Два одинаковых товара одной страны имеют попытку сохранить одинаковую цену** → для второй записи срабатывает auto-increment до ближайшей свободной цены и отображается тост.
- **У одинаковых товаров одной страны занята цепочка соседних цен** → auto-increment выбирает первое свободное значение внутри этой страны.
- **У Australia заняты 100/101/102, установить `Brazil = 100`** → Brazil сохраняет 100; цепочка Australia не влияет на другую страну.
- **Цена X занята только таким же товаром другой страны** → цена X сохраняется без auto-increment и без тоста.
- **Цена X занята таким же товаром и той же страны** → сохраняется ближайшая свободная цена, пользователь видит фактически сохранённое значение, rank рассчитывается по нему.
- **Повторно установить товару A ту же самую цену** → собственная запись не считается конфликтом сама с собой, auto-increment не срабатывает и rank не меняется.
- **Удалить `Price = X`, затем установить X другому такому же товару той же страны** → цена X сохраняется без auto-increment, если больше не занята внутри страны.

### 5.3. Конкуренция между датами
- **`iPhone 13 128 GB Midnight Australia = 100` на ближней дате и `iPhone 13 128 GB Midnight Brazil = 101` на дальней** → оба товара выводятся: каждый является лучшим оффером своей страны; Australia имеет rank `№1`, Brazil — rank `№2`.
- **`iPhone 13 128 GB Midnight Australia = 101` на ближней дате и `iPhone 13 128 GB Midnight Brazil = 100` на дальней** → оба товара выводятся: каждый является лучшим оффером своей страны; Brazil имеет rank `№1`, Australia — rank `№2`.
- **Внутри одной страны товар A на более дальней дате дешевле, чем на ближней** → в продаже отображаются оба товара с датами.
- **Внутри одной страны товар A на более ближней дате дешевле, чем на дальней** → товар на дальней дате скрывается из продажи.
- **Внутри одной страны два товара находятся на одной дате** → в продаже выводится оффер с лучшей ценой этой страны.
- **Внутри одной страны товар A на трёх и более датах образует ценовой каскад: ближняя дата дороже, следующая дешевле, ещё следующая дешевле** → отображаются офферы, не уступающие другому офферу одновременно по цене и сроку; оффер, который дороже и доступен позже другого, скрывается.
- **Australia Today/Tomorrow/+2 имеет цены 100/110/90** → Tomorrow = 110 скрывается; Today = 100 и +2 = 90 выводятся.
- **Изменить или удалить `Price` у товара A на одной дате** → видимость такого же товара на других датах пересчитывается.
- **Повторно установить ту же цену товара A на одной из дат** → логика видимости между датами не меняется, если фактическая цена не изменилась.


### 5.4. Конкуренция между поставщиками
- **Разные поставщики выставили `iPhone 13 128 GB Midnight Australia = 100` и `iPhone 13 128 GB Midnight Brazil = 100`** → обе цены сохраняются, оба товара получают rank `№1` и выводятся в продаже.
- **Разные поставщики выставили `iPhone 13 128 GB Midnight Australia = 100` и `iPhone 13 128 GB Midnight Brazil = 101`** → Australia получает rank `№1`, Brazil — rank `№2`; auto-increment не срабатывает.
- **Одинаковые товары одной страны у двух поставщиков имеют разные цены** → rank рассчитывается в общей группе со всеми таргетирующимися странами; в продажу проходит лучший оффер страны с учётом правил даты.
- **Изменить цену товара одного поставщика** → rank таргетирующихся товаров других поставщиков пересчитывается.
- **Установить цену, уже используемую другим поставщиком для такого же товара той же страны** → срабатывает auto-increment.
- **Установить цену, уже используемую другим поставщиком для такого же товара другой страны** → цена сохраняется без auto-increment.

## 6. Отображение в Admin Stock и Buyer app

### 6.1. Supplier LK vs Admin Stock
- **Товар A без `Price` / после задания `Price` / после удаления `Price`** → отображение в `Admin Stock` соответствует правилам участия в продаже.
- **Изменить `Price`, `Q-ty` или дату товара A** → изменения одинаково отражаются в `Supplier Stock` и `Admin Stock`.
- **Удалить `Q-ty` у товара A** → запись исчезает из обоих контуров.
- **Автоперенести товар A** → в `Admin Stock` не остается дубля со старой даты.
- **Перенести товар A на дату, где у того же поставщика уже есть идентичный товар той же страны** → в `Supplier Stock` и `Admin Stock` отображается одна итоговая запись с `Q-ty` целевой даты.
- **Изменить `Price` и затем купить товар** → в заказе поставщика и в заказе админа сохраняется корректная цена.

### 6.2. Supplier LK vs Buyer app
- **Товар A без `Price` / с `Price`** → отображение в Buyer app соответствует правилам таргетирования и участия в продаже.
- **Внутри одной страны более дальняя дата дешевле / более ближняя дата дешевле** → Buyer app показывает оба товара или скрывает дальний оффер согласно правилу; лучшие офферы других стран не затрагиваются.
- **Изменить `Price` / повторно установить ту же цену / перенести товар A** → Buyer app обновляет отображение без ложных изменений и дублей.
- **Удалить `Price` или `Q-ty` у товара A** → товар исчезает из Buyer app.
- **Перенести товар A на дату, где у того же поставщика уже есть идентичный товар той же страны** → Buyer app не получает дубль; количество остается согласованным с итоговой записью.
- **Изменить `Price` и затем купить товар** → в заказе клиента сохраняется корректная цена.

### 6.3. Best offer / Top 3
- **На одной дате доступны `iPhone 13 128 GB Midnight Australia = 100` и `iPhone 13 128 GB Midnight Brazil = 100`** → оба товара имеют rank `№1` и оба выводятся в продаже как лучшие офферы своих стран.
- **На одной дате доступны `iPhone 13 128 GB Midnight Australia = 100` и `iPhone 13 128 GB Midnight Brazil = 101`** → Australia имеет rank `№1`, Brazil — rank `№2`; оба товара выводятся как лучшие офферы своих стран.
- **На одной дате доступны два Australia с ценами 100 и 101 и Brazil с ценой 102** → в продаже выводятся Australia = 100 и Brazil = 102; Australia = 101 не выводится, хотя его rank выше rank товара Brazil.
- **Внутри одной страны более поздний оффер дороже более раннего** → поздний оффер не выводится.
- **Внутри одной страны более ранний оффер дороже более позднего** → выводятся оба оффера.
- **По товару нет исключения ближней/дальней даты** → в Buyer app отображается один оффер по правилам таргетирования.
- **Более дешевая цена относится к более дальней дате, где по правилу должны быть видны оба оффера** → Buyer app отображает оба оффера.
- **Открыть экран покупки товара** → покупатель видит `top 3 prices` только для даты выбранного товара.
- **Открыть `top 3 prices`** → купить можно только товар по лучшей цене; покупка по второй или третьей цене недоступна.
- **Сравнить rank в `Supplier Stock` и порядок офферов в Buyer app** → данные не противоречат друг другу в пределах правил таргетирования и выбранной даты.

### 6.4. Дубли и расхождения между контурами
- **Изменить `Price` / повторно установить ту же цену / перенести товар / автоперенести товар** → в Buyer app и `Admin Stock` не появляются некорректные дубли.
- **Оффер скрыт в Buyer app правилом цены/даты внутри своей страны** → он не отображается как активный оффер в `Admin Stock`; лучшие офферы других стран остаются в продаже.
- **Повторно установить товару A ту же `Price`** → Buyer app и `Admin Stock` не теряют синхронизацию: товар не исчезает из продажи, состояние не сбрасывается.
- **Серия действий `add -> price change -> move -> holiday move -> выкуп`** → итоговое состояние одинаково в `Supplier Stock`, `Admin Stock`, Buyer app.

## 7. Роли и доступы

### 7.1. Видимость
- **Зайти под админом / `manager full` / `manager limited`** → видимость stock entries соответствует роли.
- **Зайти под `manager limited` и открыть список после refresh / поиска / фильтрации** → чужие записи не становятся видимыми.

### 7.2. Добавление
- **Админ или `manager full` добавляет товар A** → операция разрешена.
- **`manager limited` добавляет товар A, если на выбранную дату его не добавлял другой участник команды** → операция разрешена.
- **`manager limited` добавляет товар A, если на выбранную дату его уже добавил другой участник команды** → операция запрещена.
- **Попробовать выполнить запрещенное добавление через прямой запрос** → server-side ограничение сохраняется.

### 7.3. Редактирование
- **Админ / `manager full` редактирует товар** → операция разрешена.
- **`manager limited` редактирует свой товар** → операция разрешена.
- **`manager limited` редактирует чужой товар через UI или API** → операция запрещена.
- **`manager limited` пытается изменить у чужого товара `Q-ty`, `Price` или дату** → операция запрещена.

### 7.4. Особенности `manager limited` в Add Stock
- **Открыть `Add Stock` на дату, где другой участник команды уже добавил товар A** → количество может отображаться.
- **Открыть `Add Stock` на ту же дату под `manager limited`** → редактировать чужое количество нельзя.
- **Открыть `Add Stock` на другую дату, где другой участник команды товар A не добавлял** → количество чужой записи не отображается.
- **Видеть количество чужого товара в `Add Stock`** → это не дает возможности добавить/перезаписать чужую запись.

## 8. Валидации и boundary values

### 8.1. Количество
- **Установить минимально допустимое `Q-ty`** → значение сохраняется.
- **Установить очень большое `Q-ty`** → значение либо сохраняется, либо ограничивается по бизнес-правилу, без частичного сохранения.
- **Установить `Q-ty = 0` / очистить `Q-ty`** → запись удаляется из `Supplier Stock`.
- **Установить отрицательное / дробное / нечисловое `Q-ty`** → значение не сохраняется.
- **Ввести в `Q-ty` пробелы / leading zeros / невалидный paste** → система корректно валидирует ввод.

### 8.2. Цена
- **Установить минимально допустимый `Price`** → значение сохраняется.
- **Установить очень большой `Price`** → значение либо сохраняется, либо ограничивается по бизнес-правилу, без частичного сохранения.
- **Установить `Price = 0`** → товар снимается с продажи; поле цены возвращается к значению по умолчанию, `0` не отображается; запись остается в `Supplier Stock` и исчезает из `Admin Stock` и Buyer app.
- **Очистить `Price`** → товар остается в `Supplier Stock`, исчезает из `Admin Stock` и Buyer app.
- **Установить отрицательный / дробный / нечисловой `Price`** → значение не сохраняется.
- **Ввести в `Price` пробелы / leading zeros / невалидный paste** → система корректно валидирует ввод; дробный `Price` не сохраняется.

### 8.3. Ошибки валидации
- **Ввести невалидные данные в `Q-ty` или `Price`** → сообщение об ошибке понятно и указывает проблемное поле.
- **Ввести невалидные данные и попытаться сохранить запись** → частичное сохранение не происходит.
- **Получить ошибку валидации в одном поле** → корректные данные в других полях не теряются.
- **Проверить одно и то же невалидное значение через UI и API** → client-side и server-side валидации не противоречат друг другу.

## 9. Real-time and synchronization

### 9.1. Внешние обновления
- **Покупатель выкупает часть товара A** → `Q-ty` уменьшается в real-time.
- **Наступает КТ / админ или поставщик назначает holiday для даты товара A** → товар переносится в real-time.
- **Конкурент меняет цену одинакового товара** → rank, лучшая цена и видимость товара в продаже пересчитываются в real-time.

### 9.2. Stale state
- **Открыть форму редактирования товара A, затем другой пользователь меняет запись / происходит auto-move / выкуп** → устаревшее состояние обрабатывается корректно.
- **Сохранить запись по устаревшему состоянию** → более новые данные не затираются.

### 9.3. Серии событий
- **Товар A: add -> set `Price` -> частичный выкуп -> change `Price` -> move** → итоговое состояние корректно во всех контурах.
- **Товар A: add -> holiday -> auto-move -> edit** → итоговое состояние корректно во всех контурах.
- **Товар A: два пользователя почти одновременно меняют запись** → итоговое состояние корректно во всех контурах.
- **Товар A: открыт экран редактирования, конкурент меняет цену** → итоговое состояние и rank корректны во всех контурах.
