# Чек-лист: Управление активной P2P-заявкой — все роли

## Область и статус

[Экран](../../03-screens/p2p/p2p-active-request.md) · [Правила и вопросы](../../04-business-rules/p2p-active-request.md). Создание имеет [отдельный чек-лист](../home/checklist-p2p-request.md).

Все `[ ]` — **Not run**, не Fail. Приложение/заявки/финансовые операции не проверялись. Неизвестные ожидания **Blocked**. ID стабильны.

## Подготовка данных

- Клиент/связанные корповые аккаунты, два реселлера и чужая группа; разрешённый доступ поставщика/админа для событий, иначе соответствующий пункт Blocked.
- Заявки с разными датами оформления/ценами/количествами, без ответа и со встречным; товар с гарантией/без неё, с флагом/без флага, положительная наценка реселлера.
- Средства: достаточный/недостаточный свободный остаток, уже занятый резерв конкретной заявки, иные занятые суммы; собственные средства реселлера и общие клиента/корпа.
- Успешные покупки по двум инициаторам, удалённые/истёкшие, отсутствие успешной Истории года; финансовые эффекты сверять по разрешённому источнику, не только toast.

## Вход, доступ и данные

- [ ] **P2PACT-OPEN-01** — Открыть строку списка: выбран P2P Chat, правильные дата/название/флаг либо иконка и текущая сохранённая активная заявка.
- [ ] **P2PACT-OPEN-02** — Повторное открытие того же неизменного товара из прайса показывает эту же активную заявку, не создаёт новую и не резервирует повторно.
- [ ] **P2PACT-SCOPE-01** — Клиент редактирует/принимает/удаляет общую заявку корпа и наоборот; общие лимит/депозит, без отдельного лимита корпа.
- [ ] **P2PACT-SCOPE-02** — Реселлер управляет только своей заявкой; клиент/корп и другой реселлер не могут открыть её через свою область.
- [ ] **P2PACT-DATA-01** — До ответа поставщик — прочерк, количество/«Моя цена» сохранённые; кнопка принятия встречного предложения не появляется без него.
- [ ] **P2PACT-DATA-02** — После ответа показана встречная цена и «Подтвердить», собственная цена не заменена встречной без успешного согласованного действия.
- [ ] **P2PACT-DATA-03** — Количество вида n / n — запрошенное / предложенное; поставщик не может изменить количество, частичная покупка не выводится из этого формата.
- [ ] **P2PACT-DATA-04** — Tap по дате открывает окно даты/времени/иконки как покупки; tap названия — описание этого товара как заказа, без создания новой заявки.
- [ ] **P2PACT-DATA-05** — Дата наследует дату поставщика + дни доставки; точный КТ/часовой пояс и вложенные поля — P2P-Q08 / BUY-Q08.
- [ ] **P2PACT-PRICE-01** — Клиент/корп видят обе цены без клиентской наценки; реселлер обе цены и гарантийные варианты с установленным клиентом процентом.
- [ ] **P2PACT-PRICE-02** — Смена настройки процента во время активной заявки/округление: **Blocked, P2PACT-Q03**; не приравнивать фиксацию к цене уже купленного заказа.

## Ввод и сохранение

- [ ] **P2PACT-EDIT-01** — Tap «Моя цена» открывает ввод цены с клавиатурой; «Изменить цену» открывает тот же ввод.
- [ ] **P2PACT-EDIT-02** — Tap количества открывает ввод количества; «Изменить кол-во» открывает тот же ввод, не новую заявку.
- [ ] **P2PACT-EDIT-03** — Поменять ввод без «Продолжить»: сохранённая заявка/резерв не изменились, ввод не считается успешно сохранённым.
- [ ] **P2PACT-EDIT-04** — Валидное изменение сохраняется только через «Продолжить», новые значения отражаются в открытой заявке и списке в real-time.
- [ ] **P2PACT-PRICE-03** — Минимум цены floor(P × 0,9975); для P=1293 минимум 1289 допустим, 1288.99 ниже минимума не сохраняется.
- [ ] **P2PACT-PRICE-04** — Цена до 5 целых + 2 дробных цифр, максимум 99999.99 при допустимом минимуме; шестая целая/третья дробная не добавляются. Вставка/запятая — P2P-Q01.
- [ ] **P2PACT-QTY-01** — 49 не сохраняется, 50 и 9999 допустимы при иных выполненных условиях; пятая цифра/дробное количество не становятся допустимым значением.
- [ ] **P2PACT-QTY-02** — Количество выше остатка продаваемого товара допустимо в пределах 50–9999; не применять ограничение Pre-Order по остатку.
- [ ] **P2PACT-EDIT-05** — Успешное изменение собственной цены сбрасывает прежнюю встречную цену; старое встречное больше нельзя подтвердить.
- [ ] **P2PACT-EDIT-06** — Успешное изменение собственного количества сбрасывает прежнюю встречную цену, включая её показ/фильтр списка.
- [ ] **P2PACT-EDIT-07** — Шаги ввода одного поля/сохранение второго/обычная отмена клавиатуры/пустое поле: **Blocked, P2PACT-Q01**, без предположений о маршруте.

## Резерв и лимит

- [ ] **P2PACT-LIMIT-01** — Для увеличения суммы используется резерв именно этой заявки плюс свободный остаток; дополнительная потребность новая стоимость − старый резерв.
- [ ] **P2PACT-LIMIT-02** — Старый резерв R=50000, свободно L=100, новая стоимость N=50050: дополнительная потребность 50, не второй полный резерв 50050. Использовать разрешённые цены/количества.
- [ ] **P2PACT-LIMIT-03** — N больше R+L: финансовый отказ, не успешная покупка/сохранение увеличения; точный UI/состояние предложения — P2PACT-Q05.
- [ ] **P2PACT-LIMIT-04** — Снизить валидную цену/количество и сохранить: разница стоимости освобождается; другие активные заявки/покупки не освобождаются.
- [ ] **P2PACT-LIMIT-05** — Переоткрытие/просмотр/Share/переключение вкладки не занимают резерв повторно.
- [ ] **P2PACT-LIMIT-06** — У клиента/корпа проверяется общий доступный остаток и депозит; изменение общей заявки не считает средства корпа независимыми.
- [ ] **P2PACT-LIMIT-07** — У реселлера стоимость/лимит проверяются с его клиентской наценкой; свободные средства клиента/другого реселлера не добавляют доступный остаток.
- [ ] **P2PACT-LIMIT-08** — Новая стоимость ровно R+L, дробная точность/конкуренция резервов: **Blocked, P2P-Q03 / P2PACT-Q02/05**.

## Принятие встречного покупателем

- [ ] **P2PACT-ACCEPT-01** — При встречной цене «Подтвердить» проверяет новую цену × прежнее количество с учётом уже занятого резерва и свободного остатка.
- [ ] **P2PACT-ACCEPT-02** — Лимита не хватает по встречной цене: alert о нехватке, покупка не оформлена; не показывать подтверждение как успех.
- [ ] **P2PACT-GUAR-01** — После успешной первой проверки у товара с гарантиями показаны вопрос, отказ и варианты цены единицы/срока; список сроков берётся из конфигурации, не константы скриншота.
- [ ] **P2PACT-GUAR-02** — Цена гарантийного варианта за единицу, лимит проверяется для всего количества, не одной единицы.
- [ ] **P2PACT-GUAR-03** — После выбора гарантии и продолжения выполняется проверка суммы с гарантией; лимит по встречной базовой цене не заменяет эту проверку.
- [ ] **P2PACT-GUAR-04** — На встречную цену лимита хватает, на дополнительную гарантию нет: alert, успешная покупка с недоступной гарантией не оформлена.
- [ ] **P2PACT-GUAR-05** — «Нет, спасибо» не добавляет дополнительную гарантию; точная кнопка финального завершения этой ветки — P2PACT-Q02.
- [ ] **P2PACT-BUY-01** — У товара без выбора гарантии блок отсутствует и появляется «Купить»; до завершения покупки не считать её успешной Историей.
- [ ] **P2PACT-CANCEL-01** — Отменить на этапе гарантии: активная заявка/прежнее встречное и её резерв сохранены, покупка/успешная История не созданы.
- [ ] **P2PACT-CANCEL-02** — Отменить на этапе «Купить» без гарантий: тот же возврат к активной заявке с прежним предложением/резервом.
- [ ] **P2PACT-BUY-02** — После успешного окончательного оформления toast подтверждения, экран обновлён до формы создания, заявка исключена из активных и относится к успешной Истории П2П.
- [ ] **P2PACT-BUY-03** — После сделки лимит учитывает итоговую покупку один раз, не одновременно прежнюю заявку и второй полный резерв. Чужие резервы не затронуты.
- [ ] **P2PACT-BUY-04** — Точная финальная кнопка с гарантией, номер/объединение/логист/тип оплаты заказа: **Blocked, P2PACT-Q02**; не добавлять Pre-Order-этапы автоматически.

## Подтверждение поставщиком

- [ ] **P2PACT-SUPPLIER-01** — Поставщик подтверждает собственное сохранённое предложение покупателя: успех приходит в real-time, без ручного обновления.
- [ ] **P2PACT-SUPPLIER-02** — Товар с доступными допгарантиями при подтверждении поставщиком оформляется с дефолтом без дополнительной гарантии; экран её выбора пользователю не требуется.
- [ ] **P2PACT-SUPPLIER-03** — Гарантия прежней обычной покупки/несохранённого Pre-Order не переносится в подтверждение поставщиком.
- [ ] **P2PACT-SUPPLIER-04** — Подтверждение поставщиком сохраняет запрошенное количество, не оформляет произвольное частичное количество.
- [ ] **P2PACT-SUPPLIER-05** — После успешного подтверждения toast и сброс открытого экрана до создания, заявка больше не активная; завершённая покупка учитывается в Истории П2П.
- [ ] **P2PACT-SUPPLIER-06** — Резерв не дублируется при событии подтверждения; депозит/прочие автоматические финансовые проверки и гонки — **Blocked, P2PACT-Q02/05**.

## Удаление и внешние события

- [ ] **P2PACT-DELETE-01** — «Удалить ордер» удаляет сразу без дополнительного окна подтверждения; не переносить подтверждение «Очистить все» в одиночное удаление.
- [ ] **P2PACT-DELETE-02** — После ручного удаления резерв заявки полностью освобождён, toast «Удалено», открытый экран обновлён до состояния перед созданием.
- [ ] **P2PACT-DELETE-03** — Открытая заявка по КТ удаляется в real-time: тот же toast/сброс и полное освобождение; точная граница/гонка — P2P-Q08 / P2PACT-Q05.
- [ ] **P2PACT-DELETE-04** — Отдельно сменить цену товара в продаже, рейтинг и дату поставщиком: активная заявка удалена, toast «Удалено» и сброс открытого экрана, её резерв освобождён.
- [ ] **P2PACT-DELETE-05** — Снятие товара с продажи и удаление заявки админом: открытая заявка обновляется до создания с toast «Удалено», резерв освобождён; точные поля отсутствующего товара — P2PACT-Q04.
- [ ] **P2PACT-DELETE-06** — Удаление общей заявки другим клиентом/корпом отражается в открытой заявке второго аккаунта; отдельные реселлерские не затронуты.
- [ ] **P2PACT-DELETE-07** — Удалённые/истёкшие заявки не становятся успешной Историей и не создают покупку из сброшенных значений.
- [ ] **P2PACT-LIVE-01** — Встречное предложение появляется в открытой заявке без ручного refresh; его новая цена не удаляет заявку как изменение цены товара в продаже.
- [ ] **P2PACT-LIVE-02** — При загрузке скелетон, ручного refresh нет; не использовать pull-to-refresh как условие появления ответа/удаления/подтверждения.
- [ ] **P2PACT-LIVE-03** — Внешнее событие во время клавиатуры/гарантии, конкурирующие действия, потеря сети/ответа: **Blocked, P2PACT-Q05**.

## Просмотр, Share и возврат

- [ ] **P2PACT-NAV-01** — Обычный крестик/свайп закрытия и переключение Pre-Order/P2P не удаляют сохранённую активную заявку; резерв остаётся один раз по правилам создания.
- [ ] **P2PACT-SHARE-01** — Share использует текущую цену товара для роли, не собственную/ответную цену; процент экспорта меняет только файл, без заявки/резерва/покупки.
- [ ] **P2PACT-SHARE-02** — У реселлера база Share уже включает клиентскую наценку; экспорт не раскрывает голую цену поставщика.
- [ ] **P2PACT-RESET-01** — Точные значения новой дефолтной формы после toast, сохранение фильтра/прокрутки списка и Pre-Order: **Blocked, P2PACT-Q04**. Сброс не создаёт заявку автоматически.
