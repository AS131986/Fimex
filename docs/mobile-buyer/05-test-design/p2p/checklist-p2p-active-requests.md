# Чек-лист: Список активных P2P-заявок — все роли

## Область и статус

[Экран](../../03-screens/p2p/p2p-active-requests.md) · [Правила и вопросы](../../04-business-rules/p2p-active-requests.md). Создание имеет [отдельный чек-лист](../home/checklist-p2p-request.md).

Все `[ ]` — **Not run**, не Fail. Приложение/заявки/финансовые операции не проверялись. Неизвестные ожидания **Blocked**. ID стабильны.

## Подготовка данных

- Клиент/связанные корповые аккаунты, два реселлера и чужая группа; разрешённый доступ поставщика/админа для событий, иначе соответствующий пункт Blocked.
- Заявки с разными датами оформления/ценами/количествами, без ответа и со встречным; товар с гарантией/без неё, с флагом/без флага, положительная наценка реселлера.
- Средства: достаточный/недостаточный свободный остаток, уже занятый резерв конкретной заявки, иные занятые суммы; собственные средства реселлера и общие клиента/корпа.
- Успешные покупки по двум инициаторам, удалённые/истёкшие, отсутствие успешной Истории года; финансовые эффекты сверять по разрешённому источнику, не только toast.

## Доступ и вход

- [ ] **P2PLIST-OPEN-01** — Нижняя вкладка P2P открывает «P2P Chat» со списком активных заявок соответствующей роли; создание из прайса не подменяет этот список.
- [ ] **P2PLIST-SCOPE-01** — Создать разные заявки клиентом и связанным корпом: оба видят общий набор, вправе открывать/редактировать/удалять заявки друг друга.
- [ ] **P2PLIST-SCOPE-02** — Реселлер видит только собственные заявки; активная заявка клиента/корпа на том же товаре не подставляется вместо его.
- [ ] **P2PLIST-SCOPE-03** — У клиента/корпа П2П-заявки реселлера отсутствуют, даже если его обычные заказы доступны в «Клиентских». Другой реселлер/чужая группа также не видят заявку.
- [ ] **P2PLIST-SCOPE-04** — Несколько связанных корповых аккаунтов и реселлеров с разными заявками: общая область клиента/корпа не смешивается с отдельными областями реселлеров.

## Строки и сортировка

- [ ] **P2PLIST-ROW-01** — Строка содержит флаг при наличии страны, иначе иконку, корректное название товара и собственную сохранённую цену единицы.
- [ ] **P2PLIST-ROW-02** — Ниже название/цена: запрошенное количество соответствует заявке, не текущему остатку поставщика и не сумме всех одноимённых заявок.
- [ ] **P2PLIST-PRICE-01** — Клиент/корп видят собственную и ответную цены без клиентской наценки; положительную наценку реселлера не добавлять в общий П2П.
- [ ] **P2PLIST-PRICE-02** — Реселлер видит свою и ответную цены сразу с клиентской наценкой; голая цена поставщика/себестоимость не раскрываются. Смена процента — P2PACT-Q03.
- [ ] **P2PLIST-ROW-03** — Без ответа на предоставленных образцах прочерк ниже своей цены; после ответа показана встречная цена, не замена собственной.
- [ ] **P2PLIST-ROW-04** — На тёмном образце собственная цена жёлтая, встречная красная; количество и название не перепутаны между строками.
- [ ] **P2PLIST-SORT-01** — Заявки с различными датами оформления упорядочены от новых к старым; не по цене/наличию ответа/алфавиту.
- [ ] **P2PLIST-SORT-02** — Одинаковые даты, часовой пояс и изменение порядка после редактирования: **Blocked, P2PLIST-Q01**.
- [ ] **P2PLIST-ROW-05** — Tap по разным строкам открывает соответствующую активную заявку с актуальными собственными/ответными данными; не соседний товар.

## Фильтр и история

- [ ] **P2PLIST-FILTER-01** — Есть хотя бы одно встречное предложение: показан переключатель «Все чаты» / «Поставщик».
- [ ] **P2PLIST-FILTER-02** — «Все чаты» содержит все доступные активные заявки, включая строки без ответа; «Поставщик» только со встречным предложением.
- [ ] **P2PLIST-FILTER-03** — Переключение фильтра не удаляет заявку и не меняет резерв/цену; скрытые без ответа остаются доступны во «Все чаты».
- [ ] **P2PLIST-FILTER-04** — Дефолтный выбор, сохранение при возврате/новом входе, исчезновение последнего ответа и пустой результат: **Blocked, P2PLIST-Q01**.
- [ ] **P2PLIST-HISTORY-01** — Нет успешных завершённых П2П-сделок в течение года: книга Истории скрыта; одни активные/удалённые/истёкшие не показывают её.
- [ ] **P2PLIST-HISTORY-02** — Есть успешная покупка по П2П доступной области в году: книга видна, в том числе при пустом активном списке.
- [ ] **P2PLIST-HISTORY-03** — Успешные сделки пользователя и поставщика обе учитываются для доступности Истории; удаление/КТ/снятие товара не считаются успехом.
- [ ] **P2PLIST-HISTORY-04** — Чужая успешная сделка не показывает книгу реселлеру без собственных успешных; успешная сделка корпа относится к общей области клиента/корпа.
- [ ] **P2PLIST-HISTORY-05** — Граница года/тип периода и точная дата видимости книги: **Blocked, P2PLIST-Q02**; полный экран/периоды/информация проверяются в [Истории П2П](checklist-p2p-history.md), без наследования обычной Истории заказов.

## Очистка

- [ ] **P2PLIST-CLEAR-01** — «Очистить все» открывает подтверждение с заголовком/текстом и «Отменить»/красной «Очистить все» по образцу.
- [ ] **P2PLIST-CLEAR-02** — Отменить подтверждение: все заявки/резервы остаются, не выполнено частичное удаление.
- [ ] **P2PLIST-CLEAR-03** — Подтвердить во «Все чаты»: удалены все доступные активные заявки, резервы каждой полностью освобождены.
- [ ] **P2PLIST-CLEAR-04** — Выбрать «Поставщик», подтвердить очистку: удалены и скрытые заявки без ответа; область операции не ограничена фильтром.
- [ ] **P2PLIST-CLEAR-05** — Очистка клиентом/корпом удаляет их общий активный набор; отдельные реселлерские заявки/чужая группа сохранены.
- [ ] **P2PLIST-CLEAR-06** — Очистка реселлером удаляет только его активный набор; клиент/корп и другие реселлеры сохранены.
- [ ] **P2PLIST-CLEAR-07** — Очистка активных не удаляет успешную Историю/оформленные заказы. Точный toast/атомарность массового удаления — P2PLIST-Q03.

## Жизненный цикл и real-time

- [ ] **P2PLIST-LIVE-01** — Ответная цена поставщика появляется в строке/фильтре без ручного обновления, собственной цены/количества не заменяет.
- [ ] **P2PLIST-LIVE-02** — После успешного подтверждения пользователем либо поставщиком заявка исключена из активных в real-time; другие активные остаются.
- [ ] **P2PLIST-LIVE-03** — По КТ активная заявка удаляется и резерв полностью освобождается; точная граница/гонка — P2P-Q08 / P2PACT-Q05.
- [ ] **P2PLIST-LIVE-04** — Отдельно изменение цены товара в продаже, рейтинга, даты поставщиком и снятие товара: активная заявка удаляется, её резерв освобождается.
- [ ] **P2PLIST-LIVE-05** — Удаление админом/ручное из деталки отражается в списке в real-time, удалённая строка не открывает старую активную заявку.
- [ ] **P2PLIST-LIVE-06** — Встречная П2П-цена не считается изменением цены товара в продаже: заявка остаётся активной для принятия.
- [ ] **P2PLIST-LIVE-07** — Событие в общей заявке видно клиенту и связанному корпу; ответ по чужой реселлерской заявке не добавляет строку в их список.

## Пустота, загрузка и ошибки

- [ ] **P2PLIST-EMPTY-01** — Нет активных заявок: информационная карточка с тремя пунктами о покупке дешевле, своей цене/сделках и партиях 50+, как в образцах экрана.
- [ ] **P2PLIST-EMPTY-02** — При пустоте остаются «P2P Chat» и нижнее меню; книга видна/скрыта по успешной Истории года, независимо от текущей пустоты.
- [ ] **P2PLIST-EMPTY-03** — Удалить весь доступный активный набор: нет устаревших строк; наличие чужих активных не устраняет собственную пустоту.
- [ ] **P2PLIST-LOAD-01** — При загрузке скелетон; ручного refresh / pull-to-refresh нет, real-time обновляет данные без пользовательского жеста.
- [ ] **P2PLIST-LOAD-02** — Потеря сети/фон/восстановление подписки, прежние данные/ошибки: **Blocked, P2PLIST-Q03**.
- [ ] **P2PLIST-BADGE-01** — Бейдж П2П относится к ответам поставщиков, не числу заявок/непрочитанных сообщений; точный переход после удаления/завершения — **Blocked, NAV-Q03**.
