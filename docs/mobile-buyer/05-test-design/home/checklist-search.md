# Чек-лист: Поиск — Fimex Buyer, iOS

## Область и использование

Ввод, результаты, скелетон, пустое состояние, история и ветвление в прайс/покупку. Саму покупку, Share и внутреннюю логику Price List целиком не дублировать.

Проверки не выполнялись. `[ ]` — Not run, не Fail. Результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть ожидания Blocked до ответа на SEARCH-Qxx. ID стабильные, снятые ID не переиспользовать.

## Предусловия

- Доступный аккаунт с пустой историей и аккаунт с несколькими выбранными результатами; два разных аккаунта для изоляции.
- Категория и модель с известными названиями, товары с памятью/цветом/размером ремешка, известный уникальный код.
- Название `iphone 18 pro 256GB Black` для примеров последовательности; исключить другие товары, случайно совпадающие с отрицательным запросом.
- Результаты с несколькими товарами в соответствующем прайсе и контролируемый случай единственного товара, не имеющий неоднозначности поставщика/варианта.
- Возможность наблюдать загрузку и при необходимости проверить сохранение истории через разрешённые средства. Скриншот сам по себе не подтверждает запись на backend.

## Smoke

SEARCH-OPEN-01, SEARCH-INPUT-01, SEARCH-MATCH-03, SEARCH-NAV-01/03, SEARCH-HISTORY-02, SEARCH-CLEAR-01, SEARCH-EMPTY-01. Использовать результаты основных пунктов.

## Открытие и элементы

- [ ] **SEARCH-OPEN-01** — Tap по поиску Главной открывает sheet Search с полем ввода и кнопкой закрытия.
- [ ] **SEARCH-OPEN-02** — При пустом запросе и отсутствии истории видна подсказка Search the catalog, а не No result.
- [ ] **SEARCH-OPEN-03** — При пустом запросе и существующей истории видны History, Clear all и сохранённые выбранные результаты.
- [ ] **SEARCH-OPEN-04** — Верхний крестик закрывает экран поиска и возвращает на предыдущий экран; сохранность запроса при повторном открытии — SEARCH-Q06.

## Ввод

- [ ] **SEARCH-INPUT-01** — С первого символа запускается поиск без нажатия кнопки клавиатуры.
- [ ] **SEARCH-INPUT-02** — Изменение запроса при вводе обновляет соответствующие результаты; прежний запрос не требуется подтверждать вручную.
- [ ] **SEARCH-INPUT-03** — В поле можно ввести 99 и 100 символов.
- [ ] **SEARCH-INPUT-04** — 101 символ не сохраняется как допустимое значение поля; способ ограничения/вставки — SEARCH-Q03.
- [ ] **SEARCH-INPUT-05** — Изменение регистра одинакового запроса не меняет состав совпадений. Не сравнивать порядок как обязательный.

## Поля и сопоставление

- [ ] **SEARCH-MATCH-01** — Название категории находит соответствующую категорию.
- [ ] **SEARCH-MATCH-02** — Название модели находит соответствующую модель.
- [ ] **SEARCH-MATCH-03** — Запрос `phone` находит название `iphone`; полное слово не обязательно.
- [ ] **SEARCH-MATCH-04** — Запрос `18 pro` находит `iphone 18 pro 256GB Black` как последовательный фрагмент названия.
- [ ] **SEARCH-MATCH-05** — Запрос `18 pro black` не находит этот товар через пропуск `256GB`; обеспечить отсутствие других совпадающих товаров.
- [ ] **SEARCH-MATCH-06** — Перестановка слов, отсутствующая в названии (например, `pro 18` для указанной модели), не считается совпадением только по наличию обоих слов.
- [ ] **SEARCH-MATCH-07** — Можно искать по памяти, цвету и размеру ремешка; проверить каждый тип на известной характеристике товара.
- [ ] **SEARCH-MATCH-08** — Полный известный код товара позволяет найти соответствующий товар; частичный код — SEARCH-Q03.
- [ ] **SEARCH-MATCH-09** — Несколько совпадающих товаров попадают в результаты; один из них не подменяет весь набор. Пагинация/лимит, если обнаружены, требуют отдельного уточнения.
- [ ] **SEARCH-MATCH-10** — Результаты соответствуют запросу по подтверждённым правилам; несуществующие совпадения не добавляются. Алфавитную или ценовую сортировку не назначать.

## Результаты и загрузка

- [ ] **SEARCH-RESULT-01** — При подгрузке виден скелетон; после успешного ответа показаны результаты либо No result.
- [ ] **SEARCH-RESULT-02** — В каждой совпадающей строке соответствующее значение запроса выделено жирным.
- [ ] **SEARCH-RESULT-03** — Совпадения выделяются в нескольких результатах, а не только в первой строке.
- [ ] **SEARCH-RESULT-04** — У каждой товарной строки присутствует иконка; точное сопоставление вида иконки — SEARCH-Q08.
- [ ] **SEARCH-RESULT-05** — Название и иконка строки относятся к одному выбранному результату; соседние строки не подменяют его идентичность.

## Пустой результат

- [ ] **SEARCH-EMPTY-01** — Запрос без совпадений показывает No result с иконкой поиска и сообщением об отсутствии результатов для текущего запроса.
- [ ] **SEARCH-EMPTY-02** — Сообщение содержит текущий запрос, а не предыдущий; введённый текст остаётся виден в поле.
- [ ] **SEARCH-EMPTY-03** — После изменения запроса на совпадающий No result сменяется результатами после загрузки.
- [ ] **SEARCH-EMPTY-04** — No result не создаёт запись в истории без выбора результата.

## Переходы

- [ ] **SEARCH-NAV-01** — Tap по категории с несколькими товарами открывает прайс выбранной категории, а не другой модели/категории.
- [ ] **SEARCH-NAV-02** — Tap по модели с несколькими товарами открывает прайс выбранной модели.
- [ ] **SEARCH-NAV-03** — Если в прайсе выбранного результата только один товар, tap ведёт сразу на экран покупки именно этого товара, без промежуточного открытия прайса. Неоднозначные варианты количества — SEARCH-Q02.
- [ ] **SEARCH-NAV-04** — Одна строка поиска с несколькими товарами в соответствующем прайсе не подменяет условие единственного товара: открывается прайс.
- [ ] **SEARCH-NAV-05** — Последовательный выбор разных результатов передаёт правильную область прайса либо товар, без сохранения идентичности предыдущего выбора.

## История

- [ ] **SEARCH-HISTORY-01** — Ввод и просмотр результатов без tap не добавляют запись; проверить закрытие поиска после такого ввода.
- [ ] **SEARCH-HISTORY-02** — После tap по результату он появляется в истории при следующем просмотре истории.
- [ ] **SEARCH-HISTORY-03** — История содержит выбранное название результата, а не только исходный запрос; например, запрос `phone` и выбранная модель имеют различающиеся подписи.
- [ ] **SEARCH-HISTORY-04** — У записей истории отображаются иконки товаров.
- [ ] **SEARCH-HISTORY-05** — Несколько разных последовательно выбранных результатов отображаются от новых к старым.
- [ ] **SEARCH-HISTORY-06** — Истории аккаунтов A и B раздельны: после входа B не отображаются записи A; использовать различающиеся истории. Восстановление истории A после повторного входа — SEARCH-Q05.
- [ ] **SEARCH-HISTORY-07** — Очистка собственной истории не очищает историю другого аккаунта; проверять через доступное независимое состояние, не подразумевая неподтверждённое межсессионное хранение.

## Очистка и UI

- [ ] **SEARCH-CLEAR-01** — Clear all сразу удаляет все текущие записи без confirm dialog.
- [ ] **SEARCH-CLEAR-02** — После Clear all при пустом запросе нет товарных строк истории; отображается первоначальное состояние без истории.
- [ ] **SEARCH-UI-01** — Поле, результаты/история и кнопка закрытия доступны с клавиатурой; последние строки достижимы прокруткой и не перекрываются полем.
- [ ] **SEARCH-UI-02** — Длинные запросы/названия и No result не скрывают доступные кнопки; поддерживаемые размеры iPhone учитывают safe area.
- [ ] **SEARCH-UI-03** — В русском/английском интерфейсе и обеих темах подписи и жирное выделение различимы; точные переводы — SEARCH-Q08.

## Неопределённые ожидания

SEARCH-Q01–Q08: продаваемость/глубина, точный подсчёт товара, переход из истории, дубли/лимит истории, хранение, очистка поля/возврат, ошибки/задержки и нормализация. Эти части не объявляются проверенными или согласованными. Исходные скриншоты — источник описания, не результаты прогона.
