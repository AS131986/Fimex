# Чек-лист: Поиск — Fimex Buyer, iOS

## Область и использование

Ввод, результаты, скелетон, пустое состояние, история и ветвление в прайс/покупку. Саму покупку, Share и внутреннюю логику Price List целиком не дублировать.

Проверки не выполнялись. `[ ]` — Not run, не Fail. Результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть ожидания Blocked до ответа на SEARCH-Qxx. ID стабильные, снятые ID не переиспользовать.

## Предусловия

- Доступный аккаунт с пустой историей и аккаунт с несколькими выбранными результатами; два разных аккаунта для изоляции.
- Категория и модель с известными названиями, товары с памятью/цветом/размером ремешка, известный уникальный код.
- Название `iphone 18 pro 256GB Black` для примеров последовательности; исключить другие товары, случайно совпадающие с отрицательным запросом.
- Результаты с несколькими товарами в соответствующем прайсе и контролируемый случай единственного товара, не имеющий неоднозначности поставщика/варианта.
- Возможность наблюдать загрузку и при необходимости проверить сохранение истории через разрешённые средства. Скриншот сам по себе не подтверждает запись на backend.

## Поля и сопоставление

- [ ] **SEARCH-MATCH-01 — Поиск по названию категории**

  <details>
  <summary>Подробности проверки</summary>

  - Название категории находит соответствующую категорию.

  </details>

- [ ] **SEARCH-MATCH-02 — Поиск по названию модели**

  <details>
  <summary>Подробности проверки</summary>

  - Название модели находит соответствующую модель.

  </details>

- [ ] **SEARCH-MATCH-03 — Поиск по части слова**

  <details>
  <summary>Подробности проверки</summary>

  - Запрос `phone` находит название `iphone`; полное слово не обязательно.

  </details>

- [ ] **SEARCH-MATCH-04 — Поиск по последовательному фрагменту**

  <details>
  <summary>Подробности проверки</summary>

  - Запрос `18 pro` находит `iphone 18 pro 256GB Black` как последовательный фрагмент названия.

  </details>

- [ ] **SEARCH-MATCH-05 — Отсутствие совпадения с пропуском части названия**

  <details>
  <summary>Подробности проверки</summary>

  - Запрос `18 pro black` не находит этот товар через пропуск `256GB`; обеспечить отсутствие других совпадающих товаров.

  </details>

- [ ] **SEARCH-MATCH-06 — Отсутствие совпадения с перестановкой слов**

  <details>
  <summary>Подробности проверки</summary>

  - Перестановка слов, отсутствующая в названии (например, `pro 18` для указанной модели), не считается совпадением только по наличию обоих слов.

  </details>

- [ ] **SEARCH-MATCH-07 — Поиск по памяти, цвету и ремешку**

  <details>
  <summary>Подробности проверки</summary>

  - Можно искать по памяти, цвету и размеру ремешка; проверить каждый тип на известной характеристике товара.

  </details>

- [ ] **SEARCH-MATCH-08 — Поиск по полному коду товара**

  <details>
  <summary>Подробности проверки</summary>

  - Полный известный код товара позволяет найти соответствующий товар; частичный код — SEARCH-Q03.

  </details>

- [ ] **SEARCH-MATCH-09 — Полнота нескольких совпадений**

  <details>
  <summary>Подробности проверки</summary>

  - Несколько совпадающих товаров попадают в результаты; один из них не подменяет весь набор.
  - Пагинация/лимит, если обнаружены, требуют отдельного уточнения.

  </details>

- [ ] **SEARCH-MATCH-10 — Соответствие результатов правилам поиска**

  <details>
  <summary>Подробности проверки</summary>

  - Результаты соответствуют запросу по подтверждённым правилам; несуществующие совпадения не добавляются.
  - Алфавитную или ценовую сортировку не назначать.

  </details>


## Результаты и загрузка

- [ ] **SEARCH-RESULT-01 — Скелетон загрузки результатов**

  <details>
  <summary>Подробности проверки</summary>

  - При подгрузке виден скелетон; после успешного ответа показаны результаты либо No result.

  </details>

- [ ] **SEARCH-RESULT-02 — Жирное выделение совпавшего запроса**

  <details>
  <summary>Подробности проверки</summary>

  - В каждой совпадающей строке соответствующее значение запроса выделено жирным.

  </details>

- [ ] **SEARCH-RESULT-03 — Выделение совпадений во всех результатах**

  <details>
  <summary>Подробности проверки</summary>

  - Совпадения выделяются в нескольких результатах, а не только в первой строке.

  </details>

- [ ] **SEARCH-RESULT-04 — Иконки товарных результатов**

  <details>
  <summary>Подробности проверки</summary>

  - У каждой товарной строки присутствует иконка; точное сопоставление вида иконки — SEARCH-Q08.

  </details>

- [ ] **SEARCH-RESULT-05 — Согласованность названия и иконки результата**

  <details>
  <summary>Подробности проверки</summary>

  - Название и иконка строки относятся к одному выбранному результату; соседние строки не подменяют его идентичность.

  </details>


## Пустой результат

- [ ] **SEARCH-EMPTY-01 — Состояние отсутствия результатов**

  <details>
  <summary>Подробности проверки</summary>

  - Запрос без совпадений показывает No result с иконкой поиска и сообщением об отсутствии результатов для текущего запроса.

  </details>

- [ ] **SEARCH-EMPTY-02 — Текущий запрос в сообщении No result**

  <details>
  <summary>Подробности проверки</summary>

  - Сообщение содержит текущий запрос, а не предыдущий; введённый текст остаётся виден в поле.

  </details>

- [ ] **SEARCH-EMPTY-03 — Возврат результатов после исправления запроса**

  <details>
  <summary>Подробности проверки</summary>

  - После изменения запроса на совпадающий No result сменяется результатами после загрузки.

  </details>

- [ ] **SEARCH-EMPTY-04 — Отсутствие истории для запроса без выбора**

  <details>
  <summary>Подробности проверки</summary>

  - No result не создаёт запись в истории без выбора результата.

  </details>


## Переходы

- [ ] **SEARCH-NAV-01 — Переход к прайсу выбранной категории**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по категории с несколькими товарами открывает прайс выбранной категории, а не другой модели/категории.

  </details>

- [ ] **SEARCH-NAV-02 — Переход к прайсу выбранной модели**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по модели с несколькими товарами открывает прайс выбранной модели.

  </details>

- [ ] **SEARCH-NAV-03 — Прямая покупка единственного товара результата**

  <details>
  <summary>Подробности проверки</summary>

  - Если в прайсе выбранного результата только один товар, tap ведёт сразу на экран покупки именно этого товара, без промежуточного открытия прайса.
  - Неоднозначные варианты количества — SEARCH-Q02.

  </details>

- [ ] **SEARCH-NAV-04 — Прайс для результата с несколькими товарами**

  <details>
  <summary>Подробности проверки</summary>

  - Одна строка поиска с несколькими товарами в соответствующем прайсе не подменяет условие единственного товара: открывается прайс.

  </details>

- [ ] **SEARCH-NAV-05 — Независимость последовательно выбранных результатов**

  <details>
  <summary>Подробности проверки</summary>

  - Последовательный выбор разных результатов передаёт правильную область прайса либо товар, без сохранения идентичности предыдущего выбора.

  </details>


## История

- [ ] **SEARCH-HISTORY-01 — Отсутствие истории при одном вводе запроса**

  <details>
  <summary>Подробности проверки</summary>

  - Ввод и просмотр результатов без tap не добавляют запись; проверить закрытие поиска после такого ввода.

  </details>

- [ ] **SEARCH-HISTORY-02 — Добавление выбранного результата в историю**

  <details>
  <summary>Подробности проверки</summary>

  - После tap по результату он появляется в истории при следующем просмотре истории.

  </details>

- [ ] **SEARCH-HISTORY-03 — Название результата вместо запроса в истории**

  <details>
  <summary>Подробности проверки</summary>

  - История содержит выбранное название результата, а не только исходный запрос; например, запрос `phone` и выбранная модель имеют различающиеся подписи.

  </details>

- [ ] **SEARCH-HISTORY-04 — Иконки записей истории**

  <details>
  <summary>Подробности проверки</summary>

  - У записей истории отображаются иконки товаров.

  </details>

- [ ] **SEARCH-HISTORY-05 — Порядок истории от новых выборов к старым**

  <details>
  <summary>Подробности проверки</summary>

  - Несколько разных последовательно выбранных результатов отображаются от новых к старым.

  </details>

- [ ] **SEARCH-HISTORY-06 — Изоляция историй разных аккаунтов**

  <details>
  <summary>Подробности проверки</summary>

  - Истории аккаунтов A и B раздельны: после входа B не отображаются записи A; использовать различающиеся истории.
  - Восстановление истории A после повторного входа — SEARCH-Q05.

  </details>

- [ ] **SEARCH-HISTORY-07 — Независимая очистка историй аккаунтов**

  <details>
  <summary>Подробности проверки</summary>

  - Очистка собственной истории не очищает историю другого аккаунта; проверять через доступное независимое состояние, не подразумевая неподтверждённое межсессионное хранение.

  </details>


## Очистка и UI

- [ ] **SEARCH-CLEAR-01 — Очистка всей истории без подтверждения**

  <details>
  <summary>Подробности проверки</summary>

  - Clear all сразу удаляет все текущие записи без confirm dialog.

  </details>

- [ ] **SEARCH-CLEAR-02 — Начальное состояние после очистки истории**

  <details>
  <summary>Подробности проверки</summary>

  - После Clear all при пустом запросе нет товарных строк истории; отображается первоначальное состояние без истории.

  </details>

- [ ] **SEARCH-UI-01 — Доступность поиска с клавиатурой**

  <details>
  <summary>Подробности проверки</summary>

  - Поле, результаты/история и кнопка закрытия доступны с клавиатурой; последние строки достижимы прокруткой и не перекрываются полем.

  </details>

- [ ] **SEARCH-UI-02 — Длинные запросы и безопасная область поиска**

  <details>
  <summary>Подробности проверки</summary>

  - Длинные запросы/названия и No result не скрывают доступные кнопки; поддерживаемые размеры iPhone учитывают safe area.

  </details>

- [ ] **SEARCH-UI-03 — Локализация и темы поиска**

  <details>
  <summary>Подробности проверки</summary>

  - В русском/английском интерфейсе и обеих темах подписи и жирное выделение различимы; точные переводы — SEARCH-Q08.

  </details>
