# Чек-лист: Price List — Fimex Buyer, iOS

## Область проверки

- Price List: предложения, фильтрация, конкуренты, уведомления, Share, onboarding и базовые iOS/UI-проверки.
- Purchase: передача позиции, проверка доступности и изменений цены/рейтинга при переходе; глубокая проверка покупки не входит в scope.
- Старый раздел уведомлений в Profile не входит в scope.
- Проверки ниже не выполнялись; результаты тестирования не заявляются.

## Правила использования

- `[ ]` — проверка не выполнена, не Fail. Результаты фиксировать отдельно: Pass / Fail / Blocked / Not run / N/A.
- Приоритет раздела применяется к его пунктам, если в пункте не указан другой.
- Critical — изоляция аккаунтов (предварительно); High — основная логика и целостность данных; Medium — дополнительные состояния и UI; Low — косметика.
- Приоритет проверки не равен серьёзности дефекта; критерии блокировки релиза согласуются отдельно.
- `Требует уточнения Qxx` — зависимая часть проверки Blocked до согласования ожидания.
- ID сохраняется при перемещении или изменении формулировки.

## Данные и средства проверки

- Buyer A/B, основной аккаунт и связанный Reseller; подписки на одинаковые и разные позиции.
- Товары с разными характеристиками, цветами, странами, датами; доступные, ранее продававшиеся отсутствующие и никогда не продававшиеся.
- Один и несколько поставщиков; 0/1/2/3/4+ конкурента; stock 0/1/49/50/51; положительные, дробные, равные и граничные цены.
- Возможность менять цену, stock, доступность поставщика и админские ограничения на тестовом окружении.
- Два устройства для завершения первой сессии; управление push-разрешением iOS.
- Средства задержки/потери ответов и наблюдения состояния backend. При отсутствии доступа соответствующие проверки — Blocked, а не Pass.

## 1. Открытие и закрытие

**Приоритет: High**

- [ ] **PL-OPEN-01** — Price List открывается из прайса бренда, прайса категории и выбранной модели. Проверить каждый источник отдельно.
- [ ] **PL-OPEN-02** — Заголовок соответствует выбранной модели/товару.
- [ ] **PL-OPEN-03** — **Medium:** длинный заголовок не перекрывает доступные кнопки Share и Close.
- [ ] **PL-OPEN-04** — Tap по Close закрывает Price List.
- [ ] **PL-OPEN-05** — Полное закрытие и повторное открытие возвращает экран в начальное состояние: дефолтный таб, свёрнутые цветовые группы и списки конкурентов.
- [ ] **PL-OPEN-06** — **Medium:** экран корректно отображается на поддерживаемых размерах iPhone с учётом safe area.

## 2. Загрузка, пустой результат и ошибки

**Приоритет: High**

- [ ] **PL-LOAD-01** — Во время первоначальной загрузки отображается состояние загрузки; данные другого товара не показываются.
- [ ] **PL-LOAD-02** — После успешной загрузки loader скрывается, отображаются данные выбранного товара.
- [ ] **PL-LOAD-03** — Пустой прайс отображается без сломанной вёрстки и бесконечного loader.
- [ ] **PL-LOAD-04** — Ошибка загрузки отображается как ошибка, а не пустой прайс. **Требует уточнения Q01:** конкретное представление ошибки.
- [ ] **PL-LOAD-05** — После восстановления сети повторная загрузка возвращает данные без перезапуска приложения.
- [ ] **PL-LOAD-06** — Повторная загрузка не создаёт дубли цветовых групп, предложений и строк уведомлений.
- [ ] **PL-LOAD-07** — Background → foreground не оставляет loader зависшим и не приводит к потере загруженного экрана.

## 3. Табы характеристик

**Приоритет: High**

- [ ] **PL-TAB-01** — Отображаются только характеристики с хотя бы одной видимой позицией.
- [ ] **PL-TAB-02** — Если видимых позиций нет, таб скрыт; характеристика никогда не продававшегося товара не появляется без других видимых позиций.
- [ ] **PL-TAB-03** — **Medium:** порядок табов соответствует порядку из админки.
- [ ] **PL-TAB-04** — Переключение таба меняет активную характеристику и показывает только её группы и строки.
- [ ] **PL-TAB-05** — **Medium:** активный таб визуально выделен.
- [ ] **PL-TAB-06** — Быстрое переключение не оставляет строки предыдущей характеристики и не смешивает данные.
- [ ] **PL-TAB-07** — После возврата из Purchase выбранная характеристика сохраняется.
- [ ] **PL-TAB-08** — После полного закрытия и открытия выбран дефолтный таб. **Требует уточнения Q02:** правило его выбора.

## 4. Цветовые группы

**Приоритет: Medium**

- [ ] **PL-GROUP-01** — Порядок цветовых групп соответствует порядку из админки.
- [ ] **PL-GROUP-02** — Tap по заголовку/стрелке раскрывает группу; повторный tap сворачивает её.
- [ ] **PL-GROUP-03** — При первом открытии все цветовые группы свёрнуты.
- [ ] **PL-GROUP-04** — Можно раскрыть несколько групп; раскрытие одной не сворачивает остальные.
- [ ] **PL-GROUP-05** — После возврата из Purchase состояния групп сохраняются.
- [ ] **PL-GROUP-06** — **High:** успешное добавление любого типа уведомления раскрывает соответствующую свёрнутую группу; раскрытая группа остаётся раскрытой.
- [ ] **PL-GROUP-07** — Добавление уведомления не меняет состояния других групп.
- [ ] **PL-GROUP-08** — Данные прайса обновляются только при повторном открытии; при этом цветовые группы свёрнуты, как при начальном открытии. Обновление данных внутри открытого прайса не ожидается.

## 5. Доступная строка и переход в Purchase

**Приоритет: High**

- [ ] **PL-ROW-01** — Доступная строка содержит дату, страну/флаг, цену в USD и фактическое количество.
- [ ] **PL-ROW-02** — При отсутствии страны вместо флага отображается иконка девайса.
- [ ] **PL-ROW-03** — Количество соответствует модели, характеристике, цвету, стране и дате.
- [ ] **PL-ROW-04** — Цена, количество, дата и страна не подменяются значениями соседних строк.
- [ ] **PL-ROW-05** — Tap по доступной строке открывает Purchase соответствующей позиции; возврат приводит в тот же Price List.
- [ ] **PL-ROW-06** — **Medium:** количество 1, обычное многозначное и большое значение отображаются без обрезания и наложений.

## 6. Дата

**Приоритет: High**

- [ ] **PL-DATE-01** — При delivery days = 0 отображается дата выставления товара на продажу.
- [ ] **PL-DATE-02** — При delivery days > 0 отображается дата выставления плюс дни доставки.
- [ ] **PL-DATE-03** — Расчёт корректен при переходе на следующий месяц.
- [ ] **PL-DATE-04** — Расчёт корректен при переходе на следующий год.
- [ ] **PL-DATE-05** — **Medium:** дата позиции с текущей КТ подсвечивается согласно дизайну; позиции без текущей КТ не получают такую подсветку. **Требует уточнения Q04:** определение текущей КТ.

## 7. Цена Buyer и Reseller

**Приоритет: High**

- [ ] **PL-PRICE-01** — Цена Buyer рассчитана из цены продавца с учётом процента площадки.
- [ ] **PL-PRICE-02** — Итоговая цена округляется по согласованному правилу. **Требует уточнения Q05.**
- [ ] **PL-PRICE-03** — Итоговая цена согласованно используется в основной строке, модалке и связанных UI-состояниях одного снимка прайса; текущая цена и target не смешиваются. При смене цены до перехода покупка открывается с актуальной ценой; alert по рейтингу/дате/КТ проверяется отдельно в разделе 35.
- [ ] **PL-PRICE-04** — Цена Reseller включает наценку основного клиента.
- [ ] **PL-PRICE-05** — Диапазон уведомления Reseller рассчитывается от согласованной базы. **Требует уточнения Q06:** базовая или финальная цена.

## 8. Фильтр глубины товара

**Приоритет: High**

- [ ] **PL-DEPTH-01** — При открытии Price List применяется глубина из настроек.
- [ ] **PL-DEPTH-02** — При 50+: количество 49 не проходит фильтр; 50 и 51 проходят.
- [ ] **PL-DEPTH-03** — Порог применяется к количеству каждого предложения; количества разных поставщиков не суммируются.
- [ ] **PL-DEPTH-04** — Предложения разных стран, цветов и характеристик фильтруются независимо.
- [ ] **PL-DEPTH-05** — Если в группе нет доступных предложений после фильтрации, видимость соответствует согласованному правилу; некорректных пустых строк нет. **Требует уточнения Q07.**
- [ ] **PL-DEPTH-06** — Если у характеристики нет ни одной видимой позиции после фильтрации, таб скрывается.
- [ ] **PL-DEPTH-07** — Изменение глубины применяется в согласованный момент. **Требует уточнения Q08:** возврат, обновление или повторное открытие.
- [ ] **PL-DEPTH-08** — Уменьшение порога возвращает подходящие позиции; увеличение скрывает позиции ниже порога.
- [ ] **PL-DEPTH-09** — После обновления stock 49 → 50 позиция появляется при 50+; при 50 → 49 скрывается.
- [ ] **PL-DEPTH-10** — Фильтрация не меняет фактическое количество оставшихся предложений.
- [ ] **PL-DEPTH-11** — Повторное открытие и обновление после фильтрации не создают дубли.
- [ ] **PL-DEPTH-12** — Скрытие фильтром не удаляет сохранённую подписку с backend.
- [ ] **PL-DEPTH-13** — Фильтр применяется отдельно к основной и каждой конкурентной строке; для конкурентов проверить 49, 50 и 51.
- [ ] **PL-DEPTH-14** — Стрелка конкурентов отсутствует, если подходящих конкурентов нет, и есть при наличии хотя бы одного.
- [ ] **PL-DEPTH-15** — После исключения конкурентов список заполняется следующими подходящими предложениями по сортировке.
- [ ] **PL-DEPTH-16** — После фильтрации показаны максимум три конкурента; основная строка в лимит не входит.
- [ ] **PL-DEPTH-17** — Предложение с минимальной ценой для покупки выбирается только среди прошедших фильтр; более дешёвое предложение ниже порога не подставляется.
- [ ] **PL-DEPTH-18** — При неизменных серверных данных tap по конкуренту открывает Purchase с лучшим прошедшим фильтр предложением; цена не берётся из предложения ниже порога. Изменения цены/рейтинга между запросом прайса и переходом проверяются в разделе 35.
- [ ] **PL-DEPTH-19** — Изменение stock конкурента через порог пересчитывает состав и порядок раскрытого списка.
- [ ] **PL-DEPTH-20** — Изменение глубины пересчитывает конкурентов без дублей и нарушения лимита.

## 9. Правила конкуренции и видимости

**Приоритет: High**

- [ ] **PL-RULE-01** — Конкурентная группа формируется для согласованного набора признаков. **Требует уточнения Q09:** участие цвета и даты в ключе группы.
- [ ] **PL-RULE-02** — Ближайшее предложение отображается; более дальнее и дорогое скрывается.
- [ ] **PL-RULE-03** — Если дальнее предложение дешевле ближайшего, отображаются оба.
- [ ] **PL-RULE-04** — При равных ценах ближайшего и дальнего предложений видимость соответствует согласованному правилу. **Требует уточнения Q10.**
- [ ] **PL-RULE-05** — Правила одной страны и характеристики не скрывают предложения другой страны или характеристики.
- [ ] **PL-RULE-06** — Видимые предложения сортируются по цене по возрастанию внутри соответствующего блока.
- [ ] **PL-RULE-07** — **Medium:** порядок стран соответствует порядку из админки.
- [ ] **PL-RULE-08** — Изменение цены или даты пересчитывает видимость и порядок строк без дублей.

## 10. Раскрытие и просмотр конкурентов

**Приоритет: High**

- [ ] **PL-COMP-01** — Стрелка отображается только у позиции с конкурентами.
- [ ] **PL-COMP-02** — **Medium:** при первом открытии список конкурентов свёрнут.
- [ ] **PL-COMP-03** — **Medium:** tap раскрывает список и меняет состояние стрелки; повторный tap сворачивает его, оставляя основную строку.
- [ ] **PL-COMP-04** — При одном, двух и трёх конкурентах отображается соответствующее количество строк.
- [ ] **PL-COMP-05** — При четырёх и более конкурентах отображаются только первые три по сортировке.
- [ ] **PL-COMP-06** — Лимит применяется отдельно к каждой основной позиции/стране; основная строка в него не входит.
- [ ] **PL-COMP-07** — Раскрытие не затрагивает конкурентов других стран, цветов и характеристик.
- [ ] **PL-COMP-08** — Каждая конкурентная строка содержит правильные дату, страну/флаг, цену и количество.
- [ ] **PL-COMP-09** — Конкуренты отсортированы по возрастанию цены; равные цены не вызывают пропуск или ошибочное объединение.
- [ ] **PL-COMP-10** — Повторное раскрытие и быстрые tap не создают дубли и не нарушают состояние списка.
- [ ] **PL-COMP-11** — Tap по конкурентной строке открывает Purchase с минимальной ценой подходящего предложения, а не обязательно с нажатым предложением. Если до перехода изменилась только цена, покупка использует актуальную цену без ценового alert; изменение рейтинга/даты/КТ — раздел 35. Выбор между равными ценами — остаток Q11.
- [ ] **PL-COMP-12** — При неизменных серверных данных tap по разным конкурентам одной позиции приводит к одному лучшему предложению; цена нажатого конкурента не подменяет цену выбранного лучшего предложения.
- [ ] **PL-COMP-13** — Модель, характеристика, цвет и страна в Purchase соответствуют выбранной позиции.
- [ ] **PL-COMP-14** — Long press по конкуренту не открывает модалку, не создаёт и не изменяет подписку; список и индикаторы не меняются.
- [ ] **PL-COMP-15** — Настройка ценового уведомления доступна через long press по основной строке.
- [ ] **PL-COMP-16** — **Medium:** после возврата из Purchase раскрытие конкурентов сохраняется.
- [ ] **PL-COMP-17** — После обновления исчезнувший конкурент удаляется, новый занимает правильное место; дублей нет, лимит не нарушен.

## 11. Предложения поставщиков

**Приоритет: High**

- [ ] **PL-SUP-01** — Активное предложение отображается в правильных модели, характеристике, цвете и стране.
- [ ] **PL-SUP-02** — Повышение и снижение цены поставщика отображаются после обновления с учётом комиссии.
- [ ] **PL-SUP-03** — Неуспешно сохранённая цена не появляется как актуальная.
- [ ] **PL-SUP-04** — Отключённое, архивное или удалённое предложение перестаёт отображаться среди доступных предложений.
- [ ] **PL-SUP-05** — Stock 0 убирает доступность предложения; положительный stock возвращает её, если продажа разрешена админом.
- [ ] **PL-SUP-06** — В одну конкурентную группу не объединяются предложения разных стран, характеристик и цветов.
- [ ] **PL-SUP-07** — При двух и трёх и более поставщиках лучшим для покупки является предложение с минимальной ценой среди подходящих; равные цены и основной поставщик при равенстве — остаток Q11.
- [ ] **PL-SUP-08** — Равные цены разных поставщиков не вызывают потерю или ошибочное объединение предложений.
- [ ] **PL-SUP-09** — Цена и количество строки принадлежат одному предложению; количество не подменяется stock другого поставщика.
- [ ] **PL-SUP-10** — Повышение и снижение цены пересчитывают позицию поставщика в списке.
- [ ] **PL-SUP-11** — Вошедший в первую тройку конкурент появляется; вышедший скрывается.
- [ ] **PL-SUP-12** — Изменение цены одного поставщика не меняет цену другого и не создаёт дубли.
- [ ] **PL-SUP-13** — Изменение цены учитывается при выборе минимальной цены подходящего предложения. Если цена изменилась после запроса прайса, но до перехода, покупка открывается с актуальной ценой без ценового alert. Изменение рейтинга отдельно вызывает alert и возврат на Главную. Равные цены — Q11; момент закрытия после бизнес-alert — Q32.
- [ ] **PL-SUP-14** — После повторного открытия списка используются обновлённые данные; без нового запроса строка прайса может показывать прежнюю цену. При tap покупка использует актуальную цену; доступность и изменения рейтинга/даты/КТ проверяются независимо.

- [ ] **PL-SESSION-04** — Сохранение из открытой на первом устройстве модалки после завершения сессии не меняет подписку.
- [ ] **PL-SESSION-05** — Background → foreground на первом устройстве не восстанавливает завершённую сессию.
- [ ] **PL-SESSION-06** — На втором устройстве доступны сохранённые подписки; вход не удаляет и не дублирует их.

## 31. Гонки запросов и потерянные ответы

**Приоритет: High**

- [ ] **PL-RACE-01** — Последовательные сохранения target 100, затем 90 оставляют 90 в UI и backend при обратном порядке ответов. Значения в валюте направления; подобрать допустимый диапазон.
- [ ] **PL-RACE-02** — Поздний ответ на 100 не заменяет подтверждённые 90.
- [ ] **PL-RACE-03** — Обновление списка во время сохранения не оставляет старый target после успеха.
- [ ] **PL-RACE-04** — Задержанный ответ одной позиции не меняет модалку или строку другой позиции.
- [ ] **PL-RACE-05** — После серверного создания и потери ответа retry не создаёт вторую подписку.
- [ ] **PL-RACE-06** — После серверного редактирования и потери ответа обновление восстанавливает сохранённый target.
- [ ] **PL-RACE-07** — После серверного удаления и потери ответа retry не восстанавливает подписку и не ломает экран.
- [ ] **PL-RACE-08** — После восстановления связи UI и backend согласованы: одна подписка нужного типа либо отсутствие после удаления.

- [ ] **PL-LIFE-04** — Для позиции без подписки завершение приложения до сохранения не создаёт подписку после запуска.

- [ ] **PL-LIFE-08** — **Medium:** завершение приложения с модалкой без движения ползунка не создаёт и не меняет подписку.

## 35. Проверка изменений цены, рейтинга, даты и наступления КТ при переходе к покупке

**Приоритет: High**

- [ ] **PL-FRESH-01** — После серверного изменения P1 → P2 без нового запроса Price List продолжает показывать P1; real-time обновление не ожидается.
- [ ] **PL-FRESH-02** — Открыть прайс с P1, изменить только цену на P2 до tap по товару без повторного открытия прайса: покупка открывается с P2, без alert «Упс…» из-за цены и без возврата на Главную. Пример 1000 → 1100; товар/характеристики соответствуют выбранной позиции.
- [ ] **PL-FRESH-03** — После повторного открытия прайса с новой ценой и при отсутствии дальнейших изменений переход передаёт выбранные модель, характеристику, цвет и страну без подмены соседней позицией. Состояние выбора после alert — **Q32**.
- [ ] **PL-FRESH-04** — Отдельно повысить и снизить цену после запроса прайса до tap: в обоих случаях покупка открывается с актуальной ценой без ценового alert; остальные условия неизменны.
- [ ] **PL-FRESH-05** — Изменить только цену до перехода через конкурентную строку: покупка открывается с актуальной минимальной ценой подходящего предложения без ценового alert. Отдельно изменить рейтинг: alert и возврат на Главную по прежним правилам. Равные цены — Q11; момент закрытия после бизнес-alert — Q32.
- [ ] **PL-FRESH-06** — Для Reseller покупка открывается с актуальной итоговой ценой с применимой наценкой клиента. Если итоговая цена изменилась до перехода, включая изменение наценки при прежней цене поставщика, ценового alert/возврата на Главную нет. Изменение цены после открытия покупки — BUY-FRESH-01/06.
- [ ] **PL-FRESH-07** — При неизменной цене изменение рейтинга перед переходом к покупке вызывает alert «Упс…» и возврат на Главную с закрытием покупки/прайса. Проверить обновление рейтинга при прежнем лучшем поставщике; сохранение победителя не отменяет alert.
- [ ] **PL-FRESH-08** — Между запросом прайса и переходом к покупке наступает КТ: показывается alert «Упс…», в том числе при неизменных цене и количестве. Проверить основную и конкурентную строку. **Q04:** определение КТ, часовой пояс и точная временная граница; **Q32:** поведение после alert.
- [ ] **PL-FRESH-09** — Поставщик меняет дату после запроса прайса: при переходе к покупке показывается alert «Упс…», в том числе при неизменных цене и количестве. Проверить основную и конкурентную строку. **Q32:** состояние экранов, обновление даты и повторный переход после alert.

Для PL-FRESH-02/04/06 и ценовой части PL-FRESH-05 покупка открывается с актуальной ценой; открытый прайс не обновляется в real-time. При бизнес-alert по рейтингу/дате/КТ (PL-FRESH-07–09 и рейтинговая часть PL-FRESH-05) покупка/прайс закрываются, возврат на Главную; точный момент и состояние Главной остаются Q32. Изменения после открытия покупки — [отдельный чек-лист](checklist-purchase.md).

## Ограничения и согласованность документов

- Сброс подписок установлен для отключения админом; при снятии поставщиком сброс не задан. Редкий случай сохранения подписки одновременно с отключением админом имеет предварительное ожидание PL-ADMIN-19 и требует перепроверки при прогоне.
- В проверках «обновление прайса» означает повторное открытие с новым запросом списка, не real-time. При tap после одной смены цены покупка открывается с актуальной ценой. Доступность и изменения рейтинга/даты/КТ проверяются отдельно; соответствующие бизнес-alert и возврат — Q32. Новая цена при открытии становится исходной для последующих проверок покупки.
- Закрытие до сохранения отличается от потери ответа после успешного серверного сохранения; запрос в обработке — Q23.
- Проверки двух одновременно активных устройств не включены: второй вход завершает первую сессию.
- Согласованные правила из этого чек-листа и разделы правил из описания экрана перенесены в [business-rules](../../04-business-rules/price-list.md). Более ранние формулировки сохранены с пометкой о расхождениях; отдельный документ уведомлений требует синхронизации с последними согласованиями. Перенос не меняет проверки и их ID.
