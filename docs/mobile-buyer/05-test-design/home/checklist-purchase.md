# Чек-лист: Покупка товара — Fimex Buyer, iOS

## Область и использование

Pre-Order: выбранное предложение, количество, гарантия, логист, депозит/лимит, проверки изменений, закрытие и успех; Share товара и переключение Pre-Order / P2P Chat. Создание заявки P2P и самостоятельный сценарий оплаты заказа не входят в область.

Проверки не выполнялись. `[ ]` — Not run, не Fail. Результаты: Pass / Fail / Blocked / Not run / N/A. Зависимая от BUY-Qxx часть Blocked до согласования. ID стабильные; снятые ID не переиспользовать.

[Правила и вопросы](../../04-business-rules/purchase.md) · [Описание](../../03-screens/home/purchase.md)

[Создание заявки P2P](checklist-p2p-request.md) вынесено в отдельный чек-лист. Не переносить туда ограничение количества остатком поставщика: количество P2P может превышать остаток.

## Предусловия

- Клиент, его корп и реселлер; известные общие и отдельные финансовые значения. Использовать связанные разные аккаунты, а не две активные сессии одного аккаунта.
- Продаваемые товары с/без страны, с/без гарантии, 0/1/2/3+ дополнительными предложениями на выбранную дату.
- Возможность менять цену, рейтинг, дату и остаток, управлять админской гарантией/доставкой, фиксировать КТ на тестовом окружении.
- Предложения с понятными ценами/остатками, депозит 0 и положительный, лимит достаточный/недостаточный; гарантии, переводящие сумму через доступный лимит.
- Средства проверки заказа и лимита до/после оформления и выдачи, анализа Excel, задержки/ошибки ответа. Недоступные средства — Blocked, не Pass.

## Smoke

BUY-OPEN-01, BUY-QTY-05, BUY-GUAR-01/03, BUY-LOG-01/02, BUY-LIMIT-01/04, BUY-FRESH-01/02, BUY-SUCCESS-01, BUY-SHARE-04. Использовать результаты основных пунктов.

## Открытие, переключение и закрытие

- [ ] **BUY-OPEN-01** — Открытие из прайса показывает выбранную позицию с полным названием, датой, ценой и остатком; модель, характеристика, цвет и страна не подменяются соседней строкой. Набор данных без изменений между запросами.
- [ ] **BUY-OPEN-02** — Прямой вход из поиска при одном товаре в целевом прайсе показывает соответствующий товар; вход из товарного уведомления — товар события. Данные доступны и не изменялись; итоговый экран после успеха — BUY-Q09.
- [ ] **BUY-OPEN-03** — Крестик закрывает покупку и возвращает на предыдущий экран без создания заказа.
- [ ] **BUY-OPEN-04** — Свайп вниз закрывает покупку и возвращает на предыдущий экран без создания заказа.
- [ ] **BUY-OPEN-05** — Cancel закрывает экран покупки; не возвращает к вводу количества и не создаёт заказ.
- [ ] **BUY-TAB-01** — Tap переключает Pre-Order / P2P Chat в обоих направлениях и отражает выбранную вкладку.
- [ ] **BUY-TAB-02** — Горизонтальный свайп переключает вкладки в обоих направлениях.
- [ ] **BUY-TAB-03** — Ввести количество, выбрать гарантию при наличии, перейти в P2P и вернуться: введённые данные сброшены. Проверить tap и свайп отдельно; логист аккаунта, сохранённый после Confirm в окне данных, не отменяется переключением.

## Товар, доставка и конкуренты

- [ ] **BUY-DATA-01** — Полное название, цена и остаток относятся к одному выбранному предложению; страна отображается, если задана, иначе иконка товара.
- [ ] **BUY-DATA-02** — Дата равна дате поставщика плюс дням доставки админа для дня недели этой даты. Проверить разные дни недели, 0 и положительное число дней, переход месяца/года; часовой пояс — BUY-Q08.
- [ ] **BUY-DATA-03** — Tap по дате открывает окно доставки с датой, интервалом времени и иконкой. Значения сверять с источником конфигурации; интервал/иконка для 0 дней — BUY-Q08.
- [ ] **BUY-DATA-04** — Tap по названию открывает описание именно этого товара; полное название и страна согласованы с карточкой. Обязательные поля по категориям — BUY-Q08.
- [ ] **BUY-COMP-01** — Без конкурентов на выбранную дату стрелка скрыта; при одном или нескольких — доступна.
- [ ] **BUY-COMP-02** — При раскрытии показаны ещё до двух конкурентов на ту же дату с их ценами и остатками; при трёх и более дополнительных предложениях лимит не превышается. Выбор первых двух/глубина — BUY-Q01.
- [ ] **BUY-COMP-03** — Конкуренты только для просмотра: tap не выбирает другого поставщика и не меняет цену/остаток покупки на его значения. Для проверки взять разные цены и остатки.
- [ ] **BUY-COMP-04** — При нескольких подходящих предложениях с разными ценами покупка использует минимальную цену, а не произвольного конкурента. Проверить переход по разным конкурентным строкам прайса при неизменных данных. Равные цены и фильтрация списка конкурентов в покупке — остаток BUY-Q01.

## Количество

- [ ] **BUY-QTY-01** — Ввод/вставка букв, пробелов, минуса, дробного разделителя и других нецифровых символов не добавляет их в поле количества.
- [ ] **BUY-QTY-02** — Поле позволяет ввести до 10 цифр; одиннадцатая не добавляется. Проверить набор и вставку; большие значения не обходят ограничение остатка.
- [ ] **BUY-QTY-03** — Ввод 0 сбрасывается до 1. **BUY-Q02:** момент сброса — ввод, потеря фокуса или Continue.
- [ ] **BUY-QTY-04** — Ввод 01 приводит к 1. **BUY-Q02:** момент преобразования и прочие ведущие нули; не считать 01 двумя единицами.
- [ ] **BUY-QTY-05** — При остатке X ввод X+1 показывает сообщение о доступных X единицах по данной цене и блокирует Continue. Большие остатки конкурентов не делают такое количество допустимым.
- [ ] **BUY-QTY-06** — При остатке X допустимые 1 и X позволяют пройти к следующему шагу при остальных выполненных условиях. Проверить X=1 отдельно.
- [ ] **BUY-QTY-07** — Исправление количества с X+1 на допустимое снимает ошибку превышения остатка; Continue позволяет продолжить при остальных выполненных условиях.
- [ ] **BUY-QTY-08** — Для известной цены P, количества n и без выбранной гарантии Amount соответствует стоимости P×n. Округление — BUY-Q03 / SETTINGS-Q03; использовать целые цены без неоднозначного округления для базовой проверки.
- [ ] **BUY-QTY-09** — После выбора гарантии изменить количество: покупка возвращается к первому шагу, выбор гарантии сброшен. С новым допустимым количеством снова пройти Continue, выбрать гарантию/отказ и проверить сумму для нового количества; логист, уже сохранённый подтверждением, не откатывается. Проверить увеличение и уменьшение количества.

## Гарантия

- [ ] **BUY-GUAR-01** — У товара с настроенной гарантией после допустимого количества показаны отказ и доступные варианты согласно админке; конкретные 3/6/12 месяцев не ожидаются без такой конфигурации.
- [ ] **BUY-GUAR-02** — У товара без гарантии блок выбора гарантии отсутствует; после количества доступен следующий применимый шаг получателя/покупки.
- [ ] **BUY-GUAR-03** — Отказ от гарантии отражён как выбранный вариант и не добавляет стоимость гарантии к сумме заказа.
- [ ] **BUY-GUAR-04** — Выбор каждого доступного срока отражён в UI; цена варианта — за одну единицу с гарантией. При количестве n Amount равна цене выбранного варианта × n, эта сумма участвует в проверке лимита. Проверить n=1 и n>1 с известной ценой варианта; база админского процента и округление — остаток BUY-Q03.
- [ ] **BUY-GUAR-05** — Tap по заголовку гарантии открывает информацию по бренду покупаемого товара; данные другого бренда не подставляются.
- [ ] **BUY-GUAR-06** — При изменении админом сроков/наценки новое открытие покупки использует актуальную конфигурацию. Момент реакции уже открытой покупки на изменение гарантии — BUY-Q03/06.

## Логист

- [ ] **BUY-LOG-01** — Клиент и корп открывают Ship to, выбирают логиста, видят окно данных именно этого логиста; после «Подтвердить» он сохранён и показан получателем покупки.
- [ ] **BUY-LOG-02** — При отсутствии выбранного логиста у клиента/корпа покупка недоступна; на предоставленном варианте To Buy неактивна.
- [ ] **BUY-LOG-03** — После Confirm в окне данных выбор логиста клиентом сохраняется для связанного корпа; выбор корпом — для клиента. Один tap строки списка без подтверждения не сохраняет выбор. Проверить оба направления.
- [ ] **BUY-LOG-04** — Выбрать логиста и подтвердить в окне данных, отменить покупку и открыть новую: сохранён подтверждённый логист; отмена покупки не откатывает настройку.
- [ ] **BUY-LOG-05** — Реселлер использует закреплённого у клиента логиста; самостоятельный выбор логиста в покупке недоступен. Клиент без логиста — BUY-Q05.
- [ ] **BUY-LOG-06** — Поиск одного известного названия логиста в разном регистре даёт одинаковый результат. Для базовой проверки использовать полное название; частичное совпадение — BUY-Q05.
- [ ] **BUY-LOG-07** — Выбрать нового логиста, закрыть окно данных без Confirm: прежний логист/настройка клиентской группы сохранены; при исходном отсутствии логиста выбор не становится применённым и покупка остаётся недоступной.
- [ ] **BUY-LOG-08** — Скачивание лицензии выбранного логиста открывает системный Share с соответствующей лицензией; закрытие Share не заменяет Confirm и не сохраняет неподтверждённого логиста. Реквизиты/формат/нет лицензии/ошибка — BUY-Q05.

## Депозит, лимит и роли

- [ ] **BUY-LIMIT-01** — На последнем шаге по To Buy при отсутствии гарантийного депозита показывается соответствующий alert, заказ не оформляется. Положительный баланс не заменяет депозит.
- [ ] **BUY-LIMIT-02** — При депозите 5 000 USD базовый лимит без покупок равен 100 000 USD; положительный баланс не подменяет проверку гарантийного депозита.
- [ ] **BUY-LIMIT-03** — Сумма покупки выше оставшегося лимита: на последнем шаге по To Buy показывается alert превышения лимита, заказ не оформляется. Проверить превышение на минимальную поддерживаемую денежную единицу после согласования округления.
- [ ] **BUY-LIMIT-04** — Товар без гарантии укладывается в лимит, с выбранной гарантией — превышает: на последнем шаге по To Buy покупка с гарантией отклоняется как превышение лимита. Использовать известную цену варианта за единицу × количество; база процента/округление — остаток BUY-Q03.
- [ ] **BUY-LIMIT-05** — Покупка с суммой строго меньше доступного лимита и выполненными прочими условиями занимает лимит на соответствующую сумму до выдачи заказа.
- [ ] **BUY-LIMIT-06** — После полной выдачи заказа ранее занятый этим заказом лимит возвращается; изменение не подменяется простым фактом оплаты.
- [ ] **BUY-LIMIT-07** — Покупка клиента изменяет общий доступный лимит клиента/корпа, покупка корпа — тот же лимит клиента. Проверить оба направления; баланс у пары тоже общий, саму оплату проверять в её сценарии.
- [ ] **BUY-LIMIT-08** — У реселлера нет отдельного баланса; для покупки используется его лимит на основе начисленного клиентом депозита. Не ожидать списания с вымышленного баланса реселлера; точный расчёт и влияние на клиента — BUY-Q04.
- [ ] **BUY-LIMIT-09** — Сумма покупки ровно на доступный лимит: **Blocked, BUY-Q04**, допустимость включительной границы не согласована.
- [ ] **BUY-LIMIT-10** — При отсутствии депозита либо недостаточном лимите, но допустимом количестве и выбранном логисте пройти Continue и выбор гарантии/отказа: финансовый alert не показывается до последнего шага. По To Buy появляется соответствующий alert; проверки актуальности товара на промежуточных шагах сохраняются.
- [ ] **BUY-LIMIT-11** — Отображаемые Amount и Limit пересчитываются по количеству и гарантии/отказу: `Amount = цена выбранного варианта за единицу × количество`, `Limit = доступный лимит до покупки − Amount`. Например при лимите 100 000, цене без гарантии 1 000 и количестве 2 показаны 2 000 и 98 000; при настроенной цене единицы с гарантией 1 100 — 2 200 и 97 800. Изменить количество в обе стороны, заново пройти шаги после сброса гарантии и проверить новый расчёт; отказаться от гарантии и проверить возврат к цене без неё. При превышении лимита показанный остаток отрицательный; финансовый alert ожидается по To Buy, а не вместо предварительного расчёта. Использовать целые настроенные цены, не подменять этим правило округления.

## Изменения товара на шагах

Проверить каждое указанное событие отдельно при открытии покупки, по Continue после количества, после выбора/отказа от гарантии и по To Buy. Для товара без гарантии проверить применимые точки. Обеспечить, чтобы изменение произошло после предыдущего запроса, без прочих изменений.

- [ ] **BUY-FRESH-01** — Повышение и снижение цены обнаруживаются на соответствующем шаге: alert «Упс…», покупка и прайс закрыты, возврат на Главную; заказ по старой цене не оформлен.
- [ ] **BUY-FRESH-02** — Остаток падает ниже покупаемого количества: alert «Упс…», возврат на Главную с закрытием покупки/прайса, заказ на недоступное количество не оформлен. При самом открытии количество ещё не задано; критерий проверки остатка на этой точке — BUY-Q02/06.
- [ ] **BUY-FRESH-03** — Изменение рейтинга вызывает alert «Упс…», покупка/прайс закрываются с возвратом на Главную. Проверить изменение при прежнем лучшем поставщике и цене, а также смену лучшего предложения; покупка по прежним данным не продолжается без предупреждения.
- [ ] **BUY-FRESH-04** — Изменение даты поставщиком вызывает alert «Упс…», покупка/прайс закрываются с возвратом на Главную, включая неизменные цену и количество.
- [ ] **BUY-FRESH-05** — Наступление КТ, заданной в админке, вызывает alert «Упс…» и возврат на Главную, включая неизменные цену и количество. **BUY-Q08 / Q04 прайса:** определение КТ, точная временная граница и часовой пояс приложения; МСК пока только гипотеза.
- [ ] **BUY-FRESH-06** — Изменение общего типа оплаты клиентом/корпом или наценки реселлера, меняющее итоговую цену уже открытой покупки, приводит к проверке новой цены и alert «Упс…»; заказ по старой цене не оформляется.

## Ошибки, запрос и успех

- [ ] **BUY-ERROR-01** — Ошибка сети на шаге покупки показывает стандартный alert; уже введённое количество и выбранная гарантия сохраняются. Проверить отдельно от бизнес-alert «Упс…».
- [ ] **BUY-ERROR-02** — Ошибка сервера на шаге покупки показывает стандартный alert, введённые данные сохраняются; повторная попытка/потеря ответа после оформления — BUY-Q07.
- [ ] **BUY-ERROR-03** — На время запроса To Buy повторный tap заблокирован. При задержке ответа серия tap не отправляет несколько запросов покупки и не создаёт несколько заказов; retry после потери ответа — BUY-Q07.
- [ ] **BUY-SUCCESS-01** — При успешной покупке показан toast, покупка закрыта, создан один заказ с выбранными товаром, количеством, гарантией/отказом и логистом. Данные проверить по разрешённому источнику, а не только по toast.
- [ ] **BUY-SUCCESS-02** — После успеха из прайса виден прайс, как на предоставленном примере; экран возврата для прямого входа из поиска/уведомления — BUY-Q09.

## Share

- [ ] **BUY-SHARE-01** — Share открывает барабан процента и кнопку передачи файла; при открытии выбран 0,55%.
- [ ] **BUY-SHARE-02** — Барабан содержит 0,25–0,95% с шагом 0,1, затем 1,00%, 1,25–4,25% с шагом 0,25; значения ниже 0,25% и выше 4,25% недоступны. Проверить обе границы и стык 0,95 → 1,00 → 1,25.
- [ ] **BUY-SHARE-03** — Цена единицы в Excel увеличивается на выбранный процент от цены покупки без гарантии. Например P=1 000 USD, m=1% → 1 010 USD; для дробного результата округление — BUY-Q10.
- [ ] **BUY-SHARE-04** — Файл содержит только выбранное предложение с соответствующими товаром/датой/страной и ценой за единицу; конкуренты, соседние товары и стоимость выбранной гарантии не включаются.
- [ ] **BUY-SHARE-05** — Для реселлера исходная цена экспорта соответствует его цене с применимыми комиссиями/наценкой клиента; процент барабана не начисляется на голую цену поставщика. База наценки клиента и округление — SETTINGS-Q03 / BUY-Q10.
- [ ] **BUY-SHARE-06** — Сформировать Excel с разными процентами: цена файла меняется согласно проценту; цена покупки, Amount и настройки цен аккаунта остаются прежними. При выбранной гарантии её стоимость по-прежнему не включается в экспорт. Исходные цены/настройки админки во время проверки не менять.
