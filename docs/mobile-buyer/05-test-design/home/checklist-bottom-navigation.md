## Предусловия

- Доступный клиент, корп и реселлер; заблокированный реселлер для недоступности Главной.
- Заказы в фактических статусах до выдачи; выданные заказы в истории. Для общего списка клиента/корпа Pending assembly / Order pending delivery и Released как выдача; у реселлера завершение требует ручного Paid и «Выдать» клиентом/корпом. Частичная выдача — остаток NAV-Q01.
- Собственная заявка P2P с известными ответами поставщиков, включая прочитанные и непрочитанные; данные другого пользователя для проверки принадлежности.
- Согласовать момент обновления счётчиков NAV-Q02 перед оценкой после изменения backend. Не считать отсутствие мгновенного изменения Fail без требования real-time для счётчиков.

## Счётчик Моих заказов

Пункты ниже относятся к общему списку «Мои заказы». При переключении клиента/корпа на «Клиентские» меняется источник счётчика и действуют их условия завершения; проверки переключения — CUSTORD-BADGE-01/02/03 в [отдельном чек-листе](../orders/checklist-customer-orders-client-corporate.md). У реселлера счётчик собственных заказов проверяется в RESORD-BADGE-01 и RESORD-HISTORY-01/02/03/04 [его чек-листа](../orders/checklist-my-orders-reseller.md). Не исключать заказ из этих двух списков только из-за Released, пока условия клиентского завершения не выполнены.

- [ ] **NAV-ORDERS-01 — Подсчёт заказов вместо позиций товара**

  <details>
  <summary>Подробности проверки</summary>

  - При известном числе активных заказов бейдж показывает это число, а не количество позиций или единиц товара в них.

  </details>

- [ ] **NAV-ORDERS-02 — Состав активных статусов в счётчике заказов**

  <details>
  <summary>Подробности проверки</summary>

  - Заказы во всех реальных статусах до выдачи входят в активный счётчик общего списка клиента/корпа: Pending assembly / Order pending delivery;
  - Released не входит. Частичная выдача — остаток NAV-Q01.
  - Для собственного списка реселлера использовать его отдельные проверки завершения по двум клиентским условиям.

  </details>

- [ ] **NAV-ORDERS-03 — Исключение выданного заказа из активного счётчика**

  <details>
  <summary>Подробности проверки</summary>

  - Выданный заказ находится в истории и не входит в счётчик активных.

  </details>

- [ ] **NAV-ORDERS-04 — Счётчик при сочетании активных и исторических заказов**

  <details>
  <summary>Подробности проверки</summary>

  - Несколько заказов до выдачи и несколько в истории: бейдж равен только числу заказов до выдачи.

  </details>

- [ ] **NAV-ORDERS-05 — Уменьшение счётчика после выдачи заказа**

  <details>
  <summary>Подробности проверки</summary>

  - После выдачи одного из активных заказов количество активных уменьшается на один после согласованного обновления; момент обновления — NAV-Q02.

  </details>


## Счётчик P2P

- [ ] **NAV-P2P-01 — Счётчик всех ответов на собственную P2P-заявку**

  <details>
  <summary>Подробности проверки</summary>

  - При одной собственной заявке с известным числом ответов бейдж показывает количество всех ответов поставщиков на неё.

  </details>

- [ ] **NAV-P2P-02 — Учёт прочитанных и непрочитанных P2P-ответов**

  <details>
  <summary>Подробности проверки</summary>

  - При смеси прочитанных и непрочитанных ответов учитываются обе группы; счётчик не равен только непрочитанным.

  </details>

- [ ] **NAV-P2P-03 — Исключение ответов на чужие P2P-заявки**

  <details>
  <summary>Подробности проверки</summary>

  - Ответы на заявку другого пользователя не включаются в счётчик моей заявки.

  </details>

- [ ] **NAV-P2P-04 — Подсчёт ответов вместо сообщений обсуждения**

  <details>
  <summary>Подробности проверки</summary>

  - Один ответ на заявку считается ответом, а не количеством сообщений внутри дальнейшего обсуждения; использовать данные, где эти количества различаются.

  </details>

- [ ] **NAV-P2P-05 — Обновление счётчика после нового P2P-ответа**

  <details>
  <summary>Подробности проверки</summary>

  - После появления дополнительного ответа на единственную собственную заявку количество соответствует новому полному числу ответов после согласованного обновления.
  - Момент — NAV-Q02.

  </details>

## Неопределённые ожидания

- Нулевые и большие счётчики, максимальный формат, механизм обновления — NAV-Q02.
- Несколько заявок, отозванные ответы и закрытие заявки — NAV-Q03.
- Повторный tap по другим вкладкам — NAV-Q05.

Эти случаи не объявляются Pass/Fail до уточнения. Здесь не проверяются оформление заказа, статусы каждого бизнес-перехода заказа и жизненный цикл заявки P2P целиком.
