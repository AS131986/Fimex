## Предусловия

- Доступный клиент, корп и реселлер; заблокированный реселлер для недоступности Главной.
- Заказы в фактических статусах до выдачи; выданные заказы в истории. Для общего списка клиента/корпа Pending assembly / Order pending delivery и Released как выдача; у реселлера завершение требует ручного Paid и «Выдать» клиентом/корпом. Частичная выдача — остаток NAV-Q01.
- Собственная заявка P2P с известными ответами поставщиков, включая прочитанные и непрочитанные; данные другого пользователя для проверки принадлежности.
- Согласовать момент обновления счётчиков NAV-Q02 перед оценкой после изменения backend. Не считать отсутствие мгновенного изменения Fail без требования real-time для счётчиков.

## Smoke

Использовать основные пункты NAV-TABS-01/02, NAV-HOME-01, NAV-ORDERS-01, NAV-P2P-01. Отдельные копии результатов не создавать.

## Разделы и положение

- [ ] **NAV-TABS-01** — У доступного аккаунта есть Главная, Мои заказы, P2P и Профиль в порядке предоставленного экрана.
- [ ] **NAV-TABS-02** — Tap по каждой иконке открывает соответствующий раздел; Мои заказы не ведут в корзину, P2P не обозначаются как чаты.
- [ ] **NAV-TABS-03** — Подсвечен текущий раздел, после перехода подсветка соответствует новому разделу.
- [ ] **NAV-TABS-04** — На Главной при прокрутке каталога/моделей меню остаётся закреплённым, не уходит вместе с контентом.
- [ ] **NAV-TABS-05** — После переходов между разделами меню не теряет доступные иконки, их назначение и текущую подсветку.

## Повторный tap по Главной

- [ ] **NAV-HOME-01** — Повторный tap по активной Главной из прокрученного списка возвращает экран вверх.
- [ ] **NAV-HOME-02** — Если выбран бренд и раскрыты категории, повторный tap по Главной сбрасывает выбор и сворачивает каталог.
- [ ] **NAV-HOME-03** — Если выбрана категория и раскрыты модели, повторный tap сбрасывает бренд/категорию, сворачивает модели и возвращает вверх.
- [ ] **NAV-HOME-04** — Повторный tap при уже дефолтной Главной не открывает другой раздел и оставляет Главную дефолтной в верхней позиции.

## Счётчик Моих заказов

Пункты ниже относятся к общему списку «Мои заказы». При переключении клиента/корпа на «Клиентские» меняется источник счётчика и действуют их условия завершения; проверки переключения — CUSTORD-BADGE-01/02/03 в [отдельном чек-листе](../orders/checklist-customer-orders-client-corporate.md). У реселлера счётчик собственных заказов проверяется в RESORD-BADGE-01 и RESORD-HISTORY-01/02/03/04 [его чек-листа](../orders/checklist-my-orders-reseller.md). Не исключать заказ из этих двух списков только из-за Released, пока условия клиентского завершения не выполнены.

- [ ] **NAV-ORDERS-01** — При известном числе активных заказов бейдж показывает это число, а не количество позиций или единиц товара в них.
- [ ] **NAV-ORDERS-02** — Заказы во всех реальных статусах до выдачи входят в активный счётчик общего списка клиента/корпа: Pending assembly / Order pending delivery; Released не входит. Частичная выдача — остаток NAV-Q01. Для собственного списка реселлера использовать его отдельные проверки завершения по двум клиентским условиям.
- [ ] **NAV-ORDERS-03** — Выданный заказ находится в истории и не входит в счётчик активных.
- [ ] **NAV-ORDERS-04** — Несколько заказов до выдачи и несколько в истории: бейдж равен только числу заказов до выдачи.
- [ ] **NAV-ORDERS-05** — После выдачи одного из активных заказов количество активных уменьшается на один после согласованного обновления; момент обновления — NAV-Q02.

## Счётчик P2P

- [ ] **NAV-P2P-01** — При одной собственной заявке с известным числом ответов бейдж показывает количество всех ответов поставщиков на неё.
- [ ] **NAV-P2P-02** — При смеси прочитанных и непрочитанных ответов учитываются обе группы; счётчик не равен только непрочитанным.
- [ ] **NAV-P2P-03** — Ответы на заявку другого пользователя не включаются в счётчик моей заявки.
- [ ] **NAV-P2P-04** — Один ответ на заявку считается ответом, а не количеством сообщений внутри дальнейшего обсуждения; использовать данные, где эти количества различаются.
- [ ] **NAV-P2P-05** — После появления дополнительного ответа на единственную собственную заявку количество соответствует новому полному числу ответов после согласованного обновления. Момент — NAV-Q02.

## Роли и отображение

- [ ] **NAV-ROLE-01** — Для доступных клиента, корпа и реселлера состав меню и назначения разделов одинаковы; счётчики сверяются с данными текущего аккаунта.
- [ ] **NAV-ROLE-02** — После входа заблокированного реселлера меню не даёт открыть Главную и обходить блокировку покупок; способ скрытия/блокировки вкладки — NAV-Q04.
- [ ] **NAV-UI-01** — Меню, иконки и счётчики не перекрываются системной нижней областью; области нажатия позволяют выбрать нужный раздел на поддерживаемых iPhone.
- [ ] **NAV-UI-02** — В обоих языках и темах активная вкладка различима, числа бейджей читаемы.

## Неопределённые ожидания

- Нулевые и большие счётчики, максимальный формат, механизм обновления — NAV-Q02.
- Несколько заявок, отозванные ответы и закрытие заявки — NAV-Q03.
- Повторный tap по другим вкладкам — NAV-Q05.

Эти случаи не объявляются Pass/Fail до уточнения. Здесь не проверяются оформление заказа, статусы каждого бизнес-перехода заказа и жизненный цикл заявки P2P целиком.
