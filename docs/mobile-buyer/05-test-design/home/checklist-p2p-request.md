# Чек-лист: Создание заявки P2P — Fimex Buyer, iOS

## Область и использование

Создание P2P-заявки во вкладке товара, валидация цены/количества, депозит/лимит, проверки актуальности, Share и повторное отображение активной заявки. Ответы поставщиков, изменение/удаление и исполнение заявки отложены до документации раздела P2P.

Проверки не выполнялись. `[ ]` — Not run, не Fail. Результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Зависимая от P2P-Qxx часть Blocked до ответа. ID стабильные; снятые ID не переиспользовать.

## Предусловия

- Клиент, его корп и реселлер с достаточным депозитом/лимитом; отдельные состояния без депозита и с недостаточным лимитом.
- Для проверок первичного создания использовать товар без активной заявки проверяемого аккаунта/группы. Активную заявку создавать отдельно для проверок её повторного отображения и общего доступа.
- Продаваемые товары с/без страны, известными текущими ценами; предложение 1293 USD для подтверждённого примера минимума и 1000 USD для расчётов без спорного округления.
- Возможность управлять ценой, рейтингом, датой, продажей, КТ в тестовой админке; для независимых проверок менять только выбранный параметр.
- Количества 0/1/49/50/51/9999 и попытка пятой цифры; остатки товара меньше 50 и меньше запрашиваемого количества.
- Доступ к проверке сохранённой заявки/лимита, анализу Excel, управлению сетью и задержкой ответа. Нет доступа — Blocked, не Pass.

## Smoke

P2P-OPEN-01, P2P-PRICE-02/03/07, P2P-QTY-01/02/05, P2P-CALC-01, P2P-LIMIT-03, P2P-FRESH-01, P2P-SUCCESS-01, P2P-ACTIVE-01, P2P-SHARE-03. Использовать результаты основных пунктов.

## Открытие, переключение и закрытие

- [ ] **P2P-OPEN-01** — Открыть товар из прайса и выбрать P2P Chat: показаны дата, полное название, страна/иконка, текущая стартовая цена, поле цены и Continue.
- [ ] **P2P-OPEN-02** — Стартовая цена соответствует текущей цене этого товара для роли; цена/страна/характеристики соседней строки не подставляются. Данные не меняются между запросами.
- [ ] **P2P-OPEN-03** — Крестик закрывает окно с возвратом на предыдущий экран без создания заявки и без занятия суммы в лимите.
- [ ] **P2P-OPEN-04** — Свайп вниз закрывает окно с тем же результатом; введённая несохранённая цена/количество не превращаются в активную заявку.
- [ ] **P2P-TAB-01** — Tap переключает Pre-Order / P2P Chat в обоих направлениях и отражает выбранную вкладку.
- [ ] **P2P-TAB-02** — Горизонтальный свайп переключает вкладки в обоих направлениях.
- [ ] **P2P-TAB-03** — При отсутствии активной заявки на товар ввести допустимые цену и количество, переключить в Pre-Order и вернуться: несохранённые значения P2P сброшены. Проверить tap и свайп отдельно; сохранение уже активной заявки проверяется в P2P-ACTIVE-03.

## Товар и доставка

- [ ] **P2P-DATA-01** — Страна отображается при её наличии; без страны показана иконка товара. Полное название соответствует выбранной модели/характеристикам/цвету.
- [ ] **P2P-DATA-02** — Дата равна дате поставщика плюс дням доставки админа для её дня недели; проверить 0/положительные дни и переход месяца. Часовой пояс — P2P-Q08 / BUY-Q08.
- [ ] **P2P-DATA-03** — Tap по дате открывает окно с датой, временем и иконкой; значения относятся к выбранному предложению. Иконки/граница КТ — P2P-Q08.
- [ ] **P2P-DATA-04** — Tap по названию открывает описание именно этого товара; название/страна согласованы с карточкой. Обязательные поля по категориям и сохранение ввода после просмотра — P2P-Q07/08.

## Цена

- [ ] **P2P-PRICE-01** — Минимальная цена рассчитана как `floor(текущая цена × 0,9975)` и показана до ввода. Проверить целый и нецелый результат до округления: P=1200 → 1197; P=1293 → 1289.
- [ ] **P2P-PRICE-02** — При P=1293 цена 1289 допустима; не требовать 1289,77 после округления до центов, поскольку минимум округляется вниз до целого USD.
- [ ] **P2P-PRICE-03** — Цена меньше минимума вызывает подсветку/ошибку и неактивную Continue. Для P=1293 проверить 1288 и 1288.99.
- [ ] **P2P-PRICE-04** — Минимум и значение на 0.01 выше минимума принимаются при соблюдении абсолютного максимума. Для P=1293 проверить 1289 и 1289.01.
- [ ] **P2P-PRICE-05** — Целая часть не превышает пяти цифр, дробная — двух после точки; шестая целая и третья дробная цифры не добавляются. Проверить набор и вставку; точная нормализация/запятая — P2P-Q01.
- [ ] **P2P-PRICE-06** — Максимум 99999.99 можно ввести как допустимую цену при минимуме ниже него; превышение формата не сохраняется в поле. Не считать введённую цену допустимой независимо от минимального порога. Финансовые ограничения отправки проверять отдельно на завершающем шаге.
- [ ] **P2P-PRICE-07** — После допустимой цены Continue активна и переводит к количеству, сохраняя выбранную цену для расчёта заявки; заявка на этом шаге ещё не создаётся.
- [ ] **P2P-PRICE-08** — Исправление слишком низкой цены на допустимую снимает ошибку и позволяет перейти к количеству.

## Количество

- [ ] **P2P-QTY-01** — При количестве 0/1/49 показана ошибка минимума 50 и неактивная Continue; такое количество не создаёт заявку.
- [ ] **P2P-QTY-02** — Количества 50 и 51 допустимы при валидной цене и остальных выполненных условиях.
- [ ] **P2P-QTY-03** — Количество 9999 вводится и допускается при валидной цене и достаточном лимите; пятая цифра не добавляется. Проверить набор и вставку.
- [ ] **P2P-QTY-04** — Дробное количество не вводится/не становится отправляемым значением; ограничение количества не подменяется поддержкой дробной цены.
- [ ] **P2P-QTY-05** — При продаваемом товаре с остатком меньше 50 заявка на 50 допустима; при остатке X заявка на X+1 допустима, если количество 50–9999 и соблюдены прочие условия. Ошибка Pre-Order о доступных X единицах не переносится в P2P.
- [ ] **P2P-QTY-06** — Исправление количества 49 на 50 снимает ошибку, финальная Continue активна при валидной цене; повторное снижение до 49 снова блокирует отправку.

## Предварительный расчёт

- [ ] **P2P-CALC-01** — Amount равна введённой цене × количеству; отображаемый Limit равен доступному лимиту до этой заявки минус Amount. При цене 1000, количестве 50 и лимите 100000 показаны 50000 и 50000.
- [ ] **P2P-CALC-02** — Изменение количества в обе стороны пересчитывает Amount и Limit. Для невалидного количества 10 при цене 1000 и лимите 100000 показаны 10000 и 90000, но Continue неактивна; расчёт не разрешает отправку ниже минимума.
- [ ] **P2P-CALC-03** — Для допустимой дробной цены итоговая сумма учитывает дробную часть, а не целую цену. Например 1000.01 × 50 = 50000.50; отображение точности суммы — P2P-Q02.
- [ ] **P2P-CALC-04** — При сумме выше доступного лимита отображаемый остаток отрицательный; факт предварительного расчёта не создаёт заявку. Финансовый alert ожидается на завершающей отправке.

## Депозит, лимит и создание

- [ ] **P2P-LIMIT-01** — Без гарантийного депозита финальная Continue показывает соответствующий alert, заявка не создана и её сумма не занята в лимите; положительный баланс не заменяет депозит.
- [ ] **P2P-LIMIT-02** — При сумме выше доступного лимита финальная Continue показывает alert превышения, заявка не создана и дополнительный резерв не появился.
- [ ] **P2P-LIMIT-03** — При сумме строго ниже доступного лимита и остальных выполненных условиях успешное создание уменьшает доступный лимит ровно на цену заявки × количество; пока заявка активна, сумма остаётся занятой.
- [ ] **P2P-LIMIT-04** — Несохранённый ввод цены/количества и обычное закрытие не занимают сумму как активная заявка; сопоставить состояние лимита до открытия и после закрытия без отправки.
- [ ] **P2P-LIMIT-05** — Повторное открытие той же активной заявки при неизменных данных не занимает сумму второй раз; сумма занята один раз, новой заявки не создано.
- [ ] **P2P-LIMIT-06** — Создание клиентом/корпом учитывается в их общем доступном лимите; заявка общая для обоих. Не ожидать отдельного финансового лимита корпа и повторного занятия суммы при открытии этой заявки другим связанным аккаунтом.
- [ ] **P2P-LIMIT-07** — У реселлера используется его лимит на основе начисленного клиентом депозита, без отдельного баланса реселлера; алгоритм перераспределения депозита — BUY-Q04 / P2P-Q04.
- [ ] **P2P-LIMIT-08** — Сумма ровно на доступный лимит: **Blocked, P2P-Q03**, допустимость включительной границы ещё не согласована.

## Актуальность на шагах

Для каждого события отдельно проверить открытие P2P, первую Continue после цены и финальную Continue после количества. Менять данные после предыдущего запроса; остальные причины отказа исключить.

- [ ] **P2P-FRESH-01** — Повышение/снижение текущей цены вызывает alert «Упс…», окно и прайс закрываются с возвратом на Главную; заявка по устаревшим данным не создаётся.
- [ ] **P2P-FRESH-02** — Изменение рейтинга вызывает тот же alert, включая прежнего лучшего поставщика/цену; возврат на Главную, новая заявка не создаётся.
- [ ] **P2P-FRESH-03** — Исчезновение товара с продажи вызывает alert «Упс…» и возврат на Главную; заявку на снятый товар отправить нельзя.
- [ ] **P2P-FRESH-04** — Изменение даты поставщиком вызывает alert «Упс…» и возврат на Главную, даже при прежних цене/рейтинге.
- [ ] **P2P-FRESH-05** — Наступление КТ админки вызывает alert «Упс…» и возврат на Главную. Определение КТ, часовой пояс и точная граница — P2P-Q08 / BUY-Q08.
- [ ] **P2P-FRESH-06** — Уменьшение остатка при остающемся в продаже товаре и прежних цене/рейтинге/дате не превращает количество заявки выше остатка в ошибку обычной покупки; по количеству действуют только 50–9999. Исключить наступление КТ и прочие причины отказа.

## Ошибки и успех

- [ ] **P2P-ERROR-01** — Отсутствие сети при переходе/отправке показывает стандартный alert, введённые цена/количество сохраняются; не подменять сетевую ошибку бизнес-alert с возвратом на Главную.
- [ ] **P2P-ERROR-02** — Ошибка сервера показывает стандартный alert с сохранением ввода. Потеря ответа после фактического создания — отдельный неподтверждённый сценарий P2P-Q06.
- [ ] **P2P-ERROR-03** — На время финального запроса Continue заблокирована; серия tap при задержке ответа не отправляет несколько заявок и не занимает лимит несколько раз. Retry после потери ответа — P2P-Q06.
- [ ] **P2P-SUCCESS-01** — Валидные цена/количество и выполненные условия: финальная Continue создаёт одну заявку с выбранными товаром, ценой и количеством, показывает toast и закрывает окно. Проверить сохранённые данные по разрешённому источнику, не только по toast.
- [ ] **P2P-SUCCESS-02** — При успехе после входа из прайса снова виден прайс, как на примере; источники кроме прайса — P2P-Q07.

## Повторное отображение активной заявки

- [ ] **P2P-ACTIVE-01** — После успешного создания открыть тот же неизменный товар из прайса и выбрать P2P: видна активная заявка с сохранёнными количеством и «Моей ценой», а не пустая форма нового создания.
- [ ] **P2P-ACTIVE-02** — Открытие товара из раздела активных заявок P2P показывает эту же активную заявку с согласованными данными; список/сортировка раздела будут описаны отдельно.
- [ ] **P2P-ACTIVE-03** — Для активной заявки переключить в Pre-Order и обратно tap/свайпом: заявка остаётся активной и отображается; переключение не удаляет заявку и не резервирует сумму повторно.
- [ ] **P2P-ACTIVE-04** — Обычное закрытие активной заявки крестиком/свайпом и повторное открытие не являются удалением: заявка сохраняется, её сумма остаётся занятой один раз. Проверки кнопки удаления отложены до раздела P2P.
- [ ] **P2P-ACTIVE-05** — Создать заявку клиентом, открыть тот же неизменный товар связанным корпом: видна та же активная заявка с её ценой/количеством; проверить обратное направление создания корпом и открытия клиентом. Оба имеют право редактировать; выполнение изменения будет проверяться в будущем разделе P2P.
- [ ] **P2P-ACTIVE-06** — На одном и том же неизменном товаре у клиента/корпа и реселлера свои заявки: после создания с разными допустимыми ценами/количествами каждый видит соответствующую ему заявку; данные не подменяются чужой заявкой. Общая заявка клиента/корпа не становится заявкой реселлера.

## Share

- [ ] **P2P-SHARE-01** — Share открывает барабан с дефолтом 0,55%; диапазон 0,25–4,25% и переход 0,95 → 1,00 → 1,25 соответствуют покупке/прайсу.
- [ ] **P2P-SHARE-02** — Excel содержит только конкретное предложение с датой/страной и ценой за единицу; конкуренты и стоимость гарантии не включаются.
- [ ] **P2P-SHARE-03** — Процент начисляется на текущую цену товара, а не на введённую «Мою цену». При текущей цене 1000, цене заявки 997 и проценте 1% цена Excel 1010. Проверить заполненную форму и активную заявку отдельно; исходные цены не менять.
- [ ] **P2P-SHARE-04** — Экспорт с разными процентами меняет цену файла, но не стартовую/введённую цену, количество, Amount, отображаемый Limit и резерв активной заявки; новое создание/изменение заявки не выполняется через Share.
- [ ] **P2P-SHARE-05** — Для реселлера база экспорта соответствует его текущей цене товара с применимыми комиссиями/наценкой клиента, а не голой цене поставщика. База наценки клиента/округление — SETTINGS-Q03 / BUY-Q10.
