# Чек-лист: Уведомления — Fimex Buyer, iOS

## Область и использование

Список событий, типы, переходы, прочтение, очистка и доступ по ролям. Не дублировать полную покупку, поддержку, P2P, оплату заказа или компенсацию.

Проверки не выполнялись. `[ ]` — Not run, не Fail. Результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Часть, зависимая от NOTIF-Qxx, Blocked до согласования. ID стабильные, снятые ID не переиспользовать.

## Предусловия

- Клиент и связанный корп с общими заказами/P2P/балансом; отдельные события поддержки/товарных подписок для каждого.
- Реселлер с собственными событиями заказа, P2P и депозита.
- Пустой список и набор всех подтверждённых типов с известными иконками/текстами из согласованной конфигурации.
- Товар доступен для покупки, отдельный товар снят после возникновения события; уведомление достижения цены при фактической цене ниже target.
- Разрешённые средства создания событий и ошибок. Не выполнять реальные финансовые действия ради прогона без подходящего тестового окружения.

## Smoke

NOTIF-OPEN-01, NOTIF-READ-01, NOTIF-NAV-01/03, NOTIF-P2P-01, NOTIF-CLEAR-01, NOTIF-EMPTY-01. Использовать результаты основных пунктов.

## Открытие, загрузка и обновление

- [ ] **NOTIF-OPEN-01** — Кнопка Главной открывает Notifications с закрытием и списком; для непустого списка доступен Clear.
- [ ] **NOTIF-OPEN-02** — Верхний крестик закрывает список и возвращает на предыдущий экран.
- [ ] **NOTIF-LOAD-01** — При подгрузке списка показывается скелетон, после успешного ответа отображается список либо пустое состояние.
- [ ] **NOTIF-LOAD-02** — При каждом новом открытии список обновляется и содержит актуально доступные события.
- [ ] **NOTIF-LOAD-03** — Новый event не добавляется автоматически в уже открытый список; после повторного открытия отображается. Прочтение события, пришедшего при открытом списке, — NOTIF-Q06.
- [ ] **NOTIF-SORT-01** — Более новые события выше старых; для проверки использовать разные времена, не задавать порядок одинаковых времён.

## Прочтение

- [ ] **NOTIF-READ-01** — Открытие списка помечает события прочитанными; после возврата на Главную точка скрыта, если новых событий не приходило.
- [ ] **NOTIF-READ-02** — Само открытие/прочтение не удаляет строки; они остаются до tap/Clear.

## Типы и данные

- [ ] **NOTIF-TYPE-01** — Ответ поставщика содержит данные соответствующей заявки/товара/ответа и иконку этого типа.
- [ ] **NOTIF-TYPE-02** — Ответ поддержки показан с иконкой и текстом поддержки; текст `11` не принимается как универсальное ожидание.
- [ ] **NOTIF-TYPE-03** — Поступление товара показывает правильный товар и иконку товарного события.
- [ ] **NOTIF-TYPE-04** — Достижение цены показывает правильный товар и фактическую цену, которая может быть ниже target.
- [ ] **NOTIF-TYPE-05** — Пополнение баланса показывает данные соответствующего пополнения; сумму не брать из соседнего события.
- [ ] **NOTIF-TYPE-06** — Смена статуса показывает правильный заказ/статус и иконку; проверить на известном номере заказа.
- [ ] **NOTIF-TYPE-07** — Оплата показывает правильные заказ и сумму; две оплаты разных заказов не смешиваются.
- [ ] **NOTIF-TYPE-08** — Компенсация за отменённый товар появляется как событие компенсации. Точные поля/иконка — NOTIF-Q02.

## Tap и назначение

- [ ] **NOTIF-NAV-01** — Смена статуса открывает детали соответствующего заказа, событие удаляется из списка.
- [ ] **NOTIF-NAV-02** — Оплата открывает детали соответствующего заказа, событие удаляется.
- [ ] **NOTIF-NAV-03** — Поступление товара открывает покупку соответствующего доступного товара, событие удаляется.
- [ ] **NOTIF-NAV-04** — Достижение цены открывает покупку соответствующего доступного товара, событие удаляется.
- [ ] **NOTIF-NAV-05** — Пополнение баланса открывает баланс; событие удаляется.
- [ ] **NOTIF-NAV-06** — Ответ поддержки открывает поддержку; событие удаляется.
- [ ] **NOTIF-NAV-07** — Компенсация открывает экран компенсации. Детали объекта назначения и удаление строки после tap — NOTIF-Q07.
- [ ] **NOTIF-P2P-01** — Tap по ответу поставщика P2P только скрывает событие, не открывает другой экран.
- [ ] **NOTIF-NAV-08** — При tap по товару, который стал недоступен, показывается alert. Удаление этой строки после отказа — NOTIF-Q03, не назначать ожидание без ответа.

## Clear и пустой список

- [ ] **NOTIF-CLEAR-01** — Clear сразу удаляет весь отображаемый список без confirm dialog.
- [ ] **NOTIF-CLEAR-02** — Clear очищает смесь разных типов событий, а не только один тип.
- [ ] **NOTIF-EMPTY-01** — После очистки показывается пустое состояние с колокольчиком и No notifications, без оставшихся строк.
- [ ] **NOTIF-EMPTY-02** — Изначально пустой ответ отображает то же состояние; на предоставленном образце нет Clear.

## Роли и общие/персональные события

- [ ] **NOTIF-ROLE-01** — Клиент и связанный корп получают общие события ответа поставщика P2P, компенсации, пополнения баланса, оплаты и смены статуса. Каждый тип проверить отдельно.
- [ ] **NOTIF-ROLE-02** — События поддержки клиента и корпа персональные; чужой ответ не появляется в другом аккаунте.
- [ ] **NOTIF-ROLE-03** — События поступления и достижения цены клиента и корпа персональные; подписка одного не создаёт товарное событие другому.
- [ ] **NOTIF-ROLE-04** — Реселлер получает собственные события смены статуса, оплаты, P2P и пополнения депозита, отдельные от событий других аккаунтов.
- [ ] **NOTIF-ROLE-05** — У реселлера нет событий поддержки и компенсации.
- [ ] **NOTIF-ROLE-06** — Персональные события одного несвязанного клиента не попадают в список другого; общность клиент/корп не расширяется на чужую группу.
- [ ] **NOTIF-ROLE-07** — Реселлер получает поступление товара и достижение выбранной цены по своим подпискам; эти события не смешиваются с событиями клиента/корпа.

## Ошибки и UI

- [ ] **NOTIF-ERROR-01** — Отсутствие интернета при загрузке вызывает стандартный alert; точный текст/retry — NOTIF-Q08.
- [ ] **NOTIF-ERROR-02** — Серверная ошибка загрузки вызывает стандартный alert, а не успешное пустое состояние.
- [ ] **NOTIF-UI-01** — Длинные тексты, названия товаров, номера заказов и суммы не перекрывают кнопки; список прокручивается, последние строки доступны.
- [ ] **NOTIF-UI-02** — В обоих языках и темах строки, иконки и пустое состояние читаемы; точные переводы — NOTIF-Q02.

## Ограничения

Синхронизация удаления общего события (NOTIF-Q04), судьба подписок/счётчика P2P после Clear (Q05), иконки/поля без согласованных образцов (Q02) не имеют выдуманных ожиданий. NOTIF-Q01 закрыт и покрыт NOTIF-ROLE-07. Прочтение списка, удаление события и удаление подписки — разные действия.
