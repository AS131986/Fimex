# Чек-лист: Детали клиентского заказа — клиент и корп, Fimex Buyer, iOS

## Область и использование

Заказ одного реселлера из «Клиентских» клиента/корпа: режимы цены, фиксированная наценка, документы, необратимая ручная оплата, подтверждённая выдача после админского Released, История и полный экран. Общая деталка и интерфейс самого реселлера имеют отдельную область.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть Blocked по CUSTDET-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент и связанный корп, связанный реселлер; другой реселлер/чужая группа для изоляции. Заказ с единственным владельцем и отличие его номера/состава от смешанного общего заказа.
- Первый/второй/Released, Not paid/Paid, собственная История. Для первого статуса будущий КТ; для выдачи админский Released при клиентском Not paid (автооплата общего заказа может быть Paid).
- Два отдельных Released-заказа для обоих порядков оплаты/выдачи; операция необратима, повторное использование уже оплаченного заказа вместо нового сценария недопустимо.
- Положительная наценка, разные проценты у позиций/разных покупок, согласованные зафиксированные цены с наценкой/без, гарантия/без, количество больше 1; один товар с разными ценами/гарантиями.
- Разрешённый источник цен/процентов покупки и возможность изменить настройку наценки после покупки; не вычислять ожидаемое округление по приблизительным числам скриншота.
- Доступ к состояниям общего баланса клиента/корпа и лимитов владельцев, документам Excel/PDF; сеть/задержки для наблюдений только если требуемая реакция согласована. Нет доступа — Blocked, не Pass.

## Smoke

CUSTDET-OPEN-01/02, CUSTDET-PRICE-01/02/03/06, CUSTDET-PAY-01/02/03/04, CUSTDET-ISSUE-01/03/04/05, CUSTDET-DOC-01/03, CUSTDET-FULL-01/03. Использовать результаты основных пунктов.

## Открытие, состав и ограничения

- [ ] **CUSTDET-OPEN-01** — Из клиентского списка открывается правильный заказ по его номеру, с ID единственного реселлера под статусом; не смешанный общий заказ.
- [ ] **CUSTDET-OPEN-02** — Клиент и связанный корп видят соответствующий один и тот же заказ/ручную отметку; товары основного клиента/корпа, другого реселлера и чужой группы не включены.
- [ ] **CUSTDET-OPEN-03** — Вкладок владельцев и All нет независимо от числа позиций: владелец один, его ID показан отдельно.
- [ ] **CUSTDET-MENU-01** — Три точки открывают меню только с Invoice/Накладной, Packing List/Упаковочным листом и IMEI/SN/Серийным номером; логиста/Cash/Online для изменения нет.
- [ ] **CUSTDET-ROW-01** — Флаг/иконка, название, цена за единицу, количество и текущая гарантия относятся к этой позиции; нет страны — иконка вместо выдуманного флага.
- [ ] **CUSTDET-ROW-02** — При нескольких единицах справа цена за единицу, не сумма позиции; Qty суммирует единицы, не число строк.
- [ ] **CUSTDET-ROW-03** — Порядок админки сохраняется в обоих режимах цены. Одинаковый товар с иной ценой покупки/гарантией остаётся отдельными позициями с собственными значениями.
- [ ] **CUSTDET-ROW-04** — Tap по товару не открывает редактор гарантии/логиста и не меняет данные, до и после КТ, в обоих режимах цены.

## Статус и таймлайн

- [ ] **CUSTDET-STATUS-01** — Иконка/цвет текущего статуса соответствует заказу: Pending assembly серый, Order pending delivery красный, Released зелёный; состояние оплаты не подменяет цвет статуса.
- [ ] **CUSTDET-STATUS-02** — В первом статусе отметка оплаты скрыта; со второго видна соответствующая ручная Paid/Not paid, также при оставшемся текущим Released.
- [ ] **CUSTDET-TIME-01** — В фокусе текущий статус, раскрытие показывает последовательность всех трёх статусов, сворачивание возвращает текущий.
- [ ] **CUSTDET-TIME-02** — Дата/время первого статуса равны КТ заказа, включая будущий КТ; у последующих наступивших фактическое время перехода, ненаступивших — без даты/времени.
- [ ] **CUSTDET-TIME-03** — Таймлайн по МСК; другое часовое поясное значение устройства не подставляет локальное время вместо МСК.

## Режим цены и фиксация наценки

- [ ] **CUSTDET-PRICE-01** — При первом и повторном открытии выбран «С наценкой»; ранее выбранная себестоимость не сохраняется как default.
- [ ] **CUSTDET-PRICE-02** — В «С наценкой» цены/Amount включают зафиксированную клиентскую наценку; у каждой позиции рядом с гарантией показан её собственный процент для этого реселлера/товара.
- [ ] **CUSTDET-PRICE-03** — В «Себестоимости» цены/Amount без клиентской наценки, её процент скрыт. Текущая гарантия/количество/тип оплаты заказа не меняются, себестоимость не становится ценой без гарантии.
- [ ] **CUSTDET-PRICE-04** — В обоих режимах Amount соответствует согласованным ценам единиц × количествам этого заказа, Qty одинакова. Зафиксированная наценка применяется к стоимости с гарантией от цены покупки; точное округление — CUSTDET-Q01, использовать цены из разрешённого источника. После смены гарантии самим реселлером открыть/обновить: актуальные гарантия/цены/количества после объединения, с правилом текущего режима.
- [ ] **CUSTDET-PRICE-05** — Повторные переключения не накапливают процент наценки и не изменяют сохранённые цены, состав/количество, гарантию, баланс/лимит или настройку наценки.
- [ ] **CUSTDET-PRICE-06** — Изменить настройку наценки после покупки, вновь открыть заказ: цены и проценты уже купленных позиций соответствуют моменту покупки, не новым настройкам; проверить обе цены/Amount и файл по текущему режиму.
- [ ] **CUSTDET-PRICE-07** — У позиций разных покупок/товаров с разными зафиксированными процентами показываются их собственные значения, не единый процент первой строки; в себестоимости все проценты скрыты.
- [ ] **CUSTDET-PRICE-08** — Выбрать себестоимость, вернуться в клиентский список: сумма ячейки/Amount списка остаётся с наценкой по его правилам; собственный список реселлера тоже не начинает показывать себестоимость.

## Ручное подтверждение оплаты

- [ ] **CUSTDET-PAY-01** — Со второго статуса tap по Not paid открывает подтверждение с предупреждением о необратимости и Cancel/Confirm; один tap не меняет отметку.
- [ ] **CUSTDET-PAY-02** — Cancel оставляет Not paid без изменения заказа/цен/суммы; повторное открытие подтверждения не означает автоматически Paid.
- [ ] **CUSTDET-PAY-03** — Confirm сразу меняет Not paid на Paid; обратный переход недоступен, повторный tap по Paid не позволяет вернуть Not paid. Точный вид недоступности — CUSTDET-Q03.
- [ ] **CUSTDET-PAY-04** — Подтверждение Paid до клиентской выдачи не меняет общий баланс клиента/корпа или лимиты владельцев, не списывает показанный Amount; это только ручная отметка, независимо от режима цены.
- [ ] **CUSTDET-PAY-05** — Общий заказ автоматически Paid, клиентский Not paid: здесь сохраняется Not paid до ручного Confirm. Пополнение баланса/повторный просмотр не заменяет его.
- [ ] **CUSTDET-PAY-06** — Оплату подтверждает клиент либо корп: другой связанный пользователь и реселлер после применимого открытия/обновления видят ту же Paid; не отдельные личные отметки.

## Клиентская выдача и оба порядка завершения

- [ ] **CUSTDET-ISSUE-01** — До админского Released кнопки «Выдать» нет, даже если ручная оплата уже Paid; после Released она появляется у ещё не выданного клиентом/корпом заказа. Не выводить доступность из расположения кнопки на примерном скриншоте.
- [ ] **CUSTDET-ISSUE-02** — Tap по доступной «Выдать» открывает подтверждение с пояснением о выдаче/оплате как условиях архивирования; без Confirm клиентская выдача не применяется. Закрытие/отмена этого окна — CUSTDET-Q02.
- [ ] **CUSTDET-ISSUE-03** — Released + Not paid: подтвердить «Выдать», вернуться/обновить списки. Заказ остаётся текущим в клиентском и собственном списке реселлера, входит в показатели, клиентская выдача сама не делает Paid.
- [ ] **CUSTDET-ISSUE-04** — Для уже выданного клиентом/корпом Not paid подтвердить Paid: после применимого обновления заказ в клиентской/собственной Истории реселлера, отсутствует в текущих строках/показателях. UI открытой деталки после последнего условия — CUSTDET-Q02.
- [ ] **CUSTDET-ISSUE-05** — Обратный порядок: подтвердить Paid, не выдавать — заказ остаётся текущим; после админского Released подтвердить клиентскую выдачу — он относится к Истории и исключается из текущих списков/показателей после обновления.
- [ ] **CUSTDET-ISSUE-06** — Один админский Released при невыполненной клиентской выдаче/оплате не архивирует заказ и не отмечает клиентское действие выполненным. Остальные заказы не завершаются вместе с выбранным.
- [ ] **CUSTDET-ISSUE-07** — Завершить последний текущий клиентский заказ обоими действиями и обновить полный клиентский список: «Нет заказов от клиентов», прежние строки/показатели/ID скрыты по CUSTORD-EMPTY-02/04. При одном выполненном действии этого состояния нет.

## Файлы по выбранной цене

- [ ] **CUSTDET-DOC-01** — Каждый из трёх документов доступен в Excel/PDF и открывает актуальный файл; все шесть сочетаний. Проверить доступность на первом/втором/Released и после КТ.
- [ ] **CUSTDET-DOC-02** — Файлы включают только товары реселлера данного клиентского заказа, не другие его заказы, общий смешанный состав или товары чужого реселлера.
- [ ] **CUSTDET-DOC-03** — «С наценкой» даёт в документах с ценами стоимость с зафиксированной наценкой; «Себестоимость» — без неё, с текущей гарантией/типом оплаты заказа. Не требовать цену/процент в каждом шаблоне без согласования колонок.
- [ ] **CUSTDET-DOC-04** — Сменить режим и вновь сформировать тот же тип/формат: цены соответствуют новому режиму, прежний кэш не выдаётся как актуальный файл. Последующее изменение настройки наценки не переоценивает старую покупку в файле.
- [ ] **CUSTDET-DOC-05** — Незаполненные IMEI/SN, состав колонок/имя/расширение и дальнейшее открытие/Share: **Blocked, CUSTDET-Q04** для точного содержимого/реакции. Общая доступность/актуальный состав подтверждены.

## Полный экран и закрытие

- [ ] **CUSTDET-FULL-01** — Full-screen открывает горизонтальный номер, переключатель цены, товары/количество/цену/гарантию; сведения совпадают с обычной деталкой.
- [ ] **CUSTDET-FULL-02** — В горизонтальном режиме переключение цены работает; с наценкой показаны соответствующие проценты, в себестоимости скрыты. Qty/гарантия/состав неизменны, редактор по tap не появляется.
- [ ] **CUSTDET-FULL-03** — Выбрать другой режим в full-screen и закрыть его крестиком: обычная деталка сохраняет выбранный режим, не сбрасывает как при новом открытии.
- [ ] **CUSTDET-CLOSE-01** — Крестик/свайп вниз обычной деталки возвращают в клиентский список; актуальная отметка оплаты/выдача учтены после возврата, существующие выбранные ID/статус списка сохранены. Исчезнувшие фильтры — CUSTORD-Q02/03.
- [ ] **CUSTDET-CLOSE-02** — После просмотра себестоимости закрыть и вновь открыть заказ: выбран «С наценкой», соответствуют цены/Amount/проценты и документы; ручная оплата/выдача не сбрасываются вместе с режимом отображения.

## Неопределённые ошибки и синхронизация

- [ ] **CUSTDET-ERROR-01** — Ошибки ручной оплаты/выдачи, retry/lost response и одновременно подтверждающие клиент/корп: **Blocked, CUSTDET-Q03** для точного UI/сохранения/перехода; прежний экран не считать подтверждением успешного действия.
- [ ] **CUSTDET-SYNC-01** — Loading/ручное обновление/real-time самой деталки, поворот/прокрутка: **Blocked, CUSTDET-Q05**. Вход из Истории и запрет редактирования проверяются в [архивном чек-листе](checklist-customer-orders-history-client-corporate.md). Поведение списка или другой деталки не подменяет эти требования.
