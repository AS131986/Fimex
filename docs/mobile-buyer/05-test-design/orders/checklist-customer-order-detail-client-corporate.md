# Чек-лист: Детали клиентского заказа — клиент и корп, Fimex Buyer, iOS

## Область и использование

Заказ одного реселлера из «Клиентских» клиента/корпа: режимы цены, фиксированная наценка, документы, необратимая ручная оплата, подтверждённая выдача после админского Released, История и полный экран. Общая деталка и интерфейс самого реселлера имеют отдельную область.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть Blocked по CUSTDET-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент и связанный корп, связанный реселлер; другой реселлер/чужая группа для изоляции. Заказ с единственным владельцем и отличие его номера/состава от смешанного общего заказа.
- Первый/второй/Released, Not paid/Paid, собственная История. Для первого статуса будущий КТ; для выдачи админский Released при клиентском Not paid (автооплата общего заказа может быть Paid).
- Два отдельных Released-заказа для обоих порядков оплаты/выдачи; операция необратима, повторное использование уже оплаченного заказа вместо нового сценария недопустимо.
- Положительная наценка, разные проценты у позиций/разных покупок, согласованные зафиксированные цены с наценкой/без, гарантия/без, количество больше 1; один товар с разными ценами/гарантиями.
- Разрешённый источник цен/процентов покупки и возможность изменить настройку наценки после покупки; не вычислять ожидаемое округление по приблизительным числам скриншота.
- Доступ к состояниям общего баланса клиента/корпа и лимитов владельцев, документам Excel/PDF; сеть/задержки для наблюдений только если требуемая реакция согласована. Нет доступа — Blocked, не Pass.

## Открытие, состав и ограничения

- [ ] **CUSTDET-OPEN-01 — Открытие деталей нужного клиентского заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Из клиентского списка открывается правильный заказ по его номеру, с ID единственного реселлера под статусом; не смешанный общий заказ.

  </details>

- [ ] **CUSTDET-OPEN-02 — Общие детали заказа клиента и корпа**

  <details>
  <summary>Подробности проверки</summary>

  - Клиент и связанный корп видят соответствующий один и тот же заказ/ручную отметку; товары основного клиента/корпа, другого реселлера и чужой группы не включены.

  </details>

- [ ] **CUSTDET-OPEN-03 — Единственный владелец без вкладок All**

  <details>
  <summary>Подробности проверки</summary>

  - Вкладок владельцев и All нет независимо от числа позиций: владелец один, его ID показан отдельно.

  </details>

- [ ] **CUSTDET-MENU-01 — Меню документов без изменения логиста и оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - Три точки открывают меню только с Invoice/Накладной, Packing List/Упаковочным листом и IMEI/SN/Серийным номером; логиста/Cash/Online для изменения нет.

  </details>

- [ ] **CUSTDET-ROW-01 — Данные позиции клиентского заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Флаг/иконка, название, цена за единицу, количество и текущая гарантия относятся к этой позиции; нет страны — иконка вместо выдуманного флага.

  </details>

- [ ] **CUSTDET-ROW-02 — Цена единицы и суммарное количество**

  <details>
  <summary>Подробности проверки</summary>

  - При нескольких единицах справа цена за единицу, не сумма позиции; Qty суммирует единицы, не число строк.

  </details>

- [ ] **CUSTDET-ROW-03 — Порядок и отдельность позиций с разной ценой и гарантией**

  <details>
  <summary>Подробности проверки</summary>

  - Порядок админки сохраняется в обоих режимах цены.
  - Одинаковый товар с иной ценой покупки/гарантией остаётся отдельными позициями с собственными значениями.

  </details>

- [ ] **CUSTDET-ROW-04 — Отсутствие редактирования по нажатию товара**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по товару не открывает редактор гарантии/логиста и не меняет данные, до и после КТ, в обоих режимах цены.

  </details>


## Статус и таймлайн

- [ ] **CUSTDET-STATUS-01 — Цвета и иконки статусов заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Иконка/цвет текущего статуса соответствует заказу: Pending assembly серый, Order pending delivery красный, Released зелёный; состояние оплаты не подменяет цвет статуса.

  </details>

- [ ] **CUSTDET-STATUS-02 — Видимость ручной отметки оплаты по статусам**

  <details>
  <summary>Подробности проверки</summary>

  - В первом статусе отметка оплаты скрыта; со второго видна соответствующая ручная Paid/Not paid, также при оставшемся текущим Released.

  </details>

- [ ] **CUSTDET-TIME-01 — Раскрытие и сворачивание таймлайна**

  <details>
  <summary>Подробности проверки</summary>

  - В фокусе текущий статус, раскрытие показывает последовательность всех трёх статусов, сворачивание возвращает текущий.

  </details>

- [ ] **CUSTDET-TIME-02 — Время КТ и фактические переходы таймлайна**

  <details>
  <summary>Подробности проверки</summary>

  - Дата/время первого статуса равны КТ заказа, включая будущий КТ; у последующих наступивших фактическое время перехода, ненаступивших — без даты/времени.

  </details>

- [ ] **CUSTDET-TIME-03 — Московское время таймлайна**

  <details>
  <summary>Подробности проверки</summary>

  - Таймлайн по МСК; другое часовое поясное значение устройства не подставляет локальное время вместо МСК.

  </details>


## Режим цены и фиксация наценки

- [ ] **CUSTDET-PRICE-01 — Дефолтный режим цены с наценкой**

  <details>
  <summary>Подробности проверки</summary>

  - При первом и повторном открытии выбран «С наценкой»; ранее выбранная себестоимость не сохраняется как default.

  </details>

- [ ] **CUSTDET-PRICE-02 — Цены и проценты в режиме с наценкой**

  <details>
  <summary>Подробности проверки</summary>

  - В «С наценкой» цены/Amount включают зафиксированную клиентскую наценку; у каждой позиции рядом с гарантией показан её собственный процент для этого реселлера/товара.

  </details>

- [ ] **CUSTDET-PRICE-03 — Себестоимость без клиентской наценки**

  <details>
  <summary>Подробности проверки</summary>

  - В «Себестоимости» цены/Amount без клиентской наценки, её процент скрыт.
  - Текущая гарантия/количество/тип оплаты заказа не меняются, себестоимость не становится ценой без гарантии.

  </details>

- [ ] **CUSTDET-PRICE-04 — Amount и Qty в обоих режимах цены**

  <details>
  <summary>Подробности проверки</summary>

  - В обоих режимах Amount соответствует согласованным ценам единиц × количествам этого заказа, Qty одинакова.
  - Зафиксированная наценка применяется к стоимости с гарантией от цены покупки; точное округление — CUSTDET-Q01, использовать цены из разрешённого источника.
  - После смены гарантии самим реселлером открыть/обновить: актуальные гарантия/цены/количества после объединения, с правилом текущего режима.

  </details>

- [ ] **CUSTDET-PRICE-05 — Отсутствие изменения заказа при переключении цены**

  <details>
  <summary>Подробности проверки</summary>

  - Повторные переключения не накапливают процент наценки и не изменяют сохранённые цены, состав/количество, гарантию, баланс/лимит или настройку наценки.

  </details>

- [ ] **CUSTDET-PRICE-06 — Зафиксированная наценка после смены настройки**

  <details>
  <summary>Подробности проверки</summary>

  - Изменить настройку наценки после покупки, вновь открыть заказ: цены и проценты уже купленных позиций соответствуют моменту покупки, не новым настройкам; проверить обе цены/Amount и файл по текущему режиму.

  </details>

- [ ] **CUSTDET-PRICE-07 — Индивидуальные проценты разных позиций**

  <details>
  <summary>Подробности проверки</summary>

  - У позиций разных покупок/товаров с разными зафиксированными процентами показываются их собственные значения, не единый процент первой строки; в себестоимости все проценты скрыты.

  </details>

- [ ] **CUSTDET-PRICE-08 — Независимость режима деталки от сумм списков**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать себестоимость, вернуться в клиентский список: сумма ячейки/Amount списка остаётся с наценкой по его правилам; собственный список реселлера тоже не начинает показывать себестоимость.

  </details>


## Ручное подтверждение оплаты

- [ ] **CUSTDET-PAY-01 — Подтверждение ручной оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - Со второго статуса tap по Not paid открывает подтверждение с предупреждением о необратимости и Cancel/Confirm; один tap не меняет отметку.

  </details>

- [ ] **CUSTDET-PAY-02 — Отмена ручной оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - Cancel оставляет Not paid без изменения заказа/цен/суммы; повторное открытие подтверждения не означает автоматически Paid.

  </details>

- [ ] **CUSTDET-PAY-03 — Необратимая отметка Paid**

  <details>
  <summary>Подробности проверки</summary>

  - Confirm сразу меняет Not paid на Paid; обратный переход недоступен, повторный tap по Paid не позволяет вернуть Not paid.
  - Точный вид недоступности — CUSTDET-Q03.

  </details>

- [ ] **CUSTDET-PAY-04 — Ручная оплата без списания баланса и лимита**

  <details>
  <summary>Подробности проверки</summary>

  - Подтверждение Paid до клиентской выдачи не меняет общий баланс клиента/корпа или лимиты владельцев, не списывает показанный Amount; это только ручная отметка, независимо от режима цены.

  </details>

- [ ] **CUSTDET-PAY-05 — Независимость ручной оплаты от автоматической**

  <details>
  <summary>Подробности проверки</summary>

  - Общий заказ автоматически Paid, клиентский Not paid: здесь сохраняется Not paid до ручного Confirm.
  - Пополнение баланса/повторный просмотр не заменяет его.

  </details>

- [ ] **CUSTDET-PAY-06 — Общая ручная отметка оплаты связанных аккаунтов**

  <details>
  <summary>Подробности проверки</summary>

  - Оплату подтверждает клиент либо корп: другой связанный пользователь и реселлер после применимого открытия/обновления видят ту же Paid; не отдельные личные отметки.

  </details>


## Клиентская выдача и оба порядка завершения

- [ ] **CUSTDET-ISSUE-01 — Доступность выдачи только после Released**

  <details>
  <summary>Подробности проверки</summary>

  - До админского Released кнопки «Выдать» нет, даже если ручная оплата уже Paid; после Released она появляется у ещё не выданного клиентом/корпом заказа.
  - Не выводить доступность из расположения кнопки на примерном скриншоте.

  </details>

- [ ] **CUSTDET-ISSUE-02 — Подтверждение клиентской выдачи**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по доступной «Выдать» открывает подтверждение с пояснением о выдаче/оплате как условиях архивирования; без Confirm клиентская выдача не применяется.
  - Закрытие/отмена этого окна — CUSTDET-Q02.

  </details>

- [ ] **CUSTDET-ISSUE-03 — Текущий заказ после выдачи без оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - Released + Not paid: подтвердить «Выдать», вернуться/обновить списки.
  - Заказ остаётся текущим в клиентском и собственном списке реселлера, входит в показатели, клиентская выдача сама не делает Paid.

  </details>

- [ ] **CUSTDET-ISSUE-04 — Архивирование после оплаты уже выданного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Для уже выданного клиентом/корпом Not paid подтвердить Paid: после применимого обновления заказ в клиентской/собственной Истории реселлера, отсутствует в текущих строках/показателях.
  - UI открытой деталки после последнего условия — CUSTDET-Q02.

  </details>

- [ ] **CUSTDET-ISSUE-05 — Архивирование после выдачи оплаченного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Обратный порядок: подтвердить Paid, не выдавать — заказ остаётся текущим; после админского Released подтвердить клиентскую выдачу — он относится к Истории и исключается из текущих списков/показателей после обновления.

  </details>

- [ ] **CUSTDET-ISSUE-06 — Недостаточность одного админского Released**

  <details>
  <summary>Подробности проверки</summary>

  - Один админский Released при невыполненной клиентской выдаче/оплате не архивирует заказ и не отмечает клиентское действие выполненным.
  - Остальные заказы не завершаются вместе с выбранным.

  </details>

- [ ] **CUSTDET-ISSUE-07 — Пустой список после завершения последнего заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Завершить последний текущий клиентский заказ обоими действиями и обновить полный клиентский список: «Нет заказов от клиентов», прежние строки/показатели/ID скрыты по CUSTORD-EMPTY-02/04.
  - При одном выполненном действии этого состояния нет.

  </details>


## Файлы по выбранной цене

- [ ] **CUSTDET-DOC-01 — Доступность шести сочетаний документов и форматов**

  <details>
  <summary>Подробности проверки</summary>

  - Каждый из трёх документов доступен в Excel/PDF и открывает актуальный файл; все шесть сочетаний.
  - Проверить доступность на первом/втором/Released и после КТ.

  </details>

- [ ] **CUSTDET-DOC-02 — Состав документов одного реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - Файлы включают только товары реселлера данного клиентского заказа, не другие его заказы, общий смешанный состав или товары чужого реселлера.

  </details>

- [ ] **CUSTDET-DOC-03 — Цены документов согласно режиму деталки**

  <details>
  <summary>Подробности проверки</summary>

  - «С наценкой» даёт в документах с ценами стоимость с зафиксированной наценкой; «Себестоимость» — без неё, с текущей гарантией/типом оплаты заказа.
  - Не требовать цену/процент в каждом шаблоне без согласования колонок.

  </details>

- [ ] **CUSTDET-DOC-04 — Актуализация документа после смены режима**

  <details>
  <summary>Подробности проверки</summary>

  - Сменить режим и вновь сформировать тот же тип/формат: цены соответствуют новому режиму, прежний кэш не выдаётся как актуальный файл.
  - Последующее изменение настройки наценки не переоценивает старую покупку в файле.

  </details>

- [ ] **CUSTDET-DOC-05 — Неуточнённые поля и открытие документов**

  <details>
  <summary>Подробности проверки</summary>

  - Незаполненные IMEI/SN, состав колонок/имя/расширение и дальнейшее открытие/Share: **Blocked, CUSTDET-Q04** для точного содержимого/реакции.
  - Общая доступность/актуальный состав подтверждены.

  </details>

- [ ] **CUSTDET-CLOSE-02 — Сброс режима цены при новом открытии деталей**

  <details>
  <summary>Подробности проверки</summary>

  </details>
