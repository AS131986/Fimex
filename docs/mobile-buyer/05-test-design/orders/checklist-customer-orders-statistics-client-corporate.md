# Чек-лист: Статистика клиентских заказов — клиент и корп, Fimex Buyer, iOS

## Область и использование

Статистика клиентских заказов клиента/корпа: продажи с наценкой, прибыль, разные проценты клиентов/товарных блоков, фильтр реселлера, сохранение бренда/реселлера между режимами, периоды, иерархия, нулевая прибыль и пустое состояние. Другие два интерфейса статистики имеют отдельную область.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неопределённая часть Blocked по CUSTSTAT-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент/связанный корп, минимум два связанных реселлера и чужая группа; отдельные личные покупки клиента/корпа, не относящиеся к клиентским заказам.
- Покупки реселлеров первого/второго/Released, Not paid/Paid и История; одинаковые покупки отображаются в общем/клиентском/собственном представлениях, не новая покупка для каждого.
- Согласованные периоды/даты, первый доступный не всегда 1M; полностью пустая клиентская статистика, один/несколько реселлеров и покупки с нулевой прибылью.
- Известные сохранённые себестоимость/цена с наценкой, количества больше 1, гарантии/тип оплаты; разные зафиксированные наценки и изменения прайса/настройки после покупки.
- Набор, где порядок по продажам отличается от порядка по денежной прибыли и среднего процента; несколько брендов/категорий/моделей/параметров. Для точного среднего нужна согласованная формула — CUSTSTAT-Q02.
- Полная и сокращённая цепочка параметров, модель без памяти с размерами/другим параметром; управляемые задержки/ошибки и изменение покупок. Нет доступа к разрешённым данным расчёта — Blocked для зависимой части, не Pass по скриншоту.

## Smoke

CUSTSTAT-OPEN-01/02/03, CUSTSTAT-PERIOD-01/03/04, CUSTSTAT-SALES-01/02, CUSTSTAT-PROFIT-01/02/04, CUSTSTAT-MODE-01/02/03, CUSTSTAT-CLIENT-02/03, CUSTSTAT-SHARE-02/03, CUSTSTAT-EMPTY-01/02. Использовать результаты основных пунктов.

## Вход, состав и загрузка

- [ ] **CUSTSTAT-OPEN-01** — График из «Клиентских заказов» клиента открывает соответствующую Статистику с периодами, «Продажи/Прибыль» и блоком клиентов, не общую или собственную статистику реселлера.
- [ ] **CUSTSTAT-OPEN-02** — Связанный корп видит ту же область покупок/суммы периода связанных реселлеров; личные покупки клиента/корпа и чужие реселлеры исключены.
- [ ] **CUSTSTAT-OPEN-03** — Открыть из списка с выбранным ID и статусом: статистика начинается со всех связанных реселлеров периода, без перенесённого ID/статуса и ограничения активными строками.
- [ ] **CUSTSTAT-OPEN-04** — Покупки, также входящие в общий смешанный/собственный заказ реселлера, учитываются один раз; личная часть общего заказа не увеличивает продажи/прибыль.
- [ ] **CUSTSTAT-LOAD-01** — При загрузке скелетон, после успеха актуальные данные/периоды либо полное пустое состояние; задержка не показывает успешное «Нет данных».
- [ ] **CUSTSTAT-LOAD-02** — Все статусы/Not paid/Paid/История входят в оба режима за период; отсутствие активных клиентских заказов при данных Истории не делает статистику пустой.

## Периоды и нулевая прибыль

- [ ] **CUSTSTAT-PERIOD-01** — Периоды 1M/3M/6M/12M, при входе первый доступный в этом порядке; наличие данных 12M не отменяет доступный 1M.
- [ ] **CUSTSTAT-PERIOD-02** — Пустой по покупкам период заблокирован/не выбирается; при отсутствии данных 1M выбран следующий доступный, не полное пустое состояние при данных другого периода.
- [ ] **CUSTSTAT-PERIOD-03** — Покупки/продажи есть, прибыль 0: период и «Прибыль» доступны, нулевая прибыль не блокирует период и не скрывает оба переключателя.
- [ ] **CUSTSTAT-PERIOD-04** — Сменить период: суммы/товарные блоки соответствуют новому набору, прежняя товарная ветка сброшена. Сохранение реселлерского фильтра/режима — CUSTSTAT-Q03, не задавать по аналогии с новым входом.
- [ ] **CUSTSTAT-PERIOD-05** — Поле даты заказа/границы месяцев/часовой пояс и доступность периодов при внутреннем реселлерском фильтре: **Blocked, CUSTSTAT-Q01**. Дата заказа/первый доступный/покупки вместо прибыли как критерий подтверждены.

## Продажи с наценкой

- [ ] **CUSTSTAT-SALES-01** — В «Продажах» сумма каждой строки/ветки включает сохранённую клиентскую наценку, гарантию, применимый Cash/Online и всё количество соответствующих покупок.
- [ ] **CUSTSTAT-SALES-02** — На наборе с положительной наценкой не подставляется себестоимость из общей статистики; покупки основного клиента/корпа/чужой группы не добавлены.
- [ ] **CUSTSTAT-SALES-03** — Суммы клиентов/брендов/категорий/моделей/параметров относятся к соответствующим наборам выбранного периода и фильтра; одноимённые ветки другой категории не смешаны.
- [ ] **CUSTSTAT-SALES-04** — Все блоки отсортированы по убыванию суммы продаж, включая клиентов и параметры; не по алфавиту/количеству/проценту наценки.
- [ ] **CUSTSTAT-SALES-05** — Изменить текущий прайс/настройку наценки без изменения старой покупки, повторно открыть/обновить: продажи старых позиций используют сохранённые значения, не новые настройки.

## Денежная прибыль

- [ ] **CUSTSTAT-PROFIT-01** — Прибыль позиции соответствует разнице её цены с наценкой и себестоимости для той же гарантии/типа оплаты × количество; при количестве больше 1 не берётся разница только одной единицы.
- [ ] **CUSTSTAT-PROFIT-02** — Прибыль строки реселлера/бренда/категории/модели/параметра соответствует заработку на покупках этого набора, не сумме продаж и не произвольной скидке/депозиту. Дополнительные расходы не вычитаются.
- [ ] **CUSTSTAT-PROFIT-03** — Неоплаченные/ещё не выданные покупки включают свою рассчитанную прибыль; ручной Paid/выдача не являются условием появления этой суммы и не создают вторую прибыль от той же покупки.
- [ ] **CUSTSTAT-PROFIT-04** — Во всех блоках режим прибыли сортирует по убыванию денежной прибыли; использовать набор, где порядок отличается от продаж и среднего процента.
- [ ] **CUSTSTAT-PROFIT-05** — При покупках с нулевой наценкой и положительными продажами прибыль соответствующих строк 0; режим доступен, покупка не скрыта как «Нет данных». Проценты/прогресс при общем нуле — CUSTSTAT-Q02.
- [ ] **CUSTSTAT-PROFIT-06** — Изменить текущую настройку наценки после покупки, вновь получить данные: прибыль прежних покупок использует зафиксированные значения, не новый процент для всей истории.

## Режим и сохранение выбора

- [ ] **CUSTSTAT-MODE-01** — При каждом новом открытии выбран «Продажи», первый доступный период и исходный набор всех связанных реселлеров; прошлый режим прибыли/входящие фильтры не сохраняются.
- [ ] **CUSTSTAT-MODE-02** — Выбрать реселлера и бренд, переключить на прибыль: оба выбора сохранены, нижние суммы относятся к тому же реселлеру/бренду, пересчитаны по прибыли.
- [ ] **CUSTSTAT-MODE-03** — Вернуться из прибыли в продажи: реселлер/бренд остаются выбранными, суммы/проценты/порядок соответствуют продажам. Изменившийся порядок не выбирает автоматически первый бренд.
- [ ] **CUSTSTAT-MODE-04** — Повторные переключения не меняют покупки/сохранённые цены/наценку, ручную оплату, баланс или лимит; прибыль не начисляется повторно как операция.
- [ ] **CUSTSTAT-MODE-05** — Категория/модель/параметры при смене режима, режим/реселлер после смены периода и гонки быстрых переключений: **Blocked, CUSTSTAT-Q03** для точного пути/UI. Сохранение реселлера/бренда подтверждено.

## Блок клиентов и фильтр

- [ ] **CUSTSTAT-CLIENT-01** — В блоке «Клиенты» иконка пользователя, ID связанного реселлера, сумма текущего режима, процент/прогресс; блок есть и при одном реселлере, это не ID-вкладки/All активного списка.
- [ ] **CUSTSTAT-CLIENT-02** — До выбора реселлера бренды видны по всем связанным реселлерам периода; выбор не обязателен для появления брендов.
- [ ] **CUSTSTAT-CLIENT-03** — Tap по строке реселлера выделяет её и фильтрует нижние блоки по его покупкам, в продажах/прибыли; чужие покупки исключены из нижних сумм.
- [ ] **CUSTSTAT-CLIENT-04** — Повторный tap того же реселлера снимает фильтр, нижний набор снова учитывает всех связанных реселлеров. Судьба выбранной товарной ветки — CUSTSTAT-Q03.
- [ ] **CUSTSTAT-CLIENT-05** — Выбрать другого реселлера: нижние данные относятся к нему, не прежнему или сумме обоих; блок клиента не переносит чужую группу.
- [ ] **CUSTSTAT-CLIENT-06** — Клиенты сортируются по сумме продаж в продажах, по денежной прибыли в прибыли; выбранный реселлер сохраняется между режимами независимо от нового порядка.
- [ ] **CUSTSTAT-CLIENT-07** — Несовместимый выбранный бренд при смене реселлера, исчезновение выбранного ID/автопрокрутка от клиентов: **Blocked, CUSTSTAT-Q03** для точного выбора/перехода; подтверждённое ограничение нижнего состава проверяется отдельно.

## Товарная иерархия

- [ ] **CUSTSTAT-BRAND-01** — У брендов соответствующие лого/названия, сумма режима, процент режима и прогресс; набор учитывает период и собственный фильтр реселлера статистики.
- [ ] **CUSTSTAT-BRAND-02** — Выбрать бренд: подсвечен прогресс, появляются его категории и автопрокрутка к ним; данные соответствуют текущему режиму/реселлеру.
- [ ] **CUSTSTAT-BRAND-03** — Сменить бренд: прежние выбранные категории/модель/параметры сброшены, новые дочерние данные не смешаны со старой веткой.
- [ ] **CUSTSTAT-CAT-01** — У категорий название/иконка/сумма/процент/прогресс, только покупки выбранного бренда; сортировка по денежной сумме текущего режима.
- [ ] **CUSTSTAT-CAT-02** — Выбор категории подсвечивает прогресс/открывает модели с автопрокруткой; смена категории сбрасывает прежнюю модель/характеристики.
- [ ] **CUSTSTAT-MODEL-01** — Модели относятся к выбранным бренду/категории, суммы/проценты режима и порядок соответствуют им; одноимённая модель иной ветки не добавлена.
- [ ] **CUSTSTAT-MODEL-02** — Выбор модели/промежуточного параметра открывает следующий имеющийся блок с подсветкой/автопрокруткой; смена родителя сбрасывает нижние выборы.
- [ ] **CUSTSTAT-ATTR-01** — Полная цепочка память→цвет→страна ограничена всеми выбранными выше параметрами и реселлером; суммы/порядок относятся к текущему режиму.
- [ ] **CUSTSTAT-ATTR-02** — Нет памяти/другого параметра — блок пропущен либо используется реальный иной параметр товара, например размеры/циферблат; данные телефона не подставляются для часов.
- [ ] **CUSTSTAT-ATTR-03** — Последний имеющийся блок не выбирается/не подсвечивает выбор/не открывает дальше, в обоих режимах, независимо от типа последнего параметра.

## Проценты двух режимов

- [ ] **CUSTSTAT-SHARE-01** — В продажах процент/прогресс реселлера — его доля продаж, бренда — доля продаж текущего набора, следующих уровней — доля соответствующего родителя; не процент наценки и не количество товаров.
- [ ] **CUSTSTAT-SHARE-02** — При ненулевой общей прибыли процент клиента равен его прибыли / общей прибыли ×100%; единственный реселлер с положительной прибылью имеет 100%, не свой процент наценки.
- [ ] **CUSTSTAT-SHARE-03** — Проценты бренда/категории/модели/параметров в прибыли — средний процент прибыли этого набора, не доля денежной прибыли от общей/родительской. Не требовать сумму средних процентов разных строк 100%; точная арифметика/шкала прогресса — CUSTSTAT-Q02.
- [ ] **CUSTSTAT-SHARE-04** — Среднее с разными наценками/ценами/количествами, проценты при общей прибыли 0, денежное округление/точность/равные суммы: **Blocked, CUSTSTAT-Q02**. Не выбирать арифметическое среднее или прибыль/продажи по сходству скриншота.

## Строка «Всего»

- [ ] **CUSTSTAT-TOTAL-01** — До фильтра/детализации в продажах «Всего» под клиентами — сумма покупок всех связанных реселлеров периода с наценкой, гарантией/типом оплаты и количествами; не общий смешанный заказ с личными покупками клиента.
- [ ] **CUSTSTAT-TOTAL-02** — «Всего» после выбора реселлера/бренда: **Blocked, CUSTSTAT-Q03** для видимости/значения. Ответ о сумме всех покупок не задаёт скрытие, прежнее правило общей статистики не переносить сюда автоматически.
- [ ] **CUSTSTAT-TOTAL-03** — Итоговая строка прибыли: на примере денежный итог; точное правило суммы/скрытия при выборе — **Blocked, CUSTSTAT-Q03** до подтверждения, не выдавать сумму продаж за установленный итог прибыли.

## Пустое состояние

- [ ] **CUSTSTAT-EMPTY-01** — У связанных реселлеров нет покупок во всех периодах после успешной загрузки: «Нет данных», текст «Ваши клиенты не совершили ни одного заказа», иконка диаграммы в синем круге на светлом примере.
- [ ] **CUSTSTAT-EMPTY-02** — Скрыты периоды и «Продажи/Прибыль», клиенты/бренды/дочерние блоки/«Всего»; заголовок/крестик остаются, нет прежних сумм/выбранной ветки.
- [ ] **CUSTSTAT-EMPTY-03** — Личные покупки клиента/корпа либо чужих реселлеров есть, связанных клиентских покупок нет: полное пустое состояние сохраняется.
- [ ] **CUSTSTAT-EMPTY-04** — Текущий клиентский список пуст при данных Истории: статистика непустая. Положительные продажи при прибыли 0 также не показываются как полное отсутствие данных.

## Обновление, ошибки и закрытие

- [ ] **CUSTSTAT-SYNC-01** — Повторное открытие получает актуальные клиентские покупки и возвращает «Продажи»/первый доступный период/исходный набор реселлеров; новая покупка не дублируется по представлениям.
- [ ] **CUSTSTAT-SYNC-02** — Пока статистика открыта, real-time изменений не требуется; открытие/смена периода получает актуальные соответствующие покупки.
- [ ] **CUSTSTAT-SYNC-03** — Pull-to-refresh обновляет суммы/состав текущего периода; путь/режим/реселлер после refresh отдельно CUSTSTAT-Q03, не подменять их сбросом повторного входа.
- [ ] **CUSTSTAT-ERROR-01** — Ошибка загрузки/смены периода/refresh показывает стандартный alert, не успешное «Нет данных»; retry/старые данные/точные тексты — CUSTSTAT-Q05.
- [ ] **CUSTSTAT-ERROR-02** — Частичные отмены/возвраты/выдачи/последующие изменения заказа, неоднородные/незаполненные параметры/fallback иконок: **Blocked, CUSTSTAT-Q04** для составов/сумм/отображения.
- [ ] **CUSTSTAT-CLOSE-01** — Крестик возвращает в исходные «Клиентские заказы»; фильтры после возврата, свайп закрытия/закрепление хедера — CUSTSTAT-Q05. Отсутствие входящих фильтров при открытии статистики подтверждено отдельно.
