# Чек-лист: Статистика клиентских заказов — клиент и корп, Fimex Buyer, iOS

## Область и использование

Статистика клиентских заказов клиента/корпа: продажи с наценкой, прибыль, разные проценты клиентов/товарных блоков, фильтр реселлера, сохранение бренда/реселлера между режимами, периоды, иерархия, нулевая прибыль и пустое состояние. Другие два интерфейса статистики имеют отдельную область.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неопределённая часть Blocked по CUSTSTAT-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент/связанный корп, минимум два связанных реселлера и чужая группа; отдельные личные покупки клиента/корпа, не относящиеся к клиентским заказам.
- Покупки реселлеров первого/второго/Released, Not paid/Paid и История; одинаковые покупки отображаются в общем/клиентском/собственном представлениях, не новая покупка для каждого.
- Согласованные периоды/даты, первый доступный не всегда 1M; полностью пустая клиентская статистика, один/несколько реселлеров и покупки с нулевой прибылью.
- Известные сохранённые себестоимость/цена с наценкой, количества больше 1, гарантии/тип оплаты; разные зафиксированные наценки и изменения прайса/настройки после покупки.
- Набор, где порядок по продажам отличается от порядка по денежной прибыли и среднего процента; несколько брендов/категорий/моделей/параметров. Для точного среднего нужна согласованная формула — CUSTSTAT-Q02.
- Полная и сокращённая цепочка параметров, модель без памяти с размерами/другим параметром; управляемые задержки/ошибки и изменение покупок. Нет доступа к разрешённым данным расчёта — Blocked для зависимой части, не Pass по скриншоту.

## Вход, состав и загрузка

- [ ] **CUSTSTAT-OPEN-01 — Открытие клиентской Статистики**

  <details>
  <summary>Подробности проверки</summary>

  - График из «Клиентских заказов» клиента открывает соответствующую Статистику с периодами, «Продажи/Прибыль» и блоком клиентов, не общую или собственную статистику реселлера.

  </details>

- [ ] **CUSTSTAT-OPEN-02 — Общая область статистики клиента и корпа**

  <details>
  <summary>Подробности проверки</summary>

  - Связанный корп видит ту же область покупок/суммы периода связанных реселлеров; личные покупки клиента/корпа и чужие реселлеры исключены.

  </details>

- [ ] **CUSTSTAT-OPEN-03 — Независимость статистики от входящих фильтров**

  <details>
  <summary>Подробности проверки</summary>

  - Открыть из списка с выбранным ID и статусом: статистика начинается со всех связанных реселлеров периода, без перенесённого ID/статуса и ограничения активными строками.

  </details>

- [ ] **CUSTSTAT-OPEN-04 — Однократный учёт реселлерских покупок**

  <details>
  <summary>Подробности проверки</summary>

  - Покупки, также входящие в общий смешанный/собственный заказ реселлера, учитываются один раз; личная часть общего заказа не увеличивает продажи/прибыль.

  </details>

- [ ] **CUSTSTAT-LOAD-01 — Скелетон загрузки клиентской статистики**

  <details>
  <summary>Подробности проверки</summary>

  - При загрузке скелетон, после успеха актуальные данные/периоды либо полное пустое состояние; задержка не показывает успешное «Нет данных».

  </details>

- [ ] **CUSTSTAT-LOAD-02 — Учёт всех статусов и архивных покупок**

  <details>
  <summary>Подробности проверки</summary>

  - Все статусы/Not paid/Paid/История входят в оба режима за период; отсутствие активных клиентских заказов при данных Истории не делает статистику пустой.

  </details>


## Периоды и нулевая прибыль

- [ ] **CUSTSTAT-PERIOD-01 — Первый доступный период статистики**

  <details>
  <summary>Подробности проверки</summary>

  - Периоды 1M/3M/6M/12M, при входе первый доступный в этом порядке; наличие данных 12M не отменяет доступный 1M.

  </details>

- [ ] **CUSTSTAT-PERIOD-02 — Блокировка периода без покупок**

  <details>
  <summary>Подробности проверки</summary>

  - Пустой по покупкам период заблокирован/не выбирается; при отсутствии данных 1M выбран следующий доступный, не полное пустое состояние при данных другого периода.

  </details>

- [ ] **CUSTSTAT-PERIOD-03 — Доступность периода с нулевой прибылью**

  <details>
  <summary>Подробности проверки</summary>

  - Покупки/продажи есть, прибыль 0: период и «Прибыль» доступны, нулевая прибыль не блокирует период и не скрывает оба переключателя.

  </details>

- [ ] **CUSTSTAT-PERIOD-04 — Смена периода со сбросом товарной ветки**

  <details>
  <summary>Подробности проверки</summary>

  - Сменить период: суммы/товарные блоки соответствуют новому набору, прежняя товарная ветка сброшена.
  - Сохранение реселлерского фильтра/режима — CUSTSTAT-Q03, не задавать по аналогии с новым входом.

  </details>

- [ ] **CUSTSTAT-PERIOD-05 — Неуточнённые границы периода и фильтр реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - Поле даты заказа/границы месяцев/часовой пояс и доступность периодов при внутреннем реселлерском фильтре: **Blocked, CUSTSTAT-Q01**.
  - Дата заказа/первый доступный/покупки вместо прибыли как критерий подтверждены.

  </details>


## Продажи с наценкой

- [ ] **CUSTSTAT-SALES-01 — Продажи с наценкой, гарантией и количеством**

  <details>
  <summary>Подробности проверки</summary>

  - В «Продажах» сумма каждой строки/ветки включает сохранённую клиентскую наценку, гарантию, применимый Cash/Online и всё количество соответствующих покупок.

  </details>

- [ ] **CUSTSTAT-SALES-02 — Исключение себестоимости и чужих продаж**

  <details>
  <summary>Подробности проверки</summary>

  - На наборе с положительной наценкой не подставляется себестоимость из общей статистики; покупки основного клиента/корпа/чужой группы не добавлены.

  </details>

- [ ] **CUSTSTAT-SALES-03 — Продажи соответствующего уровня детализации**

  <details>
  <summary>Подробности проверки</summary>

  - Суммы клиентов/брендов/категорий/моделей/параметров относятся к соответствующим наборам выбранного периода и фильтра; одноимённые ветки другой категории не смешаны.

  </details>

- [ ] **CUSTSTAT-SALES-04 — Сортировка блоков по сумме продаж**

  <details>
  <summary>Подробности проверки</summary>

  - Все блоки отсортированы по убыванию суммы продаж, включая клиентов и параметры; не по алфавиту/количеству/проценту наценки.

  </details>

- [ ] **CUSTSTAT-SALES-05 — Фиксированные цены прежних продаж**

  <details>
  <summary>Подробности проверки</summary>

  - Изменить текущий прайс/настройку наценки без изменения старой покупки, повторно открыть/обновить: продажи старых позиций используют сохранённые значения, не новые настройки.

  </details>


## Денежная прибыль

- [ ] **CUSTSTAT-PROFIT-01 — Расчёт прибыли позиции с количеством**

  <details>
  <summary>Подробности проверки</summary>

  - Прибыль позиции соответствует разнице её цены с наценкой и себестоимости для той же гарантии/типа оплаты × количество; при количестве больше 1 не берётся разница только одной единицы.

  </details>

- [ ] **CUSTSTAT-PROFIT-02 — Состав прибыли каждого набора покупок**

  <details>
  <summary>Подробности проверки</summary>

  - Прибыль строки реселлера/бренда/категории/модели/параметра соответствует заработку на покупках этого набора, не сумме продаж и не произвольной скидке/депозиту.
  - Дополнительные расходы не вычитаются.

  </details>

- [ ] **CUSTSTAT-PROFIT-03 — Прибыль неоплаченных и невыданных покупок**

  <details>
  <summary>Подробности проверки</summary>

  - Неоплаченные/ещё не выданные покупки включают свою рассчитанную прибыль; ручной Paid/выдача не являются условием появления этой суммы и не создают вторую прибыль от той же покупки.

  </details>

- [ ] **CUSTSTAT-PROFIT-04 — Сортировка блоков по денежной прибыли**

  <details>
  <summary>Подробности проверки</summary>

  - Во всех блоках режим прибыли сортирует по убыванию денежной прибыли; использовать набор, где порядок отличается от продаж и среднего процента.

  </details>

- [ ] **CUSTSTAT-PROFIT-05 — Нулевая прибыль без скрытия покупок**

  <details>
  <summary>Подробности проверки</summary>

  - При покупках с нулевой наценкой и положительными продажами прибыль соответствующих строк 0; режим доступен, покупка не скрыта как «Нет данных».
  - Проценты/прогресс при общем нуле — CUSTSTAT-Q02.

  </details>

- [ ] **CUSTSTAT-PROFIT-06 — Зафиксированная наценка в прежней прибыли**

  <details>
  <summary>Подробности проверки</summary>

  - Изменить текущую настройку наценки после покупки, вновь получить данные: прибыль прежних покупок использует зафиксированные значения, не новый процент для всей истории.

  </details>


## Режим и сохранение выбора

- [ ] **CUSTSTAT-MODE-01 — Дефолтный режим продаж при новом открытии**

  <details>
  <summary>Подробности проверки</summary>

  - При каждом новом открытии выбран «Продажи», первый доступный период и исходный набор всех связанных реселлеров; прошлый режим прибыли/входящие фильтры не сохраняются.

  </details>

- [ ] **CUSTSTAT-MODE-02 — Сохранение реселлера и бренда при переходе к прибыли**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать реселлера и бренд, переключить на прибыль: оба выбора сохранены, нижние суммы относятся к тому же реселлеру/бренду, пересчитаны по прибыли.

  </details>

- [ ] **CUSTSTAT-MODE-03 — Сохранение выбора при возврате к продажам**

  <details>
  <summary>Подробности проверки</summary>

  - Вернуться из прибыли в продажи: реселлер/бренд остаются выбранными, суммы/проценты/порядок соответствуют продажам.
  - Изменившийся порядок не выбирает автоматически первый бренд.

  </details>

- [ ] **CUSTSTAT-MODE-04 — Отсутствие финансовых изменений при переключении режима**

  <details>
  <summary>Подробности проверки</summary>

  - Повторные переключения не меняют покупки/сохранённые цены/наценку, ручную оплату, баланс или лимит; прибыль не начисляется повторно как операция.

  </details>

- [ ] **CUSTSTAT-MODE-05 — Неуточнённая сохранность нижних фильтров и гонки**

  <details>
  <summary>Подробности проверки</summary>

  - Категория/модель/параметры при смене режима, режим/реселлер после смены периода и гонки быстрых переключений: **Blocked, CUSTSTAT-Q03** для точного пути/UI. Сохранение реселлера/бренда подтверждено.

  </details>


## Блок клиентов и фильтр

- [ ] **CUSTSTAT-CLIENT-01 — Состав блока клиентов статистики**

  <details>
  <summary>Подробности проверки</summary>

  - В блоке «Клиенты» иконка пользователя, ID связанного реселлера, сумма текущего режима, процент/прогресс; блок есть и при одном реселлере, это не ID-вкладки/All активного списка.

  </details>

- [ ] **CUSTSTAT-CLIENT-02 — Общий набор брендов до выбора реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - До выбора реселлера бренды видны по всем связанным реселлерам периода; выбор не обязателен для появления брендов.

  </details>

- [ ] **CUSTSTAT-CLIENT-03 — Фильтрация статистики выбранным реселлером**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по строке реселлера выделяет её и фильтрует нижние блоки по его покупкам, в продажах/прибыли; чужие покупки исключены из нижних сумм.

  </details>

- [ ] **CUSTSTAT-CLIENT-04 — Снятие фильтра повторным нажатием реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - Повторный tap того же реселлера снимает фильтр, нижний набор снова учитывает всех связанных реселлеров.
  - Судьба выбранной товарной ветки — CUSTSTAT-Q03.

  </details>

- [ ] **CUSTSTAT-CLIENT-05 — Смена фильтра на другого реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать другого реселлера: нижние данные относятся к нему, не прежнему или сумме обоих; блок клиента не переносит чужую группу.

  </details>

- [ ] **CUSTSTAT-CLIENT-06 — Сортировка клиентов по текущему режиму**

  <details>
  <summary>Подробности проверки</summary>

  - Клиенты сортируются по сумме продаж в продажах, по денежной прибыли в прибыли; выбранный реселлер сохраняется между режимами независимо от нового порядка.

  </details>

- [ ] **CUSTSTAT-CLIENT-07 — Неуточнённые несовместимый бренд и исчезнувший ID**

  <details>
  <summary>Подробности проверки</summary>

  - Несовместимый выбранный бренд при смене реселлера, исчезновение выбранного ID/автопрокрутка от клиентов: **Blocked, CUSTSTAT-Q03** для точного выбора/перехода;
  - подтверждённое ограничение нижнего состава проверяется отдельно.

  </details>


## Товарная иерархия

- [ ] **CUSTSTAT-BRAND-01 — Состав и область данных брендов**

  <details>
  <summary>Подробности проверки</summary>

  - У брендов соответствующие лого/названия, сумма режима, процент режима и прогресс; набор учитывает период и собственный фильтр реселлера статистики.

  </details>

- [ ] **CUSTSTAT-BRAND-02 — Раскрытие категорий бренда с автопрокруткой**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать бренд: подсвечен прогресс, появляются его категории и автопрокрутка к ним; данные соответствуют текущему режиму/реселлеру.

  </details>

- [ ] **CUSTSTAT-BRAND-03 — Сброс дочерней ветки при смене бренда**

  <details>
  <summary>Подробности проверки</summary>

  - Сменить бренд: прежние выбранные категории/модель/параметры сброшены, новые дочерние данные не смешаны со старой веткой.

  </details>

- [ ] **CUSTSTAT-CAT-01 — Данные и сортировка категорий**

  <details>
  <summary>Подробности проверки</summary>

  - У категорий название/иконка/сумма/процент/прогресс, только покупки выбранного бренда; сортировка по денежной сумме текущего режима.

  </details>

- [ ] **CUSTSTAT-CAT-02 — Раскрытие моделей и сброс дочерних выборов**

  <details>
  <summary>Подробности проверки</summary>

  - Выбор категории подсвечивает прогресс/открывает модели с автопрокруткой; смена категории сбрасывает прежнюю модель/характеристики.

  </details>

- [ ] **CUSTSTAT-MODEL-01 — Принадлежность и показатели моделей**

  <details>
  <summary>Подробности проверки</summary>

  - Модели относятся к выбранным бренду/категории, суммы/проценты режима и порядок соответствуют им; одноимённая модель иной ветки не добавлена.

  </details>

- [ ] **CUSTSTAT-MODEL-02 — Последовательное раскрытие уровней детализации**

  <details>
  <summary>Подробности проверки</summary>

  - Выбор модели/промежуточного параметра открывает следующий имеющийся блок с подсветкой/автопрокруткой; смена родителя сбрасывает нижние выборы.

  </details>

- [ ] **CUSTSTAT-ATTR-01 — Полная цепочка товарных параметров**

  <details>
  <summary>Подробности проверки</summary>

  - Полная цепочка память→цвет→страна ограничена всеми выбранными выше параметрами и реселлером; суммы/порядок относятся к текущему режиму.

  </details>

- [ ] **CUSTSTAT-ATTR-02 — Пропуск отсутствующих и замена реальными параметрами**

  <details>
  <summary>Подробности проверки</summary>

  - Нет памяти/другого параметра — блок пропущен либо используется реальный иной параметр товара, например размеры/циферблат; данные телефона не подставляются для часов.

  </details>

- [ ] **CUSTSTAT-ATTR-03 — Неинтерактивный последний уровень параметров**

  <details>
  <summary>Подробности проверки</summary>

  - Последний имеющийся блок не выбирается/не подсвечивает выбор/не открывает дальше, в обоих режимах, независимо от типа последнего параметра.

  </details>


## Проценты двух режимов

- [ ] **CUSTSTAT-SHARE-01 — Доли продаж в процентах и прогрессе**

  <details>
  <summary>Подробности проверки</summary>

  - В продажах процент/прогресс реселлера — его доля продаж, бренда — доля продаж текущего набора, следующих уровней — доля соответствующего родителя; не процент наценки и не количество товаров.

  </details>

- [ ] **CUSTSTAT-SHARE-02 — Доля прибыли реселлера в общей прибыли**

  <details>
  <summary>Подробности проверки</summary>

  - При ненулевой общей прибыли процент клиента равен его прибыли / общей прибыли ×100%; единственный реселлер с положительной прибылью имеет 100%, не свой процент наценки.

  </details>

- [ ] **CUSTSTAT-SHARE-03 — Средний процент прибыли товарных уровней**

  <details>
  <summary>Подробности проверки</summary>

  - Проценты бренда/категории/модели/параметров в прибыли — средний процент прибыли этого набора, не доля денежной прибыли от общей/родительской.
  - Не требовать сумму средних процентов разных строк 100%; точная арифметика/шкала прогресса — CUSTSTAT-Q02.

  </details>

- [ ] **CUSTSTAT-SHARE-04 — Неуточнённые среднее, точность и нулевая база**

  <details>
  <summary>Подробности проверки</summary>

  - Среднее с разными наценками/ценами/количествами, проценты при общей прибыли 0, денежное округление/точность/равные суммы: **Blocked, CUSTSTAT-Q02**.
  - Не выбирать арифметическое среднее или прибыль/продажи по сходству скриншота.

  </details>


## Строка «Всего»

- [ ] **CUSTSTAT-TOTAL-01 — Общая сумма продаж до детализации**

  <details>
  <summary>Подробности проверки</summary>

  - До фильтра/детализации в продажах «Всего» под клиентами — сумма покупок всех связанных реселлеров периода с наценкой, гарантией/типом оплаты и количествами;
  - не общий смешанный заказ с личными покупками клиента.

  </details>

- [ ] **CUSTSTAT-TOTAL-02 — Неуточнённый итог при выборе реселлера и бренда**

  <details>
  <summary>Подробности проверки</summary>

  - «Всего» после выбора реселлера/бренда: **Blocked, CUSTSTAT-Q03** для видимости/значения.
  - Ответ о сумме всех покупок не задаёт скрытие, прежнее правило общей статистики не переносить сюда автоматически.

  </details>

- [ ] **CUSTSTAT-TOTAL-03 — Неуточнённый денежный итог прибыли**

  <details>
  <summary>Подробности проверки</summary>

  - Итоговая строка прибыли: на примере денежный итог; точное правило суммы/скрытия при выборе — **Blocked, CUSTSTAT-Q03** до подтверждения, не выдавать сумму продаж за установленный итог прибыли.

  </details>


## Пустое состояние

- [ ] **CUSTSTAT-EMPTY-01 — Полное пустое состояние клиентской статистики**

  <details>
  <summary>Подробности проверки</summary>

  - У связанных реселлеров нет покупок во всех периодах после успешной загрузки: «Нет данных», текст «Ваши клиенты не совершили ни одного заказа», иконка диаграммы в синем круге на светлом примере.

  </details>

- [ ] **CUSTSTAT-EMPTY-02 — Состав пустой клиентской статистики**

  <details>
  <summary>Подробности проверки</summary>

  - Скрыты периоды и «Продажи/Прибыль», клиенты/бренды/дочерние блоки/«Всего»; заголовок/крестик остаются, нет прежних сумм/выбранной ветки.

  </details>

- [ ] **CUSTSTAT-EMPTY-03 — Пустота при отсутствии связанных покупок**

  <details>
  <summary>Подробности проверки</summary>

  - Личные покупки клиента/корпа либо чужих реселлеров есть, связанных клиентских покупок нет: полное пустое состояние сохраняется.

  </details>

- [ ] **CUSTSTAT-EMPTY-04 — Статистика при архивных покупках и нулевой прибыли**

  <details>
  <summary>Подробности проверки</summary>

  - Текущий клиентский список пуст при данных Истории: статистика непустая.
  - Положительные продажи при прибыли 0 также не показываются как полное отсутствие данных.

  </details>


## Обновление, ошибки и закрытие

- [ ] **CUSTSTAT-SYNC-01 — Актуальные покупки и дефолты при повторном открытии**

  <details>
  <summary>Подробности проверки</summary>

  - Повторное открытие получает актуальные клиентские покупки и возвращает «Продажи»/первый доступный период/исходный набор реселлеров; новая покупка не дублируется по представлениям.

  </details>

- [ ] **CUSTSTAT-SYNC-02 — Актуализация без обязательного real-time**

  <details>
  <summary>Подробности проверки</summary>

  - Пока статистика открыта, real-time изменений не требуется; открытие/смена периода получает актуальные соответствующие покупки.

  </details>

- [ ] **CUSTSTAT-SYNC-03 — Обновление текущего периода жестом**

  <details>
  <summary>Подробности проверки</summary>

  - Pull-to-refresh обновляет суммы/состав текущего периода; путь/режим/реселлер после refresh отдельно CUSTSTAT-Q03, не подменять их сбросом повторного входа.

  </details>

- [ ] **CUSTSTAT-ERROR-01 — Ошибка статистики вместо пустого состояния**

  <details>
  <summary>Подробности проверки</summary>

  - Ошибка загрузки/смены периода/refresh показывает стандартный alert, не успешное «Нет данных»; retry/старые данные/точные тексты — CUSTSTAT-Q05.

  </details>

- [ ] **CUSTSTAT-ERROR-02 — Неуточнённые изменения заказов и неполные параметры**

  <details>
  <summary>Подробности проверки</summary>

  - Частичные отмены/возвраты/выдачи/последующие изменения заказа, неоднородные/незаполненные параметры/fallback иконок: **Blocked, CUSTSTAT-Q04** для составов/сумм/отображения.

  </details>

- [ ] **CUSTSTAT-CLOSE-01 — Закрытие клиентской статистики**

  <details>
  <summary>Подробности проверки</summary>

  - Крестик возвращает в исходные «Клиентские заказы»; фильтры после возврата, свайп закрытия/закрепление хедера — CUSTSTAT-Q05.
  - Отсутствие входящих фильтров при открытии статистики подтверждено отдельно.

  </details>
