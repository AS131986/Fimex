# Чек-лист: Статистика из «Моих заказов» — клиент и корп, Fimex Buyer, iOS

## Область и использование

Статистика общего списка клиента/корпа: покупки всей группы и всех статусов/оплаты/Истории, периоды, суммы без клиентской наценки, иерархия/выбор характеристик, доли/сортировка, пустое состояние и обновление. [Собственная статистика реселлера](checklist-my-orders-statistics-reseller.md) имеет отдельный чек-лист с суммами с наценкой; [клиентская статистика](checklist-customer-orders-statistics-client-corporate.md) покрывает продажи/прибыль отдельно.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неопределённая часть Blocked по ORDSTAT-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент и связанный корп с покупками обоих и минимум двух реселлеров; чужая группа для изоляции. Смешанный общий заказ и его отдельные клиентские/собственные представления для проверки отсутствия двойного учёта.
- Первый/второй/Released, Paid/Not paid, заказы в Истории; отдельно пустой активный список при данных статистики. Использовать обычные полные заказы без частичных возвратов для базовой арифметики.
- Согласованный источник состава доступных периодов и заказов в каждом; 1M доступен, 1M без данных при доступном следующем, единственный доступный период и все без данных. Не вычислять границы месяцев по догадке — ORDSTAT-Q01.
- Несколько брендов/категорий/моделей с различными суммами; количества больше 1, гарантия/тип оплаты, положительная клиентская наценка реселлеров, сохранённые цены отличаются от текущего прайса.
- Полная ветка память→цвет→страна, ветка без памяти с другим параметром (например размеры часов), сокращённая ветка с последним блоком другого типа. Только реальные параметры/иконки источника.
- Доли с дробной частью (в том числе менее 1%), согласованные ожидаемые суммы/доли; для базового процента использовать конечные дроби, не изобретать формат бесконечной дроби.
- Управляемая задержка/ошибки, возможность применимого изменения заказа/новой покупки и повторного получения данных. Нет доступа к источнику расчёта — Blocked, не Pass по приблизительным суммам скриншота.

## Smoke

ORDSTAT-OPEN-01/02, ORDSTAT-SCOPE-01/02/04, ORDSTAT-PERIOD-01/02/03, ORDSTAT-SUM-01/03, ORDSTAT-BRAND-02, ORDSTAT-CAT-02, ORDSTAT-ATTR-03/04, ORDSTAT-SHARE-01/02, ORDSTAT-TOTAL-01/02, ORDSTAT-EMPTY-01, ORDSTAT-SYNC-01/03. Использовать результаты основных пунктов.

## Вход и загрузка

- [ ] **ORDSTAT-OPEN-01 — Открытие общей статистики заказов**

  <details>
  <summary>Подробности проверки</summary>

  - График из «Моих заказов» клиента открывает эту Статистику с заголовком/крестиком, не клиентскую либо собственную статистику реселлера.

  </details>

- [ ] **ORDSTAT-OPEN-02 — Общая статистика клиента и корпа**

  <details>
  <summary>Подробности проверки</summary>

  - Связанный корп открывает тот же объём покупок группы/суммы периода, не только собственные покупки и не чужую группу.

  </details>

- [ ] **ORDSTAT-OPEN-03 — Все покупки периода без входящего фильтра**

  <details>
  <summary>Подробности проверки</summary>

  - Войти из списка с выбранным статусом: статистика включает все покупки группы периода, а не только отфильтрованные активные строки.

  </details>

- [ ] **ORDSTAT-LOAD-01 — Скелетон загрузки общей статистики**

  <details>
  <summary>Подробности проверки</summary>

  - При загрузке скелетон, после успеха актуальные периоды/бренды либо полное пустое состояние; задержка не показывается как успешное «Нет данных».

  </details>

- [ ] **ORDSTAT-LOAD-02 — Начальный набор брендов после загрузки**

  <details>
  <summary>Подробности проверки</summary>

  - После завершения загрузки показан первый доступный период с начальными брендами/«Всего»; прежние дочерние блоки не подставляются как выбранная ветка нового входа.

  </details>


## Все пользователи и состояния заказов

- [ ] **ORDSTAT-SCOPE-01 — Покупки всей связанной группы**

  <details>
  <summary>Подробности проверки</summary>

  - В суммы входят покупки клиента, связанного корпа и всех связанных реселлеров; не только пользователя, открывшего экран.
  - У всех выбран одинаковый согласованный период.

  </details>

- [ ] **ORDSTAT-SCOPE-02 — Учёт активных, неоплаченных и архивных покупок**

  <details>
  <summary>Подробности проверки</summary>

  - Входят активные/неоплаченные и уже выданные заказы Истории соответствующего периода; фильтра «только Paid» либо «только текущие» нет.

  </details>

- [ ] **ORDSTAT-SCOPE-03 — Исключение покупок чужой группы**

  <details>
  <summary>Подробности проверки</summary>

  - Чужая группа/чужой реселлер не попадают в суммы/доли даже при совпадении бренда/модели/даты.

  </details>

- [ ] **ORDSTAT-SCOPE-04 — Однократный учёт смешанного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Смешанный общий заказ с товарами реселлера и его отдельные клиентские/собственные представления: одни покупки не посчитаны повторно из-за нескольких экранов заказа.

  </details>


## Периоды

- [ ] **ORDSTAT-PERIOD-01 — Порядок периодов и доступный 1M по умолчанию**

  <details>
  <summary>Подробности проверки</summary>

  - Сегменты 1M/3M/6M/12M в этом порядке; при данных в 1M по умолчанию выбран он, наличие данных в 12M не меняет default.

  </details>

- [ ] **ORDSTAT-PERIOD-02 — Первый непустой период при отсутствии 1M**

  <details>
  <summary>Подробности проверки</summary>

  - 1M без данных: заблокирован и не выбирается, автоматически выбран первый следующий доступный.
  - Проверить согласованные источником варианты доступности, включая один доступный период.

  </details>

- [ ] **ORDSTAT-PERIOD-03 — Недоступность пустого периода**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по заблокированному пустому периоду не меняет выбранный непустой период/данные и не показывает полное пустое состояние вместо него.

  </details>

- [ ] **ORDSTAT-PERIOD-04 — Смена периода со сбросом детализации**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать другой доступный период: бренды/суммы/доли/порядок соответствуют его данным, предыдущая выбранная ветка сброшена, дочерних блоков нет, «Всего» вновь видна.

  </details>

- [ ] **ORDSTAT-PERIOD-05 — Неуточнённые временные границы статистики**

  <details>
  <summary>Подробности проверки</summary>

  - Календарные/скользящие окна, точное поле даты заказа, часовой пояс и границы месяцев: **Blocked, ORDSTAT-Q01**.
  - Критерий «дата заказа» подтверждён, не подменять его моментом выдачи без источника.

  </details>


## Стоимость покупок

- [ ] **ORDSTAT-SUM-01 — Стоимость всех единиц покупок группы**

  <details>
  <summary>Подробности проверки</summary>

  - Начальная общая сумма равна стоимости всех соответствующих товаров группы в периоде; учитываются количества, не только по одной единице каждой строки/заказа.

  </details>

- [ ] **ORDSTAT-SUM-02 — Гарантия и тип оплаты в сохранённой стоимости**

  <details>
  <summary>Подробности проверки</summary>

  - Выбранная гарантия и применимый Cash/Online учитываются в сохранённой стоимости; не показывается база без гарантии вместо суммы покупки.

  </details>

- [ ] **ORDSTAT-SUM-03 — Исключение реселлерской наценки из общей суммы**

  <details>
  <summary>Подробности проверки</summary>

  - Клиентская наценка на покупки реселлеров исключена.
  - На наборе с положительной наценкой общая сумма отличается от итоговой стоимости клиентских/реселлерских представлений на соответствующую наценку, но гарантия остаётся.

  </details>

- [ ] **ORDSTAT-SUM-04 — Сохранённые цены вместо текущего прайса**

  <details>
  <summary>Подробности проверки</summary>

  - Изменить текущий прайс/настройку клиентской наценки без изменения уже купленных позиций: после открытия/обновления статистика использует сохранённые цены заказа, не текущий каталог/новую наценку.

  </details>

- [ ] **ORDSTAT-SUM-05 — Соответствие дочерних сумм родителю**

  <details>
  <summary>Подробности проверки</summary>

  - Суммы дочерних строк соответствуют сумме их родителя по разрешённым данным и составу ветки; товары иных брендов/категорий не добавлены.
  - Частичные возвраты/изменения заказа и денежное округление отдельно ORDSTAT-Q02/04.

  </details>


## Бренды

- [ ] **ORDSTAT-BRAND-01 — Данные брендов выбранного периода**

  <details>
  <summary>Подробности проверки</summary>

  - Бренды показывают соответствующие название/лого, сумму, процент и прогресс; строки относятся к покупкам выбранного периода, не полному ассортименту.

  </details>

- [ ] **ORDSTAT-BRAND-02 — Выбор бренда с раскрытием категорий**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать бренд: его прогресс подсвечен, появился блок категорий только этого бренда, выполнена автопрокрутка к нему.

  </details>

- [ ] **ORDSTAT-BRAND-03 — Сортировка брендов по убыванию суммы**

  <details>
  <summary>Подробности проверки</summary>

  - Бренды отсортированы по сумме от большей к меньшей, не алфавиту/количеству заказов.
  - Равные суммы — ORDSTAT-Q02.

  </details>

- [ ] **ORDSTAT-BRAND-04 — Единственный бренд с долей 100%**

  <details>
  <summary>Подробности проверки</summary>

  - Бренд с единственной строкой/долей 100% показывает её как долю общего набора, не искусственное разделение; при наличии дочерних данных выбор открывает следующий блок.

  </details>


## Категории и модели

- [ ] **ORDSTAT-CAT-01 — Данные и сортировка категорий бренда**

  <details>
  <summary>Подробности проверки</summary>

  - У категории название/иконка, прогресс, сумма и процент; в блоке только покупки выбранного бренда, сортировка по сумме вниз.

  </details>

- [ ] **ORDSTAT-CAT-02 — Выбор категории с раскрытием моделей**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать категорию: подсвечен её прогресс, появились модели выбранных бренда/категории, автопрокрутка к новому блоку.

  </details>

- [ ] **ORDSTAT-CAT-03 — Изоляция одноимённых категорий разных брендов**

  <details>
  <summary>Подробности проверки</summary>

  - Одноимённая категория другого бренда не добавляется в текущие суммы/модели; смена бренда пересчитывает набор.

  </details>

- [ ] **ORDSTAT-MODEL-01 — Данные и сортировка моделей категории**

  <details>
  <summary>Подробности проверки</summary>

  - У моделей соответствующие иконка/название, сумма, процент и прогресс; порядок по убыванию суммы выбранной категории.

  </details>

- [ ] **ORDSTAT-MODEL-02 — Раскрытие параметров выбранной модели**

  <details>
  <summary>Подробности проверки</summary>

  - Выбор модели подсвечивает её прогресс и открывает следующий имеющийся параметр именно её ветки с автопрокруткой, без характеристик другой модели.

  </details>


## Параметры товара и последний блок

- [ ] **ORDSTAT-ATTR-01 — Полная цепочка памяти, цвета и страны**

  <details>
  <summary>Подробности проверки</summary>

  - Для полной ветки последовательно доступны память, цвет, страна; каждый блок ограничен всеми выбранными выше параметрами и содержит соответствующие сумму/долю/прогресс.

  </details>

- [ ] **ORDSTAT-ATTR-02 — Выбор промежуточного параметра**

  <details>
  <summary>Подробности проверки</summary>

  - Выбор памяти/цвета подсвечивает прогресс и открывает следующий имеющийся блок с автопрокруткой; суммы не включают другие значения уже выбранного параметра.

  </details>

- [ ] **ORDSTAT-ATTR-03 — Пропуск отсутствующего товарного параметра**

  <details>
  <summary>Подробности проверки</summary>

  - Модель без памяти: отсутствующий блок пропущен, используется её реальный следующий параметр, например размеры/циферблат; память телефона не подставлена для часов.

  </details>

- [ ] **ORDSTAT-ATTR-04 — Неинтерактивность последнего блока**

  <details>
  <summary>Подробности проверки</summary>

  - Последний имеющийся блок, в том числе страна либо размеры: tap ничего не выбирает, не подсвечивает выбор и не открывает новый блок/экран товара.

  </details>

- [ ] **ORDSTAT-ATTR-05 — Сортировка параметров по стоимости**

  <details>
  <summary>Подробности проверки</summary>

  - Память, цвет, страна, размеры/другие параметры сортируются по убыванию суммы этой ветки, не по объёму памяти/алфавиту/порядку каталога.

  </details>


## Доли и прогресс

- [ ] **ORDSTAT-SHARE-01 — Знаменатели долей каждого уровня**

  <details>
  <summary>Подробности проверки</summary>

  - Доля бренда от общей суммы периода, категории от выбранного бренда, модели от категории, каждого параметра от текущего родителя.
  - Данные позволяют отличить эти знаменатели от общей суммы всего периода.

  </details>

- [ ] **ORDSTAT-SHARE-02 — Сохранение дробной доли**

  <details>
  <summary>Подробности проверки</summary>

  - На конечных дробных долях, например 0,3%, дробь сохраняется вместо округления до целого; для сложных дробей точная точность/формат — ORDSTAT-Q02.

  </details>

- [ ] **ORDSTAT-SHARE-03 — Прогресс по денежной доле**

  <details>
  <summary>Подробности проверки</summary>

  - Длина прогресса соответствует денежной доле; бренд с максимальной суммой меньше 100% не растягивается до 100% только потому, что он первый.
  - Количество единиц с противоположным соотношением не подменяет долю стоимости.

  </details>

- [ ] **ORDSTAT-SHARE-04 — Пересчёт долей после смены периода и родителя**

  <details>
  <summary>Подробности проверки</summary>

  - Смена периода/родителя пересчитывает доли/прогресс от нового набора; прежний процент/знаменатель не остаются в дочернем блоке.
  - Минимальная видимая длина малой доли — ORDSTAT-Q02.

  </details>


## Смена выбранной ветки

- [ ] **ORDSTAT-SELECT-01 — Сброс нижней ветки при смене бренда**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать другую строку бренда после глубокой детализации: старые выборы/блоки ниже бренда сброшены, открыты категории нового бренда.
  - Приглушённые строки остаются доступны для смены.

  </details>

- [ ] **ORDSTAT-SELECT-02 — Сброс модели и параметров при смене категории**

  <details>
  <summary>Подробности проверки</summary>

  - Сменить категорию: выбранный бренд остаётся, прежние модель/параметры сброшены, модели относятся к новой категории.

  </details>

- [ ] **ORDSTAT-SELECT-03 — Сброс дочерних уровней при смене параметра**

  <details>
  <summary>Подробности проверки</summary>

  - Сменить модель или промежуточный параметр: выборы выше остаются в ветке, все нижние выборы/блоки сброшены; новые значения не смешаны со старым путём.

  </details>

- [ ] **ORDSTAT-SELECT-04 — Начальное состояние при повторном открытии**

  <details>
  <summary>Подробности проверки</summary>

  - Закрыть статистику после глубокой детализации, вновь открыть: первый доступный период, бренды/«Всего», без сохранённой выбранной ветки.

  </details>

- [ ] **ORDSTAT-SELECT-05 — Неуточнённые повторный выбор и прокрутка**

  <details>
  <summary>Подробности проверки</summary>

  - Повторный tap уже выбранной строки, точная позиция автопрокрутки и выбор/скролл после refresh: **Blocked, ORDSTAT-Q03** для неопределённой части.
  - Не выбирать произвольно между снятием/сохранением выбора.

  </details>


## Строка «Всего»

- [ ] **ORDSTAT-TOTAL-01 — Общая строка «Всего» до выбора бренда**

  <details>
  <summary>Подробности проверки</summary>

  - До выбора бренда под списком «Всего», равная общей сумме покупок периода/сумме строк брендов всей группы.

  </details>

- [ ] **ORDSTAT-TOTAL-02 — Скрытие «Всего» после выбора бренда**

  <details>
  <summary>Подробности проверки</summary>

  - После выбора бренда и при дальнейших уровнях «Всего» скрыта: не заменена суммой выбранного бренда/модели и не перенесена под последний блок.

  </details>

- [ ] **ORDSTAT-TOTAL-03 — Восстановление «Всего» после сброса ветки**

  <details>
  <summary>Подробности проверки</summary>

  - Сменить период либо повторно открыть статистику: выборы сброшены, «Всего» снова под брендами и соответствует текущему периоду, не предыдущей ветке.

  </details>


## Пустое состояние

- [ ] **ORDSTAT-EMPTY-01 — Полное пустое состояние статистики**

  <details>
  <summary>Подробности проверки</summary>

  - Во всех четырёх периодах нет данных после успешной загрузки: карточка с иконкой диаграммы, «Нет данных», текст «Похоже вы не совершили ни одного заказа, для отображения данных»;
  - на светлом примере синяя круглая иконка.

  </details>

- [ ] **ORDSTAT-EMPTY-02 — Состав полностью пустой статистики**

  <details>
  <summary>Подробности проверки</summary>

  - В полном пустом состоянии периоды, бренды/дочерние строки и «Всего» скрыты; заголовок/крестик остаются, нет прежних сумм/подсветки.
  - Отдельный заблокированный период при непустом другом не вызывает это состояние.

  </details>

- [ ] **ORDSTAT-EMPTY-03 — Непустая статистика при отсутствии активных заказов**

  <details>
  <summary>Подробности проверки</summary>

  - Активных заказов нет, но есть учитываемые покупки в Истории/у связанных пользователей: статистика непустая.
  - Пустота активного списка/личных покупок открывшего пользователя не подменяет пустоту всей группы периода.

  </details>


## Обновление, ошибки и закрытие

- [ ] **ORDSTAT-SYNC-01 — Актуализация покупок при повторном открытии**

  <details>
  <summary>Подробности проверки</summary>

  - Повторное открытие получает актуальные покупки группы/периоды и сбрасывает ветку; новая учитываемая покупка отражена в её бренде/общей сумме без дубля.

  </details>

- [ ] **ORDSTAT-SYNC-02 — Актуализация без обязательного real-time**

  <details>
  <summary>Подробности проверки</summary>

  - Пока статистика открыта, изменение на сервере не обязано показываться real-time; последующее открытие/смена периода получает актуальные данные.

  </details>

- [ ] **ORDSTAT-SYNC-03 — Обновление выбранного периода жестом**

  <details>
  <summary>Подробности проверки</summary>

  - Pull-to-refresh доступен и получает актуальные суммы/состав выбранного периода.
  - Судьба выбранной ветки/скролла после обновления — ORDSTAT-Q03, не требовать сброса по аналогии со сменой периода.

  </details>

- [ ] **ORDSTAT-ERROR-01 — Ошибки статистики вместо пустого состояния**

  <details>
  <summary>Подробности проверки</summary>

  - Ошибка сети/сервера при загрузке/смене периода/refresh показывает стандартный alert, не успешное «Нет данных»; точные тексты/кнопки и старые данные/retry — ORDSTAT-Q05.

  </details>

- [ ] **ORDSTAT-ERROR-02 — Неуточнённые отмены и неполные параметры**

  <details>
  <summary>Подробности проверки</summary>

  - Отменённые/частично возвращённые покупки, изменение заказа после покупки, неоднородные/незаполненные параметры/иконки: **Blocked, ORDSTAT-Q04** для состава/сумм/отображения.
  - Не переносить обычный полный заказ на эти состояния.

  </details>

- [ ] **ORDSTAT-ERROR-03 — Неуточнённые малые доли и точность сумм**

  <details>
  <summary>Подробности проверки</summary>

  - Очень малые доли/бесконечные дроби, денежные дроби, равные/нулевые суммы: **Blocked, ORDSTAT-Q02** для точного формата/порядка/прогресса.

  </details>

- [ ] **ORDSTAT-CLOSE-01 — Закрытие общей статистики**

  <details>
  <summary>Подробности проверки</summary>

  - Крестик возвращает в исходные «Мои заказы» клиента/корпа.
  - Свайп закрытия, поведение фильтра/обновления после возврата и закрепление хедера при прокрутке — ORDSTAT-Q05.

  </details>
