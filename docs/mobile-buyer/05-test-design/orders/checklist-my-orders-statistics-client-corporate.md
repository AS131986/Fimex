# Чек-лист: Статистика из «Моих заказов» — клиент и корп, Fimex Buyer, iOS

## Область и использование

Статистика общего списка клиента/корпа: покупки всей группы и всех статусов/оплаты/Истории, периоды, суммы без клиентской наценки, иерархия/выбор характеристик, доли/сортировка, пустое состояние и обновление. [Собственная статистика реселлера](checklist-my-orders-statistics-reseller.md) имеет отдельный чек-лист с суммами с наценкой; [клиентская статистика](checklist-customer-orders-statistics-client-corporate.md) покрывает продажи/прибыль отдельно.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неопределённая часть Blocked по ORDSTAT-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент и связанный корп с покупками обоих и минимум двух реселлеров; чужая группа для изоляции. Смешанный общий заказ и его отдельные клиентские/собственные представления для проверки отсутствия двойного учёта.
- Первый/второй/Released, Paid/Not paid, заказы в Истории; отдельно пустой активный список при данных статистики. Использовать обычные полные заказы без частичных возвратов для базовой арифметики.
- Согласованный источник состава доступных периодов и заказов в каждом; 1M доступен, 1M без данных при доступном следующем, единственный доступный период и все без данных. Не вычислять границы месяцев по догадке — ORDSTAT-Q01.
- Несколько брендов/категорий/моделей с различными суммами; количества больше 1, гарантия/тип оплаты, положительная клиентская наценка реселлеров, сохранённые цены отличаются от текущего прайса.
- Полная ветка память→цвет→страна, ветка без памяти с другим параметром (например размеры часов), сокращённая ветка с последним блоком другого типа. Только реальные параметры/иконки источника.
- Доли с дробной частью (в том числе менее 1%), согласованные ожидаемые суммы/доли; для базового процента использовать конечные дроби, не изобретать формат бесконечной дроби.
- Управляемая задержка/ошибки, возможность применимого изменения заказа/новой покупки и повторного получения данных. Нет доступа к источнику расчёта — Blocked, не Pass по приблизительным суммам скриншота.

## Smoke

ORDSTAT-OPEN-01/02, ORDSTAT-SCOPE-01/02/04, ORDSTAT-PERIOD-01/02/03, ORDSTAT-SUM-01/03, ORDSTAT-BRAND-02, ORDSTAT-CAT-02, ORDSTAT-ATTR-03/04, ORDSTAT-SHARE-01/02, ORDSTAT-TOTAL-01/02, ORDSTAT-EMPTY-01, ORDSTAT-SYNC-01/03. Использовать результаты основных пунктов.

## Вход и загрузка

- [ ] **ORDSTAT-OPEN-01** — График из «Моих заказов» клиента открывает эту Статистику с заголовком/крестиком, не клиентскую либо собственную статистику реселлера.
- [ ] **ORDSTAT-OPEN-02** — Связанный корп открывает тот же объём покупок группы/суммы периода, не только собственные покупки и не чужую группу.
- [ ] **ORDSTAT-OPEN-03** — Войти из списка с выбранным статусом: статистика включает все покупки группы периода, а не только отфильтрованные активные строки.
- [ ] **ORDSTAT-LOAD-01** — При загрузке скелетон, после успеха актуальные периоды/бренды либо полное пустое состояние; задержка не показывается как успешное «Нет данных».
- [ ] **ORDSTAT-LOAD-02** — После завершения загрузки показан первый доступный период с начальными брендами/«Всего»; прежние дочерние блоки не подставляются как выбранная ветка нового входа.

## Все пользователи и состояния заказов

- [ ] **ORDSTAT-SCOPE-01** — В суммы входят покупки клиента, связанного корпа и всех связанных реселлеров; не только пользователя, открывшего экран. У всех выбран одинаковый согласованный период.
- [ ] **ORDSTAT-SCOPE-02** — Входят активные/неоплаченные и уже выданные заказы Истории соответствующего периода; фильтра «только Paid» либо «только текущие» нет.
- [ ] **ORDSTAT-SCOPE-03** — Чужая группа/чужой реселлер не попадают в суммы/доли даже при совпадении бренда/модели/даты.
- [ ] **ORDSTAT-SCOPE-04** — Смешанный общий заказ с товарами реселлера и его отдельные клиентские/собственные представления: одни покупки не посчитаны повторно из-за нескольких экранов заказа.

## Периоды

- [ ] **ORDSTAT-PERIOD-01** — Сегменты 1M/3M/6M/12M в этом порядке; при данных в 1M по умолчанию выбран он, наличие данных в 12M не меняет default.
- [ ] **ORDSTAT-PERIOD-02** — 1M без данных: заблокирован и не выбирается, автоматически выбран первый следующий доступный. Проверить согласованные источником варианты доступности, включая один доступный период.
- [ ] **ORDSTAT-PERIOD-03** — Tap по заблокированному пустому периоду не меняет выбранный непустой период/данные и не показывает полное пустое состояние вместо него.
- [ ] **ORDSTAT-PERIOD-04** — Выбрать другой доступный период: бренды/суммы/доли/порядок соответствуют его данным, предыдущая выбранная ветка сброшена, дочерних блоков нет, «Всего» вновь видна.
- [ ] **ORDSTAT-PERIOD-05** — Календарные/скользящие окна, точное поле даты заказа, часовой пояс и границы месяцев: **Blocked, ORDSTAT-Q01**. Критерий «дата заказа» подтверждён, не подменять его моментом выдачи без источника.

## Стоимость покупок

- [ ] **ORDSTAT-SUM-01** — Начальная общая сумма равна стоимости всех соответствующих товаров группы в периоде; учитываются количества, не только по одной единице каждой строки/заказа.
- [ ] **ORDSTAT-SUM-02** — Выбранная гарантия и применимый Cash/Online учитываются в сохранённой стоимости; не показывается база без гарантии вместо суммы покупки.
- [ ] **ORDSTAT-SUM-03** — Клиентская наценка на покупки реселлеров исключена. На наборе с положительной наценкой общая сумма отличается от итоговой стоимости клиентских/реселлерских представлений на соответствующую наценку, но гарантия остаётся.
- [ ] **ORDSTAT-SUM-04** — Изменить текущий прайс/настройку клиентской наценки без изменения уже купленных позиций: после открытия/обновления статистика использует сохранённые цены заказа, не текущий каталог/новую наценку.
- [ ] **ORDSTAT-SUM-05** — Суммы дочерних строк соответствуют сумме их родителя по разрешённым данным и составу ветки; товары иных брендов/категорий не добавлены. Частичные возвраты/изменения заказа и денежное округление отдельно ORDSTAT-Q02/04.

## Бренды

- [ ] **ORDSTAT-BRAND-01** — Бренды показывают соответствующие название/лого, сумму, процент и прогресс; строки относятся к покупкам выбранного периода, не полному ассортименту.
- [ ] **ORDSTAT-BRAND-02** — Выбрать бренд: его прогресс подсвечен, появился блок категорий только этого бренда, выполнена автопрокрутка к нему.
- [ ] **ORDSTAT-BRAND-03** — Бренды отсортированы по сумме от большей к меньшей, не алфавиту/количеству заказов. Равные суммы — ORDSTAT-Q02.
- [ ] **ORDSTAT-BRAND-04** — Бренд с единственной строкой/долей 100% показывает её как долю общего набора, не искусственное разделение; при наличии дочерних данных выбор открывает следующий блок.

## Категории и модели

- [ ] **ORDSTAT-CAT-01** — У категории название/иконка, прогресс, сумма и процент; в блоке только покупки выбранного бренда, сортировка по сумме вниз.
- [ ] **ORDSTAT-CAT-02** — Выбрать категорию: подсвечен её прогресс, появились модели выбранных бренда/категории, автопрокрутка к новому блоку.
- [ ] **ORDSTAT-CAT-03** — Одноимённая категория другого бренда не добавляется в текущие суммы/модели; смена бренда пересчитывает набор.
- [ ] **ORDSTAT-MODEL-01** — У моделей соответствующие иконка/название, сумма, процент и прогресс; порядок по убыванию суммы выбранной категории.
- [ ] **ORDSTAT-MODEL-02** — Выбор модели подсвечивает её прогресс и открывает следующий имеющийся параметр именно её ветки с автопрокруткой, без характеристик другой модели.

## Параметры товара и последний блок

- [ ] **ORDSTAT-ATTR-01** — Для полной ветки последовательно доступны память, цвет, страна; каждый блок ограничен всеми выбранными выше параметрами и содержит соответствующие сумму/долю/прогресс.
- [ ] **ORDSTAT-ATTR-02** — Выбор памяти/цвета подсвечивает прогресс и открывает следующий имеющийся блок с автопрокруткой; суммы не включают другие значения уже выбранного параметра.
- [ ] **ORDSTAT-ATTR-03** — Модель без памяти: отсутствующий блок пропущен, используется её реальный следующий параметр, например размеры/циферблат; память телефона не подставлена для часов.
- [ ] **ORDSTAT-ATTR-04** — Последний имеющийся блок, в том числе страна либо размеры: tap ничего не выбирает, не подсвечивает выбор и не открывает новый блок/экран товара.
- [ ] **ORDSTAT-ATTR-05** — Память, цвет, страна, размеры/другие параметры сортируются по убыванию суммы этой ветки, не по объёму памяти/алфавиту/порядку каталога.

## Доли и прогресс

- [ ] **ORDSTAT-SHARE-01** — Доля бренда от общей суммы периода, категории от выбранного бренда, модели от категории, каждого параметра от текущего родителя. Данные позволяют отличить эти знаменатели от общей суммы всего периода.
- [ ] **ORDSTAT-SHARE-02** — На конечных дробных долях, например 0,3%, дробь сохраняется вместо округления до целого; для сложных дробей точная точность/формат — ORDSTAT-Q02.
- [ ] **ORDSTAT-SHARE-03** — Длина прогресса соответствует денежной доле; бренд с максимальной суммой меньше 100% не растягивается до 100% только потому, что он первый. Количество единиц с противоположным соотношением не подменяет долю стоимости.
- [ ] **ORDSTAT-SHARE-04** — Смена периода/родителя пересчитывает доли/прогресс от нового набора; прежний процент/знаменатель не остаются в дочернем блоке. Минимальная видимая длина малой доли — ORDSTAT-Q02.

## Смена выбранной ветки

- [ ] **ORDSTAT-SELECT-01** — Выбрать другую строку бренда после глубокой детализации: старые выборы/блоки ниже бренда сброшены, открыты категории нового бренда. Приглушённые строки остаются доступны для смены.
- [ ] **ORDSTAT-SELECT-02** — Сменить категорию: выбранный бренд остаётся, прежние модель/параметры сброшены, модели относятся к новой категории.
- [ ] **ORDSTAT-SELECT-03** — Сменить модель или промежуточный параметр: выборы выше остаются в ветке, все нижние выборы/блоки сброшены; новые значения не смешаны со старым путём.
- [ ] **ORDSTAT-SELECT-04** — Закрыть статистику после глубокой детализации, вновь открыть: первый доступный период, бренды/«Всего», без сохранённой выбранной ветки.
- [ ] **ORDSTAT-SELECT-05** — Повторный tap уже выбранной строки, точная позиция автопрокрутки и выбор/скролл после refresh: **Blocked, ORDSTAT-Q03** для неопределённой части. Не выбирать произвольно между снятием/сохранением выбора.

## Строка «Всего»

- [ ] **ORDSTAT-TOTAL-01** — До выбора бренда под списком «Всего», равная общей сумме покупок периода/сумме строк брендов всей группы.
- [ ] **ORDSTAT-TOTAL-02** — После выбора бренда и при дальнейших уровнях «Всего» скрыта: не заменена суммой выбранного бренда/модели и не перенесена под последний блок.
- [ ] **ORDSTAT-TOTAL-03** — Сменить период либо повторно открыть статистику: выборы сброшены, «Всего» снова под брендами и соответствует текущему периоду, не предыдущей ветке.

## Пустое состояние

- [ ] **ORDSTAT-EMPTY-01** — Во всех четырёх периодах нет данных после успешной загрузки: карточка с иконкой диаграммы, «Нет данных», текст «Похоже вы не совершили ни одного заказа, для отображения данных»; на светлом примере синяя круглая иконка.
- [ ] **ORDSTAT-EMPTY-02** — В полном пустом состоянии периоды, бренды/дочерние строки и «Всего» скрыты; заголовок/крестик остаются, нет прежних сумм/подсветки. Отдельный заблокированный период при непустом другом не вызывает это состояние.
- [ ] **ORDSTAT-EMPTY-03** — Активных заказов нет, но есть учитываемые покупки в Истории/у связанных пользователей: статистика непустая. Пустота активного списка/личных покупок открывшего пользователя не подменяет пустоту всей группы периода.

## Обновление, ошибки и закрытие

- [ ] **ORDSTAT-SYNC-01** — Повторное открытие получает актуальные покупки группы/периоды и сбрасывает ветку; новая учитываемая покупка отражена в её бренде/общей сумме без дубля.
- [ ] **ORDSTAT-SYNC-02** — Пока статистика открыта, изменение на сервере не обязано показываться real-time; последующее открытие/смена периода получает актуальные данные.
- [ ] **ORDSTAT-SYNC-03** — Pull-to-refresh доступен и получает актуальные суммы/состав выбранного периода. Судьба выбранной ветки/скролла после обновления — ORDSTAT-Q03, не требовать сброса по аналогии со сменой периода.
- [ ] **ORDSTAT-ERROR-01** — Ошибка сети/сервера при загрузке/смене периода/refresh показывает стандартный alert, не успешное «Нет данных»; точные тексты/кнопки и старые данные/retry — ORDSTAT-Q05.
- [ ] **ORDSTAT-ERROR-02** — Отменённые/частично возвращённые покупки, изменение заказа после покупки, неоднородные/незаполненные параметры/иконки: **Blocked, ORDSTAT-Q04** для состава/сумм/отображения. Не переносить обычный полный заказ на эти состояния.
- [ ] **ORDSTAT-ERROR-03** — Очень малые доли/бесконечные дроби, денежные дроби, равные/нулевые суммы: **Blocked, ORDSTAT-Q02** для точного формата/порядка/прогресса.
- [ ] **ORDSTAT-CLOSE-01** — Крестик возвращает в исходные «Мои заказы» клиента/корпа. Свайп закрытия, поведение фильтра/обновления после возврата и закрепление хедера при прокрутке — ORDSTAT-Q05.
