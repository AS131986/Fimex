# Чек-лист: Клиентские заказы — клиент и корп, Fimex Buyer, iOS

## Область и использование

Проверяется список заказов реселлеров в интерфейсе клиента/корпа: состав, отдельные номера, фильтры, показатели с наценкой, ручная оплата, условия Истории, обновление и пустое состояние. [Детали клиентского заказа](checklist-customer-order-detail-client-corporate.md) и [клиентская статистика](checklist-customer-orders-statistics-client-corporate.md) имеют собственные чек-листы; [История и архивный заказ](checklist-customer-orders-history-client-corporate.md) проверяются отдельно, интерфейс самого реселлера вне области.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть ожиданий Blocked по CUSTORD-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент и связанный корп; чужая группа для изоляции. Доступ к режиму реселлера включён/выключен для проверки меню.
- Два связанных реселлера с покупками на одну дату поставщика и отдельными заказами; в общем заказе есть также покупки клиента/корпа. Отдельный набор с одним реселлером.
- Pending assembly и Order pending delivery, разные даты поставщика; Released с невыполненными клиентскими условиями завершения и заказы, уже завершённые для клиентской Истории.
- Набор, где число единиц отличается от числа позиций/карточек. Известные согласованные суммы с положительной наценкой, Cash/Online и гарантией/без; без частичных отмен/выдач для базовой арифметики.
- У первого реселлера оба статуса, у второго только один: для независимого меню статусов и скрытия вкладок при фильтрации.
- Общий заказ Paid, соответствующий клиентский заказ Not paid; возможность вручную отметить оплату/выдать в разрешённой тестовой среде.
- Пустой клиентский список, последний текущий заказ и возможность добавить новый; общий список и История могут оставаться непустыми. Числа заказов общего и клиентского списков различаются для проверки бейджа.
- Возможность задержать ответ/отключить сеть/получить ошибку сервера. Нет необходимых данных или доступа — Blocked, не Pass.

## Smoke

CUSTORD-OPEN-01, CUSTORD-ROLE-01/02, CUSTORD-GROUP-01/02, CUSTORD-FILTER-04/05, CUSTORD-SUM-02/03, CUSTORD-PAY-03, CUSTORD-HISTORY-02/03, CUSTORD-BADGE-01, CUSTORD-EMPTY-01/02. Использовать результаты основных пунктов.

## Открытие, роли и переходы

- [ ] **CUSTORD-OPEN-01** — Раздел заказов по умолчанию открывает «Мои заказы»; через три точки выбрать «Клиентские»: заголовок и содержимое меняются на клиентский список, нижняя вкладка заказов остаётся активной.
- [ ] **CUSTORD-ROLE-01** — Клиент видит только заказы своих связанных реселлеров; собственные покупки клиента/корпа и заказы чужой группы не включены.
- [ ] **CUSTORD-ROLE-02** — Связанный корп видит тот же клиентский набор реселлеров; отсутствие собственных покупок корпа не делает его список пустым.
- [ ] **CUSTORD-HEADER-01** — Три точки показаны клиенту/корпу при включённом доступе к режиму реселлера и скрыты при выключенном; обе роли. Поведение при отключении во время просмотра — CUSTORD-Q03.
- [ ] **CUSTORD-HEADER-02** — Меню позволяет вернуться из «Клиентских» в «Мои заказы»; состав и цены соответствуют выбранному списку. Сохранение фильтров при таком переключении — CUSTORD-Q02.
- [ ] **CUSTORD-HEADER-03** — График открывает клиентскую Статистику с «Продажами/Прибылью», всех связанных реселлеров периода, без переданных ID/статуса активного списка; книга — клиентскую Историю. Не общая статистика клиента/корпа или собственная реселлера; полные проверки статистики и Истории отдельно; выбранные ID/статус списка в Историю не передаются.
- [ ] **CUSTORD-OPEN-02** — Tap по ячейке открывает правильный заказ реселлера по его номеру; не общий смешанный заказ и не соседнюю строку.
- [ ] **CUSTORD-OPEN-03** — Выбрать ID и статус, открыть соответствующий заказ и вернуться: остаются «Клиентские», выбранные ID/статус, данные обновлены. ID и статус должны ещё существовать; иначе CUSTORD-Q02/03.
- [ ] **CUSTORD-OPEN-04** — Из «Клиентских» перейти в другой нижний раздел и вернуться в заказы: выбраны «Мои заказы», состояние по умолчанию; клиентские фильтры не подставляются в общий список.

## Отдельные заказы реселлеров

- [ ] **CUSTORD-GROUP-01** — Товары двух реселлеров на одну дату поставщика отображаются в отдельных клиентских заказах; ни одна карточка/деталь не объединяет товары разных реселлеров.
- [ ] **CUSTORD-GROUP-02** — Эти заказы имеют разные номера; tap по каждому открывает его собственный набор товаров. Совпадение даты не делает номер общим.
- [ ] **CUSTORD-GROUP-03** — Для общего заказа с товарами клиента/корпа и двух реселлеров клиентский список содержит только соответствующие реселлерские заказы; товары клиента/корпа не входят в строки, Qty или Amount.
- [ ] **CUSTORD-GROUP-04** — Выбор ID одного реселлера не показывает заказ другого, даже если их товары входят в один общий заказ «Моих заказов».

## Вкладки и совместная фильтрация

- [ ] **CUSTORD-TABS-01** — Без фильтра при одном реселлере с текущими заказами показана его вкладка ID, All отсутствует; ID реселлера без текущих заказов не показан.
- [ ] **CUSTORD-TABS-02** — Без фильтра при нескольких реселлерах показаны All и их ID; каждый ID соответствует владельцу товаров. Порядок и выбор по умолчанию — CUSTORD-Q02.
- [ ] **CUSTORD-TABS-03** — Tap по ID показывает только его заказы; tap по All возвращает заказы всех соответствующих реселлеров с учётом выбранного статуса.
- [ ] **CUSTORD-TABS-04** — Горизонтальный свайп не переключает вкладку реселлера; переключение выполняется тапом.
- [ ] **CUSTORD-FILTER-01** — При нескольких статусах в полном клиентском списке фильтр доступен; при одном/нуле скрыт. Проверить оба одиночных статуса, затем набор с несколькими.
- [ ] **CUSTORD-FILTER-02** — Выбрать ID с одним статусом, когда у другого есть иной: меню содержит статусы полного клиентского списка, не только выбранного ID.
- [ ] **CUSTORD-FILTER-03** — Выбрать один статус из полного набора с несколькими: меню не ограничивается выбранным статусом; доступен переход к другому имеющемуся статусу и к All.
- [ ] **CUSTORD-FILTER-04** — При ID и статусе показано пересечение условий, не объединение. Проверить оба порядка выбора на наборе с непустым пересечением.
- [ ] **CUSTORD-FILTER-05** — При выборе статуса вкладки реселлеров без таких заказов скрыты; ID с подходящими заказами остаются. Снятие фильтра возвращает вкладки с текущими заказами. Поведение All при одном оставшемся ID — CUSTORD-Q02.
- [ ] **CUSTORD-FILTER-06** — Изменение статуса/завершение заказа и refresh обновляет доступные вкладки и набор статусов по актуальным данным. Выбор после исчезновения текущего ID/статуса — **Blocked, CUSTORD-Q02/03**.
- [ ] **CUSTORD-FILTER-07** — Пустое пересечение ID и статуса: вкладки без данных скрываются; точный текст, Qty/Amount и сохранение/смена выбора — **Blocked, CUSTORD-Q02/03**. Не ожидать автоматически «Нет заказов от клиентов» или сброс к All.

## Показатели, суммы и ячейки

- [ ] **CUSTORD-SUM-01** — Qty/Amount не кликабельны: tap не меняет фильтр и не открывает экран.
- [ ] **CUSTORD-SUM-02** — Qty равна сумме единиц товара в текущем наборе клиентских заказов, а не числу карточек/позиций. Покупки клиента/корпа из общего заказа исключены.
- [ ] **CUSTORD-SUM-03** — Amount равна сумме текущих клиентских заказов с наценкой клиента, применённой к стоимости с гарантией от зафиксированной цены покупки, и типом оплаты. После смены гарантии самим реселлером обновить список: сумма актуальна, Qty/число заказов не меняются от объединения товарных позиций. Использовать известные цены заказа; точное округление/изменения конфигурации — CUSTORD-Q04.
- [ ] **CUSTORD-SUM-04** — Qty/Amount пересчитываются при ID, статусе и их совместном выборе; All возвращает сумму соответствующего набора. Использовать наборы с разными итогами.
- [ ] **CUSTORD-SUM-05** — Незавершённый для клиентской Истории заказ остаётся в текущих Qty/Amount; после выполнения двух условий и обновления исключается из списка и показателей.
- [ ] **CUSTORD-ROW-01** — Номер, дата поставщика, Cash/Online и сумма в ячейке принадлежат одному клиентскому заказу, не смешанному общему заказу.
- [ ] **CUSTORD-ROW-02** — Дата равна дате поставщика без дней доставки. Задать ненулевую доставку, чтобы отличалась от даты покупки/прайса.
- [ ] **CUSTORD-ROW-03** — Сумма ячейки включает наценку клиента и стоимость гарантии с соответствующим Cash/Online. При положительной наценке не копируется цена без неё из «Моих заказов»; чужие товары не включены.
- [ ] **CUSTORD-ROW-04** — Pending assembly серый, Order pending delivery красный, Released зелёный. Жёлтый из примера другого приложения не используется как требование дополнительного статуса.
- [ ] **CUSTORD-SORT-01** — Более поздний статус выше раннего независимо от дат; оставшийся в текущем списке Released располагается выше второго и первого статуса.
- [ ] **CUSTORD-SORT-02** — Внутри каждого статуса сверху более старые даты поставщика; проверить All и выбранный ID/статус. При противоположном порядке создания в Fimex используется дата поставщика; равные даты — CUSTORD-Q01.

## Независимая отметка оплаты и завершение

- [ ] **CUSTORD-PAY-01** — В Pending assembly состояние оплаты скрыто; начиная с Order pending delivery показано соответствующее Paid/Not paid, в том числе для оставшегося Released.
- [ ] **CUSTORD-PAY-02** — Ручное подтверждение Not paid → Paid клиентом/корпом отражается в ячейке после возврата; обратно недоступно. Подробные действия в отдельной деталке CUSTDET-PAY-01/02/03/04, отметка не меняет баланс/лимит.
- [ ] **CUSTORD-PAY-03** — Общий заказ «Моих заказов» Paid, соответствующий клиентский Not paid: в «Клиентских» сохраняется Not paid. Автоплата/пополнение баланса общего заказа не заменяет ручную отметку.
- [ ] **CUSTORD-PAY-04** — После ручного изменения другой связанный пользователь (клиент/корп) открывает/обновляет список: видит ту же отметку по этому заказу; состояние не персональное для каждой роли.
- [ ] **CUSTORD-HISTORY-01** — Перевод соответствующего заказа по статусам до Released при клиентском Not paid не меняет ручную отметку и сам по себе не переносит его в клиентскую Историю.
- [ ] **CUSTORD-HISTORY-02** — После админского Released нажать «Выдать» при Not paid и подтвердить: действие разрешено, заказ остаётся текущим; после ручного Confirm оплаты и обновления переходит в клиентскую Историю.
- [ ] **CUSTORD-HISTORY-03** — Подтвердить Paid без клиентской выдачи: заказ остаётся текущим, одного Paid недостаточно. После админского Released подтвердить «Выдать» и обновить — заказ в Истории. Этот обратный порядок подтверждён деталкой.
- [ ] **CUSTORD-HISTORY-04** — После обоих подтверждённых условий заказ находится в клиентской Истории, отсутствует в текущих строках и показателях после возврата/refresh; остальные заказы не завершаются вместе с ним.
- [ ] **CUSTORD-ACTIONS-01** — В активном клиентском заказе клиент/корп не могут изменить гарантию или Cash/Online; доступные действия — отметка оплаты и выдача. Проверить обе роли, не придумывая способ блокировки неописанного экрана.
- [ ] **CUSTORD-ACTIONS-02** — Ручной Paid не меняет баланс/лимит; «Выдать» доступна после админского Released и требует Confirm. Момент освобождения лимита при выдаче остаётся **Blocked, CUSTORD-Q05/CUSTDET-Q02**; не ожидать освобождения по одному ручному Paid.

## Бейдж нижнего меню

- [ ] **CUSTORD-BADGE-01** — При разных количествах заказов двух списков переключиться из «Моих» в «Клиентские»: бейдж нижней вкладки заказов меняется на количество текущих клиентских заказов, не на Qty единиц или число реселлеров.
- [ ] **CUSTORD-BADGE-02** — Вернуться через меню в «Мои заказы»: бейдж соответствует общему списку; затем снова выбрать «Клиентские» и проверить их число. Повторное переключение не суммирует значения двух списков.
- [ ] **CUSTORD-BADGE-03** — Уйти из «Клиентских» в другой нижний раздел и вернуться: открыты «Мои заказы», бейдж соответствует этому списку, а не прежнему клиентскому. Влияние ID/статуса на бейдж — CUSTORD-Q03; нулевой/большой формат и обновление при событиях — NAV-Q02.

## Пустое состояние

- [ ] **CUSTORD-EMPTY-01** — Полностью пустой текущий клиентский список после успешной загрузки: иконка квитанции и «Нет заказов от клиентов», без дополнительного пояснения. Русский светлый вариант — синяя иконка, как в примере; не бесконечный скелетон и не ошибка.
- [ ] **CUSTORD-EMPTY-02** — В этом состоянии скрыты строки, Qty/Amount, вкладки ID/All и фильтр; остаются заголовок, Статистика, История, нижнее меню. Три точки согласно доступу; не остаются старые суммы/вкладки.
- [ ] **CUSTORD-EMPTY-03** — В «Моих заказах» есть покупки клиента/корпа, либо клиентские заказы есть только в Истории: текущие «Клиентские» всё равно пусты; клиентская История доступна.
- [ ] **CUSTORD-EMPTY-04** — Выполнить условия завершения последнего текущего клиентского заказа и обновить: пустая карточка без старой строки/показателей/ID. Только «Выдать» при Not paid или только Paid не вызывает это состояние.
- [ ] **CUSTORD-EMPTY-05** — После нового заказа реселлера обновить ранее пустой клиентский список: карточка исчезает, появляются заказ, актуальные показатели и его ID; для одного реселлера All не показана.

## Загрузка, обновление и ошибки

- [ ] **CUSTORD-LOAD-01** — При загрузке показан скелетон, после ответа — актуальный клиентский список либо полное пустое состояние; старый общий список не выдаётся за клиентский.
- [ ] **CUSTORD-LOAD-02** — Длинный скрол вниз запускает refresh со скелетоном и возвращает актуальные строки/показатели/вкладки без дублей заказов.
- [ ] **CUSTORD-SYNC-01** — Изменение на сервере при открытом списке не обязано показываться в real-time; открытие, возврат из заказа или refresh получает новые данные.
- [ ] **CUSTORD-SYNC-02** — После ручной оплаты/выдачи возврат из заказа сразу обновляет список и показатели с сохранением существующих выбранных ID/статуса; исчезнувшие варианты — CUSTORD-Q02/03.
- [ ] **CUSTORD-ERROR-01** — Ошибка сети при загрузке/refresh показывает стандартный alert; не трактуется как отсутствие заказов. Состояние старых данных и retry — CUSTORD-Q06.
- [ ] **CUSTORD-ERROR-02** — Ошибка сервера при загрузке/refresh показывает стандартный alert, не успешную карточку пустого списка; точные тексты/состояние/повтор — CUSTORD-Q06.
