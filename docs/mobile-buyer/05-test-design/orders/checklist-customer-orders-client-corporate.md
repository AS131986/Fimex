# Чек-лист: Клиентские заказы — клиент и корп, Fimex Buyer, iOS

## Область и использование

Проверяется список заказов реселлеров в интерфейсе клиента/корпа: состав, отдельные номера, фильтры, показатели с наценкой, ручная оплата, условия Истории, обновление и пустое состояние. [Детали клиентского заказа](checklist-customer-order-detail-client-corporate.md) и [клиентская статистика](checklist-customer-orders-statistics-client-corporate.md) имеют собственные чек-листы; [История и архивный заказ](checklist-customer-orders-history-client-corporate.md) проверяются отдельно, интерфейс самого реселлера вне области.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть ожиданий Blocked по CUSTORD-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент и связанный корп; чужая группа для изоляции. Доступ к режиму реселлера включён/выключен для проверки меню.
- Два связанных реселлера с покупками на одну дату поставщика и отдельными заказами; в общем заказе есть также покупки клиента/корпа. Отдельный набор с одним реселлером.
- Pending assembly и Order pending delivery, разные даты поставщика; Released с невыполненными клиентскими условиями завершения и заказы, уже завершённые для клиентской Истории.
- Набор, где число единиц отличается от числа позиций/карточек. Известные согласованные суммы с положительной наценкой, Cash/Online и гарантией/без; без частичных отмен/выдач для базовой арифметики.
- У первого реселлера оба статуса, у второго только один: для независимого меню статусов и скрытия вкладок при фильтрации.
- Общий заказ Paid, соответствующий клиентский заказ Not paid; возможность вручную отметить оплату/выдать в разрешённой тестовой среде.
- Пустой клиентский список, последний текущий заказ и возможность добавить новый; общий список и История могут оставаться непустыми. Числа заказов общего и клиентского списков различаются для проверки бейджа.
- Возможность задержать ответ/отключить сеть/получить ошибку сервера. Нет необходимых данных или доступа — Blocked, не Pass.

CUSTORD-OPEN-01, CUSTORD-ROLE-01/02, CUSTORD-GROUP-01/02, CUSTORD-FILTER-04/05, CUSTORD-SUM-02/03, CUSTORD-PAY-03, CUSTORD-HISTORY-02/03, CUSTORD-BADGE-01, CUSTORD-EMPTY-01/02. Использовать результаты основных пунктов.

## Открытие, роли и переходы

- [ ] **CUSTORD-OPEN-01 — Переход к клиентским заказам из общего списка**

  <details>
  <summary>Подробности проверки</summary>

  - Раздел заказов по умолчанию открывает «Мои заказы»; через три точки выбрать «Клиентские»: заголовок и содержимое меняются на клиентский список, нижняя вкладка заказов остаётся активной.

  </details>

- [ ] **CUSTORD-ROLE-01 — Состав клиентских заказов основной роли**

  <details>
  <summary>Подробности проверки</summary>

  - Клиент видит только заказы своих связанных реселлеров; собственные покупки клиента/корпа и заказы чужой группы не включены.

  </details>

- [ ] **CUSTORD-ROLE-02 — Общий клиентский список клиента и корпа**

  <details>
  <summary>Подробности проверки</summary>

  - Связанный корп видит тот же клиентский набор реселлеров; отсутствие собственных покупок корпа не делает его список пустым.

  </details>

- [ ] **CUSTORD-HEADER-01 — Видимость меню по доступу к реселлерам**

  <details>
  <summary>Подробности проверки</summary>

  - Три точки показаны клиенту/корпу при включённом доступе к режиму реселлера и скрыты при выключенном; обе роли.
  - Поведение при отключении во время просмотра — CUSTORD-Q03.

  </details>

- [ ] **CUSTORD-HEADER-02 — Возврат к общему списку заказов**

  <details>
  <summary>Подробности проверки</summary>

  - Меню позволяет вернуться из «Клиентских» в «Мои заказы»; состав и цены соответствуют выбранному списку.
  - Сохранение фильтров при таком переключении — CUSTORD-Q02.

  </details>

- [ ] **CUSTORD-HEADER-03 — Переходы к клиентским статистике и истории**

  <details>
  <summary>Подробности проверки</summary>

  - График открывает клиентскую Статистику с «Продажами/Прибылью», всех связанных реселлеров периода, без переданных ID/статуса активного списка;
  - книга — клиентскую Историю. Не общая статистика клиента/корпа или собственная реселлера; полные проверки статистики и Истории отдельно;
  - выбранные ID/статус списка в Историю не передаются.

  </details>

- [ ] **CUSTORD-OPEN-02 — Открытие выбранного заказа реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по ячейке открывает правильный заказ реселлера по его номеру; не общий смешанный заказ и не соседнюю строку.

  </details>

- [ ] **CUSTORD-OPEN-03 — Сохранение ID и статуса после деталки**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать ID и статус, открыть соответствующий заказ и вернуться: остаются «Клиентские», выбранные ID/статус, данные обновлены.
  - ID и статус должны ещё существовать; иначе CUSTORD-Q02/03.

  </details>

- [ ] **CUSTORD-OPEN-04 — Возврат к общему списку из другого раздела**

  <details>
  <summary>Подробности проверки</summary>

  - Из «Клиентских» перейти в другой нижний раздел и вернуться в заказы: выбраны «Мои заказы», состояние по умолчанию; клиентские фильтры не подставляются в общий список.

  </details>


## Отдельные заказы реселлеров

- [ ] **CUSTORD-GROUP-01 — Раздельные заказы реселлеров на одну дату**

  <details>
  <summary>Подробности проверки</summary>

  - Товары двух реселлеров на одну дату поставщика отображаются в отдельных клиентских заказах; ни одна карточка/деталь не объединяет товары разных реселлеров.

  </details>

- [ ] **CUSTORD-GROUP-02 — Уникальные номера заказов разных реселлеров**

  <details>
  <summary>Подробности проверки</summary>

  - Эти заказы имеют разные номера; tap по каждому открывает его собственный набор товаров.
  - Совпадение даты не делает номер общим.

  </details>

- [ ] **CUSTORD-GROUP-03 — Исключение покупок клиента и корпа из клиентского списка**

  <details>
  <summary>Подробности проверки</summary>

  - Для общего заказа с товарами клиента/корпа и двух реселлеров клиентский список содержит только соответствующие реселлерские заказы; товары клиента/корпа не входят в строки, Qty или Amount.

  </details>

- [ ] **CUSTORD-GROUP-04 — Фильтрация по владельцу общего заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Выбор ID одного реселлера не показывает заказ другого, даже если их товары входят в один общий заказ «Моих заказов».

  </details>


## Вкладки и совместная фильтрация

- [ ] **CUSTORD-TABS-01 — Вкладка единственного активного реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - Без фильтра при одном реселлере с текущими заказами показана его вкладка ID, All отсутствует; ID реселлера без текущих заказов не показан.

  </details>

- [ ] **CUSTORD-TABS-02 — Вкладки нескольких реселлеров и All**

  <details>
  <summary>Подробности проверки</summary>

  - Без фильтра при нескольких реселлерах показаны All и их ID; каждый ID соответствует владельцу товаров.
  - Порядок и выбор по умолчанию — CUSTORD-Q02.

  </details>

- [ ] **CUSTORD-TABS-03 — Фильтрация заказов по ID и All**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по ID показывает только его заказы; tap по All возвращает заказы всех соответствующих реселлеров с учётом выбранного статуса.

  </details>

- [ ] **CUSTORD-TABS-04 — Переключение ID только нажатием**

  <details>
  <summary>Подробности проверки</summary>

  - Горизонтальный свайп не переключает вкладку реселлера; переключение выполняется тапом.

  </details>

- [ ] **CUSTORD-FILTER-01 — Видимость фильтра по полному набору статусов**

  <details>
  <summary>Подробности проверки</summary>

  - При нескольких статусах в полном клиентском списке фильтр доступен; при одном/нуле скрыт.
  - Проверить оба одиночных статуса, затем набор с несколькими.

  </details>

- [ ] **CUSTORD-FILTER-02 — Полный набор статусов при выбранном ID**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать ID с одним статусом, когда у другого есть иной: меню содержит статусы полного клиентского списка, не только выбранного ID.

  </details>

- [ ] **CUSTORD-FILTER-03 — Полный набор статусов после фильтрации**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать один статус из полного набора с несколькими: меню не ограничивается выбранным статусом; доступен переход к другому имеющемуся статусу и к All.

  </details>

- [ ] **CUSTORD-FILTER-04 — Пересечение фильтров ID и статуса**

  <details>
  <summary>Подробности проверки</summary>

  - При ID и статусе показано пересечение условий, не объединение.
  - Проверить оба порядка выбора на наборе с непустым пересечением.

  </details>

- [ ] **CUSTORD-FILTER-05 — Видимость ID после фильтрации статуса**

  <details>
  <summary>Подробности проверки</summary>

  - При выборе статуса вкладки реселлеров без таких заказов скрыты; ID с подходящими заказами остаются.
  - Снятие фильтра возвращает вкладки с текущими заказами.
  - Поведение All при одном оставшемся ID — CUSTORD-Q02.

  </details>

- [ ] **CUSTORD-FILTER-06 — Актуализация вкладок и статусов после изменения**

  <details>
  <summary>Подробности проверки</summary>

  - Изменение статуса/завершение заказа и refresh обновляет доступные вкладки и набор статусов по актуальным данным.
  - Выбор после исчезновения текущего ID/статуса — **Blocked, CUSTORD-Q02/03**.

  </details>

- [ ] **CUSTORD-FILTER-07 — Неуточнённое пустое пересечение фильтров**

  <details>
  <summary>Подробности проверки</summary>

  - Пустое пересечение ID и статуса: вкладки без данных скрываются; точный текст, Qty/Amount и сохранение/смена выбора — **Blocked, CUSTORD-Q02/03**.
  - Не ожидать автоматически «Нет заказов от клиентов» или сброс к All.

  </details>


## Показатели, суммы и ячейки

- [ ] **CUSTORD-SUM-01 — Неинтерактивные показатели Qty и Amount**

  <details>
  <summary>Подробности проверки</summary>

  - Qty/Amount не кликабельны: tap не меняет фильтр и не открывает экран.

  </details>

- [ ] **CUSTORD-SUM-02 — Количество единиц клиентских заказов**

  <details>
  <summary>Подробности проверки</summary>

  - Qty равна сумме единиц товара в текущем наборе клиентских заказов, а не числу карточек/позиций.
  - Покупки клиента/корпа из общего заказа исключены.

  </details>

- [ ] **CUSTORD-SUM-03 — Сумма клиентских заказов с фиксированной наценкой**

  <details>
  <summary>Подробности проверки</summary>

  - Amount равна сумме текущих клиентских заказов с наценкой клиента, применённой к стоимости с гарантией от зафиксированной цены покупки, и типом оплаты.
  - После смены гарантии самим реселлером обновить список: сумма актуальна, Qty/число заказов не меняются от объединения товарных позиций.
  - Использовать известные цены заказа; точное округление/изменения конфигурации — CUSTORD-Q04.

  </details>

- [ ] **CUSTORD-SUM-04 — Пересчёт показателей по фильтрам**

  <details>
  <summary>Подробности проверки</summary>

  - Qty/Amount пересчитываются при ID, статусе и их совместном выборе; All возвращает сумму соответствующего набора.
  - Использовать наборы с разными итогами.

  </details>

- [ ] **CUSTORD-SUM-05 — Исключение завершённого заказа из текущих показателей**

  <details>
  <summary>Подробности проверки</summary>

  - Незавершённый для клиентской Истории заказ остаётся в текущих Qty/Amount; после выполнения двух условий и обновления исключается из списка и показателей.

  </details>

- [ ] **CUSTORD-ROW-01 — Согласованность данных ячейки клиентского заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Номер, дата поставщика, Cash/Online и сумма в ячейке принадлежат одному клиентскому заказу, не смешанному общему заказу.

  </details>

- [ ] **CUSTORD-ROW-02 — Дата поставщика без доставки в списке**

  <details>
  <summary>Подробности проверки</summary>

  - Дата равна дате поставщика без дней доставки.
  - Задать ненулевую доставку, чтобы отличалась от даты покупки/прайса.

  </details>

- [ ] **CUSTORD-ROW-03 — Сумма ячейки с наценкой и гарантией**

  <details>
  <summary>Подробности проверки</summary>

  - Сумма ячейки включает наценку клиента и стоимость гарантии с соответствующим Cash/Online.
  - При положительной наценке не копируется цена без неё из «Моих заказов»; чужие товары не включены.

  </details>

- [ ] **CUSTORD-ROW-04 — Цвета трёх статусов клиентского заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Pending assembly серый, Order pending delivery красный, Released зелёный.
  - Жёлтый из примера другого приложения не используется как требование дополнительного статуса.

  </details>

- [ ] **CUSTORD-SORT-01 — Приоритет позднего статуса в сортировке**

  <details>
  <summary>Подробности проверки</summary>

  - Более поздний статус выше раннего независимо от дат; оставшийся в текущем списке Released располагается выше второго и первого статуса.

  </details>

- [ ] **CUSTORD-SORT-02 — Старые даты поставщика внутри статуса**

  <details>
  <summary>Подробности проверки</summary>

  - Внутри каждого статуса сверху более старые даты поставщика; проверить All и выбранный ID/статус.
  - При противоположном порядке создания в Fimex используется дата поставщика; равные даты — CUSTORD-Q01.

  </details>


## Независимая отметка оплаты и завершение

- [ ] **CUSTORD-PAY-01 — Видимость отметки оплаты со второго статуса**

  <details>
  <summary>Подробности проверки</summary>

  - В Pending assembly состояние оплаты скрыто; начиная с Order pending delivery показано соответствующее Paid/Not paid, в том числе для оставшегося Released.

  </details>

- [ ] **CUSTORD-PAY-02 — Отражение ручной оплаты после возврата**

  <details>
  <summary>Подробности проверки</summary>

  - **Проверка:** Ручное подтверждение Not paid
  - **Ожидаемый результат:** Paid клиентом/корпом отражается в ячейке после возврата; обратно недоступно.
  - Подробные действия в отдельной деталке CUSTDET-PAY-01/02/03/04, отметка не меняет баланс/лимит.

  </details>

- [ ] **CUSTORD-PAY-03 — Независимость клиентской отметки от автоматической оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - Общий заказ «Моих заказов» Paid, соответствующий клиентский Not paid: в «Клиентских» сохраняется Not paid.
  - Автоплата/пополнение баланса общего заказа не заменяет ручную отметку.

  </details>

- [ ] **CUSTORD-PAY-04 — Общая отметка оплаты клиента и корпа**

  <details>
  <summary>Подробности проверки</summary>

  - После ручного изменения другой связанный пользователь (клиент/корп) открывает/обновляет список: видит ту же отметку по этому заказу; состояние не персональное для каждой роли.

  </details>

- [ ] **CUSTORD-HISTORY-01 — Отсутствие автоматического архива по одному Released**

  <details>
  <summary>Подробности проверки</summary>

  - Перевод соответствующего заказа по статусам до Released при клиентском Not paid не меняет ручную отметку и сам по себе не переносит его в клиентскую Историю.

  </details>

- [ ] **CUSTORD-HISTORY-02 — Архивирование после выдачи и последующей оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - После админского Released нажать «Выдать» при Not paid и подтвердить: действие разрешено, заказ остаётся текущим; после ручного Confirm оплаты и обновления переходит в клиентскую Историю.

  </details>

- [ ] **CUSTORD-HISTORY-03 — Архивирование после оплаты и последующей выдачи**

  <details>
  <summary>Подробности проверки</summary>

  - Подтвердить Paid без клиентской выдачи: заказ остаётся текущим, одного Paid недостаточно.
  - После админского Released подтвердить «Выдать» и обновить — заказ в Истории.
  - Этот обратный порядок подтверждён деталкой.

  </details>

- [ ] **CUSTORD-HISTORY-04 — Исключение завершённого заказа без влияния на соседние**

  <details>
  <summary>Подробности проверки</summary>

  - После обоих подтверждённых условий заказ находится в клиентской Истории, отсутствует в текущих строках и показателях после возврата/refresh; остальные заказы не завершаются вместе с ним.

  </details>

- [ ] **CUSTORD-ACTIONS-01 — Ограничения редактирования клиентского заказа**

  <details>
  <summary>Подробности проверки</summary>

  - В активном клиентском заказе клиент/корп не могут изменить гарантию или Cash/Online; доступные действия — отметка оплаты и выдача.
  - Проверить обе роли, не придумывая способ блокировки неописанного экрана.

  </details>

- [ ] **CUSTORD-ACTIONS-02 — Ручные действия и неуточнённое освобождение лимита**

  <details>
  <summary>Подробности проверки</summary>

  - Ручной Paid не меняет баланс/лимит; «Выдать» доступна после админского Released и требует Confirm.
  - Момент освобождения лимита при выдаче остаётся **Blocked, CUSTORD-Q05/CUSTDET-Q02**; не ожидать освобождения по одному ручному Paid.

  </details>


## Бейдж нижнего меню

- [ ] **CUSTORD-BADGE-01 — Бейдж текущих клиентских заказов**

  <details>
  <summary>Подробности проверки</summary>

  - При разных количествах заказов двух списков переключиться из «Моих» в «Клиентские»: бейдж нижней вкладки заказов меняется на количество текущих клиентских заказов, не на Qty единиц или число реселлеров.

  </details>

- [ ] **CUSTORD-BADGE-02 — Переключение бейджа между списками**

  <details>
  <summary>Подробности проверки</summary>

  - Вернуться через меню в «Мои заказы»: бейдж соответствует общему списку; затем снова выбрать «Клиентские» и проверить их число.
  - Повторное переключение не суммирует значения двух списков.

  </details>

- [ ] **CUSTORD-BADGE-03 — Бейдж после возврата из другого раздела**

  <details>
  <summary>Подробности проверки</summary>

  - Уйти из «Клиентских» в другой нижний раздел и вернуться: открыты «Мои заказы», бейдж соответствует этому списку, а не прежнему клиентскому.
  - Влияние ID/статуса на бейдж — CUSTORD-Q03; нулевой/большой формат и обновление при событиях — NAV-Q02.

  </details>


## Пустое состояние

- [ ] **CUSTORD-EMPTY-01 — Полностью пустой клиентский список**

  <details>
  <summary>Подробности проверки</summary>

  - Полностью пустой текущий клиентский список после успешной загрузки: иконка квитанции и «Нет заказов от клиентов», без дополнительного пояснения.
  - Русский светлый вариант — синяя иконка, как в примере; не бесконечный скелетон и не ошибка.

  </details>

- [ ] **CUSTORD-EMPTY-02 — Состав интерфейса пустого клиентского списка**

  <details>
  <summary>Подробности проверки</summary>

  - В этом состоянии скрыты строки, Qty/Amount, вкладки ID/All и фильтр; остаются заголовок, Статистика, История, нижнее меню.
  - Три точки согласно доступу; не остаются старые суммы/вкладки.

  </details>

- [ ] **CUSTORD-EMPTY-03 — Пустой текущий список при наличии иных заказов**

  <details>
  <summary>Подробности проверки</summary>

  - В «Моих заказах» есть покупки клиента/корпа, либо клиентские заказы есть только в Истории: текущие «Клиентские» всё равно пусты; клиентская История доступна.

  </details>

- [ ] **CUSTORD-EMPTY-04 — Пустое состояние после последнего завершения**

  <details>
  <summary>Подробности проверки</summary>

  - Выполнить условия завершения последнего текущего клиентского заказа и обновить: пустая карточка без старой строки/показателей/ID. Только «Выдать» при Not paid или только Paid не вызывает это состояние.

  </details>

- [ ] **CUSTORD-EMPTY-05 — Возврат из пустого состояния после нового заказа**

  <details>
  <summary>Подробности проверки</summary>

  - После нового заказа реселлера обновить ранее пустой клиентский список: карточка исчезает, появляются заказ, актуальные показатели и его ID; для одного реселлера All не показана.

  </details>


## Загрузка, обновление и ошибки

- [ ] **CUSTORD-LOAD-01 — Загрузка клиентского списка со скелетоном**

  <details>
  <summary>Подробности проверки</summary>

  - При загрузке показан скелетон, после ответа — актуальный клиентский список либо полное пустое состояние; старый общий список не выдаётся за клиентский.

  </details>

- [ ] **CUSTORD-LOAD-02 — Обновление списка жестом без дублей**

  <details>
  <summary>Подробности проверки</summary>

  - Длинный скрол вниз запускает refresh со скелетоном и возвращает актуальные строки/показатели/вкладки без дублей заказов.

  </details>

- [ ] **CUSTORD-SYNC-01 — Актуализация без обязательного real-time**

  <details>
  <summary>Подробности проверки</summary>

  - Изменение на сервере при открытом списке не обязано показываться в real-time; открытие, возврат из заказа или refresh получает новые данные.

  </details>

- [ ] **CUSTORD-SYNC-02 — Обновление после ручных действий с сохранением фильтров**

  <details>
  <summary>Подробности проверки</summary>

  - После ручной оплаты/выдачи возврат из заказа сразу обновляет список и показатели с сохранением существующих выбранных ID/статуса; исчезнувшие варианты — CUSTORD-Q02/03.

  </details>

- [ ] **CUSTORD-ERROR-01 — Сетевая ошибка клиентского списка**

  <details>
  <summary>Подробности проверки</summary>

  - Ошибка сети при загрузке/refresh показывает стандартный alert; не трактуется как отсутствие заказов.
  - Состояние старых данных и retry — CUSTORD-Q06.

  </details>

- [ ] **CUSTORD-ERROR-02 — Серверная ошибка клиентского списка**

  <details>
  <summary>Подробности проверки</summary>

  - Ошибка сервера при загрузке/refresh показывает стандартный alert, не успешную карточку пустого списка; точные тексты/состояние/повтор — CUSTORD-Q06.

  </details>
