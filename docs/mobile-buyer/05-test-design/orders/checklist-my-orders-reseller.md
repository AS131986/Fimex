# Чек-лист: Мои заказы — реселлер, Fimex Buyer, iOS

## Область и использование

Собственный список реселлера: изоляция товаров/заказов, суммы с наценкой без раскрытия базы, фильтр, показатели, ячейки, связанная ручная оплата/клиентская выдача, обновление и пустое состояние. [Деталка](checklist-order-detail-reseller.md) и [Статистика](checklist-my-orders-statistics-reseller.md) имеют отдельные чек-листы; [История и архивный заказ](checklist-my-orders-history-reseller.md) проверяются отдельно. «Выдать» реселлеру недоступно.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть ожиданий Blocked по RESORD-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Два реселлера одного клиента и реселлер чужой группы. Собственные/чужие заказы, покупки клиента/корпа, одна дата и смешанный заказ в общем списке клиента/корпа для проверки разделения.
- Несколько собственных заказов в разных статусах и датах; наборы только одного статуса. Числа единиц, позиций и заказов различаются.
- Положительная наценка клиента и согласованные итоговые суммы; варианты Cash/Online, гарантия/без. Известные базы — только у разрешённого клиентского/тестового источника для сравнения; в интерфейсе реселлера они не требуются.
- Общий заказ Paid и соответствующий собственный Not paid; Released с невыполненными клиентскими условиями, возможность клиенту/корпу отметить оплату/выдать в тестовой среде.
- Полностью пустой собственный список, только собственная История, последний текущий заказ и возможность новой покупки. Чужие заказы могут оставаться активными.
- Сеть/серверная ошибка/задержка управляемы. Отсутствие необходимых данных/доступа — Blocked, не Pass.

## Smoke

RESORD-OPEN-01, RESORD-ROLE-01/02, RESORD-PRICE-01/02, RESORD-FILTER-01/03, RESORD-SUM-02/03, RESORD-PAY-03, RESORD-HISTORY-02/03, RESORD-EMPTY-01/02. Использовать результаты основных проверок.

## Открытие, изоляция и хедер

- [ ] **RESORD-OPEN-01** — Вкладка заказов открывает собственные «Мои заказы» реселлера; заголовок соответствует языку, нижняя вкладка подсвечена.
- [ ] **RESORD-ROLE-01** — В списке и показателях только собственные заказы: чужой реселлер того же клиента, клиент/корп и чужая группа не включены.
- [ ] **RESORD-ROLE-02** — При общей дате и смешанном заказе клиента/корпа в собственной ячейке/деталях только товары текущего реселлера; чужие товары не попадают в сумму/Qty.
- [ ] **RESORD-ROLE-03** — Переключиться между тестовыми аккаунтами двух реселлеров: после загрузки каждый видит свои номера/суммы, предыдущий аккаунт не подставляется как текущий.
- [ ] **RESORD-HEADER-01** — Трёх точек, переключения в управляющие «Клиентские» и вкладок ID других реселлеров/All на экране нет; собственный фильтр доступен согласно числу статусов.
- [ ] **RESORD-HEADER-02** — График открывает собственную Статистику с суммами с наценкой и всеми собственными покупками периода, независимо от фильтра активного списка; книга — собственную Историю. Не общие/управляющие экраны клиента/корпа. Полные статистика и История в отдельных чек-листах; фильтр списка в собственную Историю не передаётся.
- [ ] **RESORD-OPEN-02** — Tap по ячейке открывает правильный собственный заказ по его номеру, не смешанный общий заказ или соседнюю строку.

## Суммы с наценкой и показатели

- [ ] **RESORD-PRICE-01** — Суммы ячеек сразу включают клиентскую наценку, гарантию и тип оплаты; использовать известные согласованные итоговые цены заказа, не текущий прайс.
- [ ] **RESORD-PRICE-02** — В списке реселлеру не показаны цена без наценки, её процент/размер или отдельная строка наценки. При положительной наценке нет дополнительного значения базы рядом с итоговой суммой.
- [ ] **RESORD-PRICE-03** — Amount включает ту же наценку, что собственные ячейки; цена без неё из общего списка клиента/корпа сюда не подставляется.
- [ ] **RESORD-SUM-01** — Qty/Amount не кликабельны: tap не открывает экран/не меняет фильтр.
- [ ] **RESORD-SUM-02** — Qty — сумма единиц товара соответствующих собственных заказов, не число позиций или карточек. Набор содержит разные значения этих трёх величин.
- [ ] **RESORD-SUM-03** — Amount равна сумме текущих собственных заказов с гарантией/типом оплаты/наценкой, без чужих товаров. Наценка применяется к стоимости с гарантией от зафиксированной цены покупки; после собственной смены гарантии возврат обновляет сумму, Qty/число заказов прежние. Точное округление/конфигурация — RESORD-Q02.
- [ ] **RESORD-SUM-04** — Выбор каждого статуса пересчитывает Qty/Amount только по его собственным заказам; All возвращает полный текущий набор.

## Фильтр статусов и возврат

- [ ] **RESORD-FILTER-01** — Несколько статусов в полном собственном списке: фильтр показан; один статус или пустой список: скрыт. Проверить по отдельности наборы первого/второго статуса.
- [ ] **RESORD-FILTER-02** — Меню содержит только статусы полного собственного списка; статусы исключительно чужих заказов не добавляются. Если собственный Released ещё не завершён по двум клиентским условиям, он входит в набор.
- [ ] **RESORD-FILTER-03** — Выбрать статус: строки и показатели ограничены им, набор пунктов меню остаётся по полному собственному списку; All возвращает все собственные текущие заказы.
- [ ] **RESORD-FILTER-04** — Выбрать статус, открыть заказ и вернуться: фильтр сохранён, данные обновлены; при изменении статуса строка не остаётся в неподходящем результате. Исчезновение выбранного статуса — RESORD-Q01.
- [ ] **RESORD-FILTER-05** — Из фильтрованного списка перейти в другой нижний раздел и вернуться: фильтр сброшен, показан полный собственный список; не управляющие «Клиентские».
- [ ] **RESORD-FILTER-06** — После исчезновения выбранного статуса/пустого результата при непустом исходном списке: **Blocked, RESORD-Q01** для выбора, текста/показателей. Не требовать автоматически сброса к All или карточки полного пустого состояния.

## Ячейка, дата и сортировка

- [ ] **RESORD-ROW-01** — Номер, дата, Cash/Online и сумма принадлежат одному собственному заказу; разные реселлеры имеют отдельные номера.
- [ ] **RESORD-ROW-02** — Дата поставщика без дней доставки; при ненулевой доставке не подставляется рассчитанная дата прайса/покупки.
- [ ] **RESORD-ROW-03** — Статусы/цвета Fimex: Pending assembly серый, Order pending delivery красный, Released зелёный. Оттенок на отдельном примере не задаёт нового статуса.
- [ ] **RESORD-SORT-01** — Более поздние статусы выше ранних независимо от дат; оставшийся текущим Released выше второго/первого.
- [ ] **RESORD-SORT-02** — Внутри статуса более старые даты поставщика сверху. Если порядок создания в Fimex противоположный, используется дата поставщика; равные даты — RESORD-Q01.

## Отметка оплаты, завершение и бейдж

- [ ] **RESORD-PAY-01** — В первом статусе отметка оплаты скрыта; со второго показано соответствующее Paid/Not paid, включая текущий Released.
- [ ] **RESORD-PAY-02** — Клиент/корп меняет ручную отметку соответствующего клиентского заказа: после открытия/возврата/refresh реселлер видит её актуальное состояние у своего заказа.
- [ ] **RESORD-PAY-03** — Общий заказ клиента/корпа Paid, собственный клиентский заказ Not paid: реселлер видит Not paid. Автоплата общего заказа не заменяет ручную отметку.
- [ ] **RESORD-HISTORY-01** — Один Released при невыполненных клиентских условиях завершения не удаляет собственный заказ из списка, Qty/Amount и бейджа; не переносить правило общего списка клиента/корпа.
- [ ] **RESORD-HISTORY-02** — После админского Released клиент/корп подтвердил «Выдать» при Not paid: после обновления у реселлера заказ остаётся текущим, в Qty/Amount и количестве заказов; одного действия недостаточно.
- [ ] **RESORD-HISTORY-03** — Клиент/корп отметил Paid, не нажимая «Выдать»: у реселлера заказ остаётся в текущем списке и показателях/количестве заказов, отображается Paid.
- [ ] **RESORD-HISTORY-04** — После админского Released подтвердить клиентскую выдачу при Not paid, затем Paid (либо сначала Paid, затем подтвердить выдачу): после обновления собственный заказ исключён из текущих строк/Qty/Amount и относится к Истории. Остальные заказы не завершаются вместе с ним.
- [ ] **RESORD-HISTORY-05** — Реселлер не может нажать «Выдать» для собственного заказа. Точный вид недоступности и другие действия в деталях будут описаны отдельно; не проверять выдачу от лица реселлера как разрешённую.
- [ ] **RESORD-BADGE-01** — Бейдж равен числу собственных текущих заказов, а не единиц товара/позиций/чужих заказов. Не завершённый по двум условиям заказ учитывается; полностью завершённый — нет. Время обновления/нулевой формат — NAV-Q02; влияние фильтра — RESORD-Q01.

## Пустое состояние

- [ ] **RESORD-EMPTY-01** — Полностью пустой собственный текущий список после успешной загрузки: иконка квитанции и карточка без пояснения; на английском «No orders», язык соответствует интерфейсу. Точная русская строка — RESORD-Q03; светлая иконка в синем круге согласно примеру.
- [ ] **RESORD-EMPTY-02** — Строки, Qty/Amount и фильтр скрыты; заголовок, Статистика, История и нижнее меню остаются. Не показываются старые суммы/карточки, нет трёх точек для управляющего списка.
- [ ] **RESORD-EMPTY-03** — Собственные заказы есть только в Истории или активны только чужие заказы: показано собственное пустое состояние; свои завершённые доступны из Истории.
- [ ] **RESORD-EMPTY-04** — Выполнить оба клиентских условия последнего собственного текущего заказа и обновить: пустая карточка без прежней строки/показателей. Одно Paid или только «Выдать» при Not paid карточку не вызывает.
- [ ] **RESORD-EMPTY-05** — Из собственного пустого списка совершить новую покупку и обновить: карточка исчезает, показаны свой заказ и актуальные Qty/Amount. Не требовать мгновенного real-time появления.

## Загрузка, обновление и ошибки

- [ ] **RESORD-LOAD-01** — При загрузке скелетон, после успеха собственные актуальные строки/показатели или полное пустое состояние; чужие данные не считаются результатом загрузки.
- [ ] **RESORD-LOAD-02** — Pull-to-refresh со скелетоном получает актуальные собственные данные без дублей карточек/показателей.
- [ ] **RESORD-SYNC-01** — Пока список открыт, серверные изменения не обязаны показываться в real-time; при следующем открытии, возврате или refresh данные актуальны.
- [ ] **RESORD-SYNC-02** — Во время просмотра деталей оплату/выдачу меняет клиент/корп либо реселлер подтверждает собственную гарантию до КТ, затем возвращается: сразу актуальны строка, статус/оплата, сумма и показатели, сохраняется существующий выбранный статус. Гарантия не даёт реселлеру право менять оплату/выдачу.
- [ ] **RESORD-ERROR-01** — Ошибка сети при загрузке/refresh показывает стандартный alert, не успешное пустое состояние; точные тексты, retry/прежние данные — RESORD-Q03.
- [ ] **RESORD-ERROR-02** — Ошибка сервера при загрузке/refresh показывает стандартный alert, не карточку «No orders» как успешный ответ; состояние после ошибки — RESORD-Q03.
