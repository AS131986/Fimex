# Чек-лист: Детали собственного заказа — реселлер, Fimex Buyer, iOS

## Область и использование

Собственный заказ реселлера: итоговые цены с наценкой, документы, просмотр оплаты, гарантия до КТ, собственный лимит, объединение позиций, обновление связанных представлений и горизонтальный просмотр. Деталки общего и клиентского заказов клиента/корпа имеют отдельные права и чек-листы.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть Blocked по RESDET-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Реселлер со своим заказом и связанный клиент/корп; другой реселлер и товары клиента в общем заказе для проверки изоляции.
- Заказы до/после КТ и возможность дождаться наступления КТ при открытом редакторе; отдельные данные для строгой границы КТ не подменять обычным временем после неё.
- Товар с несколькими доступными гарантиями, товар без выбора гарантии, количество больше 1; одинаковый товар по разным ценам покупки/гарантиям и позиции, полностью совпадающие после смены гарантии.
- Разрешённый источник зафиксированной базы покупки, наценки и цен вариантов; у самого реселлера эти внутренние данные не должны выводиться. Использовать действительные настройки, не требовать диапазон процентов из арифметического примера.
- Собственный лимит с явным запасом/явной нехваткой относительно прироста; изменение на более дешёвую гарантию; лимиты связанных пользователей для изоляции.
- Первый/второй/Released, ручные Not paid/Paid, доступ клиента/корпа для подтверждения оплаты/выдачи. Для обеих последовательностей завершения разные заказы.
- Все шесть вариантов файлов, связанные списки/деталки. Нет разрешённого доступа к финансовым/зафиксированным данным — Blocked для зависимого результата, не Pass по видимому экрану.

## Открытие, права и отображение

- [ ] **RESDET-OPEN-01 — Открытие собственного заказа реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по собственному заказу открывает соответствующий номер и его товары; чужие товары/другие собственные заказы и смешанный состав общего заказа не включены.

  </details>

- [ ] **RESDET-OPEN-02 — Соответствие собственного и клиентского представлений**

  <details>
  <summary>Подробности проверки</summary>

  - Данные этого заказа соответствуют отдельному заказу одного реселлера в клиентском списке клиента/корпа; владелец и количество не меняются из-за разных представлений.

  </details>

- [ ] **RESDET-MENU-01 — Меню документов собственной деталки**

  <details>
  <summary>Подробности проверки</summary>

  - Три точки доступны и открывают только Invoice/Накладную, Packing List/Упаковочный лист и IMEI/SN/Серийный номер; отсутствие трёх точек в списке не скрывает меню деталки.

  </details>

- [ ] **RESDET-MENU-02 — Отсутствие оплаты, логиста и вкладок других владельцев**

  <details>
  <summary>Подробности проверки</summary>

  - В меню нет смены логиста/Cash/Online; переключателя «Себестоимость / С наценкой» и вкладок других владельцев/All нет.

  </details>

- [ ] **RESDET-ROW-01 — Данные собственной товарной позиции**

  <details>
  <summary>Подробности проверки</summary>

  - У позиции правильные флаг/иконка, название, итоговая цена за единицу, количество и текущая гарантия; отсутствие страны не подменяется произвольным флагом.

  </details>

- [ ] **RESDET-ROW-02 — Цена единицы и суммарное Qty**

  <details>
  <summary>Подробности проверки</summary>

  - При количестве больше 1 цена справа остаётся ценой за единицу; Qty — сумма единиц всех строк, не число позиций.

  </details>

- [ ] **RESDET-ROW-03 — Порядок и отдельность разных покупок товара**

  <details>
  <summary>Подробности проверки</summary>

  - Сортировка товаров соответствует админской/связанному заказу; один товар с разной ценой покупки/гарантией показан отдельными позициями с собственными значениями.

  </details>


## Только итоговые цены

- [ ] **RESDET-PRICE-01 — Итоговые цены без раскрытия наценки**

  <details>
  <summary>Подробности проверки</summary>

  - Цена каждой позиции и Amount включают клиентскую наценку; нет себестоимости, процента/размера наценки или отдельной её строки, в том числе при положительной/разной наценке позиций.

  </details>

- [ ] **RESDET-PRICE-02 — Amount только выбранного собственного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Amount соответствует согласованным итоговым ценам × количествам только этого заказа.
  - Точный расчёт округления — RESDET-Q01; использовать цены из разрешённого источника.

  </details>

- [ ] **RESDET-PRICE-03 — Наценка в стоимости вариантов гарантии**

  <details>
  <summary>Подробности проверки</summary>

  - В вариантах гарантии отображается итоговая цена с наценкой.
  - Наценка применяется к стоимости вместе с гарантией, не только к базе без неё; использовать данные с различимыми результатами двух формул и известными итоговыми ценами.

  </details>

- [ ] **RESDET-PRICE-04 — Зафиксированная база гарантии после изменения прайса**

  <details>
  <summary>Подробности проверки</summary>

  - Изменить текущий прайс и настройку наценки после покупки, открыть редактор: используется зафиксированная база/наценка конкретной покупки, не новая цена прайса/новый процент.
  - Конфигурация гарантийных процентов отдельно RESDET-Q01.

  </details>

- [ ] **RESDET-PRICE-05 — Отдельные гарантийные цены разных покупок**

  <details>
  <summary>Подробности проверки</summary>

  - Две покупки одного товара по разным базовым ценам показывают соответствующие им цены вариантов гарантии; барабан второй позиции не копирует цены первой.

  </details>

- [ ] **RESDET-PRICE-06 — Отсутствие повторного начисления наценки**

  <details>
  <summary>Подробности проверки</summary>

  - Несколько повторных открытий/подтверждённых переключений гарантии не начисляют клиентскую наценку повторно поверх уже итоговой цены;
  - база остаётся ценой покупки. Использовать согласованные цены для каждого варианта.

  </details>


## Редактор и выбранная позиция

- [ ] **RESDET-WAR-01 — Редактор гарантии до КТ**

  <details>
  <summary>Подробности проверки</summary>

  - До КТ tap по поддерживающему гарантию товару открывает выбранную позицию с флагом/иконкой, названием, текущей гарантией, барабаном вариантов/цен и Confirm/Cancel.

  </details>

- [ ] **RESDET-WAR-02 — Недоступность логиста в редакторе**

  <details>
  <summary>Подробности проверки</summary>

  - Ship To/логист в редакторе недоступен; ограничение не зависит от наличия гарантии, количества или лимита.

  </details>

- [ ] **RESDET-WAR-03 — Отмена выбора гарантии без изменения резерва**

  <details>
  <summary>Подробности проверки</summary>

  - Изменить выбор барабана без Confirm: сохранённые гарантия/цена/Amount и резерв не меняются; Cancel оставляет прежнее состояние, новое открытие показывает сохранённую гарантию.

  </details>

- [ ] **RESDET-WAR-04 — Закрытие гарантии без подтверждения**

  <details>
  <summary>Подробности проверки</summary>

  - Закрыть редактор без подтверждения: выбранная новая гарантия не применяется и лимит не резервируется как при успешной смене.

  </details>

- [ ] **RESDET-WAR-05 — Успешная смена гарантии без нового заказа**

  <details>
  <summary>Подробности проверки</summary>

  - При достаточном лимите Confirm сразу обновляет гарантию/цену выбранной позиции и Amount; Qty не меняется, новая покупка не создаётся.

  </details>

- [ ] **RESDET-WAR-06 — Гарантия всех единиц выбранной позиции**

  <details>
  <summary>Подробности проверки</summary>

  - У выбранной позиции количество больше 1: гарантия применяется ко всем её единицам.
  - Другая позиция того же товара с иной ценой/гарантией не изменяется.

  </details>

- [ ] **RESDET-WAR-07 — Сохранённая гарантия при повторном открытии**

  <details>
  <summary>Подробности проверки</summary>

  - После подтверждения вновь открыть редактор до КТ: текущая гарантия соответствует сохранённой, цены вариантов относятся к той же покупке, а не цене на момент редактирования.

  </details>

- [ ] **RESDET-WAR-08 — Отсутствие редактора у товара без гарантии**

  <details>
  <summary>Подробности проверки</summary>

  - У товара без выбора гарантии tap не открывает редактор до КТ; не предлагается смена логиста как альтернативное действие.

  </details>


## Собственный лимит

Проверки прироста/возврата разницы при смене гарантии ниже выполняются для Not paid. Денежный эффект изменения стоимости уже оплаченного заказа остаётся RESDET-Q02; освобождение существующего резерва при Not paid → Paid проверяется отдельно.

- [ ] **RESDET-LIMIT-01 — Резервирование только прироста итоговой стоимости**

  <details>
  <summary>Подробности проверки</summary>

  - При удорожании с запасом лимита резервируется только разница итоговых цен с наценкой × количество выбранной позиции; доступный собственный лимит уменьшается на эту разницу, не на всю стоимость позиции заново.

  </details>

- [ ] **RESDET-LIMIT-02 — Прирост лимита всего количества позиции**

  <details>
  <summary>Подробности проверки</summary>

  - Количество больше 1: прирост проверяется для всех единиц позиции, а не одной; собственная наценка уже включена в стоимость изменения.
  - Округление — RESDET-Q01.

  </details>

- [ ] **RESDET-LIMIT-03 — Запрет смены гарантии при нехватке собственного лимита**

  <details>
  <summary>Подробности проверки</summary>

  - Явная нехватка собственного лимита: Confirm показывает alert как при покупке, прежние гарантия/цена/Amount и резерв сохраняются.
  - Свободный лимит клиента/корпа или другого реселлера не покрывает недостаток.

  </details>

- [ ] **RESDET-LIMIT-04 — Возврат разницы при удешевлении гарантии**

  <details>
  <summary>Подробности проверки</summary>

  - Подтвердить более дешёвую гарантию: собственный доступный лимит увеличивается на разницу итоговых стоимостей для всего количества, новая гарантия/цена/Amount сохранены.

  </details>

- [ ] **RESDET-LIMIT-05 — Использование лимита владельца позиции**

  <details>
  <summary>Подробности проверки</summary>

  - Успешное изменение использует лимит владельца позиции, не резерв другого реселлера/общий клиентский лимит.
  - Не трактовать его как ручной Paid или списание с несуществующего собственного баланса реселлера.

  </details>

- [ ] **RESDET-LIMIT-06 — Неуточнённое равенство лимиту и гонки резерва**

  <details>
  <summary>Подробности проверки</summary>

  - Ровно достаточный лимит, гонки резерва/ошибка после запроса: **Blocked, RESDET-Q02** для точного поведения.
  - Не переносить результат случая с запасом на равенство без согласования.

  </details>



- [ ] **RESDET-LIMIT-07 — Возврат лимита при Paid до клиентской выдачи**

  <details>
  <summary>Подробности проверки</summary>

  - На собственном Not paid заказе с ещё не подтверждённой клиентской выдачей записать доступный лимит и фактически занятый этим заказом резерв. Клиент/корп подтверждает Not paid → Paid.
  - После открытия/refresh профиля реселлера доступный лимит увеличен на ранее занятый этим заказом резерв. Заказ остаётся текущим до клиентской выдачи; открытый профиль не обязан обновляться в real-time.

  </details>

- [ ] **RESDET-LIMIT-08 — Выдача при Not paid и последующий возврат по Paid**

  <details>
  <summary>Подробности проверки</summary>

  - После админского Released клиент/корп подтверждает выдачу при Not paid: собственный лимит реселлера после открытия/refresh профиля остаётся занятым этим заказом.
  - Затем клиент/корп подтверждает Paid: ранее занятый этим заказом резерв возвращается один раз; после обновления профиль показывает доступный остаток, заказ относится к Истории по обоим условиям.

  </details>

- [ ] **RESDET-LIMIT-09 — Однократный возврат резерва только нужного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - При наличии другого неоплаченного заказа того же реселлера и заказа другого реселлера подтвердить Paid только для выбранного заказа.
  - Освобождён только ранее занятый выбранным заказом собственный резерв. Резервы других заказов и владельцев сохраняются.
  - Повторное открытие Paid-заказа, refresh и последующая выдача не увеличивают доступный лимит повторно.

  </details>

## Объединение позиций

- [ ] **RESDET-MERGE-01 — Объединение полностью совпавших позиций**

  <details>
  <summary>Подробности проверки</summary>

  - Сменить гарантию так, что две позиции полностью совпали: они объединяются, количество равно сумме обоих, Qty заказа прежняя, Amount соответствует новой итоговой стоимости.

  </details>

- [ ] **RESDET-MERGE-02 — Отдельность позиций с разными ценами и гарантией**

  <details>
  <summary>Подробности проверки</summary>

  - Тот же товар по другой цене/гарантии после изменения остаётся отдельной позицией; одинаковое название само по себе не означает полное совпадение.

  </details>

- [ ] **RESDET-MERGE-03 — Изоляция объединения разных владельцев**

  <details>
  <summary>Подробности проверки</summary>

  - В связанном общем заказе товары другого владельца не объединяются с реселлерскими; изменяются только выбранная позиция и её полные совпадения того же владельца.

  </details>

- [ ] **RESDET-MERGE-04 — Сохранность количества и резерва при слиянии**

  <details>
  <summary>Подробности проверки</summary>

  - Слияние не теряет/дублирует единицы и не возвращает резерв за «удалённую» строку повторно; финансовое изменение только по подтверждённой разнице стоимости.
  - Дополнительные признаки идентичности/порядок — RESDET-Q03.

  </details>


## Ограничение КТ

- [ ] **RESDET-KT-01 — Запрет редактора гарантии после КТ**

  <details>
  <summary>Подробности проверки</summary>

  - После КТ tap по поддерживающему гарантию товару не открывает редактор и не меняет данные; вариант без гарантии также не становится доступным.

  </details>

- [ ] **RESDET-KT-02 — Отказ Confirm после КТ в открытом редакторе**

  <details>
  <summary>Подробности проверки</summary>

  - Открыть редактор до КТ, выбрать другой вариант, Confirm после КТ: визуально ничего не происходит, гарантия/цена/Amount/резерв прежние; нет ожидаемого alert «Упс…»/закрытия в Главную.

  </details>

- [ ] **RESDET-KT-03 — Успешная смена до КТ и неуточнённая граница**

  <details>
  <summary>Подробности проверки</summary>

  - Подтвердить обычную смену до КТ с запасом времени: применяется при достаточном лимите.
  - Точный момент равенства КТ и смена КТ поставщиком — **Blocked, RESDET-Q02** для зависимой части.

  </details>


## Статусы и просмотр оплаты

- [ ] **RESDET-STATUS-01 — Цвета статуса собственного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Иконка/цвет соответствуют статусу заказа: Pending assembly серый, Order pending delivery красный, Released зелёный.
  - Not paid не перекрашивает Released в статус доставки.

  </details>

- [ ] **RESDET-PAY-01 — Ручная оплата со второго статуса**

  <details>
  <summary>Подробности проверки</summary>

  - В первом статусе оплата скрыта; со второго отображается ручная Paid/Not paid этого заказа, включая Released с Not paid.

  </details>

- [ ] **RESDET-PAY-02 — Недоступность оплаты и выдачи реселлеру**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по оплате не открывает реселлеру подтверждение смены и не меняет отметку; кнопки «Выдать» нет при любом статусе/Paid/Not paid.

  </details>

- [ ] **RESDET-PAY-03 — Независимость оплаты собственного и общего заказов**

  <details>
  <summary>Подробности проверки</summary>

  - Общий заказ Paid, клиентский Not paid: реселлер видит Not paid.
  - Автоматическое списание/пополнение общего баланса не заменяют ручной клиентский Confirm.

  </details>

- [ ] **RESDET-PAY-04 — Отражение ручной оплаты клиента у реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - Клиент/корп подтверждает Paid: после применимого повторного открытия/обновления реселлер видит ту же отметку; она не личная и не доступна для обратного изменения им. Ранее занятый этим заказом собственный лимит возвращается один раз; проверить профиль после открытия/refresh.

  </details>

- [ ] **RESDET-HISTORY-01 — История после выдачи и последующей оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - Admin Released и подтверждённая клиентская выдача при Not paid: заказ ещё текущий у реселлера. Лимит этого заказа ещё занят; после Confirm оплаты ранее занятый резерв возвращается один раз.
  - После клиентского Confirm оплаты и обновления исключён из текущих строк/показателей, относится к собственной Истории.

  </details>

- [ ] **RESDET-HISTORY-02 — История после оплаты и последующей выдачи**

  <details>
  <summary>Подробности проверки</summary>

  - Paid без подтверждённой клиентской выдачи: заказ ещё текущий. При этом собственный лимит уже освобождён; последующая выдача не возвращает его повторно.
  - После админского Released, клиентского Confirm выдачи и обновления относится к Истории; реселлер не совершает выдачу сам.

  </details>

- [ ] **RESDET-TIME-01 — Неуточнённый полный таймлайн реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - Полный таймлайн, раскрытие и источник/часовой пояс дат: **Blocked, RESDET-Q04**.
  - Свёрнутый текущий статус с датой/временем наблюдается на примере, но не задаёт правила всех временных состояний.

  </details>


## Обновление связанных представлений

- [ ] **RESDET-SYNC-01 — Сумма собственного списка после смены гарантии**

  <details>
  <summary>Подробности проверки</summary>

  - Успешно сменить гарантию и вернуться в собственный список: ячейка/Amount отражают новую итоговую стоимость, Qty прежняя, выбранный существующий статус сохранён.

  </details>

- [ ] **RESDET-SYNC-02 — Синхронизация гарантии с клиентским заказом**

  <details>
  <summary>Подробности проверки</summary>

  - После изменения открыть/обновить соответствующий клиентский заказ клиента/корпа: актуальная гарантия и количества, итоговая цена/Amount с наценкой либо себестоимость согласно его переключателю.
  - Право клиента/корпа менять гарантию здесь не появляется.

  </details>

- [ ] **RESDET-SYNC-03 — Синхронизация гарантии с общим заказом**

  <details>
  <summary>Подробности проверки</summary>

  - Открыть/обновить связанный общий заказ клиента/корпа: актуальная гарантия/количества выбранного владельца, цена/Amount без клиентской наценки, товары других владельцев прежние.

  </details>

- [ ] **RESDET-SYNC-04 — Суммы связанных списков и неизменность числа заказов**

  <details>
  <summary>Подробности проверки</summary>

  - При обновлении связанного клиентского/общего списка их суммы меняются по собственным правилам цены; объединение строк внутри этого заказа не добавляет заказ в бейдж.
  - Момент обновления бейджа — NAV-Q02.

  </details>

- [ ] **RESDET-SYNC-05 — Скрытие себестоимости после изменения режима клиентом**

  <details>
  <summary>Подробности проверки</summary>

  - Переключение себестоимости клиентом/корпом не раскрывает её в повторно открытом собственном заказе реселлера; здесь по-прежнему итоговые цены и нет процента/переключателя.

  </details>


## Документы

- [ ] **RESDET-DOC-01 — Шесть сочетаний документов на всех статусах**

  <details>
  <summary>Подробности проверки</summary>

  - Каждый из трёх документов доступен в Excel/PDF и открывает актуальный файл: все шесть сочетаний; доступность на первом/втором/Released, до и после КТ.

  </details>

- [ ] **RESDET-DOC-02 — Состав документов собственного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Файлы содержат все товары именно этого собственного заказа, не его другие заказы, чужие товары либо смешанный состав общей деталки.

  </details>

- [ ] **RESDET-DOC-03 — Итоговые цены документов без раскрытия наценки**

  <details>
  <summary>Подробности проверки</summary>

  - Цены в документах с ценовыми колонками итоговые с наценкой; нет раскрытия себестоимости/процента/размера наценки.
  - Не требовать произвольных ценовых колонок в IMEI/SN/Packing List без шаблона.

  </details>

- [ ] **RESDET-DOC-04 — Актуальность документов после гарантии и слияния**

  <details>
  <summary>Подробности проверки</summary>

  - После подтверждённой смены гарантии/слияния вновь сформированный документ использует актуальные гарантию, цены, количества/состав, а не прежний файл.

  </details>

- [ ] **RESDET-DOC-05 — Разные ценовые режимы соответствующих документов**

  <details>
  <summary>Подробности проверки</summary>

  - После того же изменения документы общего заказа используют цены без наценки, клиентского — выбранный режим, собственного реселлера — только итоговую цену с наценкой;
  - количество/гарантия согласованы между соответствующими файлами.

  </details>

- [ ] **RESDET-DOC-06 — Неуточнённые шаблоны и ошибки документов**

  <details>
  <summary>Подробности проверки</summary>

  - Точный состав колонок/формат/незаполненные серийные данные/дальнейшее Share/ошибки формирования: **Blocked, RESDET-Q05** для неопределённой части.
  - Общая доступность и актуальный состав подтверждены.

  </details>


## Полный экран и закрытие

- [ ] **RESDET-FULL-01 — Полноэкранные данные собственного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Full-screen показывает горизонтально номер, товары с количеством, итоговой ценой за единицу и текущей гарантией; значения соответствуют обычной деталке.

  </details>

- [ ] **RESDET-FULL-02 — Режим просмотра без скрытых цен и редакторов**

  <details>
  <summary>Подробности проверки</summary>

  - В полном экране нет себестоимости, процентов/отдельной наценки, переключателя цены и вкладок других владельцев; режим предназначен для просмотра, без редактора гарантии/логиста по tap.

  </details>

- [ ] **RESDET-FULL-03 — Актуальность full-screen после объединения**

  <details>
  <summary>Подробности проверки</summary>

  - После успешной смены гарантии/объединения открыть полный экран: актуальные цены/гарантии/количества, нет старой продублированной позиции.

  </details>

- [ ] **RESDET-CLOSE-01 — Возврат в список с обновлением и фильтром**

  <details>
  <summary>Подробности проверки</summary>

  - Крестик обычной деталки возвращает в собственный список: данные сразу обновлены, существующий фильтр сохранён.
  - Исчезнувший выбранный статус отдельно RESORD-Q01.

  </details>

- [ ] **RESDET-ERROR-01 — Неуточнённый жизненный цикл собственной деталки**

  <details>
  <summary>Подробности проверки</summary>

  - Loading/refresh/real-time деталки, поворот/возврат из full-screen/свайп закрытия, исчезновение заказа: **Blocked, RESDET-Q04** для точного UI/перехода;
  - не заменять их поведением списка.
  - Вход из Истории/архивный запрет редактирования проверяются в [отдельном чек-листе](checklist-my-orders-history-reseller.md).

  </details>

- [ ] **RESDET-ERROR-02 — Неуточнённые ошибки и параллельные изменения гарантии**

  <details>
  <summary>Подробности проверки</summary>

  - Ошибки подтверждения, retry/lost response и параллельная смена гарантии/лимита: **Blocked, RESDET-Q02**; старое состояние после ответа с ошибкой само не доказывает сохранение/несохранение на сервере.

  </details>
