# Чек-лист: Детали собственного заказа — реселлер, Fimex Buyer, iOS

## Область и использование

Собственный заказ реселлера: итоговые цены с наценкой, документы, просмотр оплаты, гарантия до КТ, собственный лимит, объединение позиций, обновление связанных представлений и горизонтальный просмотр. Деталки общего и клиентского заказов клиента/корпа имеют отдельные права и чек-листы.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть Blocked по RESDET-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Реселлер со своим заказом и связанный клиент/корп; другой реселлер и товары клиента в общем заказе для проверки изоляции.
- Заказы до/после КТ и возможность дождаться наступления КТ при открытом редакторе; отдельные данные для строгой границы КТ не подменять обычным временем после неё.
- Товар с несколькими доступными гарантиями, товар без выбора гарантии, количество больше 1; одинаковый товар по разным ценам покупки/гарантиям и позиции, полностью совпадающие после смены гарантии.
- Разрешённый источник зафиксированной базы покупки, наценки и цен вариантов; у самого реселлера эти внутренние данные не должны выводиться. Использовать действительные настройки, не требовать диапазон процентов из арифметического примера.
- Собственный лимит с явным запасом/явной нехваткой относительно прироста; изменение на более дешёвую гарантию; лимиты связанных пользователей для изоляции.
- Первый/второй/Released, ручные Not paid/Paid, доступ клиента/корпа для подтверждения оплаты/выдачи. Для обеих последовательностей завершения разные заказы.
- Все шесть вариантов файлов, связанные списки/деталки. Нет разрешённого доступа к финансовым/зафиксированным данным — Blocked для зависимого результата, не Pass по видимому экрану.

## Smoke

RESDET-OPEN-01, RESDET-MENU-01, RESDET-PRICE-01/03, RESDET-PAY-01/02, RESDET-WAR-01/03/05, RESDET-LIMIT-01/03/04, RESDET-KT-01/02, RESDET-SYNC-01/02, RESDET-DOC-01/03, RESDET-FULL-01. Использовать результаты основных пунктов.

## Открытие, права и отображение

- [ ] **RESDET-OPEN-01** — Tap по собственному заказу открывает соответствующий номер и его товары; чужие товары/другие собственные заказы и смешанный состав общего заказа не включены.
- [ ] **RESDET-OPEN-02** — Данные этого заказа соответствуют отдельному заказу одного реселлера в клиентском списке клиента/корпа; владелец и количество не меняются из-за разных представлений.
- [ ] **RESDET-MENU-01** — Три точки доступны и открывают только Invoice/Накладную, Packing List/Упаковочный лист и IMEI/SN/Серийный номер; отсутствие трёх точек в списке не скрывает меню деталки.
- [ ] **RESDET-MENU-02** — В меню нет смены логиста/Cash/Online; переключателя «Себестоимость / С наценкой» и вкладок других владельцев/All нет.
- [ ] **RESDET-ROW-01** — У позиции правильные флаг/иконка, название, итоговая цена за единицу, количество и текущая гарантия; отсутствие страны не подменяется произвольным флагом.
- [ ] **RESDET-ROW-02** — При количестве больше 1 цена справа остаётся ценой за единицу; Qty — сумма единиц всех строк, не число позиций.
- [ ] **RESDET-ROW-03** — Сортировка товаров соответствует админской/связанному заказу; один товар с разной ценой покупки/гарантией показан отдельными позициями с собственными значениями.

## Только итоговые цены

- [ ] **RESDET-PRICE-01** — Цена каждой позиции и Amount включают клиентскую наценку; нет себестоимости, процента/размера наценки или отдельной её строки, в том числе при положительной/разной наценке позиций.
- [ ] **RESDET-PRICE-02** — Amount соответствует согласованным итоговым ценам × количествам только этого заказа. Точный расчёт округления — RESDET-Q01; использовать цены из разрешённого источника.
- [ ] **RESDET-PRICE-03** — В вариантах гарантии отображается итоговая цена с наценкой. Наценка применяется к стоимости вместе с гарантией, не только к базе без неё; использовать данные с различимыми результатами двух формул и известными итоговыми ценами.
- [ ] **RESDET-PRICE-04** — Изменить текущий прайс и настройку наценки после покупки, открыть редактор: используется зафиксированная база/наценка конкретной покупки, не новая цена прайса/новый процент. Конфигурация гарантийных процентов отдельно RESDET-Q01.
- [ ] **RESDET-PRICE-05** — Две покупки одного товара по разным базовым ценам показывают соответствующие им цены вариантов гарантии; барабан второй позиции не копирует цены первой.
- [ ] **RESDET-PRICE-06** — Несколько повторных открытий/подтверждённых переключений гарантии не начисляют клиентскую наценку повторно поверх уже итоговой цены; база остаётся ценой покупки. Использовать согласованные цены для каждого варианта.

## Редактор и выбранная позиция

- [ ] **RESDET-WAR-01** — До КТ tap по поддерживающему гарантию товару открывает выбранную позицию с флагом/иконкой, названием, текущей гарантией, барабаном вариантов/цен и Confirm/Cancel.
- [ ] **RESDET-WAR-02** — Ship To/логист в редакторе недоступен; ограничение не зависит от наличия гарантии, количества или лимита.
- [ ] **RESDET-WAR-03** — Изменить выбор барабана без Confirm: сохранённые гарантия/цена/Amount и резерв не меняются; Cancel оставляет прежнее состояние, новое открытие показывает сохранённую гарантию.
- [ ] **RESDET-WAR-04** — Закрыть редактор без подтверждения: выбранная новая гарантия не применяется и лимит не резервируется как при успешной смене.
- [ ] **RESDET-WAR-05** — При достаточном лимите Confirm сразу обновляет гарантию/цену выбранной позиции и Amount; Qty не меняется, новая покупка не создаётся.
- [ ] **RESDET-WAR-06** — У выбранной позиции количество больше 1: гарантия применяется ко всем её единицам. Другая позиция того же товара с иной ценой/гарантией не изменяется.
- [ ] **RESDET-WAR-07** — После подтверждения вновь открыть редактор до КТ: текущая гарантия соответствует сохранённой, цены вариантов относятся к той же покупке, а не цене на момент редактирования.
- [ ] **RESDET-WAR-08** — У товара без выбора гарантии tap не открывает редактор до КТ; не предлагается смена логиста как альтернативное действие.

## Собственный лимит

- [ ] **RESDET-LIMIT-01** — При удорожании с запасом лимита резервируется только разница итоговых цен с наценкой × количество выбранной позиции; доступный собственный лимит уменьшается на эту разницу, не на всю стоимость позиции заново.
- [ ] **RESDET-LIMIT-02** — Количество больше 1: прирост проверяется для всех единиц позиции, а не одной; собственная наценка уже включена в стоимость изменения. Округление — RESDET-Q01.
- [ ] **RESDET-LIMIT-03** — Явная нехватка собственного лимита: Confirm показывает alert как при покупке, прежние гарантия/цена/Amount и резерв сохраняются. Свободный лимит клиента/корпа или другого реселлера не покрывает недостаток.
- [ ] **RESDET-LIMIT-04** — Подтвердить более дешёвую гарантию: собственный доступный лимит увеличивается на разницу итоговых стоимостей для всего количества, новая гарантия/цена/Amount сохранены.
- [ ] **RESDET-LIMIT-05** — Успешное изменение использует лимит владельца позиции, не резерв другого реселлера/общий клиентский лимит. Не трактовать его как ручной Paid или списание с несуществующего собственного баланса реселлера.
- [ ] **RESDET-LIMIT-06** — Ровно достаточный лимит, гонки резерва/ошибка после запроса: **Blocked, RESDET-Q02** для точного поведения. Не переносить результат случая с запасом на равенство без согласования.

## Объединение позиций

- [ ] **RESDET-MERGE-01** — Сменить гарантию так, что две позиции полностью совпали: они объединяются, количество равно сумме обоих, Qty заказа прежняя, Amount соответствует новой итоговой стоимости.
- [ ] **RESDET-MERGE-02** — Тот же товар по другой цене/гарантии после изменения остаётся отдельной позицией; одинаковое название само по себе не означает полное совпадение.
- [ ] **RESDET-MERGE-03** — В связанном общем заказе товары другого владельца не объединяются с реселлерскими; изменяются только выбранная позиция и её полные совпадения того же владельца.
- [ ] **RESDET-MERGE-04** — Слияние не теряет/дублирует единицы и не возвращает резерв за «удалённую» строку повторно; финансовое изменение только по подтверждённой разнице стоимости. Дополнительные признаки идентичности/порядок — RESDET-Q03.

## Ограничение КТ

- [ ] **RESDET-KT-01** — После КТ tap по поддерживающему гарантию товару не открывает редактор и не меняет данные; вариант без гарантии также не становится доступным.
- [ ] **RESDET-KT-02** — Открыть редактор до КТ, выбрать другой вариант, Confirm после КТ: визуально ничего не происходит, гарантия/цена/Amount/резерв прежние; нет ожидаемого alert «Упс…»/закрытия в Главную.
- [ ] **RESDET-KT-03** — Подтвердить обычную смену до КТ с запасом времени: применяется при достаточном лимите. Точный момент равенства КТ и смена КТ поставщиком — **Blocked, RESDET-Q02** для зависимой части.

## Статусы и просмотр оплаты

- [ ] **RESDET-STATUS-01** — Иконка/цвет соответствуют статусу заказа: Pending assembly серый, Order pending delivery красный, Released зелёный. Not paid не перекрашивает Released в статус доставки.
- [ ] **RESDET-PAY-01** — В первом статусе оплата скрыта; со второго отображается ручная Paid/Not paid этого заказа, включая Released с Not paid.
- [ ] **RESDET-PAY-02** — Tap по оплате не открывает реселлеру подтверждение смены и не меняет отметку; кнопки «Выдать» нет при любом статусе/Paid/Not paid.
- [ ] **RESDET-PAY-03** — Общий заказ Paid, клиентский Not paid: реселлер видит Not paid. Автоматическое списание/пополнение общего баланса не заменяют ручной клиентский Confirm.
- [ ] **RESDET-PAY-04** — Клиент/корп подтверждает Paid: после применимого повторного открытия/обновления реселлер видит ту же отметку; она не личная и не доступна для обратного изменения им.
- [ ] **RESDET-HISTORY-01** — Admin Released и подтверждённая клиентская выдача при Not paid: заказ ещё текущий у реселлера. После клиентского Confirm оплаты и обновления исключён из текущих строк/показателей, относится к собственной Истории.
- [ ] **RESDET-HISTORY-02** — Paid без подтверждённой клиентской выдачи: заказ ещё текущий. После админского Released, клиентского Confirm выдачи и обновления относится к Истории; реселлер не совершает выдачу сам.
- [ ] **RESDET-TIME-01** — Полный таймлайн, раскрытие и источник/часовой пояс дат: **Blocked, RESDET-Q04**. Свёрнутый текущий статус с датой/временем наблюдается на примере, но не задаёт правила всех временных состояний.

## Обновление связанных представлений

- [ ] **RESDET-SYNC-01** — Успешно сменить гарантию и вернуться в собственный список: ячейка/Amount отражают новую итоговую стоимость, Qty прежняя, выбранный существующий статус сохранён.
- [ ] **RESDET-SYNC-02** — После изменения открыть/обновить соответствующий клиентский заказ клиента/корпа: актуальная гарантия и количества, итоговая цена/Amount с наценкой либо себестоимость согласно его переключателю. Право клиента/корпа менять гарантию здесь не появляется.
- [ ] **RESDET-SYNC-03** — Открыть/обновить связанный общий заказ клиента/корпа: актуальная гарантия/количества выбранного владельца, цена/Amount без клиентской наценки, товары других владельцев прежние.
- [ ] **RESDET-SYNC-04** — При обновлении связанного клиентского/общего списка их суммы меняются по собственным правилам цены; объединение строк внутри этого заказа не добавляет заказ в бейдж. Момент обновления бейджа — NAV-Q02.
- [ ] **RESDET-SYNC-05** — Переключение себестоимости клиентом/корпом не раскрывает её в повторно открытом собственном заказе реселлера; здесь по-прежнему итоговые цены и нет процента/переключателя.

## Документы

- [ ] **RESDET-DOC-01** — Каждый из трёх документов доступен в Excel/PDF и открывает актуальный файл: все шесть сочетаний; доступность на первом/втором/Released, до и после КТ.
- [ ] **RESDET-DOC-02** — Файлы содержат все товары именно этого собственного заказа, не его другие заказы, чужие товары либо смешанный состав общей деталки.
- [ ] **RESDET-DOC-03** — Цены в документах с ценовыми колонками итоговые с наценкой; нет раскрытия себестоимости/процента/размера наценки. Не требовать произвольных ценовых колонок в IMEI/SN/Packing List без шаблона.
- [ ] **RESDET-DOC-04** — После подтверждённой смены гарантии/слияния вновь сформированный документ использует актуальные гарантию, цены, количества/состав, а не прежний файл.
- [ ] **RESDET-DOC-05** — После того же изменения документы общего заказа используют цены без наценки, клиентского — выбранный режим, собственного реселлера — только итоговую цену с наценкой; количество/гарантия согласованы между соответствующими файлами.
- [ ] **RESDET-DOC-06** — Точный состав колонок/формат/незаполненные серийные данные/дальнейшее Share/ошибки формирования: **Blocked, RESDET-Q05** для неопределённой части. Общая доступность и актуальный состав подтверждены.

## Полный экран и закрытие

- [ ] **RESDET-FULL-01** — Full-screen показывает горизонтально номер, товары с количеством, итоговой ценой за единицу и текущей гарантией; значения соответствуют обычной деталке.
- [ ] **RESDET-FULL-02** — В полном экране нет себестоимости, процентов/отдельной наценки, переключателя цены и вкладок других владельцев; режим предназначен для просмотра, без редактора гарантии/логиста по tap.
- [ ] **RESDET-FULL-03** — После успешной смены гарантии/объединения открыть полный экран: актуальные цены/гарантии/количества, нет старой продублированной позиции.
- [ ] **RESDET-CLOSE-01** — Крестик обычной деталки возвращает в собственный список: данные сразу обновлены, существующий фильтр сохранён. Исчезнувший выбранный статус отдельно RESORD-Q01.
- [ ] **RESDET-ERROR-01** — Loading/refresh/real-time деталки, поворот/возврат из full-screen/свайп закрытия, исчезновение заказа: **Blocked, RESDET-Q04** для точного UI/перехода; не заменять их поведением списка. Вход из Истории/архивный запрет редактирования проверяются в [отдельном чек-листе](checklist-my-orders-history-reseller.md).
- [ ] **RESDET-ERROR-02** — Ошибки подтверждения, retry/lost response и параллельная смена гарантии/лимита: **Blocked, RESDET-Q02**; старое состояние после ответа с ошибкой само не доказывает сохранение/несохранение на сервере.
