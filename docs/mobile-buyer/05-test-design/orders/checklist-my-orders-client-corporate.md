# Чек-лист: Мои заказы — клиент и корп, Fimex Buyer, iOS

## Область и использование

Проверяется интерфейс «Моих заказов» клиента/корпа: общий активный список, фильтр, показатели, ячейки, оплата и обновление. Заказы связанных реселлеров входят в тестовые данные; [«Клиентские заказы»](checklist-customer-orders-client-corporate.md) и [собственный список реселлера](checklist-my-orders-reseller.md) имеют отдельные чек-листы. История/Статистика покрыты переходом и базовым перемещением выданного заказа, не полным содержимым экранов.

Проверки не выполнялись. `[ ]` — Not run, не Fail. Результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Зависимая от ORD-Qxx часть Blocked до ответа. ID стабильные; снятые ID не переиспользовать.

## Предусловия

- Клиент и связанный корп с включённым/выключенным доступом к режиму реселлера; отдельная чужая группа для проверки изоляции.
- Заказы клиента, корпа и связанных реселлеров в обоих активных статусах; выданные заказы в Истории. Для базовых сумм — без отменённых/частично выданных товаров.
- Разные даты поставщика, порядок создания противоположный порядку дат; разные количества единиц/позиций/заказов.
- Известные согласованные суммы с гарантией/без, Cash/Online, положительная наценка клиента на товары реселлера; ожидаемые цены без этой наценки получены из разрешённого источника, не выведены произвольным делением итоговой цены.
- Состояния достаточного/недостаточного баланса, один неоплаченный заказ для примера долга, возможность пополнения/смены статуса в тестовой среде.
- Группа без активных заказов: вообще без заказов и с заказами только в Истории; один последний активный заказ для перехода в пустое состояние и возможность создать новый активный заказ.
- Доступ к проверке баланса, заказа, прав админской выдачи, управлению сетью и задержкой ответа. Нет доступа — Blocked, не Pass.

## Smoke

ORD-OPEN-01, ORD-ROLE-01/02, ORD-HEADER-01/02, ORD-FILTER-01/04, ORD-SUM-02/03, ORD-SORT-01/02, ORD-PAY-03/04/05, ORD-SYNC-02/03, ORD-EMPTY-01. Использовать результаты основных пунктов.

## Открытие, роли и хедер

- [ ] **ORD-OPEN-01** — Вкладка Моих заказов открывает соответствующий экран, нижняя вкладка подсвечена; после загрузки виден активный список и показатели.
- [ ] **ORD-ROLE-01** — Клиент видит заказы клиента, связанного корпа и связанных реселлеров; выданные и заказы чужой группы не попадают в активный список.
- [ ] **ORD-ROLE-02** — Связанный корп видит тот же соответствующий набор активных заказов клиента/корпа/реселлеров; список не ограничен только собственными покупками корпа.
- [ ] **ORD-HEADER-01** — При включённом доступе к режиму реселлера у клиента/корпа показаны три точки; проверить обе роли.
- [ ] **ORD-HEADER-02** — При выключенном доступе у клиента/корпа три точки скрыты; доступ к остальному списку не исчезает.
- [ ] **ORD-HEADER-03** — Tap по трём точкам открывает меню My orders / Customers; выбор Customers переводит к клиентским заказам. Их состав/суммы/работа с заказом проверяются в отдельном чек-листе; смена источника бейджа — CUSTORD-BADGE-01/02.
- [ ] **ORD-HEADER-04** — Кнопка Статистики открывает Статистику клиента/корпа, кнопка Истории — Историю; это разные переходы.

## Фильтр статусов

- [ ] **ORD-FILTER-01** — При наличии обоих активных статусов доступна кнопка фильтра; меню содержит представленные статусы, не добавляет Released как активный статус.
- [ ] **ORD-FILTER-02** — При единственном статусе кнопка фильтра скрыта; проверить отдельно список только первого и только второго статуса. При пустом наборе условие больше одного статуса тоже не выполнено.
- [ ] **ORD-FILTER-03** — Выбор Pending assembly показывает только заказы первого статуса; выбор Order pending delivery — только второго. Состав брать из исходного набора; видимость кнопки после выбора — ORD-Q02.
- [ ] **ORD-FILTER-04** — Выбор доступного All возвращает весь активный набор; выданные не включаются. Способ выбрать All при возможном скрытии кнопки после фильтрации — ORD-Q02; не считать его согласованным без ответа.
- [ ] **ORD-FILTER-05** — При возврате из заказа сохраняется выбранный статус, обновлённые строки соответствуют ему; изменивший статус заказ не остаётся в неподходящем наборе. Новый состав пунктов/видимость кнопки — ORD-Q02.
- [ ] **ORD-FILTER-06** — Выбрать статус, перейти в другой раздел нижнего меню и вернуться: фильтр сброшен, показан полный активный список; проверить оба направления первоначального выбора.

## Верхние показатели

- [ ] **ORD-SUM-01** — Qty/Amount не кликабельны: tap не открывает отдельный экран и не переключает фильтр.
- [ ] **ORD-SUM-02** — Qty равна сумме количеств единиц товара во всех соответствующих активных заказах клиента/корпа/реселлеров, не числу позиций или заказов. Использовать набор, где все три числа различаются.
- [ ] **ORD-SUM-03** — Amount равна сумме соответствующих активных заказов с учётом типа оплаты и гарантии, без клиентской наценки на товары реселлера; положительную наценку задать для различимости расчётов.
- [ ] **ORD-SUM-04** — При выборе каждого статуса Qty/Amount пересчитаны только по его заказам; All соответствует полному активному набору.
- [ ] **ORD-SUM-05** — Выданные заказы не входят в активные Qty/Amount; при обновлении после выдачи показатели уменьшаются на соответствующие единицы/сумму. Частичная выдача/отменённые товары — ORD-Q03.

## Ячейка, дата и сортировка

- [ ] **ORD-ROW-01** — Номер, дата поставщика, Cash/Online и сумма принадлежат одному заказу; значения соседней ячейки не подставляются.
- [ ] **ORD-ROW-02** — Дата ячейки равна дате поставщика без дней доставки. Использовать ненулевые дни доставки, чтобы дата прайса/покупки отличалась и ошибка была заметна.
- [ ] **ORD-ROW-03** — В ячейке сумма всех соответствующих товаров с гарантией и применимым типом оплаты; наценка клиента на товары реселлера исключена, как и в Amount. База гарантии/округление при исключении наценки — ORD-Q05.
- [ ] **ORD-ROW-04** — Иконка/цвет первого статуса серые, второго красные; в Истории для Released зелёный статус. Не подменять проверку цвета статуса цветом Paid/Not paid.
- [ ] **ORD-ROW-05** — Tap по заказу клиента/корпа открывает правильный заказ с соответствующим номером, а не соседнюю строку; полная работа с деталями вне этого чек-листа.
- [ ] **ORD-ROW-06** — Tap по строке заказа реселлера в «Моих заказах»: **Blocked, ORD-Q01**. Уточнить переход/доступ к просмотру; не требовать возможности работать с ним здесь, поскольку работа предусмотрена в «Клиентских заказах».
- [ ] **ORD-SORT-01** — Заказы второго статуса расположены выше первого независимо от дат; более старая дата первого статуса не перемещает его выше второго.
- [ ] **ORD-SORT-02** — Внутри каждого статуса сверху более ранние даты поставщика, снизу более поздние. Проверить оба статуса и фильтр одного статуса.
- [ ] **ORD-SORT-03** — Когда дата создания в Fimex и дата поставщика дают противоположный порядок, используется дата поставщика; датой оформления не заменяется.
- [ ] **ORD-SORT-04** — После обновления изменивший статус/дату заказ занимает место по новому статусу и дате без дубля. Равные даты — ORD-Q04.

## Состояние оплаты и баланс

- [ ] **ORD-PAY-01** — В первом статусе состояние оплаты в ячейке скрыто; не показывается Not paid как обязательный элемент первого статуса.
- [ ] **ORD-PAY-02** — При втором статусе состояние оплаты видно: Paid для оплаченного, Not paid для неоплаченного. На примере Paid зелёный, Not paid красный, иконка статуса заказа остаётся красной в обоих случаях.
- [ ] **ORD-PAY-03** — При достаточном общем балансе переход заказа клиента/корпа во второй статус выполняет оплату: баланс уменьшается на согласованную сумму заказа, отображается Paid после обновления списка.
- [ ] **ORD-PAY-04** — Один заказ клиента/корпа 1000 USD при балансе 300 USD переходит во второй статус: баланс −700 USD, заказ Not paid. Отрицательный баланс сам по себе не означает Paid.
- [ ] **ORD-PAY-05** — Для предыдущего случая пополнить баланс на 700 USD: баланс 0, заказ автоматически Paid; после обновления видна оплата. Не ожидается дополнительное списание 1000 USD после погашения этого долга.
- [ ] **ORD-PAY-06** — Повторное открытие/refresh списка после списания или автоплаты не выполняет платёж второй раз; состояние баланса соответствует одному списанию и зачислениям, а не числу загрузок UI.
- [ ] **ORD-PAY-07** — Клиент и связанный корп используют общий баланс/состояние оплаты: после изменения открыть/обновить список другой роли и сопоставить Paid/Not paid по одному заказу.
- [ ] **ORD-PAY-08** — Заказ реселлера оплачивается с баланса клиента/общего баланса клиента-корпа, отдельного баланса реселлера для оплаты нет. Точная сумма списания для такого заказа — ORD-Q06; не выводить её из цены другого экрана с наценкой.
- [ ] **ORD-PAY-09** — Для Not paid во втором статусе админская попытка перевода в Released отклоняется; заказ не попадает в Историю. Нужен разрешённый доступ к админке; его отсутствие — Blocked.
- [ ] **ORD-PAY-10** — После полной оплаты разрешённый перевод в Released приводит к Истории и исключению из активного списка после обновления; лимит по этому заказу освобождается при выдаче согласно BUY-LIMIT-06, а не из-за оплаты как таковой.

## Пустое состояние

- [ ] **ORD-EMPTY-01** — При отсутствии активных заказов после успешной загрузки показаны иконка квитанции и карточка пустого состояния, строки заказов отсутствуют. Для русского светлого варианта текст: «Нет активных заказов» и «Сделайте заказ в Fimex и получите его в короткие сроки»; иконка в синем круге, как на предоставленном примере. Не подменять это бесконечным скелетоном или alert ошибки.
- [ ] **ORD-EMPTY-02** — В пустом активном списке Qty/Amount и фильтр скрыты; не отображаются устаревшие суммы или нулевые плитки. Заголовок, Статистика, История и нижнее меню остаются доступными; три точки показаны только при включённом доступе к режиму реселлера. Проверить клиента и корпа с доступом и без.
- [ ] **ORD-EMPTY-03** — Все существующие заказы выданы: активный список показывает пустую карточку, История доступна и содержит выданные заказы. Наличие истории не делает активный список непустым.
- [ ] **ORD-EMPTY-04** — Выдать последний активный заказ и обновить список: показана пустая карточка, прежняя строка/Qty/Amount отсутствуют. Проверять полный активный набор без фильтра; частичная выдача — ORD-Q03.
- [ ] **ORD-EMPTY-05** — Из состояния без активных заказов создать новый активный заказ и обновить список: пустая карточка исчезает, показаны заказ и актуальные Qty/Amount. Мгновенного появления в уже открытом экране не требовать; real-time обновление не согласовано.

## Загрузка, обновление и ошибки

- [ ] **ORD-LOAD-01** — При первоначальной загрузке отображается скелетон; после успешной загрузки показаны актуальные строки/показатели клиента/корпа либо пустое состояние без активных заказов согласно ORD-EMPTY-01/02.
- [ ] **ORD-LOAD-02** — При pull-to-refresh отображается загрузочный скелетон и затем актуальные данные; повторные загрузки не создают дубли заказов и не списывают оплату повторно.
- [ ] **ORD-SYNC-01** — Пока список открыт, изменение данных на сервере не обязано отображаться в real-time; при следующем открытии/возврате или pull-to-refresh данные актуальны.
- [ ] **ORD-SYNC-02** — Открыть заказ, изменить тип оплаты допустимым действием/в тестовой админке, вернуться: ячейка и Amount сразу используют актуальную сумму; выбранный фильтр сохраняется. Работа с деталями не подменяется шагами, которых ещё нет в документации.
- [ ] **ORD-SYNC-03** — Во время просмотра заказа меняются статус/оплата, вернуться: список сразу учитывает новые данные, порядок и фильтр; не показывает прежнюю ячейку как актуальную.
- [ ] **ORD-SYNC-04** — Выданный заказ после refresh/возврата отсутствует в активном списке и показателях, доступен из Истории. Проверки бейджа NAV-ORDERS-03/05 использовать с отдельным вопросом времени его обновления NAV-Q02.
- [ ] **ORD-ERROR-01** — Отсутствие сети при загрузке/refresh показывает стандартный alert. Сохранение прежних строк/фильтра и retry — ORD-Q07.
- [ ] **ORD-ERROR-02** — Ошибка сервера при загрузке/refresh показывает стандартный alert; её не подменять успешным пустым списком. Точное состояние после ошибки — ORD-Q07.
