# Чек-лист: Мои заказы — клиент и корп, Fimex Buyer, iOS

## Область и использование

Проверяется интерфейс «Моих заказов» клиента/корпа: общий активный список, фильтр, показатели, ячейки, оплата и обновление. Заказы связанных реселлеров входят в тестовые данные; [«Клиентские заказы»](checklist-customer-orders-client-corporate.md) и [собственный список реселлера](checklist-my-orders-reseller.md) имеют отдельные чек-листы. [Статистика покупок группы](checklist-my-orders-statistics-client-corporate.md) покрыта отдельно; здесь её переход и базовое перемещение выданного заказа в Историю, не полное содержимое Истории.

Проверки не выполнялись. `[ ]` — Not run, не Fail. Результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Зависимая от ORD-Qxx часть Blocked до ответа. ID стабильные; снятые ID не переиспользовать.

## Информация о прогоне

- Версия/build, окружение, устройство/iOS, язык/тема:
- Роль клиент/корп, связанная группа, доступ к режиму реселлера:
- Активные/выданные заказы, статусы, даты поставщика, количества/суммы, фильтр:
- Баланс/депозит/лимит до и после событий, конфигурация оплаты/гарантии/наценки:
- Дата/исполнитель, результаты/дефекты:

## Предусловия

- Клиент и связанный корп с включённым/выключенным доступом к режиму реселлера; отдельная чужая группа для проверки изоляции.
- Заказы клиента, корпа и связанных реселлеров в обоих активных статусах; выданные заказы в Истории. Для базовых сумм — без отменённых/частично выданных товаров.
- Разные даты поставщика, порядок создания противоположный порядку дат; разные количества единиц/позиций/заказов.
- Известные согласованные суммы с гарантией/без, Cash/Online, положительная наценка клиента на товары реселлера; ожидаемые цены без этой наценки получены из разрешённого источника, не выведены произвольным делением итоговой цены.
- Состояния достаточного/недостаточного баланса, один неоплаченный заказ для примера долга, возможность пополнения/смены статуса в тестовой среде.
- Группа без активных заказов: вообще без заказов и с заказами только в Истории; один последний активный заказ для перехода в пустое состояние и возможность создать новый активный заказ.
- Доступ к проверке баланса, заказа, прав админской выдачи, управлению сетью и задержкой ответа. Нет доступа — Blocked, не Pass.

## Smoke

ORD-OPEN-01, ORD-ROLE-01/02, ORD-HEADER-01/02, ORD-FILTER-01/04, ORD-SUM-02/03, ORD-SORT-01/02, ORD-PAY-03/04/05, ORD-SYNC-02/03, ORD-EMPTY-01. Использовать результаты основных пунктов.

## Открытие, роли и хедер

- [ ] **ORD-OPEN-01 — Открытие общего списка Моих заказов**

  <details>
  <summary>Подробности проверки</summary>

  - Вкладка Моих заказов открывает соответствующий экран, нижняя вкладка подсвечена; после загрузки виден активный список и показатели.

  </details>

- [ ] **ORD-ROLE-01 — Состав активных заказов клиента**

  <details>
  <summary>Подробности проверки</summary>

  - Клиент видит заказы клиента, связанного корпа и связанных реселлеров; выданные и заказы чужой группы не попадают в активный список.

  </details>

- [ ] **ORD-ROLE-02 — Общий активный список клиента и корпа**

  <details>
  <summary>Подробности проверки</summary>

  - Связанный корп видит тот же соответствующий набор активных заказов клиента/корпа/реселлеров; список не ограничен только собственными покупками корпа.

  </details>

- [ ] **ORD-HEADER-01 — Меню при доступном режиме реселлера**

  <details>
  <summary>Подробности проверки</summary>

  - При включённом доступе к режиму реселлера у клиента/корпа показаны три точки; проверить обе роли.

  </details>

- [ ] **ORD-HEADER-02 — Скрытие меню без доступа к реселлерам**

  <details>
  <summary>Подробности проверки</summary>

  - При выключенном доступе у клиента/корпа три точки скрыты; доступ к остальному списку не исчезает.

  </details>

- [ ] **ORD-HEADER-03 — Переход к клиентским заказам**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по трём точкам открывает меню My orders / Customers; выбор Customers переводит к клиентским заказам.
  - Их состав/суммы/работа с заказом проверяются в отдельном чек-листе; смена источника бейджа — CUSTORD-BADGE-01/02.

  </details>

- [ ] **ORD-HEADER-04 — Переходы к общей статистике и Истории**

  <details>
  <summary>Подробности проверки</summary>

  - Кнопка Статистики открывает статистику покупок всей группы клиента/корпа за период, независимо от фильтра активного списка и включая Историю/неоплаченные;
  - кнопка Истории — Историю. Полные статистика и [История](checklist-my-orders-history-client-corporate.md) в отдельных чек-листах;
  - фильтр списка в Историю не передаётся, переходы не подменяют друг друга.

  </details>


## Фильтр статусов

- [ ] **ORD-FILTER-01 — Фильтр двух активных статусов**

  <details>
  <summary>Подробности проверки</summary>

  - При наличии обоих активных статусов доступна кнопка фильтра; меню содержит представленные статусы, не добавляет Released как активный статус.

  </details>

- [ ] **ORD-FILTER-02 — Скрытие фильтра при одном или нуле статусов**

  <details>
  <summary>Подробности проверки</summary>

  - При единственном статусе кнопка фильтра скрыта; проверить отдельно список только первого и только второго статуса.
  - При пустом наборе условие больше одного статуса тоже не выполнено.

  </details>

- [ ] **ORD-FILTER-03 — Фильтрация каждого активного статуса**

  <details>
  <summary>Подробности проверки</summary>

  - Выбор Pending assembly показывает только заказы первого статуса; выбор Order pending delivery — только второго.
  - Состав брать из исходного набора; видимость кнопки после выбора — ORD-Q02.

  </details>

- [ ] **ORD-FILTER-04 — Возврат полного набора через All**

  <details>
  <summary>Подробности проверки</summary>

  - Выбор доступного All возвращает весь активный набор; выданные не включаются.
  - Способ выбрать All при возможном скрытии кнопки после фильтрации — ORD-Q02; не считать его согласованным без ответа.

  </details>

- [ ] **ORD-FILTER-05 — Сохранение фильтра после возврата из заказа**

  <details>
  <summary>Подробности проверки</summary>

  - При возврате из заказа сохраняется выбранный статус, обновлённые строки соответствуют ему; изменивший статус заказ не остаётся в неподходящем наборе.
  - Новый состав пунктов/видимость кнопки — ORD-Q02.

  </details>

- [ ] **ORD-FILTER-06 — Сброс фильтра после другого нижнего раздела**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать статус, перейти в другой раздел нижнего меню и вернуться: фильтр сброшен, показан полный активный список; проверить оба направления первоначального выбора.

  </details>


## Верхние показатели

- [ ] **ORD-SUM-01 — Неинтерактивность Qty и Amount**

  <details>
  <summary>Подробности проверки</summary>

  - Qty/Amount не кликабельны: tap не открывает отдельный экран и не переключает фильтр.

  </details>

- [ ] **ORD-SUM-02 — Суммарное количество единиц активных заказов**

  <details>
  <summary>Подробности проверки</summary>

  - Qty равна сумме количеств единиц товара во всех соответствующих активных заказах клиента/корпа/реселлеров, не числу позиций или заказов.
  - Использовать набор, где все три числа различаются.

  </details>

- [ ] **ORD-SUM-03 — Сумма активных заказов без реселлерской наценки**

  <details>
  <summary>Подробности проверки</summary>

  - Amount равна сумме соответствующих активных заказов с учётом типа оплаты и гарантии, без клиентской наценки на товары реселлера; положительную наценку задать для различимости расчётов.

  </details>

- [ ] **ORD-SUM-04 — Пересчёт итогов по статусу**

  <details>
  <summary>Подробности проверки</summary>

  - При выборе каждого статуса Qty/Amount пересчитаны только по его заказам; All соответствует полному активному набору.

  </details>

- [ ] **ORD-SUM-05 — Исключение выданных заказов из итогов**

  <details>
  <summary>Подробности проверки</summary>

  - Выданные заказы не входят в активные Qty/Amount; при обновлении после выдачи показатели уменьшаются на соответствующие единицы/сумму.
  - Частичная выдача/отменённые товары — ORD-Q03.

  </details>


## Ячейка, дата и сортировка

- [ ] **ORD-ROW-01 — Соответствие данных ячейки одному заказу**

  <details>
  <summary>Подробности проверки</summary>

  - Номер, дата поставщика, Cash/Online и сумма принадлежат одному заказу; значения соседней ячейки не подставляются.

  </details>

- [ ] **ORD-ROW-02 — Дата поставщика без дней доставки**

  <details>
  <summary>Подробности проверки</summary>

  - Дата ячейки равна дате поставщика без дней доставки.
  - Использовать ненулевые дни доставки, чтобы дата прайса/покупки отличалась и ошибка была заметна.

  </details>

- [ ] **ORD-ROW-03 — Сумма ячейки с гарантией без наценки**

  <details>
  <summary>Подробности проверки</summary>

  - В ячейке сумма всех соответствующих товаров с гарантией и применимым типом оплаты; наценка клиента на товары реселлера исключена, как и в Amount.
  - База гарантии/округление при исключении наценки — ORD-Q05.

  </details>

- [ ] **ORD-ROW-04 — Различие цветов статуса и оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - Иконка/цвет первого статуса серые, второго красные; в Истории для Released зелёный статус.
  - Не подменять проверку цвета статуса цветом Paid/Not paid.

  </details>

- [ ] **ORD-ROW-05 — Открытие деталей своего заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по заказу клиента/корпа открывает правильный заказ с соответствующим номером, а не соседнюю строку; полная работа с деталями вне этого чек-листа.

  </details>

- [ ] **ORD-ROW-06 — Общие детали реселлерской части заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по заказу с товарами реселлера в «Моих заказах» открывает правильную деталку общего заказа с ценами без наценки;
  - до КТ смена логиста позиции доступна, гарантия недоступна.
  - Ручная клиентская оплата/выдача остаётся в «Клиентских»; подробные проверки — ORDDET-KT-03.
  - ORD-Q01 закрыт, ID сохранён.

  </details>

- [ ] **ORD-SORT-01 — Приоритет второго статуса в сортировке**

  <details>
  <summary>Подробности проверки</summary>

  - Заказы второго статуса расположены выше первого независимо от дат; более старая дата первого статуса не перемещает его выше второго.

  </details>

- [ ] **ORD-SORT-02 — Сортировка по старым датам внутри статуса**

  <details>
  <summary>Подробности проверки</summary>

  - Внутри каждого статуса сверху более ранние даты поставщика, снизу более поздние.
  - Проверить оба статуса и фильтр одного статуса.

  </details>

- [ ] **ORD-SORT-03 — Дата поставщика вместо даты оформления**

  <details>
  <summary>Подробности проверки</summary>

  - Когда дата создания в Fimex и дата поставщика дают противоположный порядок, используется дата поставщика; датой оформления не заменяется.

  </details>

- [ ] **ORD-SORT-04 — Пересортировка изменённого заказа без дублей**

  <details>
  <summary>Подробности проверки</summary>

  - После обновления изменивший статус/дату заказ занимает место по новому статусу и дате без дубля.
  - Равные даты — ORD-Q04.

  </details>


## Состояние оплаты и баланс

- [ ] **ORD-PAY-01 — Отсутствие оплаты в первом статусе**

  <details>
  <summary>Подробности проверки</summary>

  - В первом статусе состояние оплаты в ячейке скрыто; не показывается Not paid как обязательный элемент первого статуса.

  </details>

- [ ] **ORD-PAY-02 — Paid и Not paid во втором статусе**

  <details>
  <summary>Подробности проверки</summary>

  - При втором статусе состояние оплаты видно: Paid для оплаченного, Not paid для неоплаченного.
  - На примере Paid зелёный, Not paid красный, иконка статуса заказа остаётся красной в обоих случаях.

  </details>

- [ ] **ORD-PAY-03 — Автооплата при достаточном балансе**

  <details>
  <summary>Подробности проверки</summary>

  - При достаточном общем балансе переход заказа клиента/корпа во второй статус выполняет оплату: баланс уменьшается на согласованную сумму заказа, отображается Paid после обновления списка.

  </details>

- [ ] **ORD-PAY-04 — Долг и Not paid при недостаточном балансе**

  <details>
  <summary>Подробности проверки</summary>

  - Один заказ клиента/корпа 1000 USD при балансе 300 USD переходит во второй статус: баланс −700 USD, заказ Not paid.
  - Отрицательный баланс сам по себе не означает Paid.

  </details>

- [ ] **ORD-PAY-05 — Автооплата после погашения долга**

  <details>
  <summary>Подробности проверки</summary>

  - Для предыдущего случая пополнить баланс на 700 USD: баланс 0, заказ автоматически Paid; после обновления видна оплата.
  - Не ожидается дополнительное списание 1000 USD после погашения этого долга.

  </details>

- [ ] **ORD-PAY-06 — Отсутствие повторного списания при загрузке**

  <details>
  <summary>Подробности проверки</summary>

  - Повторное открытие/refresh списка после списания или автоплаты не выполняет платёж второй раз; состояние баланса соответствует одному списанию и зачислениям, а не числу загрузок UI.

  </details>

- [ ] **ORD-PAY-07 — Общая оплата клиента и корпа**

  <details>
  <summary>Подробности проверки</summary>

  - Клиент и связанный корп используют общий баланс/состояние оплаты: после изменения открыть/обновить список другой роли и сопоставить Paid/Not paid по одному заказу.

  </details>

- [ ] **ORD-PAY-08 — Оплата реселлерского заказа с общего баланса**

  <details>
  <summary>Подробности проверки</summary>

  - Заказ реселлера оплачивается с баланса клиента/общего баланса клиента-корпа, отдельного баланса реселлера для оплаты нет.
  - Точная сумма списания для такого заказа — ORD-Q06; не выводить её из цены другого экрана с наценкой.

  </details>

- [ ] **ORD-PAY-09 — Запрет админской выдачи неоплаченного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Для Not paid во втором статусе админская попытка перевода в Released отклоняется; заказ не попадает в Историю.
  - Нужен разрешённый доступ к админке; его отсутствие — Blocked.

  </details>

- [ ] **ORD-PAY-10 — Архивирование оплаченного выданного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - После полной оплаты разрешённый перевод в Released приводит к Истории и исключению из активного списка после обновления;
  - лимит по этому заказу освобождается при выдаче согласно BUY-LIMIT-06, а не из-за оплаты как таковой.

  </details>


## Пустое состояние

- [ ] **ORD-EMPTY-01 — Полное пустое состояние активных заказов**

  <details>
  <summary>Подробности проверки</summary>

  - При отсутствии активных заказов после успешной загрузки показаны иконка квитанции и карточка пустого состояния, строки заказов отсутствуют.
  - Для русского светлого варианта текст: «Нет активных заказов» и «Сделайте заказ в Fimex и получите его в короткие сроки»;
  - иконка в синем круге, как на предоставленном примере.
  - Не подменять это бесконечным скелетоном или alert ошибки.

  </details>

- [ ] **ORD-EMPTY-02 — Состав интерфейса без активных заказов**

  <details>
  <summary>Подробности проверки</summary>

  - В пустом активном списке Qty/Amount и фильтр скрыты; не отображаются устаревшие суммы или нулевые плитки.
  - Заголовок, Статистика, История и нижнее меню остаются доступными; три точки показаны только при включённом доступе к режиму реселлера.
  - Проверить клиента и корпа с доступом и без.

  </details>

- [ ] **ORD-EMPTY-03 — Пустой активный список при наличии Истории**

  <details>
  <summary>Подробности проверки</summary>

  - Все существующие заказы выданы: активный список показывает пустую карточку, История доступна и содержит выданные заказы.
  - Наличие истории не делает активный список непустым.

  </details>

- [ ] **ORD-EMPTY-04 — Пустое состояние после выдачи последнего заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Выдать последний активный заказ и обновить список: показана пустая карточка, прежняя строка/Qty/Amount отсутствуют.
  - Проверять полный активный набор без фильтра; частичная выдача — ORD-Q03.

  </details>

- [ ] **ORD-EMPTY-05 — Возврат из пустоты после нового заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Из состояния без активных заказов создать новый активный заказ и обновить список: пустая карточка исчезает, показаны заказ и актуальные Qty/Amount.
  - Мгновенного появления в уже открытом экране не требовать; real-time обновление не согласовано.

  </details>


## Загрузка, обновление и ошибки

- [ ] **ORD-LOAD-01 — Скелетон первоначальной загрузки заказов**

  <details>
  <summary>Подробности проверки</summary>

  - При первоначальной загрузке отображается скелетон; после успешной загрузки показаны актуальные строки/показатели клиента/корпа либо пустое состояние без активных заказов согласно ORD-EMPTY-01/02.

  </details>

- [ ] **ORD-LOAD-02 — Обновление со скелетоном без повторной оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - При pull-to-refresh отображается загрузочный скелетон и затем актуальные данные; повторные загрузки не создают дубли заказов и не списывают оплату повторно.

  </details>

- [ ] **ORD-SYNC-01 — Актуализация без обязательного real-time**

  <details>
  <summary>Подробности проверки</summary>

  - Пока список открыт, изменение данных на сервере не обязано отображаться в real-time; при следующем открытии/возврате или pull-to-refresh данные актуальны.

  </details>

- [ ] **ORD-SYNC-02 — Обновление суммы после изменения оплаты в деталке**

  <details>
  <summary>Подробности проверки</summary>

  - Открыть заказ, изменить тип оплаты допустимым действием/в тестовой админке, вернуться: ячейка и Amount сразу используют актуальную сумму;
  - выбранный фильтр сохраняется. Работа с деталями не подменяется шагами, которых ещё нет в документации.

  </details>

- [ ] **ORD-SYNC-03 — Актуализация статуса и оплаты после возврата**

  <details>
  <summary>Подробности проверки</summary>

  - Во время просмотра заказа меняются статус/оплата, вернуться: список сразу учитывает новые данные, порядок и фильтр; не показывает прежнюю ячейку как актуальную.

  </details>

- [ ] **ORD-SYNC-04 — Исключение выданного заказа после обновления**

  <details>
  <summary>Подробности проверки</summary>

  - Выданный заказ после refresh/возврата отсутствует в активном списке и показателях, доступен из Истории.
  - Проверки бейджа NAV-ORDERS-03/05 использовать с отдельным вопросом времени его обновления NAV-Q02.

  </details>

- [ ] **ORD-ERROR-01 — Сетевая ошибка общего списка**

  <details>
  <summary>Подробности проверки</summary>

  - Отсутствие сети при загрузке/refresh показывает стандартный alert.
  - Сохранение прежних строк/фильтра и retry — ORD-Q07.

  </details>

- [ ] **ORD-ERROR-02 — Серверная ошибка общего списка**

  <details>
  <summary>Подробности проверки</summary>

  - Ошибка сервера при загрузке/refresh показывает стандартный alert; её не подменять успешным пустым списком.
  - Точное состояние после ошибки — ORD-Q07.

  </details>
