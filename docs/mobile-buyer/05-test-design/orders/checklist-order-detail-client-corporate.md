# Чек-лист: Детали общего заказа — клиент и корп, Fimex Buyer, iOS

## Область и использование

Заказ из общего списка «Мои заказы» клиента/корпа: статусы/автооплата, вкладки владельцев, суммы без наценки, меню, гарантия/логист позиции, лимит владельца, группировка, файлы, КТ и full-screen. Детали клиентского заказа и самого реселлера будут отдельными чек-листами.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть Blocked по ORDDET-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент и связанный корп, связанные реселлеры и чужая группа. Заказы только клиента, только корпа, только реселлера и смешанный заказ; доступ к разрешённым данным состава/владельцев.
- Заказы до/после КТ, окно гарантии/логиста открыто до КТ с подтверждением после; возможность контролировать время/переход в тестовой среде. Не выполнять реальные финансовые операции ради подготовки.
- Оба активных статуса, Paid/Not paid, последующие ненаступившие статусы, будущий КТ первого статуса, завершённый заказ для проверки доступности файлов.
- Товары с гарантией/без её возможности, флагом/без страны, длинными именами, несколько единиц одной позиции; один товар с разными ценами покупки/гарантиями и согласованной сортировкой админки.
- Известные цены/комиссии/варианты гарантии: отдельно цена покупки, текущая цена прайса, положительная клиентская наценка. Для базовых сумм без частичных отмен/выдач.
- Достаточный/недостаточный прирост лимита владельца, чужой лимит с противоположным состоянием. Смешанный заказ с клиентом/корпом и реселлерами.
- Заказ назначения с совпадающим ключом и без него; совпадающая позиция назначения и позиции с иной ценой/гарантией; перенос последней/непоследней позиции.
- Данные логиста/лицензия и доступ к проверке Excel/PDF из разрешённого источника. Нет доступа — Blocked, не Pass.

## Открытие, хедер и навигация

- [ ] **ORDDET-OPEN-01** — Tap по общему заказу клиента/корпа открывает деталку с соответствующим номером, составом и владельцами; не деталку клиентского заказа/реселлера с ручной оплатой.
- [ ] **ORDDET-OPEN-02** — Три точки видны клиенту/корпу и открывают меню заказа с логистом, допустимым типом оплаты и тремя документами. Не использовать условие трёх точек списка как условие меню деталки.
- [ ] **ORDDET-OPEN-03** — Связанный корп открывает тот же общий заказ и видит его актуальный состав/цены/статус; сведения чужой группы не подставляются.
- [ ] **ORDDET-CLOSE-01** — Крестик закрывает деталку в исходный список; выбранный существующий статус фильтра списка сохраняется, его данные обновляются.
- [ ] **ORDDET-CLOSE-02** — Свайп вниз закрывает деталку в список с тем же результатом; не возврат на Главную по сценарию покупки.
- [ ] **ORDDET-CLOSE-03** — После изменения/переноса и возврата общий список показывает актуальные суммы/логические заказы, удалённый пустой источник не остаётся строкой; исходный фильтр списка применяется по его правилам.

## Текущий статус, автоматическая оплата и таймлайн

- [ ] **ORDDET-STATUS-01** — Номер/иконка/цвет соответствуют открытому заказу: Pending assembly серый, Order pending delivery красный, Released зелёный; не чужой статус.
- [ ] **ORDDET-STATUS-02** — В Pending assembly отметка оплаты скрыта; со второго статуса Paid/Not paid соответствует автоматической оплате общего заказа, не ручной отметке клиентского заказа реселлера.
- [ ] **ORDDET-STATUS-03** — Состояния достаточного баланса, задолженности и погашения из ORD-PAY-03/04/05 дают соответствующее состояние деталки при открытии. Повторное открытие не выполняет дополнительное списание; независимую ручную оплату сюда не добавлять.
- [ ] **ORDDET-TIME-01** — По умолчанию таймлайн фокусируется на текущем статусе; раскрытие показывает все статусы в порядке Pending assembly → Order pending delivery → Released, сворачивание возвращает текущий.
- [ ] **ORDDET-TIME-02** — Первый статус показывает дату/время КТ соответствующего заказа, не момент покупки; проверить будущий КТ, чтобы дата всё равно отображалась.
- [ ] **ORDDET-TIME-03** — Последующие наступившие статусы показывают фактическую дату/время, ещё не наступившие — без даты/времени; первый статус с будущим КТ проверяется отдельно как исключение.
- [ ] **ORDDET-TIME-04** — Время таймлайна отображается по МСК; на устройстве с другим часовым поясом не заменяется локальным временем. Граница КТ/расчёт доставки других экранов — отдельные вопросы, не считать закрытыми этим тестом.

## Вкладки, товары и суммы

- [ ] **ORDDET-TABS-01** — Заказ только с товарами клиента: вкладки владельцев и All не показаны, весь состав отображается.
- [ ] **ORDDET-TABS-02** — Только корп или только один реселлер: показаны его вкладка и All. All не скрывается по правилу одного реселлера из клиентского списка.
- [ ] **ORDDET-TABS-03** — Смешанный заказ клиента/корпа/реселлеров показывает вкладки всех присутствующих владельцев и All; владелец без товаров в заказе не добавляется.
- [ ] **ORDDET-TABS-04** — Выбор вкладки ограничивает товары владельцем и пересчитывает Qty/Amount; All возвращает весь состав. Выбор по умолчанию/свайп — ORDDET-Q04.
- [ ] **ORDDET-SUM-01** — Qty — сумма единиц товара выбранного набора, не число позиций; разные цены одного товара остаются разными строками, но их единицы учитываются.
- [ ] **ORDDET-SUM-02** — Amount по All/всему заказу равна сумме цен единиц × количества с гарантией/типом оплаты, без наценки клиента на товары реселлера. Использовать известные согласованные цены без наценки; формула округления — ORDDET-Q02.
- [ ] **ORDDET-SUM-03** — На вкладке каждого владельца Amount и Qty относятся только к его товарам; показанные цены реселлерских товаров тоже без наценки.
- [ ] **ORDDET-ROW-01** — Позиция показывает правильные название, флаг/иконку, цену за единицу, количество и текущую гарантию; цена не заменена общей суммой позиции при количестве больше 1.
- [ ] **ORDDET-ROW-02** — Нет страны: иконка товара вместо выдуманного флага; длинное имя не подставляет данные соседней строки и не перекрывает цену/количество.
- [ ] **ORDDET-ROW-03** — Порядок товаров соответствует заданному админом на All и вкладке владельца; дату покупки/цену как самовольную сортировку не применять.
- [ ] **ORDDET-ROW-04** — Один товар с разными ценами покупки либо разной гарантией отображается отдельными позициями с собственными ценами/количествами/гарантиями.

## КТ и доступность редактирования

- [ ] **ORDDET-KT-01** — До КТ логист в меню доступен, Cash/Online показаны с текущим выбором; после КТ логист остаётся видимым, tap недоступен, тип оплаты скрыт. Документы остаются доступными.
- [ ] **ORDDET-KT-02** — До КТ товар клиента/корпа с гарантией открывает Warranty / Ship To; у товара без возможности гарантии только Ship To.
- [ ] **ORDDET-KT-03** — Позиция реселлера до КТ открывает только смену логиста: гарантия недоступна даже при наличии гарантийных вариантов у товара; после КТ tap по любой позиции не открывает редактор.
- [ ] **ORDDET-KT-04** — Открыть Warranty до КТ, выбрать изменение, нажать Confirm после КТ: визуально ничего не происходит, гарантия/цена/Amount не меняются. Не ожидать «Упс…»/закрытия на Главную; принятое текущее поведение.
- [ ] **ORDDET-KT-05** — Открыть смену логиста до КТ, подтвердить после КТ: визуально ничего не происходит, логист/состав/группировка не меняются. Проверить редактор позиции и выбор из меню; не требовать alert покупки.
- [ ] **ORDDET-KT-06** — Подтверждение ровно в КТ, смена типа оплаты в меню, открытом до КТ, изменение КТ поставщиком: **Blocked, ORDDET-Q07**, границы/реакция не определены.

## Логист всего заказа и лицензия

- [ ] **ORDDET-LOG-01** — До КТ tap по логисту меню открывает список; выбор нового — окно данных именно этого логиста с подтверждением. Чужие реквизиты не подставляются; полный состав полей — ORDDET-Q06.
- [ ] **ORDDET-LOG-02** — Выбрать логиста, закрыть окно данных без Confirm: логист/состав заказа прежние. Сохранение не выполняется по одному выбору строки списка.
- [ ] **ORDDET-LOG-03** — Подтвердить нового логиста из меню при выбранной вкладке одного владельца: изменение относится ко всему заказу, включая скрытые этой вкладкой позиции. После успеха новое значение в меню заказа назначения.
- [ ] **ORDDET-LOG-04** — Смена логиста текущего заказа не меняет логиста аккаунта для следующих покупок клиента/корпа/реселлера. Не переносить сюда сохранение настройки из покупки.
- [ ] **ORDDET-LOG-05** — Скачивание лицензии в данных выбранного логиста открывает системный Share с его лицензией; выбор/закрытие Share не заменяет подтверждение логиста. Формат/отсутствующая лицензия/ошибка — ORDDET-Q06.

## Тип оплаты и лимит владельца

- [ ] **ORDDET-PAYTYPE-01** — До КТ текущий Cash/Online соответствует заказу, выбор другого варианта из меню действует на весь заказ независимо от вкладки, не только на видимые товары.
- [ ] **ORDDET-PAYTYPE-02** — При достаточном приросте лимита всех владельцев успешная смена оплаты сразу пересчитывает цены каждой позиции, гарантии в итоговой стоимости и общую/выбранную Amount по согласованным ценам; открывается заказ назначения по новой оплате.
- [ ] **ORDDET-PAYTYPE-03** — Смена оплаты заказа не меняет тип оплаты аккаунта для будущих покупок и не переносится на другие несвязанные заказы.
- [ ] **ORDDET-LIMIT-01** — Удорожание проверяет только прирост занятой суммы. Например согласованные суммы позиции клиента/корпа 1 000 → 1 100 и доступный лимит 150: прирост 100 укладывается, отказ по полной сумме 1 100 не ожидается; после успеха доступно 50. Использовать известные цены, не угадывать формулу Cash/Online.
- [ ] **ORDDET-LIMIT-02** — При недостатке прироста по гарантии владельца показан alert превышения лимита как в покупке; гарантия/цена/Amount не применяются, чужой достаточный лимит не заменяет лимит владельца.
- [ ] **ORDDET-LIMIT-03** — В смешанном заказе удорожание оплаты проверяет общий лимит для товаров клиента/корпа и отдельный лимит каждого реселлера. Подготовить нехватку именно у реселлера при достаточном общем лимите: его ограничение не пропускается. Атомарность/текст отказа при смешанном заказе — **Blocked, ORDDET-Q03/06**.
- [ ] **ORDDET-LIMIT-04** — В обратном случае хватает лимита реселлера, но не общего лимита для позиции клиента/корпа: изменение не оценивается только по достаточному лимиту реселлера. Частичный отказ/сохранение остальных позиций — ORDDET-Q03.
- [ ] **ORDDET-LIMIT-05** — Удешевление оплаты/гарантии возвращает разницу в доступный лимит владельца. Пример согласованной позиции клиента/корпа 1 100 → 1 000, доступно 50 → 150; другие лимиты не получают эту разницу.
- [ ] **ORDDET-LIMIT-06** — Повторные открытия/просмотр барабана/Cancel не занимают прирост лимита; применённое изменение учитывается один раз. Повторный Confirm/потерянный ответ и учёт переноса — ORDDET-Q03/06.

## Гарантия конкретной позиции

- [ ] **ORDDET-GUAR-01** — Warranty показывает именно выбранную позицию, флаг/иконку, имя, текущую гарантию и варианты цены/сроков; другая позиция одноимённого товара не подставляется.
- [ ] **ORDDET-GUAR-02** — Прокрутка барабана и Cancel/закрытие без Confirm не меняют гарантию/цены/сумму; выбор применяется после подтверждения.
- [ ] **ORDDET-GUAR-03** — При достаточном лимите Confirm меняет гарантию всех единиц выбранной позиции: при количестве 2 обе получают её, Amount пересчитывается по цене варианта × 2. Иная позиция того же товара по другой цене/гарантии не изменяется.
- [ ] **ORDDET-GUAR-04** — Один товар куплен до и после изменения цены: барабаны гарантии используют базу каждой покупки и отличаются; текущая цена прайса не заменяет зафиксированную. Конфигурация процентов при её изменении — ORDDET-Q02.
- [ ] **ORDDET-GUAR-05** — После успешной смены актуальны строка гарантии, цена, выбранная Amount, Amount всего заказа и сумма в общем списке после возврата; клиентская наценка не появляется.

## Логист позиции, перенос и объединение

- [ ] **ORDDET-MOVE-01** — Ship To выбранной позиции показывает её имя/флаг либо иконку, текущего логиста и барабан; до Confirm позиция не перемещается, Cancel оставляет исходный заказ.
- [ ] **ORDDET-MOVE-02** — Подтвердить смену логиста непоследней позиции: она исчезает из источника, его Qty/Amount пересчитаны; открывается назначение с этой позицией и новым логистом, оставшиеся товары источника не перенесены.
- [ ] **ORDDET-MOVE-03** — Есть назначение с той же датой поставщика, поставщиком, типом оплаты и новым логистом: позиция объединяется с ним. Изменить по одному компоненту ключа в контрольных данных — неподходящий заказ не используется как совпадающий.
- [ ] **ORDDET-MOVE-04** — Назначения с нужным ключом нет: создаётся и открывается соответствующий заказ с перенесённой позицией; источник и назначение не содержат её одновременно. Номер нового заказа — ORDDET-Q01.
- [ ] **ORDDET-MOVE-05** — В назначении есть совпадающий товар того же владельца с той же ценой/гарантией: количество суммируется. Сумма/Qty учитывают прежние и перенесённые единицы без потерь/дублей.
- [ ] **ORDDET-MOVE-06** — Такой же товар назначения с другой ценой или гарантией остаётся отдельной позицией; не усреднять цены. Владельцы разных вкладок не смешиваются при объединении общего заказа.
- [ ] **ORDDET-MOVE-07** — Перенос последней позиции удаляет пустой источник; после закрытия назначения и возврата в список исходного заказа нет. Перенос непоследней позиции источник не удаляет.
- [ ] **ORDDET-MOVE-08** — Смена логиста всего заказа/оплаты из меню переносит весь состав по новому ключу и открывает назначение; существующий подходящий заказ объединяется, опустевший источник удаляется. Не ограничивать перенос выбранной вкладкой.

## Документы Excel/PDF

- [ ] **ORDDET-DOC-01** — Invoice, Packing List и IMEI/SN открывают выбор Excel/PDF; каждый вариант формирует/открывает соответствующий файл. Проверить все шесть сочетаний; расширения/колонки/приложение открытия — ORDDET-Q05.
- [ ] **ORDDET-DOC-02** — Документы доступны до/после КТ и на каждом статусе, включая первый; отсутствие заполненных серийных данных не подменять произвольным запретом формирования. Точное отображение незаполненного IMEI/SN — ORDDET-Q05.
- [ ] **ORDDET-DOC-03** — На All либо без вкладок файл относится ко всему заказу; на ID только к товарам выбранного владельца, остальные не включаются. Проверить каждого владельца и оба формата применимых документов.
- [ ] **ORDDET-DOC-04** — В документах с ценами указаны актуальные цены без клиентской наценки, включая реселлерские товары; в общем заказе и файле нет наценки из интерфейса реселлера. Не требовать ценовую колонку в каждом типе документа без шаблона.
- [ ] **ORDDET-DOC-05** — После смены гарантии/оплаты/переноса вновь открытый файл соответствует текущему заказу/выбранному владельцу: новые цены/состав/количества, не прежний кэш. Перемещённые позиции не остаются в документе непустого источника.

## Полноэкранный просмотр

- [ ] **ORDDET-FULL-01** — Full-screen mode открывает горизонтальный просмотр правильного номера, товаров, Qty/цены/текущей гарантии; данные совпадают с обычной деталкой, наценка клиента не добавляется.
- [ ] **ORDDET-FULL-02** — Если вкладки есть, они доступны в full-screen и фильтруют товары; только клиент — вкладок нет. Просмотр и прокрутка не включают редактирование гарантии/логиста.
- [ ] **ORDDET-FULL-03** — Крестик full-screen возвращает в обычную деталку с сохранением выбранной вкладки, не закрывает сразу общий заказ в список. Поворот/позиция прокрутки — ORDDET-Q08.

## Неопределённые ошибки и синхронизация

- [ ] **ORDDET-ERROR-01** — Ошибки изменения заказа/формирования файла/лицензии, retry и потерянный ответ: **Blocked, ORDDET-Q06** для точного UI/сохранения/перехода; отсутствие ответа не считать успешным изменением по данным старого экрана.
- [ ] **ORDDET-SYNC-01** — Загрузка/ручной refresh/real-time самой деталки и удаление её номера другой сессией: **Blocked, ORDDET-Q08**. Отсутствие real-time в списке не задаёт это поведение автоматически.
