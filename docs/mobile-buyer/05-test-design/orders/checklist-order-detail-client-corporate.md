# Чек-лист: Детали общего заказа — клиент и корп, Fimex Buyer, iOS

## Область и использование

Заказ из общего списка «Мои заказы» клиента/корпа: статусы/автооплата, вкладки владельцев, суммы без наценки, меню, гарантия/логист позиции, лимит владельца, группировка, файлы, КТ и full-screen. Детали клиентского заказа и самого реселлера будут отдельными чек-листами.

Проверки не выполнялись. `[ ]` — Not run, не Fail; результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Неизвестная часть Blocked по ORDDET-Qxx. ID стабильные, снятые не переиспользовать.

## Предусловия

- Клиент и связанный корп, связанные реселлеры и чужая группа. Заказы только клиента, только корпа, только реселлера и смешанный заказ; доступ к разрешённым данным состава/владельцев.
- Заказы до/после КТ, окно гарантии/логиста открыто до КТ с подтверждением после; возможность контролировать время/переход в тестовой среде. Не выполнять реальные финансовые операции ради подготовки.
- Оба активных статуса, Paid/Not paid, последующие ненаступившие статусы, будущий КТ первого статуса, завершённый заказ для проверки доступности файлов.
- Товары с гарантией/без её возможности, флагом/без страны, длинными именами, несколько единиц одной позиции; один товар с разными ценами покупки/гарантиями и согласованной сортировкой админки.
- Известные цены/комиссии/варианты гарантии: отдельно цена покупки, текущая цена прайса, положительная клиентская наценка. Для базовых сумм без частичных отмен/выдач.
- Достаточный/недостаточный прирост лимита владельца, чужой лимит с противоположным состоянием. Смешанный заказ с клиентом/корпом и реселлерами.
- Заказ назначения с совпадающим ключом и без него; совпадающая позиция назначения и позиции с иной ценой/гарантией; перенос последней/непоследней позиции.
- Данные логиста/лицензия и доступ к проверке Excel/PDF из разрешённого источника. Нет доступа — Blocked, не Pass.

## Открытие, хедер и навигация

- [ ] **ORDDET-OPEN-01 — Открытие общей деталки выбранного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Tap по общему заказу клиента/корпа открывает деталку с соответствующим номером, составом и владельцами; не деталку клиентского заказа/реселлера с ручной оплатой.

  </details>

- [ ] **ORDDET-OPEN-02 — Меню действий общей деталки**

  <details>
  <summary>Подробности проверки</summary>

  - Три точки видны клиенту/корпу и открывают меню заказа с логистом, допустимым типом оплаты и тремя документами.
  - Не использовать условие трёх точек списка как условие меню деталки.

  </details>

- [ ] **ORDDET-OPEN-03 — Общие актуальные детали клиента и корпа**

  <details>
  <summary>Подробности проверки</summary>

  - Связанный корп открывает тот же общий заказ и видит его актуальный состав/цены/статус; сведения чужой группы не подставляются.

  </details>

- [ ] **ORDDET-CLOSE-01 — Закрытие деталки крестиком с сохранением фильтра**

  <details>
  <summary>Подробности проверки</summary>

  - Крестик закрывает деталку в исходный список; выбранный существующий статус фильтра списка сохраняется, его данные обновляются.

  </details>

- [ ] **ORDDET-CLOSE-02 — Закрытие деталки свайпом**

  <details>
  <summary>Подробности проверки</summary>

  - Свайп вниз закрывает деталку в список с тем же результатом; не возврат на Главную по сценарию покупки.

  </details>

- [ ] **ORDDET-CLOSE-03 — Актуальный список после изменения или переноса**

  <details>
  <summary>Подробности проверки</summary>

  - После изменения/переноса и возврата общий список показывает актуальные суммы/логические заказы, удалённый пустой источник не остаётся строкой; исходный фильтр списка применяется по его правилам.

  </details>


## Текущий статус, автоматическая оплата и таймлайн

- [ ] **ORDDET-STATUS-01 — Статус, цвет и номер общего заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Номер/иконка/цвет соответствуют открытому заказу: Pending assembly серый, Order pending delivery красный, Released зелёный; не чужой статус.

  </details>

- [ ] **ORDDET-STATUS-02 — Автоматическая оплата в общей деталке**

  <details>
  <summary>Подробности проверки</summary>

  - В Pending assembly отметка оплаты скрыта; со второго статуса Paid/Not paid соответствует автоматической оплате общего заказа, не ручной отметке клиентского заказа реселлера.

  </details>

- [ ] **ORDDET-STATUS-03 — Отображение оплаты без повторного списания**

  <details>
  <summary>Подробности проверки</summary>

  - Состояния достаточного баланса, задолженности и погашения из ORD-PAY-03/04/05 дают соответствующее состояние деталки при открытии.
  - Повторное открытие не выполняет дополнительное списание; независимую ручную оплату сюда не добавлять.

  </details>

- [ ] **ORDDET-TIME-01 — Раскрытие последовательности таймлайна**

  <details>
  <summary>Подробности проверки</summary>

  - По умолчанию таймлайн фокусируется на текущем статусе; раскрытие показывает все статусы в порядке Pending assembly → Order pending delivery → Released, сворачивание возвращает текущий.

  </details>

- [ ] **ORDDET-TIME-02 — Время КТ первого статуса**

  <details>
  <summary>Подробности проверки</summary>

  - Первый статус показывает дату/время КТ соответствующего заказа, не момент покупки; проверить будущий КТ, чтобы дата всё равно отображалась.

  </details>

- [ ] **ORDDET-TIME-03 — Фактическое время последующих статусов**

  <details>
  <summary>Подробности проверки</summary>

  - Последующие наступившие статусы показывают фактическую дату/время, ещё не наступившие — без даты/времени; первый статус с будущим КТ проверяется отдельно как исключение.

  </details>

- [ ] **ORDDET-TIME-04 — Московское время общего таймлайна**

  <details>
  <summary>Подробности проверки</summary>

  - Время таймлайна отображается по МСК; на устройстве с другим часовым поясом не заменяется локальным временем.
  - Граница КТ/расчёт доставки других экранов — отдельные вопросы, не считать закрытыми этим тестом.

  </details>


## Вкладки, товары и суммы

- [ ] **ORDDET-TABS-01 — Отсутствие вкладок для одного основного клиента**

  <details>
  <summary>Подробности проверки</summary>

  - Заказ только с товарами клиента: вкладки владельцев и All не показаны, весь состав отображается.

  </details>

- [ ] **ORDDET-TABS-02 — Вкладки единственного дочернего владельца и All**

  <details>
  <summary>Подробности проверки</summary>

  - Только корп или только один реселлер: показаны его вкладка и All.
  - All не скрывается по правилу одного реселлера из клиентского списка.

  </details>

- [ ] **ORDDET-TABS-03 — Вкладки владельцев смешанного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Смешанный заказ клиента/корпа/реселлеров показывает вкладки всех присутствующих владельцев и All; владелец без товаров в заказе не добавляется.

  </details>

- [ ] **ORDDET-TABS-04 — Состав и показатели выбранного владельца**

  <details>
  <summary>Подробности проверки</summary>

  - Выбор вкладки ограничивает товары владельцем и пересчитывает Qty/Amount; All возвращает весь состав.
  - Выбор по умолчанию/свайп — ORDDET-Q04.

  </details>

- [ ] **ORDDET-SUM-01 — Суммарное количество единиц выбранного набора**

  <details>
  <summary>Подробности проверки</summary>

  - Qty — сумма единиц товара выбранного набора, не число позиций; разные цены одного товара остаются разными строками, но их единицы учитываются.

  </details>

- [ ] **ORDDET-SUM-02 — Сумма общего заказа без клиентской наценки**

  <details>
  <summary>Подробности проверки</summary>

  - Amount по All/всему заказу равна сумме цен единиц × количества с гарантией/типом оплаты, без наценки клиента на товары реселлера.
  - Использовать известные согласованные цены без наценки; формула округления — ORDDET-Q02.

  </details>

- [ ] **ORDDET-SUM-03 — Суммы и количества отдельного владельца**

  <details>
  <summary>Подробности проверки</summary>

  - На вкладке каждого владельца Amount и Qty относятся только к его товарам; показанные цены реселлерских товаров тоже без наценки.

  </details>

- [ ] **ORDDET-ROW-01 — Параметры товарной позиции общего заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Позиция показывает правильные название, флаг/иконку, цену за единицу, количество и текущую гарантию; цена не заменена общей суммой позиции при количестве больше 1.

  </details>

- [ ] **ORDDET-ROW-02 — Иконка без страны и длинное название**

  <details>
  <summary>Подробности проверки</summary>

  - Нет страны: иконка товара вместо выдуманного флага; длинное имя не подставляет данные соседней строки и не перекрывает цену/количество.

  </details>

- [ ] **ORDDET-ROW-03 — Админский порядок товаров**

  <details>
  <summary>Подробности проверки</summary>

  - Порядок товаров соответствует заданному админом на All и вкладке владельца; дату покупки/цену как самовольную сортировку не применять.

  </details>

- [ ] **ORDDET-ROW-04 — Отдельность позиций с разными ценами и гарантией**

  <details>
  <summary>Подробности проверки</summary>

  - Один товар с разными ценами покупки либо разной гарантией отображается отдельными позициями с собственными ценами/количествами/гарантиями.

  </details>


## КТ и доступность редактирования

- [ ] **ORDDET-KT-01 — Доступность меню до и после КТ**

  <details>
  <summary>Подробности проверки</summary>

  - До КТ логист в меню доступен, Cash/Online показаны с текущим выбором; после КТ логист остаётся видимым, tap недоступен, тип оплаты скрыт.
  - Документы остаются доступными.

  </details>

- [ ] **ORDDET-KT-02 — Редакторы клиентской позиции до КТ**

  <details>
  <summary>Подробности проверки</summary>

  - До КТ товар клиента/корпа с гарантией открывает Warranty / Ship To; у товара без возможности гарантии только Ship To.

  </details>

- [ ] **ORDDET-KT-03 — Ограничения реселлерской позиции и блокировка после КТ**

  <details>
  <summary>Подробности проверки</summary>

  - Позиция реселлера до КТ открывает только смену логиста: гарантия недоступна даже при наличии гарантийных вариантов у товара; после КТ tap по любой позиции не открывает редактор.

  </details>

- [ ] **ORDDET-KT-04 — Отказ изменения гарантии после КТ в открытом редакторе**

  <details>
  <summary>Подробности проверки</summary>

  - Открыть Warranty до КТ, выбрать изменение, нажать Confirm после КТ: визуально ничего не происходит, гарантия/цена/Amount не меняются.
  - Не ожидать «Упс…»/закрытия на Главную; принятое текущее поведение.

  </details>

- [ ] **ORDDET-KT-05 — Отказ изменения логиста после КТ в открытом редакторе**

  <details>
  <summary>Подробности проверки</summary>

  - Открыть смену логиста до КТ, подтвердить после КТ: визуально ничего не происходит, логист/состав/группировка не меняются.
  - Проверить редактор позиции и выбор из меню; не требовать alert покупки.

  </details>

- [ ] **ORDDET-KT-06 — Неуточнённая точная граница КТ**

  <details>
  <summary>Подробности проверки</summary>

  - Подтверждение ровно в КТ, смена типа оплаты в меню, открытом до КТ, изменение КТ поставщиком: **Blocked, ORDDET-Q07**, границы/реакция не определены.

  </details>


## Логист всего заказа и лицензия

- [ ] **ORDDET-LOG-01 — Выбор логиста и соответствующие данные**

  <details>
  <summary>Подробности проверки</summary>

  - До КТ tap по логисту меню открывает список; выбор нового — окно данных именно этого логиста с подтверждением.
  - Чужие реквизиты не подставляются; полный состав полей — ORDDET-Q06.

  </details>

- [ ] **ORDDET-LOG-02 — Отмена неподтверждённого логиста заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Выбрать логиста, закрыть окно данных без Confirm: логист/состав заказа прежние.
  - Сохранение не выполняется по одному выбору строки списка.

  </details>

- [ ] **ORDDET-LOG-03 — Смена логиста всего заказа независимо от вкладки**

  <details>
  <summary>Подробности проверки</summary>

  - Подтвердить нового логиста из меню при выбранной вкладке одного владельца: изменение относится ко всему заказу, включая скрытые этой вкладкой позиции.
  - После успеха новое значение в меню заказа назначения.

  </details>

- [ ] **ORDDET-LOG-04 — Независимость логиста заказа от настройки аккаунта**

  <details>
  <summary>Подробности проверки</summary>

  - Смена логиста текущего заказа не меняет логиста аккаунта для следующих покупок клиента/корпа/реселлера.
  - Не переносить сюда сохранение настройки из покупки.

  </details>

- [ ] **ORDDET-LOG-05 — Скачивание лицензии без подтверждения логиста**

  <details>
  <summary>Подробности проверки</summary>

  - Скачивание лицензии в данных выбранного логиста открывает системный Share с его лицензией; выбор/закрытие Share не заменяет подтверждение логиста.
  - Формат/отсутствующая лицензия/ошибка — ORDDET-Q06.

  </details>


## Тип оплаты и лимит владельца

- [ ] **ORDDET-PAYTYPE-01 — Смена типа оплаты всего заказа**

  <details>
  <summary>Подробности проверки</summary>

  - До КТ текущий Cash/Online соответствует заказу, выбор другого варианта из меню действует на весь заказ независимо от вкладки, не только на видимые товары.

  </details>

- [ ] **ORDDET-PAYTYPE-02 — Пересчёт цен после смены оплаты**

  <details>
  <summary>Подробности проверки</summary>

  - При достаточном приросте лимита всех владельцев успешная смена оплаты сразу пересчитывает цены каждой позиции, гарантии в итоговой стоимости и общую/выбранную Amount по согласованным ценам;
  - открывается заказ назначения по новой оплате.

  </details>

- [ ] **ORDDET-PAYTYPE-03 — Независимость оплаты заказа от будущих покупок**

  <details>
  <summary>Подробности проверки</summary>

  - Смена оплаты заказа не меняет тип оплаты аккаунта для будущих покупок и не переносится на другие несвязанные заказы.

  </details>

- [ ] **ORDDET-LIMIT-01 — Проверка только прироста занятого лимита**

  <details>
  <summary>Подробности проверки</summary>

  - Удорожание проверяет только прирост занятой суммы.
  - Например согласованные суммы позиции клиента/корпа 1 000 → 1 100 и доступный лимит 150: прирост 100 укладывается, отказ по полной сумме 1 100 не ожидается;
  - после успеха доступно 50. Использовать известные цены, не угадывать формулу Cash/Online.

  </details>

- [ ] **ORDDET-LIMIT-02 — Запрет удорожания гарантии при нехватке лимита**

  <details>
  <summary>Подробности проверки</summary>

  - При недостатке прироста по гарантии владельца показан alert превышения лимита как в покупке; гарантия/цена/Amount не применяются, чужой достаточный лимит не заменяет лимит владельца.

  </details>

- [ ] **ORDDET-LIMIT-03 — Проверка лимита каждого реселлера смешанного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - В смешанном заказе удорожание оплаты проверяет общий лимит для товаров клиента/корпа и отдельный лимит каждого реселлера.
  - Подготовить нехватку именно у реселлера при достаточном общем лимите: его ограничение не пропускается.
  - Атомарность/текст отказа при смешанном заказе — **Blocked, ORDDET-Q03/06**.

  </details>

- [ ] **ORDDET-LIMIT-04 — Проверка общего лимита смешанного заказа**

  <details>
  <summary>Подробности проверки</summary>

  - В обратном случае хватает лимита реселлера, но не общего лимита для позиции клиента/корпа: изменение не оценивается только по достаточному лимиту реселлера.
  - Частичный отказ/сохранение остальных позиций — ORDDET-Q03.

  </details>

- [ ] **ORDDET-LIMIT-05 — Возврат разницы лимита при удешевлении**

  <details>
  <summary>Подробности проверки</summary>

  - Удешевление оплаты/гарантии возвращает разницу в доступный лимит владельца.
  - Пример согласованной позиции клиента/корпа 1 100 → 1 000, доступно 50 → 150; другие лимиты не получают эту разницу.

  </details>

- [ ] **ORDDET-LIMIT-06 — Однократный учёт применённого прироста лимита**

  <details>
  <summary>Подробности проверки</summary>

  - Повторные открытия/просмотр барабана/Cancel не занимают прирост лимита; применённое изменение учитывается один раз.
  - Повторный Confirm/потерянный ответ и учёт переноса — ORDDET-Q03/06.

  </details>


## Гарантия конкретной позиции

- [ ] **ORDDET-GUAR-01 — Данные редактора гарантии выбранной позиции**

  <details>
  <summary>Подробности проверки</summary>

  - Warranty показывает именно выбранную позицию, флаг/иконку, имя, текущую гарантию и варианты цены/сроков; другая позиция одноимённого товара не подставляется.

  </details>

- [ ] **ORDDET-GUAR-02 — Отмена неподтверждённого выбора гарантии**

  <details>
  <summary>Подробности проверки</summary>

  - Прокрутка барабана и Cancel/закрытие без Confirm не меняют гарантию/цены/сумму; выбор применяется после подтверждения.

  </details>

- [ ] **ORDDET-GUAR-03 — Смена гарантии всех единиц выбранной позиции**

  <details>
  <summary>Подробности проверки</summary>

  - При достаточном лимите Confirm меняет гарантию всех единиц выбранной позиции: при количестве 2 обе получают её, Amount пересчитывается по цене варианта × 2.
  - Иная позиция того же товара по другой цене/гарантии не изменяется.

  </details>

- [ ] **ORDDET-GUAR-04 — База гарантии каждой отдельной покупки**

  <details>
  <summary>Подробности проверки</summary>

  - Один товар куплен до и после изменения цены: барабаны гарантии используют базу каждой покупки и отличаются;
  - текущая цена прайса не заменяет зафиксированную.
  - Конфигурация процентов при её изменении — ORDDET-Q02.

  </details>

- [ ] **ORDDET-GUAR-05 — Актуализация гарантийных сумм без наценки**

  <details>
  <summary>Подробности проверки</summary>

  - После успешной смены актуальны строка гарантии, цена, выбранная Amount, Amount всего заказа и сумма в общем списке после возврата; клиентская наценка не появляется.

  </details>


## Логист позиции, перенос и объединение

- [ ] **ORDDET-MOVE-01 — Редактор логиста отдельной позиции**

  <details>
  <summary>Подробности проверки</summary>

  - Ship To выбранной позиции показывает её имя/флаг либо иконку, текущего логиста и барабан; до Confirm позиция не перемещается, Cancel оставляет исходный заказ.

  </details>

- [ ] **ORDDET-MOVE-02 — Перенос непоследней позиции в заказ назначения**

  <details>
  <summary>Подробности проверки</summary>

  - Подтвердить смену логиста непоследней позиции: она исчезает из источника, его Qty/Amount пересчитаны; открывается назначение с этой позицией и новым логистом, оставшиеся товары источника не перенесены.

  </details>

- [ ] **ORDDET-MOVE-03 — Поиск назначения по полному ключу заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Есть назначение с той же датой поставщика, поставщиком, типом оплаты и новым логистом: позиция объединяется с ним.
  - Изменить по одному компоненту ключа в контрольных данных — неподходящий заказ не используется как совпадающий.

  </details>

- [ ] **ORDDET-MOVE-04 — Создание назначения при отсутствии совпадения**

  <details>
  <summary>Подробности проверки</summary>

  - Назначения с нужным ключом нет: создаётся и открывается соответствующий заказ с перенесённой позицией; источник и назначение не содержат её одновременно.
  - Номер нового заказа — ORDDET-Q01.

  </details>

- [ ] **ORDDET-MOVE-05 — Объединение одинаковой позиции одного владельца**

  <details>
  <summary>Подробности проверки</summary>

  - В назначении есть совпадающий товар того же владельца с той же ценой/гарантией: количество суммируется.
  - Сумма/Qty учитывают прежние и перенесённые единицы без потерь/дублей.

  </details>

- [ ] **ORDDET-MOVE-06 — Отдельность позиций с разными ценами и гарантией**

  <details>
  <summary>Подробности проверки</summary>

  - Такой же товар назначения с другой ценой или гарантией остаётся отдельной позицией; не усреднять цены.
  - Владельцы разных вкладок не смешиваются при объединении общего заказа.

  </details>

- [ ] **ORDDET-MOVE-07 — Удаление источника только после последней позиции**

  <details>
  <summary>Подробности проверки</summary>

  - Перенос последней позиции удаляет пустой источник; после закрытия назначения и возврата в список исходного заказа нет.
  - Перенос непоследней позиции источник не удаляет.

  </details>

- [ ] **ORDDET-MOVE-08 — Перенос всего состава из меню заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Смена логиста всего заказа/оплаты из меню переносит весь состав по новому ключу и открывает назначение;
  - существующий подходящий заказ объединяется, опустевший источник удаляется.
  - Не ограничивать перенос выбранной вкладкой.

  </details>


## Документы Excel/PDF

- [ ] **ORDDET-DOC-01 — Шесть сочетаний документов общей деталки**

  <details>
  <summary>Подробности проверки</summary>

  - Invoice, Packing List и IMEI/SN открывают выбор Excel/PDF; каждый вариант формирует/открывает соответствующий файл.
  - Проверить все шесть сочетаний; расширения/колонки/приложение открытия — ORDDET-Q05.

  </details>

- [ ] **ORDDET-DOC-02 — Доступность документов на всех статусах и после КТ**

  <details>
  <summary>Подробности проверки</summary>

  - Документы доступны до/после КТ и на каждом статусе, включая первый; отсутствие заполненных серийных данных не подменять произвольным запретом формирования.
  - Точное отображение незаполненного IMEI/SN — ORDDET-Q05.

  </details>

- [ ] **ORDDET-DOC-03 — Фильтрация документов по владельцу**

  <details>
  <summary>Подробности проверки</summary>

  - На All либо без вкладок файл относится ко всему заказу; на ID только к товарам выбранного владельца, остальные не включаются.
  - Проверить каждого владельца и оба формата применимых документов.

  </details>

- [ ] **ORDDET-DOC-04 — Цены документов без клиентской наценки**

  <details>
  <summary>Подробности проверки</summary>

  - В документах с ценами указаны актуальные цены без клиентской наценки, включая реселлерские товары; в общем заказе и файле нет наценки из интерфейса реселлера.
  - Не требовать ценовую колонку в каждом типе документа без шаблона.

  </details>

- [ ] **ORDDET-DOC-05 — Актуальные документы после изменения и переноса**

  <details>
  <summary>Подробности проверки</summary>

  - После смены гарантии/оплаты/переноса вновь открытый файл соответствует текущему заказу/выбранному владельцу: новые цены/состав/количества, не прежний кэш.
  - Перемещённые позиции не остаются в документе непустого источника.

  </details>


## Полноэкранный просмотр

- [ ] **ORDDET-FULL-01 — Горизонтальный просмотр общего заказа**

  <details>
  <summary>Подробности проверки</summary>

  - Full-screen mode открывает горизонтальный просмотр правильного номера, товаров, Qty/цены/текущей гарантии; данные совпадают с обычной деталкой, наценка клиента не добавляется.

  </details>

- [ ] **ORDDET-FULL-02 — Фильтрация владельцев в полноэкранном просмотре**

  <details>
  <summary>Подробности проверки</summary>

  - Если вкладки есть, они доступны в full-screen и фильтруют товары; только клиент — вкладок нет.
  - Просмотр и прокрутка не включают редактирование гарантии/логиста.

  </details>

- [ ] **ORDDET-FULL-03 — Возврат из full-screen с прежней вкладкой**

  <details>
  <summary>Подробности проверки</summary>

  - Крестик full-screen возвращает в обычную деталку с сохранением выбранной вкладки, не закрывает сразу общий заказ в список.
  - Поворот/позиция прокрутки — ORDDET-Q08.

  </details>


## Неопределённые ошибки и синхронизация

- [ ] **ORDDET-ERROR-01 — Неуточнённые ошибки изменения и экспорта**

  <details>
  <summary>Подробности проверки</summary>

  - Ошибки изменения заказа/формирования файла/лицензии, retry и потерянный ответ: **Blocked, ORDDET-Q06** для точного UI/сохранения/перехода;
  - отсутствие ответа не считать успешным изменением по данным старого экрана.

  </details>

- [ ] **ORDDET-SYNC-01 — Неуточнённые обновление и удаление другой сессией**

  <details>
  <summary>Подробности проверки</summary>

  - Загрузка/ручной refresh/real-time самой деталки и удаление её номера другой сессией: **Blocked, ORDDET-Q08**.
  - Отсутствие real-time в списке не задаёт это поведение автоматически.

  </details>
