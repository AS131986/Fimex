### Предусловия

Свободный email и email существующего клиента. Для email-регистра проверить разные регистры одного адреса. Иметь доступ к почте и тестовой базе через разрешённые средства, если проверяется сохранение аккаунта.

### Форма и email

- [ ] **REG-FORM-01** — Присутствуют email, оба поля пароля, переключатели видимости, Continue, возврат, язык и юридические ссылки.
- [ ] **REG-FORM-02** — При пустых полях Continue неактивна; после заполнения полей активируется. Обязательность Confirmation — REG-Q02.
- [ ] **REG-FORM-03** — Валидация заполненных полей срабатывает при закрытии клавиатуры.
- [ ] **REG-EMAIL-01** — Корректный свободный email принимается при допустимом пароле и согласованном подтверждении.
- [ ] **REG-EMAIL-02** — Email без `@`, без локальной части или без домена не проходит проверку формата; точное представление ошибок — REG-Q01.
- [ ] **REG-EMAIL-03** — Нельзя ввести пробел в начале, середине или конце email; вставку проверить после уточнения REG-Q04.
- [ ] **REG-EMAIL-04** — Email из базы не позволяет завершить регистрацию нового клиента.
- [ ] **REG-EMAIL-05** — Изменение регистра занятого email не обходит проверку занятости.

### Пароль

- [ ] **REG-PASS-01** — Пароль из 7 разрешённых символов с заглавной буквой и цифрой отклоняется.
- [ ] **REG-PASS-02** — Пароль из 8 разрешённых символов с заглавной буквой и цифрой принимается.
- [ ] **REG-PASS-03** — Пароль из 99 и 100 разрешённых символов с обязательными категориями принимается.
- [ ] **REG-PASS-04** — Пароль из 101 символа не принимается как допустимый; способ ограничения — REG-Q05.
- [ ] **REG-PASS-05** — Пароль без заглавной буквы отклоняется.
- [ ] **REG-PASS-06** — Пароль без цифры отклоняется.
- [ ] **REG-PASS-07** — Латинские буквы обоих регистров, цифры и точка допустимы при выполнении остальных условий.
- [ ] **REG-PASS-08** — Кириллица, пробел, дефис, подчёркивание, `@` и emoji в пароле не принимаются.
- [ ] **REG-PASS-09** — Допустимый пароль без точки принимается; точка не обязательна.
- [ ] **REG-PASS-10** — Допустимый пароль без строчной буквы принимается; строчная буква не обязательна.
- [ ] **REG-PASS-11** — Видимость переключается отдельно в каждом поле без изменения введённого значения.
- [ ] **REG-PASS-12** — Совпадение и несовпадение Confirmation, в том числе отличие регистра, проверяются после согласования REG-Q02.

### Переходы

- [ ] **REG-NAV-01** — Успешный ввод данных открывает экран четырёхзначного кода для указанного email.
- [ ] **REG-NAV-02** — Возврат открывает стартовый экран.
- [ ] **REG-LEGAL-01** — Обе юридические ссылки доступны; назначения и способ открытия — REG-Q07.
- [ ] **REG-UI-01** — Поля и Continue доступны с открытой клавиатурой; ошибки и длинные значения не перекрывают управление.

Сохранение аккаунта и доступ до подписки проверяются в [чек-листе подписки](checklist-registration.md#subscription-onboarding).

- [ ] **REGCODE-INPUT-03** — Буквы и специальные символы не принимаются как допустимый код; механизм ограничения ввода не задан.

- [ ] **REGCODE-INPUT-05** — Неверный код не даёт перейти к заполнению профиля; текст ошибки и очистка ввода — REGCODE-Q05.

- [ ] **REGCODE-RESEND-02** — Повторная отправка направляет код на email текущей регистрации; судьба предыдущего кода — REGCODE-Q03.
- [ ] **REGCODE-UI-02** — Цифровая клавиатура не перекрывает ввод и Continue; введённые цифры видны в соответствующих позициях.

Срок действия, лимиты, ведущий ноль, вставка и автопроверка не объявлены проверенными или согласованными; см. REGCODE-Q01–Q06.

## Онбординг и подписка

Проверки не выполнялись. `[ ]` — Not run. Результаты отдельно: Pass / Fail / Blocked / Not run / N/A. Зависимые ожидания Blocked до уточнения Q. ID стабильные. [Правила](../../04-business-rules/registration.md#subscription-onboarding).

### Предусловия

Новый клиент прошёл регистрацию, код и профиль. Для оформления использовать разрешённое тестовое окружение подписок без реального списания; при отсутствии такого доступа финансовые проверки Blocked. Для проверки базы нужен разрешённый способ чтения состояния, иначе backend-часть Blocked.

- [ ] **SUB-UI-01** — После профиля появляется онбординг с информацией о возможностях, вариантами подписки и юридическими ссылками.
- [ ] **SUB-UI-02** — Отображается информация о первых трёх бесплатных днях для сценария с доступным пробным периодом.
- [ ] **SUB-UI-03** — Месячный и годовой варианты различимы; конкретные суммы и валюта сверяются с согласованными тарифами после SUB-Q01.
- [ ] **SUB-ACCESS-01** — До успешного оформления подписки нет доступа в аккаунт и к покупкам.
- [ ] **SUB-PAY-01** — Успешное оформление месячной подписки с пробным периодом открывает доступ в аккаунт без немедленного списания.
- [ ] **SUB-PAY-02** — Успешное оформление годовой подписки с пробным периодом открывает доступ в аккаунт без немедленного списания.
- [ ] **SUB-PAY-03** — Ошибка оформления оставляет пользователя на экране подписки без доступа в аккаунт.
- [ ] **SUB-DRAFT-01** — Закрытие приложения на этом шаге без завершённой подписки и повторный запуск не восстанавливают авторизацию.
- [ ] **SUB-DRAFT-02** — После незавершённой регистрации аккаунт и email отсутствуют в базе; отсутствие авторизации само по себе не считать доказательством состояния backend.
- [ ] **SUB-LEGAL-01** — Юридические ссылки доступны; корректность назначения зависит от SUB-Q06.
- [ ] **SUB-UI-04** — Текст и обе кнопки доступны на поддерживаемых iPhone в обоих языках и темах, не перекрываются системными областями.

Отмена, восстановление и потерянный ответ на успешную покупку требуют SUB-Q03/Q04. Доступность пробного периода для каждого варианта подтверждается тестовыми условиями; не применять ожидание к не имеющему права на trial аккаунту.
