# Приоритетные проверки перед релизом iOS / Liquid Glass

## Область и статус

70 пунктов для короткого прогона основных рисков. Это выборка сгруппированных сценариев из имеющихся чек-листов, а не 70 новых кейсов и не ровно 70 выполнений: роли, варианты данных и устройства требуют повторов. Покупку и П2П проверять для клиента, корпа и реселлера; общие средства — для клиента/корпа. Финансовый результат сверять с разрешённым источником данных, не только с тостом.

Все проверки **Not run**. Неуточнённые ожидания — **Blocked** по вопросам исходных документов. Обнаруженные дефекты повторно проверять после исправления. Внутренние экраны профиля пока описаны не полностью; эта выборка не заменяет полный регресс и не является отчётом о качестве сборки.

## Уточнения к прогону

- Пункты 1, 67–70 выделены как риски большого обновления интерфейса. Полная матрица поддерживаемых iOS/устройств и ожидаемые состояния при обновлении/повороте ещё требуют согласования; не объявлять непроверенный вариант Pass.
- Пункт 15: точные переходы бейджа П2П после завершения/удаления пока NAV-Q03. Пункт 32: неуточнённые поля/часовые пояса дат проверять по вопросам конкретного экрана, не по предположению.
- Пункт 38 относится к клиентской выдаче заказов реселлера. Пункт 40: собственный лимит реселлера освобождается при подтверждённом ручном Not paid → Paid, общий лимит клиента/корпа по его покупкам — при выдаче. Гонки/частичная выдача и прочие остаточные вопросы финансов не закрыты этой выборкой.
- Пункт 61: обычная История по дате заказа, П2П по созданию заявки; дата строки/сортировки П2П по покупке. Пункт 62: общая статистика без клиентской наценки, собственная реселлера с наценкой, клиентская — продажи/прибыль. Не использовать одну формулу для всех областей.
- Пункт 65: у профиля ручной refresh есть, real-time финансовых карточек нет. У активных П2П real-time есть, ручного refresh нет; не смешивать эти ожидания.
