# Активная P2P-заявка — все роли, Fimex Buyer, iOS

## Вход и состав

Открывается tap по строке [списка P2P](p2p-active-requests.md), также при повторном открытии того же товара из прайса во вкладке P2P Chat. Клиент/корп управляют общей заявкой, реселлер — только своей. Цена клиента/корпа без клиентской наценки; реселлер видит собственную/встречную цены и варианты гарантии сразу с наценкой, установленной клиентом.

Верхняя панель: Share, Pre-Order / P2P Chat, крестик. Дата с иконкой открывает окно как при [покупке](../home/purchase.md); название/флаг либо иконка открывают описание товара как в заказе. Дата наследует правило создания (дата поставщика + дни доставки); точная граница КТ/часовой пояс остаются P2P-Q08.

Показаны «Поставщик», «Кол-во», «Моя цена»: до ответа поставщик — прочерк, собственные сохранённые количество и цена видны. После ответа показана встречная цена и «Подтвердить». Количество `51 / 51` на примере — запрошенное / предложенное; поставщик **не может менять количество**, поэтому встречное относится к тому же количеству. Пример не означает текущий остаток товара или разрешение частичной сделки.

## Изменение и удаление

Tap по своей цене/количеству либо «Изменить цену» / «Изменить кол-во» открывает соответствующий ввод с клавиатурой. Ограничения как при [создании](../../04-business-rules/p2p-request.md): цена не ниже `floor(P × 0,9975)`, максимум 99999.99, до 5+2 цифр; количество целое 50–9999, не ограничивается остатком товара в продаже.

Сохранение **только через «Продолжить»**: ввод сам по себе не изменяет заявку. Проверяется дополнительный лимит при увеличении стоимости; уменьшение освобождает разницу. После успешного изменения цены/количества прежнее встречное предложение сбрасывается. Точный маршрут шагов, отмена ввода и сетевые ошибки — P2PACT-Q01/05.

«Удалить ордер» / удаление заявки действует сразу, без отдельного подтверждения. Резерв полностью освобождается; toast **«Удалено»**, обновление открытого экрана до состояния перед созданием заявки. Внешнее удаление по КТ/изменению цены, рейтинга, даты/снятию товара/админом даёт такой же сброс и toast в real-time. Новая заявка не появляется автоматически из прежнего ввода.

## Принятие встречного предложения покупателем

1. По «Подтвердить» проверяется лимит для всей покупки по новой цене и прежнему количеству, с учётом уже занятой заявкой суммы и свободного остатка. Не требуется второй полный резерв поверх первого.
2. При недостатке — alert о нехватке лимита, покупка не выполняется. Точный вид/дальнейший этап — P2PACT-Q02/05.
3. Если у товара доступна гарантия, показан блок «Желаете оформить дополнительную гарантию?» с «Нет, спасибо» и вариантами цены единицы со сроком. После выбора и продолжения снова проверяется лимит уже с гарантией для всего количества. Точная кнопка окончательного завершения этой ветки — P2PACT-Q02.
4. Если гарантии у товара нет, её блок отсутствует, появляется «Купить». До успешной покупки это ещё активная заявка.
5. «Отменить» на этапе гарантии/покупки возвращает активную заявку с прежним встречным предложением и её резервом.
6. Успешное завершение покупки: toast подтверждения (на примере **«Подтверждено»**), обновление экрана до дефолтной формы создания. Сделка относится к успешной Истории P2P; она больше не активная. Точные стартовые значения после сброса — P2PACT-Q04.

Сроки/проценты гарантии не фиксируются по скриншоту. Дополнительная сумма гарантии проверяется отдельно: лимита по встречной цене может хватать, а для выбранной гарантии — не хватать. Нельзя переносить правило Pre-Order «финансовая проверка только по Купить» на П2П: здесь есть проверка по «Подтвердить» и после выбора гарантии/продолжения.

## Подтверждение поставщиком

Когда поставщик сам подтверждает собственное предложение покупателя, покупка завершается **с дефолтом без дополнительной гарантии**. Этап выбора гарантии пользователем не требуется. Toast подтверждения и обновление открытого экрана до формы создания — как после успешного принятия предложения пользователем. Завершённая заявка относится к успешной Истории P2P.

Гарантия, выбранная когда-либо в другой покупке/Pre-Order, не переносится в этот дефолт. Технические финансовые проверки/гонки подтверждения поставщиком — P2PACT-Q02/05; подтверждение не означает списание второго полного резерва заявки.

## Средства, цены и обновление

У клиента/корпа общие лимит и депозит. При сохранении изменения или покупке используется уже занятая этой заявкой сумма плюс доступный остаток. У реселлера свои средства/лимит по правилам создания, цены включая его клиентскую наценку. Конфигурация процента при её смене после создания, округление гарантии/наценки и тип оплаты/логист П2П-покупки ещё не уточнены — P2PACT-Q02/03; не добавлять шаг логиста обычного Pre-Order по аналогии.

При загрузке скелетон, **ручного refresh нет**, real-time действует и во время открытой заявки. Ответная цена, подтверждение поставщика, удаление/истечение/изменения товара обновляют данные. Несохранённый ввод одновременно с событием, повторное нажатие/ошибка после фактической покупки — P2PACT-Q05.

Share наследует [правила создания](../../04-business-rules/p2p-request.md#share): меняет только файл, база — текущая цена товара для роли, не собственная или встречная цена заявки. Обычное закрытие/переключение вкладок не удаляет существующую заявку и не занимает резерв ещё раз.

## История успешной покупки

[История П2П](p2p-history.md) хранит успешную сделку с инициатором завершения. В период она входит по дате создания заявки, строка/сортировка по дате покупки. Цена в Истории без дополнительной гарантии, с клиентской наценкой только для реселлера; это представление Истории не исключает выбранную гарантию из фактической стоимости покупки/проверки лимита.
