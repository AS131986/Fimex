# Клиентские заказы — клиент и корп, Fimex Buyer, iOS

## Назначение и область

Список заказов связанных реселлеров для клиента и корпа. Здесь выполняется работа с такими заказами; покупки самого клиента/корпа в этот список не входят. Для каждого реселлера отдельный заказ со своим номером: товары разных реселлеров не объединяются даже при одной дате поставщика. В общем списке «Мои заказы» соответствующие товары могут входить в один заказ вместе с покупками клиента/корпа.

Этот документ покрывает список, фильтры, показатели, переходы и условия перемещения в Историю. [Детали клиентского заказа](customer-order-detail-client-corporate.md), [клиентская статистика](customer-orders-statistics-client-corporate.md), [собственный список](my-orders-reseller.md) и [деталка реселлера](order-detail-reseller.md) описаны отдельно; [История и архивный заказ](customer-orders-history-client-corporate.md) описаны отдельно; фильтры списка туда не передаются.

## Элементы и переходы

- Заголовок «Клиентские» / Customers.
- Три точки при включённом доступе к режиму реселлера у клиента/корпа; меню «Мои заказы» / «Клиентские». По умолчанию раздел заказов открывается в «Моих заказах», выбор «Клиентских» переключает список.
- Фильтр статусов: доступные статусы из всего списка клиентских заказов, независимо от выбранного реселлера; при одном статусе кнопка скрыта.
- Кнопка графика открывает [Статистику клиентских заказов](customer-orders-statistics-client-corporate.md) с «Продажами/Прибылью» по связанным реселлерам. ID/статус этого списка не передаются в неё; она включает все покупки периода, также неоплаченные/Историю. Книга — клиентская История.
- Некликабельные Qty и Amount: сумма единиц товара и сумма заказов текущего набора, с наценкой клиента, гарантией и типом оплаты.
- Вкладки ID реселлеров с активными заказами. Один реселлер — только его вкладка, без All; несколько — также All. Переключение только тапом.
- Ячейка: номер отдельного заказа реселлера, дата поставщика без дней доставки, Cash/Online, сумма с наценкой клиента, иконка/цвет статуса; начиная со второго статуса состояние оплаты.
- Tap по ячейке открывает соответствующий заказ реселлера.
- Нижнее меню остаётся доступным. Его общие правила — [в отдельном документе](../../04-business-rules/home.md#нижнее-меню).

При переключении в «Клиентские» бейдж нижней вкладки заказов меняется на количество клиентских заказов; при возврате в «Мои» — на количество общего списка. Это число заказов, не Qty единиц товара. Влияние фильтров на счётчик ещё не определено.

## Фильтрация и обновление

Вкладка реселлера и статус работают совместно: показаны заказы выбранного реселлера с выбранным статусом. Qty/Amount пересчитываются для полученного набора. При фильтрации по статусу вкладки реселлеров без соответствующих заказов скрываются; набор статусов меню берётся из полного клиентского списка, а не из выбранной вкладки.

Возврат из заказа сохраняет «Клиентские», вкладку и статус и обновляет данные. После перехода в другой раздел нижнего меню и возврата выбраны «Мои заказы», состояние по умолчанию. Длинный скрол вниз обновляет список. При загрузке скелетон, ошибки сети/сервера — стандартные alert; real-time обновления открытого списка нет.

## Статусы, оплата и История

| Статус | Цвет | Состояние оплаты |
|---|---|---|
| Pending assembly | Серый | Скрыто |
| Order pending delivery | Красный | Paid / Not paid |
| Released | Зелёный | Ручная отметка оплаты остаётся независимой |

Сверху более поздние статусы, внутри каждого — более старые даты поставщика. Жёлтая коробка на примере из другого приложения не задаёт дополнительный статус или цвет Fimex.

Paid/Not paid здесь — отдельная ручная отметка. Со второго статуса клиент/корп подтверждает Not paid → Paid в деталях; обратный переход недоступен, баланс/лимит от отметки не меняются. Автоматическая оплата с баланса в «Моих заказах» не делает этот заказ Paid в «Клиентских». Кнопка «Выдать» доступна после админского Released; подтвердить выдачу можно при Not paid. Заказ остаётся в списке до обоих условий: Paid и подтверждённой клиентской выдачи. Порядок этих действий любой. Нельзя переносить сюда запрет выдачи неоплаченного общего заказа.

Клиент/корп могут подтвердить оплату и выдать заказ; гарантия и тип оплаты уже активного заказа недоступны для изменения. Цены списка с наценкой, зафиксированной при покупке; выбор себестоимости в деталке их не меняет. Момент освобождения лимита при двух видах выдачи и UI после завершения остаются открытыми.

## Пустое состояние

При отсутствии заказов в этом списке после успешной загрузки показаны иконка квитанции и карточка «Нет заказов от клиентов», без дополнительного пояснения. На светлом русском примере иконка в синем круге.

Скрыты строки, Qty/Amount, вкладки реселлеров и фильтр. Заголовок, Статистика, История и нижнее меню сохраняются; три точки зависят от доступа к режиму реселлера. Заказы клиента/корпа в «Моих заказах» и наличие клиентской Истории не делают этот список непустым.

Скрытие вкладок без данных при фильтрации подтверждено. Текст/показатели при полностью пустом результате фильтра и выбор после исчезновения текущей вкладки ещё не определены; не приравнивать такой результат к полному отсутствию клиентских заказов.
