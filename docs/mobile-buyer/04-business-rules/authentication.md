## Авторизация

### Подтверждённые способы входа

| Роль | Email | ID | Формат ID |
|---|---|---|---|
| Клиент | Да | Да | `F:01011` |
| Корпоративный пользователь | Да | Да | `F:01011/A` |
| Реселлер | Нет | Да | `F:01011/1` |

- Первая буква и буквенный суффикс корпоративного ID — латиница; буква может отличаться от F/A. Количество цифр переменное, регистр неважен. Двоеточие обязательно; для дочерних аккаунтов обязательны slash и суффикс.
- Для входа используются идентификатор и пароль. Точная принадлежность пароля для дочерних аккаунтов требует LOGIN-Q01.
- Email проверяется на формат и соответствие паролю; сравнение email не зависит от регистра, ввод пробелов запрещён.
- Кнопка Login активируется при заполнении полей. Валидация полей срабатывает при закрытии клавиатуры.
- После авторизации язык и тема берутся из аккаунта и хранятся на backend.
- Вход на другом устройстве завершает предыдущую сессию; двух активных сессий не предполагается.

### Статусы и доступ

| Условие | Подтверждённый результат |
|---|---|
| Клиент заблокирован | Ошибка авторизации |
| У клиента закончилась подписка | Успешная авторизация; alert о продлении перекрывает главную и блокирует покупки; доступны продление и выход |
| Реселлер удалён | Ошибка авторизации |
| Реселлер заблокирован | Авторизация с сообщением о блокировке, главная недоступна для покупок |
| У основного аккаунта нет подписки | Корп и реселлер получают alert о необходимости связаться с основным аккаунтом; доступ к главной/покупкам блокируется |
| Основной аккаунт заблокирован | Корп и реселлер также блокируются; точный ответ входа и UI не определены |

Не путать блокировку клиента, блокировку самого реселлера и отсутствие подписки основного аккаунта: результаты входа различаются.

### Обязательное обновление

После авторизации проверяется требование обновить приложение. Alert блокирует использование, ссылка ведёт на скачивание в App Store. После возврата без обновления alert остаётся. По указанию пользователя достаточно одной проверки этой механики.

### Переходы

- Forgot your password? открывает [ввод email для восстановления](authentication.md#password-reset-email).
- Create an account открывает [регистрацию](registration.md#registration).

### Открытые вопросы

- **LOGIN-Q01:** для ID используется пароль именно соответствующего аккаунта? Допустимость старых паролей, не удовлетворяющих новым правилам регистрации.
- **LOGIN-Q02:** точные сообщения неверных данных, удаления, блокировки и отсутствия подписки; самостоятельная блокировка/удаление корпоративного пользователя.
- **LOGIN-Q03:** число букв в ID, ограничения длины числовых частей, ведущие нули, обработка пробелов и невалидного ID.
- **LOGIN-Q04:** точное состояние входа/UI дочерних аккаунтов при блокировке основного; последствия удаления основного аккаунта; доступность выхода из каждого блокирующего состояния.
- **LOGIN-Q05:** кнопки обязательного обновления, приоритет этого alert относительно блокировки/подписки, реакция на недоступный App Store.
- **LOGIN-Q06:** UI и момент завершения предыдущей сессии, поведение запроса уже в обработке.
- **LOGIN-Q07:** обработка сетевой ошибки и повторного Login, сохранение идентификатора; лимит неверных попыток.

### Источник

Описание, ответы и скриншот пользователя. Пример корпоративного ID нормализован до латинского A согласно уточнению. Не результаты прогона.

## Запрос восстановления по email

### Подтверждённые правила

- Самостоятельное восстановление доступно клиенту и корпоративному пользователю по email из базы.
- Реселлер восстанавливает доступ через клиента; самостоятельный сценарий по email не предназначен для реселлера.
- Email проверяется на наличие в базе. Общие правила email: без возможности ввода пробелов, без зависимости от регистра; валидация при закрытии клавиатуры.
- Кнопка активируется при заполнении поля; это не подтверждает существование email.
- Для заблокированного аккаунта сообщение появляется уже при запросе кода, до его ввода. Далее к вводу кода пользователь не проходит.
- На скриншотах после запроса есть отдельный [экран сообщения о письме](authentication.md#password-reset-message), затем ввод кода.

### Открытые вопросы

- **RESETEMAIL-Q01:** точные сообщения отсутствующего/некорректного email, блокировки, сетевой ошибки.
- **RESETEMAIL-Q02:** самостоятельная блокировка корпа и блокировка/удаление основного аккаунта при запросе восстановления.
- **RESETEMAIL-Q03:** реакция формы на email реселлера, если такой email существует; отдельное сообщение или общий отказ.
- **RESETEMAIL-Q04:** повторные запросы, лимиты отправок, работа таймера до перехода к коду; восстановление после незавершённой регистрации.
- **RESETEMAIL-Q05:** обработка пробелов при вставке email, возврат и сохранение поля.

### Источник

## Сообщение о письме

### Правила и границы подтверждения

- Экран содержит адрес, введённый для восстановления; не должен показывать чужой адрес.
- Следующий предоставленный экран — [ввод кода восстановления](authentication.md#password-reset-code); Continue ведёт к этому шагу.
- Текст сообщения не является доказательством доставки: получение письма проверяется отдельно на тестовой почте.
- Заблокированный аккаунт не проходит к вводу кода; проверка отказа находится на предыдущем шаге.

### Открытые вопросы

- **RESETMSG-Q01:** точные локализованные тексты; момент отправки письма и реакция на ошибку отправки.
- **RESETMSG-Q02:** действие возврата, возможность изменить email, повторная отправка с этого экрана.
- **RESETMSG-Q03:** сохранение состояния при сворачивании/закрытии приложения и момент начала таймера кода.

### Источник

Предоставленная последовательность скриншотов и описание пользователя. Не результаты проверки доставки.

## Код восстановления

### Подтверждённые правила

- Код всегда состоит из четырёх цифр.
- Правила кода одинаковы с [подтверждением регистрации](registration.md#registration-code).
- Повторная отправка доступна через 120 секунд.
- Правильное подтверждение открывает [ввод нового пароля](authentication.md#password-reset-new-password).
- Срок действия кода неизвестен; 120 секунд — задержка повторной отправки, а не подтверждённый срок действия.

### Открытые вопросы

Общие вопросы кода централизованы в REGCODE-Q01–Q06: срок действия, лимиты, действительность старого кода, запуск проверки, ошибочные/потерянные ответы, вставка и ведущий ноль.

- **RESETCODE-Q01:** может ли код регистрации подтверждать восстановление или наоборот? Ожидаемая изоляция назначений не подтверждена.
- **RESETCODE-Q02:** последствия смены email/повторного запуска восстановления; изменение статуса аккаунта между отправкой и подтверждением.

## Новый пароль и автоматический вход

### Подтверждённые правила

- Валидация нового пароля совпадает с [регистрацией](registration.md#registration): 8–100 символов включительно, только латинские буквы, цифры и точка, минимум одна заглавная буква и одна цифра.
- Обязательная строчная буква или точка не заявлены.
- Валидация при закрытии клавиатуры; кнопка активируется при заполнении полей, а не только после успешной проверки.
- После успешного сохранения выполняется автоматический вход в аккаунт без отдельного повторного ввода логина/пароля.
- Ограничения статуса аккаунта и подписки сохраняются: автоматический вход не обходит блокировку покупок при истёкшей подписке/недоступном основном аккаунте.
- Для заблокированного аккаунта отказ происходит уже при отправке кода, до этого экрана.
- Автоматическая авторизация после восстановления завершает авторизацию на другом устройстве.
- При успешном входе язык и тема берутся из аккаунта.

### Открытые вопросы

- Правило Password Confirmation, точные тексты ошибок и способ ограничения длины — REG-Q01/Q02/Q05.
- **NEWPASS-Q01:** разрешено ли повторно установить прежний пароль; старый пароль после фактического изменения должен ли сразу перестать работать во всех способах входа; история паролей.
- **NEWPASS-Q02:** отказ/потеря ответа при сохранении, retry, возврат и закрытие приложения; момент смены пароля относительно входа.
- **NEWPASS-Q03:** изменение статуса аккаунта после выдачи кода, но до сохранения; ожидаемое поведение такой гонки.

### Источник

Описание, ответы и скриншот пользователя. Автоматический вход и завершение другой сессии подтверждены; требования истории паролей отдельно не определены. Проверки не выполнялись.
