# Price List — бизнес-правила Fimex Buyer, iOS

Содержание перенесено из описания экрана и чек-листа. Проверки не выполнялись. Более поздние согласования из чек-листа выделены отдельно; формулировки прежнего описания сохранены для последующей синхронизации, а не приняты заново.

[Описание экрана](../03-screens/home/price-list.md) · [Чек-лист и вопросы Qxx](../05-test-design/home/checklist-price-list.md) · [Правила уведомлений](price-list-notifications.md)

## Согласованные правила

- Fimex: цены в USD; ширина диапазона уведомления — 50 USD; минимальный шаг ползунка — 1 USD.
- Смена аккаунта только через logout/login; подписки отдельные для каждого аккаунта.
- Reseller — отдельный аккаунт, создаваемый основным аккаунтом и привязанный к нему.
- Вход на втором устройстве завершает сессию на первом; двух активных сессий не предполагается.
- Подписки можно создавать при запрещённых push; системный push при этом не отображается.
- Сохраняется последний выбранный target; закрытие до сохранения отменяет новый выбор, после сохранения не откатывает его.
- Подписка на поступление снимается обычным tap; галочка снимается. Ценовая подписка редактируется через long press и удаляется перемещением ползунка до конца вправо. Кнопки «Отменить» (Undo) после удаления подписки нет.
- Возможность переключения in-stock → price требует подтверждения. Временно: прежняя подписка не сохраняется даже при ошибке создания новой.
- Данные Price List обновляются только при повторном открытии прайса. Экран показывает цену на момент запроса. При переходе к покупке проверяются изменения цены и рейтинга; при обнаружении изменения показывается alert «Упс…», а не ожидается простая замена цены без предупреждения. Изменение рейтинга также вызывает alert при прежнем лучшем поставщике/цене. Возврат на Главную с закрытием прайса/покупки подтверждён; момент закрытия относительно подтверждения alert — остаток Q32 в чек-листе.
- Дополнительные причины alert «Упс…» — наступление КТ и изменение даты поставщиком. Они учитываются при проверке перехода к покупке наряду с ценой/рейтингом, даже если цена не изменилась. Определение и точная временная граница КТ — открытая часть Q04.
- После такого бизнес-alert покупка и Price List закрываются, возврат на Главную; это также относится к обнаружению изменения во время перехода из прайса. Точный момент закрытия относительно подтверждения alert и состояние Главной ещё не заданы. [Правила покупки](purchase.md) отделяют это от сетевой ошибки с сохранением ввода.
- Сохранённый target не меняется при изменении цены, даже если оказался вне нового диапазона. При редактировании отображаются актуальные границы диапазона; положение ползунка для target вне диапазона — Q29.
- Уведомление достижения цены срабатывает при фактической цене, равной или ниже target, включая падение сразу ниже target. В событии списка Notifications показывается фактическая цена, а не сохранённый порог.
- Строка существующей подписки внутри Price List показывает target, а не цену события. Фактическая цена события ниже target не подменяет порог. Состояние подписки после срабатывания остаётся Q28; [правила списка событий](notifications.md) отделены от строк подписок и текста системного push.
- Админ может отключить бренд, модель или спецификацию: предложения скрываются, подписки сбрасываются. При включении активные подходящие предложения возвращаются.
- Доступность проверяется при переходе к покупке; если товар снят админом или нет подходящих предложений поставщиков, показывается alert недоступности.

## Расхождения прежних документов с последними согласованиями

- Q30 закрыт: Undo отсутствует; ценовая подписка редактируется через long press. Ниже и в отдельном документе уведомлений встречаются прежние требования Undo и обычного tap.
- Q03 закрыт: обновление прайса только при повторном открытии, группы сбрасываются. Прежняя формулировка об неизвестном сохранении раскрытия устарела.
- Переключение in-stock → price условное, Q22; прежнее безусловное описание не подтверждает доступность механики.
- Long press по отсутствующей позиции зависит от Q14; прежняя формулировка без условия не закрывает вопрос.
- Согласование экрана покупки уточняет прежнюю актуализацию цены: изменение цены или рейтинга при переходе вызывает alert. Выбор лучшего предложения после нового запроса прайса сохраняется. Старые проверки автоматической подстановки новой цены уточнены с сохранением ID.
- Последующие ответы уточнили основное поведение после бизнес-alert: возврат на Главную с закрытием прайса/покупки. Лучшее предложение для покупки — с минимальной ценой среди подходящих предложений; прежний термин «лучшее по рейтингу» не разрешает выбирать более дорогую цену. Равные цены остаются Q11 / BUY-Q01.

## Правила из прежнего описания экрана

Следующие разделы перенесены без изменения формулировок. При расхождении применять более поздние согласованные правила выше и статусы вопросов в чек-листе.

### Data interpretation
- Date слева — дата, на которую товар выставлен на продажу, плюс дни доставки; если дней доставки 0, отображается дата выставления.
- Подсветка даты показывает товар с текущей КТ.
- Флаг / страна в строке — спецификация устройства для страны производства; если страны нет, отображается иконка девайса.
- Цена — стоимость продавца плюс процент площадки; для reseller дополнительно учитывается наценка основного клиента.
- Красное число справа — количество товара.
- Верхние табы характеристик — значения характеристики товара (например, память для телефона).
- Группы Blue / Orange / Silver — значения цвета.

### Main interactions
- Переключение характеристики в верхнем сегменте.
- Раскрытие и сворачивание группы по цвету.
- Тап по доступной строке открывает экран покупки товара.
- Long press по доступной строке открывает модалку настройки уведомления по цене.
- Тап по строке отсутствующего товара ставит/снимает уведомление о появлении в продаже.
- Long press по отсутствующему товару открывает модалку настройки уведомления по цене.
- Тап по строке price notification открывает редактирование уведомления по цене.
- Удаление price notification происходит в модалке, если довести ползунок до крайнего правого значения удаления.
- Тап по строке in-stock notification снимает уведомление, скрывает check и показывает toast/snackbar с undo.
- Share формирует файл с ценами на товар.
- Close закрывает экран.

### Display rules
- По умолчанию при первом открытии все цветовые группы свернуты.
- После успешного добавления любого уведомления в свернутой группе эта группа должна автоматически раскрыться.
- После успешного добавления уведомления в уже раскрытой группе она остается раскрытой.
- При возврате с экрана покупки выбранная характеристика и состояние раскрытия групп сохраняются.
- При полном закрытии прайса и повторном открытии выбранная характеристика и состояние раскрытия сбрасываются.
- Возможность сохранения состояния раскрытия при обновлении данных не зафиксирована и должна быть проверена.
- Если для характеристики нет ни одной видимой строки, таб характеристики скрывается полностью.
- Для товаров, которые никогда не продавались, строки в прайсе не отображаются, так как нет базы для расчета ценового диапазона.
- Для отсутствующего товара строка не содержит дату и цену.
- Для отсутствующего товара отображается страна/флаг так же, как у обычной строки; если страны нет, показывается иконка девайса.
- Отсутствующий товар не ведет на экран покупки.
- Notification rows отображаются только внутри раскрытой группы.
- В collapsed state группа не показывает отдельный индикатор, что внутри уже есть уведомления.

### Product depth filter
- В настройках пользователь может выбрать минимальную глубину товара.
- При значении `50+` в Price List должны отображаться только предложения с количеством 50 или больше.
- Граница включительная: количество 50 проходит фильтр, количество 49 — нет.
- Фильтр применяется к каждому предложению отдельно, включая раскрытые конкурентные предложения.
- После фильтрации отображается не более трех подходящих конкурентов.
- Предложение с минимальной ценой для перехода в Purchase screen выбирается среди предложений, прошедших фильтр глубины.
- Изменение stock через границу выбранной глубины должно пересчитывать видимость основной и конкурентных строк.
- Применение фильтра не должно удалять существующие подписки с backend.

### Sorting and grouping rules
- Конкуренция сравнивается по модели, стране и характеристике.
- Если есть товар на ближайшую дату, более дальняя дата скрывается.
- Если товар на дальней дате дешевле товара на ближайшей дате, показываются оба.
- Если товар на дальней дате дороже товара на ближайшей дате, дальняя строка скрывается.
- Сортировка товаров внутри списка идет по товару, а внутри — по цене от меньшей к большей.
- Порядок стран задается в админке.
- Порядок цветовых групп задается в админке.
- Порядок значений верхней характеристики задается в админке; обычно идет по возрастанию.
- Строки созданных уведомлений добавляются вниз раскрытой группы и следуют порядку стран, заданному в админке.
- Если уведомление создается/обновляется для той же страны, но по строке с другой датой, обновляется уже существующая notification row.
- У позиции с конкурентными предложениями отображается стрелка раскрытия.
- В раскрытом виде выводится не более трех конкурентных предложений для одной основной позиции/страны.
- Основная строка не входит в лимит: отображается одна основная строка и до трех конкурентных строк.
- Если конкурентов больше трех, четвертое и последующие предложения не отображаются.
- В лимит попадают первые три предложения согласно сортировке по цене от меньшей к большей.
- Tap по любой конкурентной строке открывает Purchase screen.
- В Purchase screen выбирается предложение с минимальной ценой среди подходящих, а не конкретное конкурентное предложение, по строке которого выполнен tap.
- Цена в Purchase screen соответствует минимальной цене подходящего предложения; выбор между равными ценами — Q11.
- Long press по конкурентной строке не открывает модалку настройки price notification и не создаёт/не изменяет уведомление.
- Настройка price notification выполняется через long press по основной строке товарной позиции.

### Notification rules
- Поддерживаются два взаимоисключающих типа уведомления на одну товарную позицию/страну:
  - без суммы — сообщить, когда товар появится в продаже;
  - с суммой — сообщить, когда цена станет равной или ниже целевой.
- Одновременно два типа уведомления на одну и ту же товарную позицию/страну существовать не должны.
- Если сначала было установлено уведомление о поступлении, а затем пользователь настраивает уведомление по цене, остается только уведомление по цене; уведомление о поступлении сбрасывается.
- Для доступной строки long press создает или редактирует ценовое уведомление.
- Для отсутствующей строки tap работает как уведомление о поступлении.
- Для отсутствующей строки long press открывает модалку ценового уведомления.
- После успешного добавления уведомления по цене в списке появляется колокольчик и отдельная notification row внизу раскрытой группы.
- После успешного добавления уведомления о поступлении у товара появляется check, строка не пересортировывается, также появляется колокольчик / notification row внизу раскрытой группы.
- Тап по price notification row открывает редактирование.
- Тап по in-stock notification row удаляет уведомление без confirm dialog и показывает toast/snackbar с undo.
- Удаление ценового уведомления выполняется через модалку, если ползунок довести до крайнего правого значения удаления; после этого notification row исчезает.

### Price modal rules
- Верхняя граница диапазона равна текущей / максимальной цене товара.
- Нижняя граница диапазона равна текущей / максимальной цене минус 50 USD.
- Шаг ползунка — 1 USD.
- Валюта — USD.
- После отпускания ползунка значение сохраняется автоматически.
- Дополнительная задержка после отпускания ползунка ожидается около 0.5 секунды.
- Модалку можно закрыть без сохранения.
- Если ценовое уведомление уже было задано ранее, модалка должна открываться с текущим выбранным значением.
- Поведение для очень дешевых товаров, где price - 50 может уходить за допустимую границу, должно быть отдельно проверено.
- Для reseller остается открытый вопрос: целевая цена должна считаться по финальной отображаемой цене или по базовой цене без reseller markup.

### Push / notification copy
- Тип уведомления о поступлении: `Now in stock`.
- Тип уведомления о целевой цене: `The price has reached your target`.
- Локализацию этих текстов стоит проверить хотя бы один раз.

### Validation rules
- Для недоступных ранее не продававшихся товаров уведомление не может быть создано, потому что строка не выводится в прайс.
- Уведомление можно поставить только на позиции, которые отображаются в прайсе.
- Для одной товарной позиции/страны должна сохраняться только одна актуальная подписка.

### Error states
- Backend может не вернуть отсутствующие ранее продававшиеся товары, и тогда UX уведомлений о поступлении будет неполным.
- Возможны расхождения между UI и backend по типу уведомления, стране или условию по цене.
- Нужно отдельно проверять поведение при обновлении данных экрана, чтобы понять, сохраняется ли раскрытие групп.

### Open questions
- Для reseller нужно подтвердить, считается ли порог ценового уведомления от финальной отображаемой цены или от базовой цены без reseller markup.
- Нужно зафиксировать фактическое поведение long press по отсутствующему товару, если продукт доступен только для сценария уведомления о поступлении: сейчас отмечено потенциальное расхождение/упущение в реализации.
