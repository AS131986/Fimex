# Правила: Детали общего заказа — клиент и корп, Fimex Buyer, iOS

[Описание](../03-screens/orders/order-detail-client-corporate.md) · [Чек-лист](../05-test-design/orders/checklist-order-detail-client-corporate.md)

## Область и связь со списками

- Этот экран открывается из общего списка «Мои заказы» клиентом/корпом; в нём могут быть товары клиента, корпа и связанных реселлеров.
- Цена позиции, Amount и содержащие цены документы без клиентской наценки, включая товары реселлера. Стоимость гарантии и применимый Cash/Online учитываются.
- Детали «Клиентских» и собственного заказа реселлера будут отдельными документами; их ручная оплата/выдача не копируются сюда.
- Последнее описание уточняет раннюю формулировку «работа с заказом реселлера только из Клиентских»: в общем заказе до КТ клиент/корп может менять логиста позиции реселлера и применять общие действия меню. Гарантию реселлерской позиции здесь менять нельзя; отдельная клиентская оплата/выдача остаётся в «Клиентских».

## Хедер, статусы и автоматическая оплата

- Хедер: номер заказа по центру, три точки с меню, крестик. Не переносить условие видимости трёх точек списка (доступ к режиму реселлера) в деталку: здесь меню заказа доступно клиенту/корпу.
- Pending assembly → Order pending delivery → Released, цвета серый → красный → зелёный.
- В первом статусе отметка оплаты скрыта; со второго отражает автоматическую оплату с общего баланса клиента/корпа по [правилам общего списка](my-orders-client-corporate.md). Изменение вкладки владельца не превращает общую оплату в ручную отметку реселлера.
- Достаточный баланс — Paid; недостаток — отрицательный баланс на недостающую сумму и Not paid, после покрытия задолженности автоматически Paid. Точные суммы для товаров реселлеров/нескольких долгов остаются ORD-Q06.
- По умолчанию в блоке статусов фокус на текущем. Раскрытие показывает все статусы в порядке перехода, сворачивание возвращает текущий.
- У первого статуса дата/время соответствующей КТ, даже если время ещё впереди; это исключение из правила скрытия даты будущих статусов. Не использовать вместо неё момент покупки/создания заказа.
- У последующих наступивших статусов фактическая дата/время, у ненаступивших их нет. Отображение времени истории статусов по МСК подтверждено; это не закрывает часовой пояс расчёта доставки/границу КТ в других экранах.

## Вкладки, показатели и товары

- Только товары основного клиента — вкладок нет. Только корп либо только реселлер — вкладка владельца и All. Несколько владельцев — вкладки присутствующих покупателей и All.
- All есть всегда, если показана хотя бы одна вкладка. Не переносить сюда правило клиентского списка о скрытии All при одном реселлере. На одном примере All выбрана; обязательный выбор по умолчанию не подтверждён — ORDDET-Q04.
- Выбор вкладки фильтрует товары по владельцу и пересчитывает Qty/Amount. All показывает весь заказ; если вкладок нет, тоже весь заказ. Поддержка горизонтального свайпа не уточнена — ORDDET-Q04.
- Qty — сумма количеств единиц, не позиций. Amount — сумма соответствующих товаров с гарантией/типом оплаты, без наценки клиента.
- Список товаров в порядке админки. В строке флаг страны либо иконка, название, цена за единицу и количество; ниже текущая гарантия.
- Покупки одного товара по разным ценам либо с разной гарантией — отдельные позиции. Для проверки не подменять цену заказа текущей ценой прайса.
- Порядок вкладок/позиции при равенстве сортировки, сохранение выбора после переноса/исчезновения владельца и обычного повторного входа — ORDDET-Q04.

## Меню: логист и тип оплаты

- До КТ текущий логист доступен для смены, Cash/Online показаны и могут быть изменены. После КТ логист виден, tap недоступен; тип оплаты скрыт.
- Изменение из меню применяется ко всему заказу, даже при выбранной вкладке одного владельца. Вкладка ограничивает просмотр/документы, не область этих двух действий.
- Меняются только данные текущего заказа, а не настройки логиста/тип оплаты аккаунта для будущих покупок.
- Логист из меню: список логистов → выбор → окно его данных/лицензии → «Подтвердить». Только подтверждение применяет выбор, закрытие без подтверждения оставляет прежнего. Выбранный пункт до подтверждения не считается сохранённым.
- Скачивание лицензии открывает системный Share. Точный набор реквизитов, формат/срок лицензии, отсутствующая лицензия и ошибки — ORDDET-Q06.
- После успешной смены актуальный логист в меню; при смене оплаты текущий выбранный вариант, новые цены каждой позиции и Amount. Группировка/переход в заказ назначения ниже.
- Тип оплаты при удорожании проверяет доступный лимит каждого владельца затронутых товаров. Клиент/корп используют общий лимит, реселлер — свой. Чужой достаточный лимит не заменяет недостаточный лимит владельца.
- Проверяется прирост занятой суммы, не полная сумма как новая покупка; при удешевлении разница возвращается в доступный лимит. База расчёта резерва реселлера относительно отображаемых цен без наценки, включительная граница и частичная/атомарная обработка смешанного заказа при отказе — ORDDET-Q03.
- Полные правила пересчёта Cash/Online относительно зафиксированной цены/комиссий — ORDDET-Q02. Не трактовать изменение оплаты как повторную покупку по текущему прайсу.

## Редактирование гарантии и логиста позиции

- До КТ tap по товару клиента/корпа с доступной гарантией открывает Warranty / Ship To. У реселлерской позиции и товара без возможности гарантии — только Ship To, без доступной смены гарантии клиентом/корпом. Сам реселлер меняет гарантию до КТ из [собственной деталки](order-detail-reseller.md), без смены логиста; после применимого открытия/обновления здесь актуальны гарантия, объединение совпадений своего владельца и суммы без клиентской наценки.
- После КТ tap по позиции не открывает редактор.
- Warranty показывает выбранную позицию (название/флаг либо иконка), текущую гарантию, барабан сроков и цен, Confirm/Cancel.
- Цена конкретной покупки фиксируется на момент покупки, от неё считается гарантия. У одного товара, купленного по разным ценам, значения барабана различаются. Сроки/проценты задаёт админ; применение текущей либо зафиксированной конфигурации процентов при последующей смене — ORDDET-Q02.
- Выбор барабана применяется только после Confirm ко всему количеству выбранной позиции. Другая позиция того же товара по иной цене/гарантии не меняется вместе с ней. Cancel/закрытие без Confirm не применяет выбор.
- При увеличении суммы по гарантии проверяется прирост по лимиту владельца, при нехватке — alert превышения лимита как в покупке; выбранная гарантия не применяется. При уменьшении освобождается разница. Успех обновляет цену/гарантию позиции и Amount текущей вкладки/заказа.
- Ship To показывает конкретную позицию, текущего логиста, барабан логистов и Confirm/Cancel. Применение после Confirm; до него позиция остаётся в прежнем заказе.
- Подтверждённая смена логиста переносит всю выбранную позицию со всеми её единицами в заказ назначения, открывает его и пересчитывает оба заказа. Перенос логиста не объявлен освобождением лимита/новой покупкой; точный учёт резерва при перемещении — ORDDET-Q03.
- Порядок сохранения чернового выбора при переключении Warranty / Ship To и точное оформление ограниченных редакторов — ORDDET-Q04.

## Группировка, перенос и объединение

- Ключ общего заказа: дата поставщика + тип оплаты + поставщик + логист. Логист — подтверждённая часть ключа, несмотря на его пропуск в первом описании.
- После изменения логиста позиции/всего заказа или типа оплаты открывается заказ назначения с новыми параметрами. Если такой уже есть, товары объединяются в нём; иначе создаётся соответствующий заказ.
- Совпадающие позиции одного владельца с одинаковым товаром/ценой/гарантией суммируют количество. Разные цены/гарантии не сливаются; владельцы не теряются при объединении смешанного общего заказа.
- Позиция не остаётся одновременно в источнике и назначении. Остаток источника пересчитывается; если товаров больше нет, исходный заказ удаляется. Qty/Amount назначения учитывают принятые позиции, не теряя прежние.
- Новые номера, выбранная вкладка/история статусов объединённого заказа, дополнительные признаки идентичности товара (страна/код и прочее), слияние после одной смены гарантии и применение КТ к уже существующему назначению — ORDDET-Q01/04. Не присваивать номер или таймлайн произвольно.

## Документы

- Invoice, Packing List и IMEI/SN доступны на любом статусе, каждый в Excel и PDF. После выбора открывается файл в актуальном состоянии.
- All либо отсутствие вкладок — документы по всему заказу; ID — только по товарам соответствующего владельца. Формирование не ограничивает общие действия меню по логисту/оплате.
- Цены в документах, содержащих цены, без наценки клиента, включая товары реселлера. Не добавлять произвольные ценовые колонки в Packing List/IMEI только ради проверки этого правила.
- После гарантии/оплаты/переноса файл соответствует актуальным данным соответствующего заказа и выбранного владельца, не прежнему кэшу.
- Доступность IMEI/SN не требует заранее заполненных серийных данных; файл содержит актуальные данные. Вид незаполненных полей/колонки/формат имён/расширения и способ открытия/дальнейшего Share — ORDDET-Q05; ответ о файле не подтверждает системный Share документов заказа.

## КТ, закрытие, полный экран и ошибки

- После КТ заказ не редактируется: меню логиста недоступно, тип оплаты скрыт, редактор по tap не открывается. Документы остаются доступны.
- Если гарантию/логиста начали менять до КТ, а Confirm нажали после КТ, визуально ничего не происходит и данные не меняются. Alert «Упс…»/возврат на Главную не ожидаются: такое текущее поведение принято пользователем. Не объявлять отсутствие feedback дефектом в этом кейсе.
- Ровно в КТ, смена времени КТ поставщиком, тип оплаты в уже открытом меню и реакция остальных элементов при наступлении КТ на открытом экране — ORDDET-Q07.
- Крестик и свайп вниз закрывают деталку в список. Список обновляется с сохранением существующего фильтра по своим правилам; перемещение/удаление исходного заказа отражается после возврата.
- Full-screen mode открывает горизонтальный просмотр номера, вкладок (если есть), товаров/количества/цены/гарантии. Это просмотр без редактирования. Его крестик возвращает в обычную деталку с сохранением выбранной вкладки.
- Автоматический поворот/возврат к портрету, положение прокрутки, загрузка/refresh/real-time самой деталки, ошибки действий/файлов/потерянный ответ — ORDDET-Q06/08. Стандартные ошибки общего списка не задают автоматически конкретное поведение каждого действия деталки.

## Открытые вопросы

- **ORDDET-Q01:** номер/история статусов при создании и объединении, дополнительные признаки идентичности позиции, повторные покупки одного владельца/слияние после гарантии, перенос в заказ с уже наступившим КТ. Основной ключ и суммирование совпадений подтверждены.
- **ORDDET-Q02:** проценты гарантии/комиссий при изменении админской конфигурации после покупки, точная формула Cash/Online и округление. Зафиксированная цена конкретной покупки как база гарантии подтверждена.
- **ORDDET-Q03:** стоимость резерва реселлера при показе цен без его наценки, равенство прироста доступному лимиту, атомарность смешанного заказа при нехватке у одного владельца, гонки лимита и перенос резерва без повторного занятия. Проверка прироста/возврат разницы и лимит именно владельца подтверждены.
- **ORDDET-Q04:** порядок и выбор вкладки по умолчанию, поддержка свайпа, порядок равных позиций, выбранная вкладка после переноса/удаления владельца и повторного входа, черновики Warranty / Ship To, повторное подтверждение без изменения. All всегда при наличии вкладок и сохранение вкладки после full-screen подтверждены.
- **ORDDET-Q05:** колонки/имена/расширения файлов, незаполненные IMEI/SN, способ открытия/дальнейшей передачи и повторная генерация во время изменения заказа. Все три документа, оба формата, любой статус и актуальные данные подтверждены.
- **ORDDET-Q06:** состав данных логиста/формат лицензии, отсутствие лицензии, ошибки загрузки/сохранения/формирования/Share, retry и потерянный ответ. Лицензия открывает системный Share, выбор логиста применяется только после подтверждения.
- **ORDDET-Q07:** точная граница КТ, смена КТ поставщиком, гонка типа оплаты и обновление элементов открытого экрана при КТ. Для гарантии/логиста Confirm после КТ — без визуальной реакции и без изменения; время таймлайна по МСК подтверждено.
- **ORDDET-Q08:** загрузка/ручной refresh/real-time самой деталки, обновление при возврате из вложенных окон, поворот устройства/портрет после full-screen, позиция прокрутки и экран старого номера после его удаления другим пользователем.

## Статус

Основано на описании, ответах и скриншотах пользователя. Неизвестные части ожиданий Blocked до уточнения. Проверки приложения, файлов, лимита и перемещения товаров не выполнялись.
