# Правила: Управление активной P2P-заявкой — все роли

## Доступ и данные

- Общая заявка клиента/корпа доступна обоим для изменения/удаления/принятия предложения; общие лимит и депозит. Реселлер только собственные П2П, клиент/корп его П2П не видят.
- Собственная цена/запрошенное количество берутся из сохранённой заявки. Встречная цена — отдельное поле; поставщик не меняет количество. Пара `запрошенное / предложенное` относится к одинаковому количеству, не текущему остатку в продаже.
- Клиент/корп без клиентской наценки; реселлер видит собственную/встречную цену и гарантийные варианты с процентом клиента. Момент фиксации этого процента пока P2PACT-Q03.
- Дата, информация о товаре, Share, переключение Pre-Order/P2P наследуют [создание](p2p-request.md); обычное закрытие/переключение не удаляет активную заявку.

## Изменение и резерв

- Tap поля либо кнопки изменения открывает ввод с клавиатурой. Цена: минимум `floor(P × 0,9975)`, максимум 99999.99, 5 целых + 2 дробных цифры; количество целое 50–9999, максимум 4 цифры, допускается выше остатка продаваемого товара. Не нормализовать количество по правилам Pre-Order.
- Сохранение только через «Продолжить»; несохранённый ввод не меняет заявку и не является новым резервом.
- Увеличение стоимости проверяется относительно резерва именно этой заявки и свободного остатка; при уменьшении разница освобождается. После успешного изменения цены/количества прежняя встречная цена сбрасывается; отменённый/неуспешный ввод не считать сохранённым изменением.
- Пусть R — резерв заявки до действия, L — свободный остаток, N — требуемая стоимость по новой цене/количеству/гарантии. Доступная для этого действия сумма — **R + L**, дополнительная потребность при увеличении — **N − R**. Чужие резервы не входят в R. Точность/равенство границе и атомарность остаются P2P-Q03 / P2PACT-Q02/05.
- В результате успешной покупки занимающая лимит сумма относится к покупке, не одновременно к прежней активной заявке и второму полному заказу. Не объявлять снятие заявки после сделки полным освобождением лимита покупки.

## Принятие предложения покупателем

- «Подтвердить» доступно при встречном предложении, проверяет лимит по его цене и неизменному количеству с учётом R + L.
- Недостаток лимита — финансовый alert, не успешная покупка.
- Гарантия доступна у товара — показывается выбор/отказ; цена варианта за единицу, для проверки нужно всё количество. После выбора/продолжения ещё одна проверка лимита с гарантией.
- Без возможности гарантии блок не показан, появляется «Купить». Точная финальная кнопка/число шагов при наличии гарантии — P2PACT-Q02.
- «Отменить» возвращает активную заявку с прежним предложением/резервом; это отмена процесса покупки, не удаление заявки.
- После успешного окончательного оформления toast подтверждения и обновление до дефолтной формы создания; подтверждение только первого этапа не считать успехом сделки.
- Только успешная подтверждённая сделка становится завершённой в Истории P2P. Конкретный номер/состав/объединение созданного заказа и его логист/тип оплаты пока P2PACT-Q02.

## Подтверждение поставщиком

- Поставщик принимает сохранённую собственную цену и количество покупателя; дополнительную гарантию пользователь не выбирает, дефолт — без неё.
- Успех отражается в real-time: toast подтверждения, обновление открытого окна до формы создания, заявка больше не активная и считается успешной для Истории P2P.
- Инициатор подтверждения не меняет область средств: общий лимит/депозит клиента/корпа либо собственный реселлера. Технические проверки/конфликт действий — P2PACT-Q02/05.

## Удаление и real-time

- Удаление вручную сразу, без отдельного подтверждения; массовое удаление из списка требует подтверждения.
- КТ, изменение цены/рейтинга/даты товара, снятие с продажи и удаление админом удаляют активную заявку. Ответная цена в П2П не является этим изменением цены товара.
- При удалении резерв полностью освобождается, заявка не становится успешной Историей. В открытом окне toast «Удалено», обновление к состоянию перед созданием — и для ручного, и для внешнего удаления.
- Список/открытая заявка real-time, скелетон при загрузке. Ручного refresh нет. Не подменять внешнее удаление активной заявки бизнес-alert создания/покупки с возвратом на Главную.

## Открытые вопросы

- **P2PACT-Q01:** точный маршрут изменения одного поля/кнопки «Продолжить», сохранение второго значения, отмена/закрытие клавиатуры/несохранённого ввода, минимум для очень малой цены; наследуемые запятая/вставка/ведущие нули — P2P-Q01/02. Только Continue, валидация как создания и сброс старого встречного после изменения подтверждены.
- **P2PACT-Q02:** точная финальная кнопка ветки с гарантией; депозит/прочие проверки при подтверждении поставщиком; номер/состав/объединение нового заказа, его логист/тип оплаты; разрешение N = R + L и точность сумм. Финансовые точки П2П, учёт резерва/остатка, общие средства клиента/корпа и дефолт без дополнительной гарантии при подтверждении поставщиком подтверждены. Равенство лимиту также P2P-Q03.
- **P2PACT-Q03:** какой процент клиента применяется реселлеру после изменения настройки наценки во время активной заявки, момент его фиксации; база/округление вариантов гарантии и цены с наценкой. Показ всех цен/вариантов реселлеру с установленной клиентом наценкой подтверждён; нельзя объявить её замороженной при создании без ответа.
- **P2PACT-Q04:** точные стартовые значения дефолтной формы после удаления/успеха, состояние Pre-Order при переходе, какой товар остаётся при снятии с продажи; сохранение фильтра/прокрутки списка при обычном возврате. Обновление открытой заявки до создания и toast «Удалено»/подтверждения заданы; автоматическая новая заявка не создаётся.
- **P2PACT-Q05:** конкурирующие Continue/подтверждение/КТ/внешнее удаление и редактирование другим аккаунтом, события во время клавиатуры/гарантии, повторный tap/потеря ответа после фактической сделки, ошибки/восстановление real-time, точные тексты/сохранение предложения при финансовом отказе. Серверная идемпотентность не доказана блокировкой UI. Скелетон/отсутствие ручного refresh/real-time и полное освобождение при удалении подтверждены.

## Представление в Истории

[История П2П](p2p-history.md) показывает цену успешной покупки без дополнительной гарантии и инициатора завершения; наценка реселлера сохраняется в представлении роли. Отбор по созданию заявки, строка/сортировка по покупке. Отсутствие гарантии в цене Истории не отменяет её стоимости в оформленной покупке/резерве.
