# Правила: Настройки — Fimex Buyer, iOS

[Описание](../03-screens/home/settings.md) · [Чек-лист](../05-test-design/home/checklist-settings.md)

## Глубина

- Доступны только `1+`, `5+`, `20+`, `50+`, `100+`, без промежуточных значений.
- Глубину можно выбирать ползунком или tap по конкретному значению.
- Граница включительная для каждого значения: количество, равное порогу, подходит; меньше порога — нет.
- Выбор доступен клиенту, корпоративному пользователю и реселлеру.
- Глубина индивидуальна для каждого аккаунта, не является общей настройкой клиента с дочерними аккаунтами.
- Выбранная глубина применяется только по галочке сохранения.
- После сохранения Главная обновляется и показывает бренды/категории/модели с учётом сохранённой глубины; отдельный ручной refresh для применения не требуется.

## Сохранение и отмена

- Галочка сохраняет изменения и закрывает sheet.
- Закрытие жестом либо tap снаружи без галочки отменяет выбранные изменения глубины и типа оплаты.
- До сохранения выбор не считается применённой настройкой. Экспорт до галочки использует ранее сохранённые глубину и тип оплаты, а не новые выбранные значения. SETTINGS-Q01 закрыт.
- Для ошибки сервера/отсутствия интернета при сохранении или экспорте показывается стандартный alert. Точные строки и состояние sheet после ошибки не заданы.

## Тип оплаты и связанные аккаунты

- Выбор Cash/Online доступен только клиенту и корпоративному пользователю; у реселлера блок скрыт.
- Тип оплаты общий для клиента и связанных корпов. Изменение клиентом либо любым его корпом влияет на всю связанную группу, включая реселлеров.
- Реселлер использует установленный группой тип оплаты и не может выбрать свой в этих настройках.
- Выбор применяется только после галочки сохранения.
- У изменяющего аккаунта настройка/цены обновляются сразу после сохранения.
- У других уже вошедших связанных аккаунтов при попытке купить по прежней цене возникает ошибка, что цена товара изменилась. При повторном запросе прайса цены актуальны.
- Это не подтверждение real-time обновления открытого прайса на другом аккаунте. Момент реакции и способ повторного запроса не заменять вымышленным сценарием.

## Экспорт Excel

- Строка Price-list открывает барабан выбора процента.
- Минимум — 0,25%, максимум — 4,25%.
- От 0,25% до 0,95% шаг — 0,1 процентного пункта; далее 1,00%, затем 1,25–4,25% с шагом 0,25. Стык 0,95 → 1,00 → 1,25 подтверждён при согласовании такого же барабана [покупки](purchase.md); SETTINGS-Q02 закрыт.
- При открытии выбран процент 0,55%; он допустим для уточнённого шага нижнего диапазона. Первоначальное сообщение о едином шаге 0,25 исправлено пользователем.
- После выбора процента формируется Excel-файл со всем соответствующим прайсом и ценами с выбранной наценкой.
- На состав файла влияет глубина аккаунта.
- В файле только товары с первым рейтингом, которые сейчас в продаже. Не экспортируются все конкуренты, отсутствующие товары и строки подписок.
- Алгоритм рейтинга, равенства рейтинга, точные колонки и расширение файла требуют уточнения.
- Настройки оплаты и применимая цена аккаунта влияют на цену экспорта. Выбранная наценка экспорта начисляется на итоговую цену приложения для соответствующей роли.
- Если P — итоговая цена приложения, а m — процент экспорта, цена файла до округления равна `P × (1 + m / 100)`. Точность/округление и база дополнительной наценки реселлера — SETTINGS-Q03.
- Экспорт до галочки использует сохранённые значения глубины/оплаты — SETTINGS-Q01 закрыт.

## Цена и настройки админки

- Наценка по типу оплаты задаётся админом и может меняться.
- В исходном описании текущие значения — 0,5% Cash и 0,25% Online. Это пример текущей конфигурации, не постоянные требования.
- Процент может задаваться для бренда, модели, спецификации. Более конкретная строка переопределяет общее значение: если для iPhone 1%, а для iPhone 18 0,5%, модель 18 получает 0,5%, остальные — общее 1%.
- Комиссия площадки и есть процент, зависящий от выбранного типа оплаты. Второй раз отдельную комиссию площадки поверх него не добавлять.
- Клиент и корп: цена поставщика с комиссией площадки для применимого типа оплаты и товара.
- Только у реселлера дополнительно применяется наценка, установленная клиентом. У корпа этой дополнительной наценки нет; прежний ответ о ней для корпа уточнён пользователем.
- Excel применяет выбранный процент к уже итоговой цене приложения, включающей применимые компоненты роли.
- База начисления дополнительного процента клиента реселлеру и точность/округление не подтверждены; не вычислять эти части произвольно.
- Точная цепочка приоритетов спецификация/модель/бренд и fallback также требуют уточнения.

## Открытые вопросы

- **SETTINGS-Q01:** закрыт — экспорт до галочки использует ранее сохранённые настройки.
- **SETTINGS-Q02:** закрыт — дефолт 0,55%; значения 0,25–0,95 с шагом 0,1, затем 1,00 и 1,25–4,25 с шагом 0,25. Переход 0,95 → 1,00 → 1,25 подтверждён.
- **SETTINGS-Q03:** частично закрыт — дополнительная наценка клиента только у реселлера; комиссия площадки равна проценту типа оплаты; наценка Excel на итоговую цену приложения. Остались база наценки клиента реселлеру и точность/округление.
- **SETTINGS-Q04:** точные приоритеты спецификации/модели/бренда, общий процент по умолчанию и поведение без настроенной строки; взаимодействие нескольких подходящих строк.
- **SETTINGS-Q05:** алгоритм первого рейтинга/равенства и влияние глубины на выбор победителя, если предложение с первым рейтингом не проходит глубину; структура колонок, расширение, имя и способ передачи файла.
- **SETTINGS-Q06:** подтверждение/отмена барабана, сохранение выбранного процента для следующего открытия; меняет ли процент только файл, без изменения цен приложения?
- **SETTINGS-Q07:** где сохраняется индивидуальная глубина, восстановление после logout/login/перезапуска; начальная глубина нового аккаунта.
- **SETTINGS-Q08:** тексты/кнопки стандартного alert, состояние sheet/выбранных значений и retry после неудачного сохранения/экспорта; потеря ответа после успешного серверного сохранения.
- **SETTINGS-Q09:** UI ошибки изменения цены на другом аккаунте, способ повторного запроса прайса, переход в покупку без изменения числовой цены; сброс выбора Главной после сохранения и поведение сохранения без изменений.

## Согласованность

Подтверждённый момент применения глубины уточняет часть HOME-Q02 в [правилах Главной](home.md); остальные части вопроса остаются открытыми. Вопросы расчёта цены в Price List не закрывать целиком: точность и наценка Reseller ещё требуют уточнения. Реальные расчёты и получение файла не проверялись.
