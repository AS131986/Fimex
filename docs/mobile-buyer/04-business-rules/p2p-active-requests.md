# Правила: Список активных P2P-заявок — все роли

## Доступ и стоимость

- Клиент и связанный корп видят общие заявки и вправе редактировать/удалять их. Общий лимит и депозит; отдельный лимит корпа не создаётся.
- Реселлер видит только свои заявки; клиент/корп не видят его П2П и не управляют ими через общий список. Заявки другого реселлера/группы также исключены.
- Собственная и встречная цены единицы: клиент/корп без клиентской наценки, реселлер с наценкой клиента. Не подменять цену заявки текущей ценой товара; изменение текущей цены в продаже удаляет заявку, а встречное предложение не удаляет.
- Строка показывает название/флаг либо иконку, сохранённую собственную цену/количество, ответную цену при её наличии. Встречная цена не становится собственной до успешного согласованного действия.

## Порядок, фильтр и история

- По дате оформления, новые первыми. Равные даты/редактирование относительно даты сортировки — P2PLIST-Q01.
- «Все чаты» включает все активные заявки, «Поставщик» только со встречной ценой. Переключатель появляется при наличии ответа; дефолт/сохранение/исчезновение последнего ответа не уточнены.
- «Очистить все» действует на **весь доступный активный набор**, а не только строки выбранного фильтра; подтверждение обязательно. Отмена сохраняет все заявки/резервы.
- Книга «История P2P» скрыта, если в течение года не было успешной сделки доступной области. Только успешно завершённая покупка, подтверждённая пользователем или поставщиком, учитывается как завершённая заявка; удаление/КТ/снятие товара не становятся успехом.
- [История P2P](p2p-history.md) описана отдельно: период по дате создания заявки, показ/сортировка по покупке, цена без гарантии. Границы года остаются P2PLIST-Q02; периоды/архивирование обычных заказов не переносить автоматически.

## Жизненный цикл и обновление

- Активность до КТ. Удаление также при смене цены/рейтинга/даты товара, снятии с продажи, удалении админом и вручную.
- Удаление полностью освобождает резерв этой заявки, не чужих активных заявок/покупок. Успешная сделка переносит сумму в покупку по правилам [деталки](p2p-active-request.md), а не освобождает её как простое удаление.
- Real-time применяется к списку и открытой деталке: ответ поставщика, подтверждение, изменение товара и удаление. Ручного refresh нет, скелетон при загрузке.
- В открытой удалённой заявке refresh и возврат к форме до создания, toast «Удалено», как при ручном удалении; без обязательного возврата на Главную из сценария создания.
- Бейдж показывает ответы поставщиков, а не число заявок/непрочитанных. Изменения после удаления/завершения — NAV-Q03; не закрывать вопрос одним экранным значением.

## Пустота

- Нет активных заявок — информационная карточка с тремя пунктами о покупке дешевле, своей цене и партиях 50+ по [образцам](../03-screens/p2p/p2p-active-requests.md#пустое-состояние-и-обновление).
- Заголовок/нижнее меню остаются. Книга может быть видна и при пустом активном списке, если есть успешная История года.
- Реакция пустого фильтра «Поставщик» при других активных заявках отдельно P2PLIST-Q01, не считать это полной пустотой.

## Открытые вопросы

- **P2PLIST-Q01:** дефолт/сохранение «Все чаты» или «Поставщик» при новом входе/возврате, исчезновение последнего ответа, пустой результат фильтра, позиция прокрутки; равные даты/часовой пояс, меняет ли редактирование дату оформления/порядок. Новые первыми и состав фильтра подтверждены.
- **P2PLIST-Q02:** частично закрыт — [История P2P](p2p-history.md) и оба режима просмотра описаны; её периоды по созданию заявки, строки/сортировка по покупке, цена без гарантии, только успешные сделки. Остались «в течение года» для книги — скользящие 12 месяцев или календарный год, точное поле даты/граница/часовой пояс проверки её видимости. Дата отбора внутри Истории не определяет автоматически проверку доступности книги.
- **P2PLIST-Q03:** ошибки/старые данные/восстановление real-time после потери сети/возврата из фона, loading при возвращении, задержка/атомарность массового удаления, toast массовой очистки. Скелетон/real-time и отсутствие ручного refresh подтверждены, стандартный alert управления отдельно не подтверждён.
