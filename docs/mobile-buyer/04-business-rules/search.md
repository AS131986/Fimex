# Правила: Поиск — Fimex Buyer, iOS

[Описание](../03-screens/home/search.md) · [Чек-лист](../05-test-design/home/checklist-search.md)

## Запрос

- Поиск выполняется при вводе с первого символа; отдельное нажатие поиска на клавиатуре не является обязательным запуском.
- Максимум поля — 100 символов.
- Поиск не зависит от регистра.
- Поиск выполняется по категории, модели, характеристикам (память, цвет, размер ремешка и другие) и коду товара. Поиск по бренду отдельно не заявлен.
- Работает часть слова: `phone` находит `iphone`.
- Для нескольких слов важна последовательность в названии; пропуск промежуточной части не является совпадением из описанного примера.
- Пример пользователя: название `iphone 18 pro 256GB Black`, запрос `18 pro black` не даёт результата для этого товара. Запрос не считается произвольным набором независимых слов.
- Точный технический алгоритм, нормализация пробелов, кириллица/транслитерация и частичный код товара не определены; пример не подтверждает любую дополнительную нормализацию.

## Загрузка и результаты

- При загрузке показывается скелетон.
- В результатах показываются все совпадения; определённый порядок или правило сортировки не заявлены. Проверять состав, не назначать алфавитный/ценовой порядок.
- Каждое совпадение значения поиска выделено жирным.
- У найденных товаров отображаются иконки.
- Если результатов нет, показывается состояние No result с сообщением для введённого запроса; это отличается от начальной подсказки без запроса.
- Визуальный пример на английском: `No result`, `Sorry, we couldn’t find any results for “<запрос>”`. Точные переводы и типографика строки не согласованы отдельно.

## Выбор результата

- Tap по результату открывает прайс соответствующей категории либо модели.
- Если в прайсе по выбранному результату поиска только один товар, сразу открывается экран покупки этого товара.
- Один товар в прайсе не равнозначен одной строке результатов поиска. Подсчёт поставщиков, спецификаций, цветов, стран и дат в условии «один товар» требует SEARCH-Q02.
- Запрос-пример пользователя `iphone 18 pro 256GB Black Silver` иллюстрирует ветвление при единственном товаре в прайсе; наличие такого товара в данных не подтверждено.

## История

- История содержит выбранный результат, а не просто текст введённого запроса.
- Запись сохраняется только после tap по результату. Сам ввод, получение списка либо No result не добавляют запись.
- В истории показываются иконки товаров.
- Сортировка по времени поиска, сначала новые.
- История отдельная для каждого аккаунта.
- Clear all очищает историю сразу, без подтверждения.
- Повторный выбор, лимит записей, точный момент сортировки и хранение между сессиями не определены.

## Открытые вопросы

- **SEARCH-Q01:** продаваемость и сохранённая глубина в поиске; alert при снятии результата с продажи между загрузкой и tap; поведение ранее выбранной, но теперь недоступной записи истории.
- **SEARCH-Q02:** что считается одним товаром в прайсе: позиция, вариант, страна/дата или предложение поставщика; выбор поставщика по рейтингу; переходы для кода и конкретной характеристики.
- **SEARCH-Q03:** точное сопоставление нескольких слов/пробелов, частичный код, русские и английские названия, транслитерация, допустимые символы и способ ограничения 101-го символа.
- **SEARCH-Q04:** повторный выбор результата добавляет дубль или переносит запись; лимит истории; время запроса или выбора для сортировки; переход по записи истории.
- **SEARCH-Q05:** локальное/backend-хранение, восстановление после logout/login/перезапуска и на другом устройстве; судьба истории после удаления аккаунта.
- **SEARCH-Q06:** очистка поля крестиком и возврат истории; сохранение запроса при закрытии/возврате из прайса или покупки; сброс поля при новом открытии.
- **SEARCH-Q07:** ошибка сети/сервера и retry, задержка запроса, поздние ответы при быстром вводе; отличия ролей и ограничения доступности поиска.
- **SEARCH-Q08:** точные локализованные тексты пустого состояния, критерий иконки результата, метка NEW; правила выделения повторных/частичных совпадений при сложном запросе.

## Границы согласований

Ответ №3 пользователя уточняет частичное совпадение и последовательность слов, а не подтверждает предыдущий вопрос о глубине/продаваемости. Эти условия не перенесены автоматически из Главной в поиск. Ответ №8 подтверждает немедленную очистку истории, но не поведение крестика поля и повторного открытия. Открытые вопросы остаются явно отмеченными.

Проверки приложения не выполнялись. Price List и история поиска — разные артефакты; обновление истории не доказывает актуальность цены/наличия товара.
